# Rust HTTP API

В кандидате 803 фоновый `POST /api/rag/index-external` записывает нативное
задание, а `GET /api/light/intake` возвращает его этап, причину ожидания и
число восстановлений. Предыдущие записи читаются по прежней схеме.
Мутации точек Qdrant доступны только внутри экземпляра Леса.

С 801 `rust.library` обслуживает создание датасета, пользовательский
каталог, карту и статус импорта. При чтении скрывает служебные наборы и
временные файлы. `/api/light/agent-workspace` использует существующий
Rust-владелец файлов, роль агента и ревизии. Отдельный классический
интерфейс остаётся для настроек, почты и управления документами.

`api/` — Axum 0.8.9 executable `les-api`. Режим Tauri `--native-api` также
включает Rust-запускатель. Внешний loopback-порт API принадлежит Rust; прежний
FastAPI слушает отдельный внутренний порт. Все процессы принадлежат одному
runtime, наблюдаются и завершаются вместе. Отсутствующий binary не включает
скрытый откат. Без флага остаётся прежний режим кандидата 775.

Кандидат 799 передаёт ядру Rust SQL для миграции истории, приёма SSE,
сохранения фрагментов перед доставкой, фиксации финального ответа и
обратной связи. При старте старые незавершённые записи получают статус
`INTERRUPTED`. Переписка и JSON-поля остаются в прежней таблице.
Отдельное чтение назначения модели, актуальной головы и снимка
возможностей заменено одной транзакцией чтения Rust. Проверка секретов,
DNS, политики и пользовательские формы настройки остаются в Python.

Транзакции журнала замены индекса также принадлежат Rust. Решение commit
фиксируется до удаления старых точек, а ревизия и инвалидирование BM25
фиксируются вместе. Qdrant, FTS и возобновление используют тот же журнал
через прежнего координатора Python. [Индекс](bm25-index.md).

Изолированный Windows-пакет прошёл одну цепочку с тестовым провайдером:
регистрация исходника, индексация и поиск Qdrant, модельный вызов
инструмента памяти и отзыв. Остановка процесса посреди потока сохранила
уже видимый фрагмент. После старта история показала `INTERRUPTED` без
повторного вызова модели. Тесты восстановления охватывают остановку до
и после решения commit журнала индекса.

Кандидат 798 разбирает ответ `/api/embed` локальной Ollama в Rust.
Rust ограничивает тело тем же входным лимитом, проверяет наличие ID модели,
ожидаемое количество строк, общую ненулевую размерность и конечность
чисел. Ошибка отклоняет весь пакет. Только превышение размера позволяет
существующему RAG-клиенту повторить запрос меньшими пакетами.
Приватный протокол `ollama-embed.v1` передаёт метаданные одной строкой
JSON и значения в little-endian f64. RAG сохраняет проверку ID модели и
размерности действующего индекса. Для LAN, облака и OpenAI-compatible
эмбеддингов сохраняется прежний транспорт.
На тестовом провайдере значения совпали побитово, включая отрицательный
ноль и субнормальное число. Изолированный Windows-пакет проиндексировал
тестовый файл и нашёл его по векторному запросу без общих слов с текстом.
Неверный ответ второго файла зарегистрирован в журнале и дал ноль
фрагментов. Контрольные суммы исходников совпали.

Кандидат 797 переводит разбор успешного NDJSON-потока локальной Ollama в Rust.
По приватному протоколу `ollama-chat.v1` в Python приходят фрагменты ответа,
сигнал размышления и завершение со статистикой и вызовами инструментов.
Rust отделяет скрытое размышление, сохраняет точность чисел в аргументах
и ограничивает размер строки до её накопления. Окончание без `done`
считается обрывом. Отмена закрывает запрос и до, и после первого фрагмента.
Для декодирования Rust запрашивает несжатый поток. Произвольный
`Content-Encoding` отклоняется. Формирование запросов, инструменты,
история и внешний транспорт по-прежнему Python.
Для сборки использованы уже зафиксированные версии библиотек.
На стенде проверены границы строки без перевода строки, UTF-8 по частям,
разорванные теги размышления, большие целые в аргументах и отмена.
Изолированный Windows-пакет выполнил запрос через `/api/chat/stream`,
прочитал тестовый `USER.md` по вызову инструмента и сохранил ответ.

В кандидате 796 Rust открывает соединение с локальной моделью для
`POST /api/chat` и `POST /api/embed` нативного протокола Ollama. Это
внутренняя операция, поэтому счётчик публичных маршрутов прежний. Python
передаёт уже разрешённый endpoint и готовое тело, затем сохраняет
контракт чата и RAG.

Шлюз включается Rust-запускателем. Он проверяет отдельный случайный токен
на один запуск и отклоняет браузерные запросы, HTTPS, LAN и публичные
адреса, произвольные пути, адреса самого шлюза и FastAPI. Поддерживаются
точные HTTP-адреса loopback без ключа провайдера. Для `localhost` нужны
обе стандартные петли из предварительной проверки, и Rust использует
ровно эти адреса. Прокси окружения, редиректы и повторы отключены. Тело
и ответ передаются потоком. Секрет шлюза и локальные заголовки не
уходят в сервис модели. Журнал сбоев Rust содержит только код и статус.

Облачные, LAN и другие протоколы остаются на существующем транспорте.
Отказ выбранного нативного транспорта не вызывает второй запрос через
Python. Назначения моделей, проверка возможностей, лимиты семантического
ответа, валидация векторов, сохранение и модельный цикл остаются прежними.
На тестовом loopback-сервере проверены ранняя доставка текста, отмена
соединения, оборванный поток, 404 модели, отклонение редиректа и векторы.
Изолированный Windows-пакет прошёл публичный `/api/chat/stream` с записью
ответа в историю. Реальная генерация Ollama в этом испытании не запускалась.

С кандидата 793 прямые локальные запросы к этим маршрутам авторизует Rust.
Он получает политику у FastAPI один раз, затем проверяет ключи и их сроки
в существующей `data/les_meta.db` только на чтение. Роли ключей не кэшируются.
Обычный пользователь может читать проекты, изменение требует admin. Настройки
доверенной сети и списка допустимых Origin применяются с прежней семантикой.

Запросы с заголовками прокси, произвольной настройкой CORS regex и старый
backend используют прежние `require_user`/`require_admin`.
Внутренний маршрут начальной политики исключён из OpenAPI и закрыт с
публичного порта Rust API. Host/Origin ограничены локальными адресами.
OPTIONS и диагностический `/api/auth/trust` пока обрабатывает FastAPI.

С 794 Rust обслуживает список, создание, отключение, отвязку устройства,
удаление и проверку ключей. Проверка роли выполняется в одной транзакции
с изменением. Конкурирующие первые привязки устройства получают один
успешный результат. Особые права защищённых ключей сохранены.
Используется прежний реестр и совместимые миграции колонок. Ответы
маршрутов помечены `x-les-handler: rust.auth-keys` и `Cache-Control: no-store`.
Запросы через прокси и пользовательское правило CORS по-прежнему передаются FastAPI.

Остальные пути явно проксируются прежнему API. Загрузка и ответ идут потоком,
без накопления всего тела; SSE/UTF-8 передаются без перекодирования, отмена
закрывает upstream. Адрес upstream фиксирован в конфигурации, произвольный URL из
запроса не используется. Сохраняется проверенный публичный Host для ссылок на
документы/превью, локальные абсолютные редиректы становятся относительными.
Hop-by-hop заголовки удаляются. `x-les-handler` различает `rust.workspace`,
`rust.catalog`, `rust.agent-state` и `legacy.proxy`, поэтому проксирование нельзя
выдать за перенос реализации.

`--contract` описывает реальное владение. Сборка: `tools/build_native_api.py
--offline --output NEW_DIR`, пакетирование `--native-api FILE` требует
`--native-runtime FILE`. При staging проверяются SHA binary, digest текущих
core/API/version/lock и remap. В локальном патче 779 стандартный ярлык явно
включает `--native-api --svelte`; прямой EXE без флагов сохраняет classic.
Полный установщик не пересобран;
Чат, harness и остальные 238 пар пока проксируются.

Поведенческий gate `tests/test_light_native_api.py`: доступ, CORS, CAS-конкуренция,
неблокирующий отказ занятой БД, побайтовый SSE, отмена, загрузка 2 МиБ, ссылки и
редиректы. Используются отдельный тестовый upstream и собственная временная БД,
модели/документы владельца не нужны. Baseline OpenAPI проверяется отдельно:
`tools/native_api_contract.py --check`. [Runtime](native-runtime.md).
