# DWG, RVT и IFC в папках ЛЕС

Папку с чертежами и моделями можно подключить через «Данные» или
`attach_folder` в MCP ЛЕС. Файлы остаются в исходной папке. Очередь выбирает
читателя по расширению и передаёт поисковые карточки общему индексу. Ссылка
показывает handle DWG, ElementId Revit или STEP ID IFC с проверкой SHA-256 оригинала.
Зарегистрированные проекты Увязки для этого маршрута не требуются.
Открытие оригинала использует установленное приложение для формата.

Читатель DWG получает тексты, блоки и атрибуты, слои и доступные данные листов
через LibreDWG/WASM. Он пропускает геометрию без поисковых свойств.
Для объектов листа ЛЕС сопоставляет `ownerBlockRecordSoftId` с
`paperSpaceTableId`. Карточка получает имя листа и, при однозначном выборе,
текст самой крупной видимой надписи на нём. Источник сохраняет handle объекта,
листа и надписи. При одинаковом максимальном размере разных надписей остаётся
имя листа. Объекты Model и определения блоков не получают контекст видового экрана.
Читатель RVT выбирает классы элементов, семейств, типов, уровней, систем, видов
и спецификаций по родительским классам в записанной схеме. Системы передают
контекст элементам по списку сохранённых участников. Ссылки на уровни и типы
разрешаются по ElementId. Для до 512 недостающих подписей за файл читатель
запрашивает поля графа; неизвестные имена остаются без подстановки.
Если сохранённые связи разрешились в имена, для элемента с именем или
именованным типом создаётся короткий фрагмент связей с тем же ElementId.

При индексации RVT в одном дочернем фрагменте каждого объекта сохраняется
запись `les.rvt-record.v1`: доступные свойства и параметры с исходным
значением, типом хранения, ID и единицами, которые вернул читатель. Имена
параметров берутся из реестра определений этой модели по ID. Формат
отображения проекта хранится отдельно от исходного числа. Значения без
расшифровки сохраняются с доступным ID. Данные объекта меняются вместе
с его индексом. Для ранее проиндексированного RVT запись появляется после
повторной индексации.

При сборке контекста ЛЕС запрашивает записи найденных объектов и сохранённых
типов по ключу из набора, имени файла, SHA-256, раздела и ElementId. Параметры
сопоставляются с вопросом по имени. Выдержка содержит адрес своего объекта
или типа. Повторное чтение RVT для этого шага не требуется.

Читатель IFC использует WebIFC/WASM. Извлекает названия и сохранённые свойства
объектов, простые количества, привязки к типам, помещениям, этажам и системам.
Связи проверяются по `IfcRel*` и сохраняют STEP ID записей. У исходного объекта
сохраняется и GlobalId. При наличии явной единицы она имеет приоритет. Для
распознанных числовых типов применяется сохранённая единица единственного
проекта. Входной формат — файл `.ifc`.

Охват частичный. Внешние ссылки, геометрия и вычисление спецификаций
не входят в обработку. Пределы кандидата: исходник до 1 ГиБ,
до 20 000 записей и до 24 МиБ суммарного поискового текста.

## Сборка кандидата

947 добавляет поверх структурированных записей ведомости `model_inventory`.
Табличная выборка проверяет редакцию индекса и строит списки экземпляров,
вендор-листы и раздельные суммы электрических величин в Вт и ВА.
[Публичный лог по RVT](../public/rvt-inventory-log.md).

948 добавляет режим `dwg_blocks` в эту операцию. Запись `les.dwg-insert.v1`
хранится в одном фрагменте на каждую подтверждённую прямую вставку блока в Model
и содержит её имя, слой, атрибуты и количество с учётом массива. Ведомость
использует эти записи выбранной ревизии, а мощность складывает по явным
значениям атрибута POWER_W. [Публичный лог по DWG](../public/dwg-inventory-log.md).

Режим `model_inventory(mode="dwg_spec")` сверяет одну индексированную книгу Excel
с DWG в том же датасете. Когда книг несколько, выбирается `spec_doc_id`.
Можно ограничить чертёж параметром `doc_id` и задать `spec_sheet` вместе с
`row_start` и `row_end`. Без диапазона используется однозначный раздел
«Светотехническая продукция», если он присутствует, либо строки с единицей «шт.».

Книга читается из опубликованного Parquet. Выноски выбираются из индексированных
карточек TEXT и MTEXT по подтверждённому владельцу пространства модели. Текст
листа и определения блока остаётся доступен обычным поиском. Редакция индекса
закрепляется для всей операции и для продолжения в MCP. Сравнение использует записанные
названия, варианты изделий и коды продукции. Совпадение количества с единственной
подходящей группой блоков при наличии именной выноски возвращается как возможная
связь. Сумма выносок и число вставок показываются раздельно.

С кандидата 950 чат предлагает `model_inventory` моделям с поддержкой
инструментов в пределах выбранного набора с индексированным DWG или RVT.
Вопрос передаётся модели вместе с поисковым контекстом. Расчёт начинается
по вызову инструмента от модели. Профиль чата управляет его доступностью.
Через MCP клиент может вызвать тот же инструмент напрямую.

`tools/engineering_reader_assets.py` принимает существующие локальные
`read-data.mjs` из комплекта Увязки с соседним пакетом LibreDWG/WASM,
исполняемый Node и `ifccs-rvt-metadata`. Он собирает самостоятельный комплект
с хешами файлов. Для локального теста переменная `LES_ENGINEERING_READERS`
указывает на этот комплект. Windows-пакет принимает его параметром
`--engineering-readers` и ставит в `native/engineering-readers`. Установленный
лаунчер сам передаёт этот путь API при наличии `reader-receipt.json`. Для упаковки
используется комплект с лицензиями и ссылками на соответствующие исходники
компонентов. GPL-читатель DWG работает отдельным процессом.
Параметр `--ifc-module` при подготовке комплекта добавляет существующий Node
пакет `web-ifc` с бинарником WASM и лицензией MPL-2.0.
Для `make package` каталог передаётся как `ENGINEERING_READERS`.

Компонент изолирован от моделей и сетевых настроек ЛЕС. Параметры запуска
берутся из локального проверенного комплекта. Путь к исходнику ограничен
правилами внешних папок ЛЕС. Старый маршрут Увязки продолжает обслуживать
снимки и их ссылки на вьювер.

## Приёмка

Настоящий форматный обработчик кандидата прочитал DWG и RVT из внешней папки.
Полученные фрагменты с SHA-256 оригиналов нашли контрольные записи в SQLite
BM25. Rust-тест проверяет отказ при смене содержимого во время чтения.

На проверочном наборе из DWG и RVT (3 724 фрагмента) добавление контекста
листа подняло исходную строку с мощностью освещения с 5-го на 3-е место
по общему вопросу. Использованы BM25, локальный bge-m3 и объединение RRF из
ядра ЛЕС. В выдаче только BM25 по этому вопросу исходной строки не было.

В кандидате 945 пакетная очередь подготовила 12 119 фрагментов из RVT,
реального IFC2X3, тестового IFC4 и DWG. Тест проверил контрольные значения
и связь с исходной ревизией на выходе нативной очереди. На этих фрагментах
поиск BM25 и bge-m3 с объединением RRF поднял связи бойлера с 14-го на 2-е место
после добавления короткого фрагмента. Точные фрагменты IFC заняли 2-е место
по вопросу о системах, 7-е по диаметру и 1-е по напряжению тестовой розетки.
Хранилище в этом прогоне тестовое. Ответы модели и установленная сборка
требуют отдельной проверки.

На нативном стенде 946 с заранее подготовленным контрактом Qdrant
реальная модель RVT дала 1 014 уникальных записей. Обычный вопрос по набору
нашёл параметр изготовителя в записи типа и передал его тестовому ответчику.
Ответ сослался на запись типа. ОС блокировала открытие тестового RVT на
время поиска и ответа.
