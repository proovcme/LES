# Готовые компоненты: приёмка на копии

Статус 870: [Rho подключён к координатору приложения](native-rho-coordinator.md)
в кандидате исходников. Старый цикл удалён, рабочая установка не переключена.
Tantivy пока остаётся отдельным испытанием. Набор согласован владельцем
12.11.2026 для приёмки на копии.
Отдельное [сравнение Swiftide и Rho](../acceptance/native-harness-comparison-869.md)
завершило 39 пар Qwen на том же поиске и читателе: выбран Rho для цикла.
Причины — сохранение протокола/незавершённой истории и меньший объём
необходимых дополнений. Сравнение 869 само не устанавливало SDK в LES;
подключение к исходникам выполнено следующим изменением 870. Рабочие индекс
и назначения моделей не меняются.

| Узел | Компонент | Граница |
|---|---|---|
| Цикл модель → инструменты → модель | Rho SDK 5.15.2 | Один владелец цикла, событий, отмены и снимка сессии |
| Лексический поиск | Tantivy 0.27.0 | Готовые postings, BM25, русский анализатор, фильтры и commit/readers |
| Dense-поиск | Существующий Qdrant Edge | Векторы сохраняются, пересчёт dense не требуется |
| Каталог и состояние | Существующий SQLite/rusqlite | Документы, задания, память и журнал публикации |
| Извлечение | Существующие PDFium, Calamine, XML и OCR-адаптеры | Страницы, таблицы, исходники и ошибки |
| Модели | Существующие Ollama/OpenAI-совместимые подключения | Назначенная роль и фиксированный профиль |

Свой код LES остаётся в проверках области доступа, редакции, исходных
страниц и видимого контекста. SDK не получает права самостоятельно выбирать
модель, читать произвольные файлы или изменять рабочий корпус.

## Почему этот набор

[Rho SDK](https://docs.rs/rho-sdk/5.15.2/rho_sdk/) — встраиваемый runtime,
а не одно из одноимённых приложений. Метаданные crates.io: MIT, Rust 1.86,
семь обязательных зависимостей, default features пусты. Исходный архив
проверен по checksum реестра; отдельный нативный пробник собран и выполнен.
Собственные ModelProvider
и Tool позволяют использовать существующие подключения и инструменты LES.

[Tantivy](https://docs.rs/tantivy/0.27.0/tantivy/) — встраиваемая поисковая
библиотека, MIT, Rust 1.88. Предлагаются features mmap, stemmer,
lz4-compression. Ранжирование, индекс и анализатор берутся готовыми.

Последние Rig 0.46.0/rig-agent требуют Rust 1.97.1 при установленном 1.97.0.
Swiftide Agents 0.34.0 также включает indexing/tasks. Размер зависимостей
сам по себе не определяет выбор: учитываются удаляемый код, Windows,
целостность протокола, остановка, история и продуктовые проверки LES.
Context Harness — отдельный RAG-продукт со своим SQLite-хранилищем; HARNESS
из результатов поиска ориентирован на middleware инференса.

## Приёмка до включения

1. Изолированная сборка на текущем Windows/Rust: вызов инструмента, отмена,
   снимок сессии, русский поиск и жёсткая область доступа.
2. Tantivy строится из тех же зарегистрированных фрагментов копии. Проверяются
   источники, ответные абзацы, фильтры, обновление и восстановление. Фрагменты
   и dense-векторы для этого сравнения не пересчитываются.
3. Новый runtime вызывает существующие инструменты чтения. Проверяются
   связь, лимиты, сбой инструмента и запрет уверенного ответа после
   неподтверждённого чтения; затем Qwen на реальных документах без ручного
   выбора файла, включая обзорные вопросы.
4. Адаптер заменяет общий цикл целиком после приёмки. Старые AgentLoop и
   поисковый backend удаляются после проверки потребителей.

RRF для внешних списков имеет один проверенный адаптер. Корректная цитата
не гарантирует соответствия вопросу: редакция, стадия, достаточность и
полнота остаются отдельной приёмкой.
