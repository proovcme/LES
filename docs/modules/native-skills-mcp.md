# Автономные навыки и MCP в Rust

827 добавляет [отдельную поставку исполнителя](skill-runtime-package.md),
проверенный pywin32 и [встроенные расчёты в Rust](native-builtin-calculations.md).
Ниже сохранён исходный контракт 821; общий Python приложения ещё не удалён.

Кандидат 821. Общий Python приложения пока остаётся; этот документ фиксирует
перенесённых владельцев, не объявляет готовым перенос всего LES.

## Старые навыки

`core/src/skills/` владеет библиотекой, чтением UTF-8 с нормализацией CRLF,
постраничным чтением инструкций, разрешениями скриптов, SHA-256, заданиями,
лимитами и атомарным сохранением строк. Python-сервисы стали кодеками C ABI;
старый `tools/skill_compute_worker.py` удалён из исходников и пакета.

Нативный `les-api --skill-host` принимает один JSON-запрос в stdin с протоколом
`les.skills.v1`. Административный вызывающий задаёт абсолютные `library`,
`artifacts`, `program`; модель не выбирает интерпретатор или разрешённые хеши.
Действия: `catalog`, `read`, `approvals`, `calculate`, `read_job`, `resume`.
Для выполнения нужны `skill`, относительный `path`, массив `items` с уникальными
`id` и объектами `input`. CPython явно выбирается через `program`;
адаптер штатного запуска получает его через `LES_SKILL_PYTHON`.

CPython нужен только для функции старого одобренного скрипта. Он не импортирует
backend/proxy LES. В нём остаётся минимальный стандартный протокол вызова функции;
персистентность, очередь строк, контроль времени и восстановление — Rust.
Это исполнитель доверенного проверенного кода, не sandbox произвольных программ.

Перед скриптом host оставляет в `sys.path` стандартную библиотеку и явные
каталоги зависимостей выбранного интерпретатора. Сохраняются NumPy/OpenPyXL
старых навыков, каталог приложения удаляется из путей импорта. Учтена особенность
Windows embedded CPython: строка `import site` в прежнем `._pth` переопределяет
`-S`. Кандидат 827 устраняет это в отдельном комплекте навыков: `_pth` без
startup site и приложения, явные разрешённые пути/DLL после process guard.
Исторический общий app runtime ещё нужен оставшимся частям приложения и
не считается удалённым этим изменением.

Лимиты прежнего сценария сохранены: 100 строк, 256 КБ входа, 20 с задания,
15 с CPU, 512 МиБ, один процесс Windows. Интерпретатор получает разрешающий
первый кадр после подключения Job Object. Venv redirector разрешается через
его `pyvenv.cfg` до запуска базового CPython. Нет импорта приложения для лимитов.
На Unix CPython применяет rlimit; на macOS Rust дополнительно следит за RSS.

`resume` сверяет актуальное разрешение, хеш и точку входа. Подтверждённые строки
не вычисляются повторно. Ошибка отдельной строки сохраняется и не блокирует
остальные. После остановки владельца задания остаются `summary.json`,
подтверждённые строки и код причины. Модельные ключи/PYTHONPATH не передаются
интерпретатору. Источники библиотеки открываются для чтения.

## MCP

`core/src/mcp_registry.rs` сохраняет существующие подключения в SQLite.
`api/src/mcp/` владеет валидацией адресов, JSON-RPC, HTTP/SSE, stdio, версиями
протокола, сессиями, пагинацией списка и вызовом разрешённых инструментов.
`/api/mcp` и маршруты создания, probe, выбора и удаления обслуживаются Rust;
проверка пользователя/администратора остаётся общей с другими нативными API.

Подключение и выбор инструментов выполняются явно. Разрешаются только инструменты
с `readOnlyHint=true` и локальными ссылками JSON Schema. Перед вызовом проверяются
актуальная схема, сохранённое разрешение и аргументы. Изменение схемы требует
повторного включения пользователем. Серверные `instructions` не входят в профиль.
Необъявленные клиентские возможности, включая доступ к roots, не предоставляются.

HTTP поддерживает JSON и SSE, фиксирует DNS/peer, сохраняет Session ID и версию,
не следует redirect и не принимает сжатый ответ. HTTP без TLS разрешён только
loopback. Stdio запускает явно выбранный существующий exe без shell и без
наследования переменных приложения. Общий предел обмена — 25 с, ответа — 1 МБ,
списка — 128 инструментов/8 страниц; выбранных инструментов — до 32.

Совместимый сервис вызывает `les-api --serve-mcp` через отдельный пул
`worker_mcp`; Python SDK и Python SQLite/JSON Schema логика удалены из этого пути.
Публичный `/api/tools/call` проходит [нативную политику допуска и журнал](native-tool-execution.md)
через совместимый асинхронный диспетчер; новые переходы не обходят этот слой.

Протоколы сверены с [MCP transports](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)
и [lifecycle](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle).

## Проверка и границы

Нативный exe скопирован в отдельную папку без Python-модулей приложения:
70 строк, UTF-8, paging, отказ после изменения SHA, потеря процесса и продолжение
без повтора подтверждённой строки, тайм-аут и отсутствующий интерпретатор.
Windows-проверка подтверждает, что дочерний CPython не переживает владельца.

MCP проверяется с настоящим HTTP/stdio сервером и stateful SSE-стендом:
CRUD, доступ только к выбранному чтению, отзыв кешированного обработчика,
неверный ID ответа, изменение схемы, запрет внешних schema refs, UTF-8 по частям,
Session ID/версия и закрытие сессии. Python SDK отключается в проверке клиента.

Новая установка на чистой Windows, macOS/Unix и полный разговор Qwen в основном
чате этим шагом не приняты. Пакет пока содержит общий Python для оставшихся
координаторов; отдельная поставка только CPython для навыков — часть Python-exit.
