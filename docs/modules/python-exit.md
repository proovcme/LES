# Перенос основы Леса в Rust с сохранением автономных Python-навыков

Кандидат 804 переносит замену лексической копии файла в SQLite и проверку
исходных попаданий с дочитыванием родителя в Qdrant. В основном чате Rust
разбирает предложения модели о вызове инструментов и отбирает новые
доказательства для следующего хода. Адаптеры Python продолжают исполнять
инструменты и вызовы модели. OCR, часть форматов Office и соседние страницы
PDF остаются в прежних обработчиках.

Кандидат 803 переносит фоновую регистрацию внешних папок и управление партиями
индексации в Rust. После перезапуска регистрация продолжается с последней
зафиксированной партии. Для индексации очередь читает фактические статусы
документов и сохраняет причины ожидания. Rust также читает текстовый слой PDF
и Unicode-текст и пишет точки в Qdrant. Исполнитель одной партии пока запускает
часть парсеров, OCR, нарезку, запрос эмбеддингов и обновление лексического индекса.
[Контракт очереди](auto-parse-resume.md).

Кандидат 801 раздаёт карту «Лес знаний» из Rust API и переносит в Rust
чтение пользовательского каталога, создание датасета и чтение статуса
импорта. MCP использует эти маршруты и штатные транзакции проектов и рабочих
файлов. Чат по MCP выполняет тот же модельный цикл и вызывает те же инструменты,
что и чат Леса. Движок импорта, модельный цикл, выдача оригиналов и прочие
экраны classic остаются на прежних службах. Автономные одобренные
Python-навыки выполняются через поставляемый CPython.

Кандидат 800 переносит лексическую оценку выдачи и политику расширения
поиска в Rust. Unicode-нормализация использует общую функцию Python.
[Контракт оценки](rag-ranking.md). Пакетное чтение страниц PDF пока
оркестрирует Python. [Границы чтения](chat-section-context.md).

Кандидат 799 переносит три операции на пути чата и RAG.
Rust записывает историю, частичные ответы и обратную связь, читает
назначение модели и возможности одной транзакцией, фиксирует публикацию
и восстановление ревизий индекса. Чтение публичной истории, модельный
цикл, сетевой транспорт LAN/HTTPS и сами операции с Qdrant ещё Python.
[Контракт API и SQLite](native-api.md).

Кандидат 798 переносит разбор и проверку ответов локальной Ollama на
запросы эмбеддингов. RAG получает готовые f64 и сверяет их с действующим
индексом. Выбор роли модели и публикация индекса пока Python.
[Граница транспорта](native-api.md).

Кандидат 797 разбирает поток локальной Ollama в Rust. Новый чат получает
готовые фрагменты ответа, вызовы инструментов, статус размышления и
статистику. Модельный цикл и внешние подключения ещё Python.
[Граница HTTP и потока](native-api.md).

Кандидат 796 открывает HTTP-соединения с локальной Ollama из Rust для
генерации и эмбеддингов по её нативному протоколу. Python ещё выбирает
назначенную модель, собирает запрос, читает поток и управляет модельным
циклом. LAN, облако и прочие протоколы остаются на прежнем транспорте.
[Граница HTTP](native-api.md).

Кандидат 795 раздаёт новый интерфейс и его файлы через Rust.
В нативном режиме FastAPI больше не обслуживает `/app/`. Старые экраны
по-прежнему требуют NiceGUI. [Граница frontend](svelte-desktop.md).

Кандидат 794 переносит семь прямых локальных маршрутов реестра ключей в Rust.
В FastAPI остаются начальная настройка политики, диагностика доверия,
первичное создание admin-ключа при запуске и совместимость с прокси.
[Контракт](native-api.md).

Кандидат 793 авторизует прямые локальные вызовы нативных маршрутов в Rust.
Настройки доверия загружаются один раз, состояние ключей читается на каждом
запросе. FastAPI ещё задаёт политику на старте и обслуживает прокси-запросы,
нестандартный CORS. [Контракт](native-api.md).

Кандидат 792 переводит установленную командную строку и внешний MCP stdio
в Rust. Старые конфигурации с Python-путём используют совместимый запуск
того же Rust-кода. Основной API чата и входящий MCP пока Python.
[Контракт](native-runtime.md).

Кандидат 791 подключает Rust к классификации XLSX/XLSM и чтению XLSX
для Parquet. Публикация индекса и нормализация строк ещё Python.
[Проверки и границы](document-tasks.md).

Кандидат 790 переводит снимки XLSX/XLSM из чата в Rust. Calamine читает
координаты, формулы и сохранённые значения. Сложные книги сохраняют
совместимость через прежний адаптер.
[Потребители и границы](document-tasks.md).

785: Rust считает ожидающие документы и атомарно выдаёт право запуска
единственной очереди. Исполнитель порций и HTTP ещё Python.

Установленный локальный 784: SQL заданий и политика освобождения RAM в Rust, прежние Python

Установленный локальный 783 переносит чтение DOC на Windows и разбор/канонизацию ссылок в Rust,
включая manifest/счётчики. Предпросмотр DOC использует тот же reader, с явным

Сохранены этапы 780–782: [BM25/RRF/контекст](native-rag-harness.md),
[ограничения цикла инструментов и receipts](native-harness-loop.md) в Rust.
Сетевой модельный цикл, executor/MCP, дочитывание, сводки и публикация индекса
ещё Python. [Установленная приёмка и ограничения](../acceptance/auto-parse-resume-782.md).

Уточнение владельца 01.11.2026: требуется автономная работа всех прежних
Python-навыков. Поэтому буквальное отсутствие любого Python-движка в поставке
больше не является достижимым критерием при сохранении совместимости. Цель:
Rust/Tauri, TypeScript, нативный Qdrant и обработчики; отдельный совместимый
локальный Python-исполнитель только для одобренных навыков. Нельзя называть такую
поставку полностью свободной от Python. Внешний обработчик вместо автономности
владельцем отклонён. Это целевая граница, а не описание готового build 775.

Python не должен оставаться владельцем API, поиска, индекса, папок, очередей,
восстановления или UI. Нельзя переносить эти функции в исполнитель навыков и
называть это миграцией. Прежний контракт навыков: одобренный hash/entrypoint,
изолированный процесс, JSON-входы, Decimal и доступные прежним скриптам библиотеки,
построчное сохранение и лимиты. Набор библиотек исполнителя определяется по
совместимости одобренных скриптов; нельзя обещать stdlib-only и молча лишить
существующий навык pandas или другого ранее доступного модуля.
Самовольная подмена совместимости RustPython/упрощёнными формулами не допускается.

Порядок: стабилизировать границы обработки и измерения → закончить frontend →
переносить API и хранилища небольшими совместимыми вертикальными сценариями →
заменять форматные адаптеры → удалить общий Python runtime и его серверные зависимости,
оставив выделенную совместимость навыков. Не держать две
активные записи одного индекса или две очереди. Существующие журналы, модельные роли,
локальные данные и доказательства сохраняют свои контракты.

Согласованные нативные замены:
[Calamine](https://github.com/tafia/calamine) подключён для снимков Excel,
[PDFium bindings](https://github.com/ajrcarey/pdfium-render) для PDF,
[Windows OCR](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine.trycreatefromuserprofilelanguages)
для установленного системного OCR. Наличие библиотеки не доказывает паритет:
нужно проверять объединённые ячейки/формулы, таблицы PDF, страницы/координаты,
кодировки, старые Office/MSG/PST и вложения. Замену Docling и сложной структуры
документа нельзя объявлять эквивалентной по одному успешному извлечению текста.

Кандидат 775 выделяет [нативного владельца служб](native-runtime.md), опция
`--native-launcher`. Поставленная 773 остаётся прежней; API/UI пока Python.
Библиотеки API/SQLite подключены в кандидате 776, Calamine в 790;
PDFium согласован и ожидает проверки паритета: [решение](native-dependencies.md).
[Хранилище диалогов](native-workspace.md) и [граница API](native-api.md)
не означают завершение переноса остальных сценариев.
Кандидат 777 расширяет [SQLite-владение](native-catalog.md) на проекты, заметки,
состояние контекста и чтение истории. Оркестрация RAG, модельная генерация сводки,
граф связей, отдельный Memory Core, очереди, авторизация и форматные адаптеры ещё

Кандидат 778 добавляет Rust-владение USER.md/MEMORY.md и рабочими UTF-8 файлами
с восстановлением и историей. Python пока связывает встроенный инструмент и

отдельным модулем работы с кодом; его адаптер ещё не реализован и не является

Кандидат 779 переносит из Python в Rust схему, привязку/scope инструмента,
порционное чтение и проекцию памяти. Добавлены delete/export с историей.
Реальная Qwen прошла файловый цикл и память между разговорами;
[результаты и границы](../acceptance/agent-native-779.md). Harness и модельная
оркестрация по-прежнему Python, завершение их переноса не заявляется.

Критерии готовности: чистая Windows без системного Python, с поставленным
изолированным исполнителем навыков; исходные папки
доступны только для чтения; успешные импорт/переиндексация/поиск/цитата/оригинал;
письма/OCR/таблицы с прежними доказательствами; падение на каждой стадии публикации
не теряет прежний индекс; обновление и откат сохраняют пользовательские данные.
Сравниваются холодный старт, потребление памяти, скорость и качество выдачи на
одном корпусе. Один язык сам по себе эти результаты не гарантирует.
