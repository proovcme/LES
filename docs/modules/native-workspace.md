# Rust: диалоги и черновики · кандидат 776

`core/src/workspace/` владеет SQLite-операциями диалогов и черновиков.
`mod.rs` открывает соединения и транзакции, `records.rs` читает существующие и
унаследованные записи, `writes.rs` проверяет значения и выполняет изменения.
Таблицы `les_chat_sessions` и `les_chat_drafts` остаются в прежней meta.db;
второй каталог, перенос данных и фоновая синхронизация не добавлены.

Чтение открывает существующую БД read-only, не создаёт отсутствующую и не
продвигает старые записи chat_history. Запись использует BEGIN IMMEDIATE,
busy_timeout 10 секунд, synchronous FULL и один commit. Проверка revision и
сохранение черновика выполняются в одной транзакции: запоздавшее окно получает
конфликт. Ошибка/прерывание откатывают связанные изменения. Владение проектом
сохраняется, исходная область копирует связи проекта с наборами.

Python-фасады `chat_session_service.py` и `chat_draft_service.py` сохраняют
публичные функции, но SQL больше не выполняют. `backend/workspace_native.py`
вызывает обязательную операцию `workspace`, схема `les.workspace.v1`, через
проверенный ABI/SHA `native_core.required`. Настройка необязательного ускорителя
LES_CORE_MODE эту зависимость не отключает. Отсутствующий/несовместимый модуль
выдаёт ошибку восстановления установки; пустой список вместо отказа недопустим.
Откат выполняется полным согласованным набором исходников и DLL, а не скрытым
переключением текущего кода на Python SQL.

Предыдущая реализация сохранена только в `tests/oracles/`, в пакет не входит.
Одни и те же поведенческие проверки выполняются против неё и Rust. Проверяются
Unicode/пробелы, attachment, неизменность байтов при чтении, старые даты с разными
UTC-смещениями, legacy-сессии, scope, идентичность проекта и откат триггера SQLite.
Это не перенос остальных таблиц: проекты, память, задания и индекс ещё имеют
прежних владельцев. [HTTP-граница](native-api.md), [план](python-exit.md).
