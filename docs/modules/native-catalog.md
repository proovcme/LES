# Rust: проекты, заметки и состояние контекста · кандидат 777

`core/src/catalog/` продолжает перенос существующей meta.db, не создаёт второй
каталог и не меняет ID. `projects.rs` владеет проектами/привязками/чтением метаданных,
`notes.rs` — заметками и миграцией их старых колонок, `conversation.rs` — сводкой,
revision, границей забывания и выборками истории. `mod.rs` содержит соединение,
фиксированную диспетчеризацию и преобразование строк SQLite в JSON.
Схема FFI `les.catalog.v1`, обязательная операция `catalog`.

В Python-сервисах project_service, memory_service и conversation_context_service
SQL удалён. Остаются фасады, сборка досье из других сервисов, скоринг/форматирование
памяти, команды, вызов модели и построение связей заметки. Старый SQL заморожен в
`tests/oracles/` только для дифференциальных проверок; в runtime не поставляется.
Отсутствующий или повреждённый native-модуль — ошибка восстановления установки,
а не пустая память. Откат требует прежнего согласованного кода и DLL.

Запись — BEGIN IMMEDIATE, synchronous FULL, commit после полного действия.
Удаление проекта и его привязок атомарно; остальные таблицы сохраняются.
Изменение заметки адресуется парой id/project_id, не переносит её между проектами;
явное редактирование/переключение enabled снимает флаг auto как прежде.
Миграция старых les_notes идёт в той же транзакции, включая list_notes, поскольку
это существующий контракт. Чистая проекция заметок ничего не мигрирует и не пишет.
Отсутствующие файлы на чистом чтении не создаются; остальные чтения выполняются в
read-only соединении со снимком транзакции. Занятая или повреждённая БД не выдаётся
за пустую. Python HTTP-совместимость преобразует отказ хранилища в понятный 503.

Revision сводки проверяется и изменяется в одной транзакции. Forget вычисляет
границу успешных сообщений под той же блокировкой и очищает сводку, сохраняя
исходную историю. Поздняя генерация не перезаписывает забывание: её revision
устарел. Формирование сводки моделью и её существующая проверка выбора исходных
утверждений пока Python, модельные роли и политика допуска не меняются.

Axum напрямую обслуживает ещё 14 method/path пар: 8 проектов/связей, 3 чтения/
изменения/удаления заметок и 3 состояния контекста. Всего **20 из 265**, остальные
245 явно проксируются. Права проектов проверяются прежним require_admin через
отдельный скрытый служебный endpoint; чтение/память — require_user.
Авторизация не перенесена в Rust и не кэшируется.

POST заметки, досье проекта и запрос генерации сводки ещё проходят старые HTTP-
обработчики. В частности, POST сохраняет через Rust и затем вызывает прежнее
derive_edges_from_text; объявлять его чисто нативным нельзя. Отдельный Memory Core
с его очередью/типизированными записями и собственной БД также пока Python.

Проверки: одинаковые сценарии против замороженного Python и Rust, чужая область,
старые колонки, байтовая неизменность чтения, триггеры отказа, конкурентный CAS,
отложенная сводка/forget, сохранность графовых связей. HTTP-проверки отдельно
покрывают права администратора, scope до изменения, миграцию и сохранение истории.
