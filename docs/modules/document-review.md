# Продолжение проверки документов

Build 765, кандидат исходников. Самостоятельная реализация общих идей учёта
работы и происхождения выводов; код другого проекта не переносился.

`document_review` — инструмент основного чата для профилей с поиском/чтением
документов. Доступен только в Light, в сохранённом диалоге с выбранными наборами.
При выключенных инструментах не включается. Привязка включает диалог, проект,
наборы, область, выбранные файлы и ревизии модели/профиля. Пути к произвольным
файлам инструмент не принимает. Исходники остаются только для чтения.
При малом лимите инструментов сначала сохраняются места для существующего
поиска и явно приложенной таблицы; очередь предлагается только при свободном
месте. Она не вытесняет эти функции из ограниченного shortlist.

Модель явно выбирает до 32 документов или родительских разделов из поискового
происхождения: dataset_id + file_name + необязательный parent_id. `start` создаёт
фиксированный список и цель по текущему сообщению пользователя. Повтор той же
цели и списка возвращает прежнюю проверку. Самопроизвольной фоновой работы нет.
`status` без task_id перечисляет последние пять проверок; task_id возобновляет
нужную. Список не расширяется автоматически при обнаружении новых файлов.

`ReviewSourceReader` проверяет реальный SHA-256 оригинала против каталога
индексации. Изменение байтов при прежних размере и mtime тоже обнаруживается.
Непроиндексированный/пропавший/изменившийся источник нельзя объявить актуальным.
Qdrant читается с точной областью, без навигационных узлов и недопустимых
доказательств, с проверкой поколения до/после чтения и всего списка проверки.
Ограничение единицы: 2048 фрагментов / 2 млн символов. Для большего документа
нужно выбрать конкретный parent_id. Последние восемь единиц кэшируются только
в одном запросе чата и при прежнем поколении; оригинал проверяется заново.
Каталог разрешает исходник точным индексированным запросом dataset_id/file_name;
список всей базы не загружается. Неоднозначные записи отклоняются. Для подсчёта
состояний читаются последние ревизии, а зависимости вычисляются с мемоизацией:
сходящиеся цепочки не вызывают повторный обход одних и тех же выводов.

`read` возвращает до 4000 символов одного фрагмента, его точное происхождение,
SHA оригинала, fingerprint раздела и next_cursor(fragment_index, offset).
Курсор считает символы Python, не UTF-8 байты. Каждая порция целиком проходит
обязательный бюджет ContextGovernor в связанной паре assistant/tool. В журнале
чтения порция засчитывается только после успешного вызова модели с полным
сообщением инструмента. Выдача инструмента, обрезанный/неотправленный пакет,
обрыв или ошибка модели сами по себе прогресс не продвигают. Последний шаг
хранится в контексте, прежние шаги остаются в журнале/trace. Фрагменты также
проходят штатный ChatSectionReader и построение доказательств/источников.
Перед следующим вызовом модели повторно проверяется актуальность чтения.

`record` требует текущую ревизию, request_id, fingerprint полученного источника,
статус, объяснение и 1–4 буквальные цитаты из переданных модели порций.
reviewed разрешён после передачи всех фрагментов единицы без пропусков.
Частичный/сомнительный разбор допускает needs_review; исключение требует
объяснения и цитаты. Семантическую истинность объяснения код не удостоверяет.
`dependencies` — явно указанные моделью ID других проверенных выводов этой
очереди. Нет автоматического извлечения всех логических зависимостей из текста.

SQLite хранит неизменяемые ревизии выводов, их цитаты, исходные SHA, локаторы,
версии зависимостей, диапазоны переданного чтения и квитанции request_id.
Общий транспорт БД вынесен в `document_task_database.py`; таблицы строк и
общих проверок имеют независимые схемы в прежнем файле состояния
`data/document-tasks.sqlite3`. Запись атомарна, конкурирующая устаревшая ревизия
отклоняется, повтор того же request_id безопасен; другой результат по нему
отклоняется. Журнал не заменяется сводкой диалога.

Эффективное состояние needs_recheck вычисляется при обращении к проверке,
если изменились оригинал, индексированный текст/происхождение или ревизия
использованного вывода. Инвалидация распространяется по явно сохранённым
зависимостям. Циклы не приводят к зависанию. После перечитывания можно сохранить
новую ревизию; `history` сохраняет доступ к прежним (порциями по восемь событий).
Исторический вывод не становится актуальным автоматически.

Счётчики покрытия вычисляет код. coverage_complete означает наличие актуальных
решений для всех выбранных единиц; needs_review/excluded учитываются отдельно.
Это не проверка всего проекта, оригинальных изображений, полноты OCR или
правильности ответов. accepted всегда false; принятие решения пользователем
этот инструмент не реализует. В чате есть этапы с числом проверенных единиц и
нуждающихся в перепроверке. Отдельная панель управления очередью пока отсутствует.
