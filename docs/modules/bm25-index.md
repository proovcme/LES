# Рабочий BM25 без генеративной модели

Build 755: `backend/sparse_index.py` материализует полноценный BM25 в прежний
named vector `bm25_sparse`. Dense-векторы, ID, payload и иерархия сохраняются.
Qwen, новый OCR и повторное вычисление эмбеддингов для миграции не нужны.

## Формула и корпус

Вес терма: `ln(1 + (N-df+0.5)/(df+0.5)) * tf*(k1+1) /
(tf+k1*(1-b+b*length/average_length))`, k1=1.2, b=0.75. Запрос содержит единичные
веса уникальных термов. IDF применяется ровно один раз в документном векторе;
модификатор Qdrant переключается в `none` под журналом обновления. См.
[контракт модификатора Qdrant](https://qdrant.tech/documentation/manage-data/indexing/).
Проверка реального установленного сервера показала, что его динамический IDF
после удаления не сразу соответствует текущему числу документов. Поэтому
755 рассчитывает IDF самостоятельно по живым точкам, а не поверх модификатора.

Единица корпуса — индексная точка, включая навигационные узлы; статистика общая
для коллекции, фильтры ограничивают результаты. Пустой текст учитывается в N
и средней длине с нулевой длиной; пустой корпус использует безопасное значение
average_length=1 и не создаёт фиктивных точек. Токенизация остаётся
`les.lexical.v1`: стемминг русского, регистр, ё/е, прежние технические маркеры.
Это не исправляет потерю коротких обозначений внутри смешанного текста.

## Обновление и восстановление

Перед гибридным поиском `_prepare_sparse_index` сверяет ревизию журнала, число
точек, физическую коллекцию и sparse-модификатор. Первая проверка старого индекса
строит BM25; неизменённая версия не переписывается. Замена файла изменяет ревизию;
удаление набора и ремонт целостности также ограждены тем же OS lease и журналом.
После изменения корпуса BM25 пересчитывается перед первым следующим поиском.

Обработка идёт пакетами 128 точек через SQLite spool, без загрузки корпуса в RAM.
Фаза `sparse_refresh` записывается до изменения векторов; поиск в этой фазе
закрыт. После подтверждения всех пакетов публикуются контракт и новая ревизия.
Сбой на любом этапе оставляет журнал для повторяемого восстановления.
Приходящие запросы получают понятную ошибку занятости, а не смесь поколений.
IDF, средняя длина и все веса относятся к одной версии корпуса.

Пересчёт линейный по всему корпусу. Он выполняется один раз после изменения
перед поиском, а не после каждого импортированного файла. На больших корпусах
первая выдача после изменения будет дороже; многосоттысячный корпус пока не
измерен. Прогресс пакетов пишется в журнал приложения; чат показывает этап поиска.
Редактирование Qdrant в обход приложения не является поддерживаемой операцией:
равное число точек с заменённым текстом без ревизии не обнаруживается автоматически.

## Диагностика и откат

`health_snapshot.sparse_index` показывает сохранённый контракт и статус его
ревизии. Это не самостоятельная полная сверка внешних изменений Qdrant.
`tools/rebuild_sparse_index.py --url URL --collection NAME --content-dir PATH`
читает состояние. Для изменения нужен `--apply`; `--mode bm25` включает BM25,
`--mode tf` восстанавливает прежние TF-веса и модификатор IDF из сохранённых
текстов. Явно выбранный TF не превращается обратно в BM25 при следующем поиске.
Параметры относятся только к собственному экземпляру; модели и источники не меняются.
