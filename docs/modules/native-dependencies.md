## Согласовано 12.11.2026: сравнение Swiftide и Rho на копии

Владелец прямо поручил сравнить оба SDK на своих документах, сохраняя
рабочую установку. Swiftide Agents/Core 0.34.0 (MIT, Rust 1.97) добавлены
только в отдельный испытательный Cargo-проект вместе с согласованным
Rho SDK 5.15.2. Cargo.lock приложения этим не меняется.
Используются существующие по назначению Tokio, serde_json, async-trait,
anyhow и tokio-stream для одинакового тестового транспорта.

Опубликованный Swiftide Core 0.34.0 не собирается на Windows:
node.rs безусловно импортирует std::os::unix::ffi::OsStrExt. Только
в испытательной копии убран этот импорт и использован as_encoded_bytes.
Поправка и необходимость её сопровождения входят в оценку кандидата;
проверку нельзя описывать как сборку неизменённого Swiftide.

Приёмка сравнивает один поиск, читатель, модель и вопросы. Сторонний SDK
не получает рабочий индекс, новые назначения моделей или полномочия
читать/менять произвольные файлы.

## Согласовано 12.11.2026: русский лексический анализ

- `qdrant-rust-stemmers = 1.3.0`, MIT/BSD-3-Clause: стандартный русский
  Snowball вместо собственного списка окончаний. Эта версия уже присутствует
  транзитивно в `api/Cargo.lock` через Edge и в локальном кэше.
  Прямое использование ядром согласовано владельцем, без Python и загрузки моделей.
- Причина: текущий `les.lexical.v2` разводит формы «заключение/заключения»,
  «ведомость/ведомости», «система/систем» и короткое «том/тома/томов».
  Это дефект анализа терминов, не формулы BM25.
- Нельзя менять смысл `v2` задним числом. Нужен отдельный анализатор,
  одинаковый для индекса и запроса, и отдельное лексическое поколение на копии.
  Dense-векторы не пересчитываются, RRF и рабочий индекс не переключаются.
  До сравнения точечных и обзорных запросов вариант не становится штатным.
- Ограничение стандартного стеммера: «система/систем» остаются разными
  терминами и в v3. Snowball не заменяет морфологический словарь;
  специальные исключения под корпус не добавляются.

Версия и лицензия сверены с локальным манифестом уже закреплённого пакета.
Прямое подключение выполнено для отдельного `les.lexical.v3`. Штатный
`les.lexical.v2` остаётся неизменным; [сравнение на копии](../acceptance/native-lexical-experiment-866.md)
не подтвердило улучшение общей выдачи. Переключение рабочего индекса не принято.
Первичный исходный код: [qdrant/rust-stemmers](https://github.com/qdrant/rust-stemmers),
алгоритм: [Snowball Russian](https://snowballstem.org/algorithms/russian/stemmer.html).

## Согласовано для Parquet, build 829

Предлагается `parquet = 60.1.0` (Apache-2.0), `default-features=false`,
`features=["snap"]`. Нативный record/column API читает и пишет нынешние
производные Snappy-файлы без PyArrow/Pandas, без Arrow runtime, DuckDB,
сетевого object-store и асинхронных загрузчиков. Неподдерживаемый codec
обязан давать понятную ошибку, а не частичный результат.

Чтение ограничено собственным каталогом производных документов; запись —
через приватный временный файл, завершение footer/fsync и публикацию целого
файла. Приёмка включает Python → Rust и Rust → PyArrow, null/Unicode/числа,
повреждения и реальный корпус. Рабочее состояние не переключается.

Метаданные crates.io: MSRV 1.88 соответствует локальному rustc 1.97;
[официальный пакет/документация](https://docs.rs/parquet/60.1.0/parquet/).
Владелец явно согласовал эту версию и набор возможностей 08.11.2026.
Cargo.lock фиксирует транзитивные версии/checksum; обычный запуск ничего
не скачивает. Автономный runtime внешних навыков остаётся отдельным компонентом.

## Ранее согласованный набор

Статус: весь набор согласован владельцем 01.11.2026. Первым подключается
SQLite и Axum для переноса владения диалогами/черновиками и HTTP-границы;
Calamine подключён в 790 для чтения XLSX/XLSM в чате. Для проверки архива
Rust использует ту же библиотеку zip, которую подключает Calamine. Кандидат 803
подключает pdfium-render для текстового слоя и использует уже поставляемый PDFium
7825 через набор функций 7763.
Кандидат 807 использует `quick-xml` 0.42.0 напрямую для Word. Эта точная версия
уже входит в Cargo.lock через Calamine. Набор пакетов и версии в lock сохранены.
Для 808 согласован `tokenizers` 0.22.2. Используется та же версия, что в `uv.lock`,
с локальным `tokenizer.json` и без функций загрузки моделей по сети. Сборка
фиксирует зависимости в Cargo.lock. Готовый комплект не требует Cargo.
Уже выполненная сборка `runtime/` использует существующий локальный Cargo-кэш,
`--offline`, точные прямые версии и отдельный Cargo.lock; модели не устанавливались.

| Пакет | Предлагаемая версия | Назначение | Первичный источник |
| --- | --- | --- | --- |
| axum | 0.8.9 | Rust HTTP API, потоковый чат и общая граница запросов | [Документация](https://docs.rs/crate/axum/0.8.9) |
| rusqlite | 0.41.1 + bundled | Совместимые SQLite-транзакции, каталог, память, задания и BM25 | [Документация](https://docs.rs/crate/rusqlite/0.41.1) |
| calamine | 0.37.0 | Чтение Excel без openpyxl/pandas | [Документация](https://docs.rs/crate/calamine/0.37.0) |
| pdfium-render | 0.9.3 | PDF текст/координаты/превью с фиксированным PDFium | [Документация](https://docs.rs/crate/pdfium-render/0.9.3) |

Это не автоматическое разрешение заменить поведение парсеров. Для каждого формата
нужен паритет доказательств, координат, формул, пустых значений, ошибок и лимитов.
Docling не считается заменённым одним PDF-reader. OCR и почта сохраняются до
проверки их собственных замен. Существующий нативный PDFium предпочтителен новому
дублирующему дистрибутиву; ABI выбирается после сверки фактического asset.

При подключении: закрепить точные версии и транзитивные checksum в Cargo.lock,
проверить лицензии/уведомления и сборку из lock; новые загрузки выполнять только
сборщику, не пользователю при обычном запуске. Изменение моделей/их ролей не входит
в этот пакет. CPython для автономных навыков остаётся отдельной явно учтённой частью.
