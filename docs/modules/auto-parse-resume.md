# Автовозобновление и допуск чата — 782

В 813 ручной запуск выбирает документы в Rust: сначала обычные файлы,
затем OCR, внутри группы — меньшие известные размеры и имя. Приоритет имеет
точный относительный путь. Старое имя без каталога разрешается, только если
подходит один файл. Неоднозначность, недоступный источник и неверный путь
видны как ошибки конкретного файла. Временные документы и `_parquet` не
участвуют. Внешние файлы читаются по зарегистрированному абсолютному пути.
Перед разбором Rust проверяет, что файл не заменили во время расчёта SHA-256;
перед публикацией действуют прежние проверки регистрации и содержимого.
При успешной публикации каталог сохраняет тот же ID, а имя внутреннего файла
приводит к проверенному относительному пути. Поиск и ссылка на оригинал
используют одно имя; если оно уже занято другой записью, публикация отменяется.

Проверка 813 на изолированной копии прежнего Qdrant: старый внешний файл
переиндексирован с двумя векторами из кеша; вложенный внутренний файл
с пробелами и Unicode попал в индекс. Запрос по ID его фрагмента вернул
байты оригинала, а неверный отпечаток редакции отклонён. Неоднозначное имя
записано как ошибка файла. Содержимое и время изменения оригинала сохранены.
Поставляемый CPython в этом комплекте выполнил 70 позиций контрольного
навыка с pandas и Decimal.

В 812 кеш Qdrant читается нативным API. Выбираются только плотные векторы
нужного файла, набора и модели. Rust ограничивает размер порций и общий
размер временного кеша до 64 МиБ. Старые точки без контрольной суммы текста,
несовпадающие по размерности и пропущенные из-за лимита векторы вычисляются
заново. Ошибка кеша не отменяет индексацию. Временные файлы удаляются
после попытки. При аварии Rust-запускатель очищает оставшиеся файлы
подготовки после захвата каталога состояния и перед запуском служб.
При краткой блокировке файла состояния сторонним читателем в Windows
запускатель повторяет атомарную публикацию вместо остановки восстановления.

В 811 сборщик Rust сам рассчитывает совместимый именованный sparse-вектор
и проверяет пригодность фрагмента до вызова эмбеддера. Сохранены имена
векторов, терминные идентификаторы и частоты существующих коллекций.
Кириллица, латиница и короткие обозначения проходят сравнение с прежним
кодом. При отсутствии пригодных фрагментов причина — `NO_SEARCHABLE_TEXT`.

В 810 Rust выполняет этап от готовых фрагментов до файла точек Qdrant.
Он повторно использует векторы подходящей размерности и вызывает
настроенный эмбеддер только для отсутствующих векторов. Публикация начинается
после проверки всего файла. При ошибке последней порции прежняя редакция
остаётся доступной, а недописанный файл подготовки удаляется. Диспетчер
проверяет попытки длинного ручного запуска блоками по 500 записей.

Изолированный Windows-комплект 810 продолжил работу после остановки API
на двух из пяти файлов. Итог партии — пять индексированных файлов и 31
фрагмент в Qdrant и SQLite. Поиск сохранил ссылку на ячейку Word, строку
Excel и страницу скана. При повторной обработке неизменившегося DOCX оба
вектора взяты из кеша, новых запросов эмбеддингов для документа не было.
Для этой повторной проверки использован отдельный тестовый порог памяти.
Комплектный Python в той же сборке автономно выполнил 70 позиций
одобренного контрольного навыка с pandas и Decimal.

В 808 Rust сверяет состав фоновой партии, отмечает попытку обработки каждого
файла и пропускает источник, привязка которого изменилась. При незавершённой
публикации диспетчер останавливается до восстановления журнала. В штатном
профиле Rust также выполняет диспетчеризацию ручной партии до 500 файлов.
Адаптер Python пока подготавливает данные отдельного файла и ведёт выбор модели.

В изолированном Windows-комплекте партия из пяти файлов продолжилась после
остановки API на отметке двух опубликованных файлов. С локальным токенизатором
BGE-M3 SQLite и Qdrant показали по 31 фрагменту. Поиск вернул точную ячейку
Word, строку Excel и текст первой страницы скана. Поставляемый CPython выполнил
одобренный контрольный навык с pandas и Decimal на 70 строках.

В кандидате 806 Rust выбирает только ожидающие файлы из манифеста текущего
импорта. Индексация внешней партии не обходит хранилище скопированных файлов и
не захватывает ожидающие документы других операций в том же наборе.
Прежний обработчик готовит узлы и эмбеддинги. В штатном профиле его результат
передаётся через временный JSONL-файл в каталоге Леса.

Rust удерживает общую блокировку записи, проверяет регистрацию и контрольную
сумму оригинала. При сбое до решения о публикации удаляются только новые точки.
После решения Rust сверяет точки в Qdrant, восстанавливает FTS5 и оставляет
документ в очереди для повторной проверки оригинала. Каталог и полнотекстовый
индекс обновляются в одной транзакции SQLite. Журнал старых операций поддерживает
совместимый обработчик. В логах отдельно фиксируются публикация, остановка и
восстановление с кодом причины.

Изолированный Windows-комплект проиндексировал TXT, PDF и XLSX. После
принудительной остановки API между партиями очередь продолжила тот же импорт.
SQLite и Qdrant показали по 28 фрагментов. Поиск вернул точную строку XLSX,
а ссылка с контрольной суммой открыла оригинал. Отдельная проверка комплектного
CPython выполнила одобренный навык с pandas и Decimal на 70 позициях.

В кандидате 803 фоновое подключение папки через Rust API ставит задание в SQLite
до обхода файлов. Rust сохраняет полный список, регистрирует документы по 25 и
фиксирует позицию в той же транзакции. После остановки службы тот же ID импорта
продолжает работу. Если остановка произошла до сохранения списка, обход повторяется.
Исходники открываются только для чтения, производные данные остаются в каталоге Леса.

Rust также вызывает обработку одной партии за раз и сохраняет отдельно число
зарегистрированных, проиндексированных, пропущенных и ожидающих документов.
Во время партии статус показывает текущий файл и стадию обработки.
Запись с нулём чанков не считается готовой к поиску. Недоступная модель, нехватка
памяти и отсутствие прогресса оставляют понятную причину и время повторной попытки.
Общее автовозобновление уступает набор с активным нативным импортом этой очереди.
Обработчик одной партии ещё запускает классификацию, подготовку узлов и запрос
эмбеддингов. Нативное извлечение и запись в Qdrant описаны в [контракте обработки](document-extraction.md).
Синхронное подключение, план импорта и наблюдение за папкой ещё обслуживаются
прежним API.

На изолированной сборке Windows служба API была принудительно остановлена
после первой зафиксированной партии. Rust-запускатель поднял службы, тот же
импорт продолжился и зарегистрировал все 324 документа без дубликатов.
Запрос принят за 10,5 мс. После падения очередь дошла до следующего этапа за
11 секунд, а проверка готовности после запуска отвечала не дольше 10,8 мс.
В профиле без назначенного эмбеддера сохранилась причина `INDEX_NOT_CONFIGURED`.
Сведения о размерах и времени изменения исходников совпали до и после проверки.

В build 785 число PENDING читает Rust. Ручной запуск (включая синхронный HTTP)
и автовозобновление захватывают одну запись `rag_parse_scheduler`: проверка
активной записи и вставка идут в одной SQLite-транзакции. Проигравший ручной
запрос получает 409, автовозобновление просто ждёт следующего прохода.
Прерванная запись освобождается штатным recovery. Сами порции, вызовы модели
поиска и выдача прогресса пока выполняются Python; пороги памяти сохранены.

При установленной проверке 781 реальный чат получил CHAT_INDEXING_BUSY.
Логи показали: scheduler уже завершился ошибкой проверки модели поиска,
но startup callback оставил его в PARSING. Это не работающий парсер.

`auto_parse_resume_service.py` выделяет оставшийся Python startup-адаптер из
`proxy/app.py`. Он проверяет назначенный embedder, Qdrant и память до создания
job, повторно проверяет конкурентный scheduler после await и удерживает task
до завершения. Ошибка после старта фиксируется как failed, отмена — cancelled;
tracker отражает фактически сохранённую строку. Политика допустимых переходов
остаётся в существующем Rust job_policy. Никакие memory/model guards не отключены.

Прогресс автоочереди ограничен исходным числом ожидающих документов вместо
фиктивного total=10000. PENDING-источники не удаляются и не считаются готовыми.
Этот адаптер пока Python; с 784 SQL job service в Rust. Полный перенос очереди ещё
не завершён. Назначения моделей не меняются, автоматический fallback отсутствует.

Шесть регрессионных случаев: отказ preflight без job; ошибка после preflight
освобождает допуск чата; гонка не создаёт второй scheduler; отмена не теряет
PENDING; устаревшая проверка отличается от отсутствующей роли; неизвестная
ошибка не раскрывает внутренние адреса. HTTP detail остаётся строкой.
