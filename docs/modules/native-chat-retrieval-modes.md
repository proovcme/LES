# Режимы поиска в чате

873: в смешанном корпусе оба читателя доступны в обычном окне четырёх схем;
`max_tools` профиля остаётся верхним пределом, размер схем учитывается полностью.
Терминальный договор выбора строк включается после закрытия инструментов,
не при выборе следующего чтения. [Причины и проверка](../acceptance/native-reader-admission-873.md).

864: начальная подборка использует `model_evidence_k` и квоту начальных совпадений
`document_diversity_k`; дочитывание страниц квотой не ограничено. Явный поиск
пагинирует весь пул. Неиспользуемая навигация при начальной подготовке отключена,
при вызове инструмента сохраняется. [Аудит](../acceptance/rag-architecture-audit-864.md).

863: меньший бюджет Hybrid больше не требует исключать все страницы
необязательного документа. Полное включение предпочтительно; иначе передаются
целые блоки и неполное покрытие. `offset` поиска применяется к ранжированным
совпадениям; `next_offset` ограничен окном кандидатов, не всем корпусом.
[Причины и проверка](../acceptance/native-context-budget-863.md).

862: поисковый текст PDF отделён от представления ячеек для чтения. Push и
инструментальное дочитывание используют одну проекцию и проверку хеша.
В Push без активного табличного задания с любым профилем и в документном
чтении вне Agent числовые факты
выдаются через проверенное копирование выбранных моделью строк, независимо
от флага строгой области. Agent с инструментами в Pull/Hybrid этим финальным
договором пока не покрыт; это относится и к Agent с активным табличным заданием.
[Приёмка и границы](../acceptance/native-numeric-evidence-862.md).

861: найденная страница больше не ограничивает чтение своим родителем.
Общий читатель проверяет полный индексированный документ ограниченной порцией;
помещающийся документ имеет приоритет перед менее релевантными совпадениями.
Большие документы остаются на чтении разделов. Полная единица неделима в
контексте, идентичность и ссылка сохраняются отдельно для каждой страницы.
[Причина, проверки и ограничения](../acceptance/native-context-selection-861.md).

860 убирает отдельный контроллер чтения: источниками, допуском блоков и передачей
владеет один `Evidence`. Начальная подборка и восстановление вызывают общий
`retrieval::initial`. Экспериментальное изменение значения по умолчанию из 859
отменено; явный выбор режима сохраняется. [Изменения и проверка](../acceptance/native-rag-cleanup-860.md).

Кандидат 859: источник считается прочитанным по квитанции общего Rust-reader,
а не по тому, вызвала ли модель инструмент. Проверяются поколение, фактические
фрагменты и присутствие доказательств в подтверждённом контексте. Карточки
обнаружения отделены от содержимого. [Причины и границы приёмки](../acceptance/native-retrieval-859.md).

Константа RRF берётся из общей политики профиля (`rrf_rank_constant`, в кандидате
10, явный выбор сохраняется). Диагностический набор улучшился по попаданию
нужного документа в первые четыре результата с 13/20 до 16/20; это не приёмка
полноты всех релевантных фрагментов и не доказательство качества ответа.

Кандидат 858 разделяет ранжирование доказательств и навигацию. Глобальный
Dense + BM25 → RRF возвращает один неизменённый список; иерархия не голосует
за те же фрагменты второй раз. Её кандидаты передаются отдельно и сами по себе
не подтверждают ответ. Изменения проверяются на копии; рабочая установка не меняется.

Распределение контекста сохраняет ранжированные совпадения, затем раскрывает
помещающиеся целиком родители и распределяет остаток между частичными разделами.
Большая первая таблица не должна вытеснять продолжение небольшого следующего
раздела. Фрагменты не обрезаются; неполное покрытие остаётся `bounded`.
Краткие карточки найденных документов сохраняют зарегистрированный ID, SHA-256
и страницу даже при исключении текста из контекста; эти карточки не являются
доказательством и не добавляются в допустимую карту цитат.

В нативном поиске для ответа только по выбранным источникам требуется
успешное чтение перед финалом — Rust или инструментом модели. Текущее чтение обязательно, прежние
доказательства сохраняются по [бюджету окна](native-chat-context.md).
Один отклонённый черновик можно исправить
в прежнем бюджете; повторное завершение без чтения даёт `SOURCE_READ_REQUIRED`,
пустой ответ и сохранённую причину. Это защита от пропущенного чтения, а не
семантическая проверка правильности вывода. Push остаётся режимом без инструментов;
если Rust не получил проверенного текста, модель не вызывается.
Поиск по именам `search_sources view=documents` ограничен текущей областью,
постраничен и не вызывает эмбеддинги. Дата файла не определяет актуальную редакцию.

854: Hybrid получает ту же начальную ширину, что Push (до четырёх кандидатов,
6000 символов). Если модель с инструментами завершает документный запрос без
источников, при доступном индексе выполняется один поиск с удалением черновика.
`grounding_retry` сохраняется в трассе. [Границы и приёмка](../acceptance/real-corpus-854.md).
Для завершённого документного ответа проверяются известные номера/адреса
цитат. Один повтор оформления не открывает инструменты и не пополняет бюджет.
Повтор без ссылок останавливается с сохранённой причиной. Признак OCR
передаётся модели вместе с предупреждением о возможных ошибках распознавания.

Историческое закрепление двух глобальных совпадений из 853 заменено в кандидате
858 полным разделением списков в Server и Edge. В раскрытом
контексте совпавший фрагмент предшествует соседним. Для таблицы источник
передаёт имя листа и физическую строку. Полное чтение страницы заменяет её
прежние фрагменты в контексте. Краткая конкурирующая публикация допускает
ограниченное повторное чтение с проверкой поколения. Резерв ответа
вычисляется по выбранному окну модели. Диагностика переполнения хранит
размеры частей контекста без их текста.

В «Параметрах ответа» есть три варианта поиска в выбранных документах.

| Вариант | Когда выполняется поиск |
| --- | --- |
| По запросу модели (Pull) | Модель сама обращается к инструментам поиска и чтения. Прежнее поведение по умолчанию. |
| Лес ищет перед ответом (Push) | Лес ищет до первого вызова модели. Работает с моделью без вызовов инструментов. |
| Лес ищет, модель может дочитать (Hybrid) | Лес передаёт небольшую первичную подборку. Модель может уточнить поиск или дочитать источник. |

Настройка сохраняется в текущем браузере или WebView. При отсутствии
выбранных документов обычный диалог работает без поиска по базе.
Сохранённый выбор передаётся явно. Дополнительного протокола переключения
значений по умолчанию между профилями нет.
Клиенты API могут передать `retrieval_mode` со значением `push`, `pull`
или `hybrid` в запросе `/api/chat` или `/api/chat/stream`.

Все варианты используют одну функцию поиска и дочитывания, проверку редакции,
допуск к источникам и общий бюджет контекста. Первичная подборка занимает
только доступную часть контекста. В Hybrid подтверждённый результат
вызова инструмента получает приоритет, а ссылка сохраняет идентификатор.
В списке источников отражаются материалы, дошедшие до модели.

В журнале запроса сохраняются режим, покрытие, поколение индекса и число
источников первичной подборки. Гибридный поиск по Server и Edge использует
один механизм публикации BM25. При обновлении меняются затронутые документы,
а выдача проверяет совпадение поколений векторного и лексического индексов.
