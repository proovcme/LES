# Режимы поиска в чате

В 930 Hybrid определяет названные в вопросе оригиналы по каталогу результатов
поиска. Для каждого совпавшего ID отбираются собственные выдержки. Если хотя бы
один из этих документов отсутствует в подборке, сохраняется обычная выдача с
навигацией. После упаковки проверяется, какие из ожидаемых ID видит модель.
Одиночный номер в квадратных скобках обозначает короткую ссылку. Перечень
источников модель может записать как `[Источники 1, 2]`. Числовые интервалы
и массивы вида `[0, 10]` сохраняются в тексте.

В исходниках 929 поиск по ID документа использует набор и путь из одной записи
каталога. Перед поиском проверяется, что набор входит в запрошенную область.
Excel-читатель включает в выдержку числовой ноль и логическое значение False.
Для перехода на следующую страницу вызывающий передаёт полученный объект
`continuation`. Он содержит адрес документа, хеши оригинала и таблицы,
границы выборки, смещение и заданные ограничения страницы.

В 927 начальный вызов Hybrid с нативными инструментами учитывает несколько
обозначений документов из вопроса, в том числе латинское написание в имени файла.
В каждой группе выдержек фрагмент с более полным совпадением вытесняет
выдержку, которая совпала только по части тех же терминов. Полный набор прочитанных
фрагментов остаётся в текущем запросе и доступен при уточнении. Схемы
дополнительных читателей модель запрашивает через инструмент расширений.
Повтор для исправления цитат использует ту же подборку, если она полностью
поместилась в первый запрос модели.
В подключении MLX поле `max_tokens` берётся из остатка окна после упаковки
вопроса, выдержек и схем инструментов.

В 911 при финальном выборе цитат после расширения окна ЛЕС может собрать
короткую подборку по отдельным явно указанным файлам. Отбор включается, если
в вопросе есть самостоятельная часть про каждый файл. В подборке остаются
фрагменты с разными совпавшими термами и фрагменты с равным покрытием.
Адреса исходных фрагментов сохраняются. Если модель не подтверждает часть
вопроса или пропускает источник, координатор использует существующий
повтор с полным окном. Явное дочитывание моделью сохраняет обычный отбор.

В 910 ответ с отказом от выбора строк содержит пустую квитанцию цитирования.
Просмотренные источники сохраняются в карте материалов. Поисковый адрес
строки или абзаца стабилен при изменении оформления окна модели.

`read_excel_source` читает активный Parquet той же редакции XLSX. Поля
`sheet_name`, `row_start` и `row_end` задают физические координаты,
`q` ищет значения внутри книги. Продолжение включает снимок Parquet.
Начальная подборка открывает крупную книгу, найденную по обзорной карточке.
Индексация сохраняет заполненные строки и выбирает шапку только при
распознавании исходных названий колонок. В старых индексах потерянные строки
восстанавливаются повторной обработкой оригинала.

Общий читатель `read_source(q=…)` листает ранжированные совпадения BM25
в одном документе. `clause` получает позиции главы из каталога публикации.
`index_revision` закрепляет один снимок при продолжении.

В сборке 909 поисковый Hybrid использует отбор PDF-выдержек при первом
автоматическом поиске. Если в вопросе есть отдельная часть про выбранный файл,
она уточняет отбор строк в этом PDF. Уточняющие вызовы остаются доступны.
Когда инструменты закрыты, модель получает адреса и текст фрагментов без
повторяющихся технических идентификаторов. Привязку к редакции оригинала
Rust проверяет по карте источников. Финальный выбор адресов допускает частичный
ответ и требует подтверждения для каждого выбранного фрагмента.

В сборке 908 PDF-выдержки передаются общему отбору без порога относительно
лучшей строки и отдельного лимита на поисковое попадание. Попадание без
лексических совпадений остаётся кандидатом. Явный `view=passages` работает
с `next_offset` и редакцией индекса. Автоматические PDF-выдержки доступны в
`view=context` и в первом поиске Pull без явно выбранного представления.
Для первого `view=passages` в чате ЛЕС также добавляет PDF-выдержки в контекст
из того же поиска, отдельно от ответа инструмента и его курсора.
У ограниченного ранжированного `read_source` или `read_excel_source` поле
`continuation` содержит запрос, следующий курсор и хеши для того же порядка
чтения. Пустой курсор означает конец ранжированных совпадений.

В сборке 906 первый поиск фрагментов в Pull при наличии PDF-попаданий ранжирует
выдержки с учётом вопроса и помещает их в окно до отбора целых блоков.
Из подходящих строк сохраняются исходный текст, заголовок распознанной
таблицы и привязка к странице. Чтение PDF без точного места внутри страницы
использует тот же отбор. Вызов с курсором или успешным дословным совпадением
сохраняет режим чтения оригинала. Отобранная выдержка не запускает
автоматическое дочитывание всей страницы. Ответ инструмента хранит привязку
каждого фрагмента один раз, а фрагмент ссылается на неё. При нескольких
поисковых вызовах в Pull первые прочитанные фрагменты каждого вызова получают
место до остальных результатов.

900: если файл явно назван в отдельной части вопроса, автоматическое
дочитывание использует эту часть. При совместной формулировке для нескольких
файлов остаётся исходный вопрос целиком.

899: в поисковом Pull выбор файла без параметров места чтения запускает
отбор внутри этого файла по исходному вопросу. При отсутствии совпадений
читатель возвращает начало документа. Явные запросы и позиции чтения
исполняются по своим параметрам. В окне после чтения нескольких документов
сперва рассматривается по лучшему фрагменту из каждого, затем остальные
фрагменты. В пределах одного чтения сохраняется исходный порядок отбора.

874: явные инструменты читают непрерывный префикс единиц, без добавления
соседей в счётчик курсора. `retrieval/pagination.rs` вычисляет продолжение
после окончательного допуска; `retrieval/envelope.rs` ограничивает конверт
целыми блоками. Начальная автоматическая подборка сохраняет раскрытие
родителей и подходящего целого документа. [Договор и проверка](../acceptance/native-source-pagination-874.md).

873: в смешанном корпусе оба читателя доступны в обычном окне четырёх схем;
`max_tools` профиля остаётся верхним пределом, размер схем учитывается полностью.
Терминальный договор выбора строк включается после закрытия инструментов,
не при выборе следующего чтения. [Причины и проверка](../acceptance/native-reader-admission-873.md).

864: начальная подборка использует `model_evidence_k` и квоту начальных совпадений
`document_diversity_k`; дочитывание страниц квотой не ограничено. Явный поиск
пагинирует весь пул. Неиспользуемая навигация при начальной подготовке отключена,
при вызове инструмента сохраняется. [Аудит](../acceptance/rag-architecture-audit-864.md).

863: меньший бюджет Hybrid больше не требует исключать все страницы
необязательного документа. Полное включение предпочтительно; иначе передаются
целые блоки и неполное покрытие. `offset` поиска применяется к ранжированным
совпадениям; `next_offset` ограничен окном кандидатов, не всем корпусом.
[Причины и проверка](../acceptance/native-context-budget-863.md).

862: поисковый текст PDF отделён от представления ячеек для чтения. Push и
инструментальное дочитывание используют одну проекцию и проверку хеша.
В Push без активного табличного задания с любым профилем и в документном
чтении вне Agent числовые факты
выдаются через проверенное копирование выбранных моделью строк, независимо
от флага строгой области. Agent с инструментами в Pull/Hybrid этим финальным
договором пока не покрыт; это относится и к Agent с активным табличным заданием.
[Приёмка и границы](../acceptance/native-numeric-evidence-862.md).

861: найденная страница больше не ограничивает чтение своим родителем.
Общий читатель проверяет полный индексированный документ ограниченной порцией;
помещающийся документ имеет приоритет перед менее релевантными совпадениями.
Большие документы остаются на чтении разделов. Полная единица неделима в
контексте, идентичность и ссылка сохраняются отдельно для каждой страницы.
[Причина, проверки и ограничения](../acceptance/native-context-selection-861.md).

860 убирает отдельный контроллер чтения: источниками, допуском блоков и передачей
владеет один `Evidence`. Начальная подборка и восстановление вызывают общий
`retrieval::initial`. Экспериментальное изменение значения по умолчанию из 859
отменено; явный выбор режима сохраняется. [Изменения и проверка](../acceptance/native-rag-cleanup-860.md).

Кандидат 859: источник считается прочитанным по квитанции общего Rust-reader,
а не по тому, вызвала ли модель инструмент. Проверяются поколение, фактические
фрагменты и присутствие доказательств в подтверждённом контексте. Карточки
обнаружения отделены от содержимого. [Причины и границы приёмки](../acceptance/native-retrieval-859.md).

Константа RRF берётся из общей политики профиля (`rrf_rank_constant`, в кандидате
10, явный выбор сохраняется). Диагностический набор улучшился по попаданию
нужного документа в первые четыре результата с 13/20 до 16/20; это не приёмка
полноты всех релевантных фрагментов и не доказательство качества ответа.

Кандидат 858 разделяет ранжирование доказательств и навигацию. Глобальный
Dense + BM25 → RRF возвращает один неизменённый список; иерархия не голосует
за те же фрагменты второй раз. Её кандидаты передаются отдельно и сами по себе
не подтверждают ответ. Изменения проверяются на копии; рабочая установка не меняется.

Распределение контекста сохраняет ранжированные совпадения, затем раскрывает
помещающиеся целиком родители и распределяет остаток между частичными разделами.
Большая первая таблица не должна вытеснять продолжение небольшого следующего
раздела. Фрагменты не обрезаются; неполное покрытие остаётся `bounded`.
Краткие карточки найденных документов сохраняют зарегистрированный ID, SHA-256
и страницу даже при исключении текста из контекста; эти карточки не являются
доказательством и не добавляются в допустимую карту цитат.

В нативном поиске для ответа только по выбранным источникам требуется
успешное чтение перед финалом — Rust или инструментом модели. Текущее чтение обязательно, прежние
доказательства сохраняются по [бюджету окна](native-chat-context.md).
Один отклонённый черновик можно исправить
в прежнем бюджете; повторное завершение без чтения даёт `SOURCE_READ_REQUIRED`,
пустой ответ и сохранённую причину. Это защита от пропущенного чтения, а не
семантическая проверка правильности вывода. Push остаётся режимом без инструментов;
если Rust не получил проверенного текста, модель не вызывается.
Поиск по именам `search_sources view=documents` ограничен текущей областью,
постраничен и не вызывает эмбеддинги. Дата файла не определяет актуальную редакцию.

854: Hybrid получает ту же начальную ширину, что Push (до четырёх кандидатов,
6000 символов). Если модель с инструментами завершает документный запрос без
источников, при доступном индексе выполняется один поиск с удалением черновика.
`grounding_retry` сохраняется в трассе. [Границы и приёмка](../acceptance/real-corpus-854.md).
Для завершённого документного ответа проверяются известные номера/адреса
цитат. Один повтор оформления не открывает инструменты и не пополняет бюджет.
Повтор без ссылок останавливается с сохранённой причиной. Признак OCR
передаётся модели вместе с предупреждением о возможных ошибках распознавания.

Историческое закрепление двух глобальных совпадений из 853 заменено в кандидате
858 полным разделением списков в Server и Edge. В раскрытом
контексте совпавший фрагмент предшествует соседним. Для таблицы источник
передаёт имя листа и физическую строку. Полное чтение страницы заменяет её
прежние фрагменты в контексте. Краткая конкурирующая публикация допускает
ограниченное повторное чтение с проверкой поколения. Резерв ответа
вычисляется по выбранному окну модели. Диагностика переполнения хранит
размеры частей контекста без их текста.

С 925 настольный чат и его веб-интерфейс передают `hybrid` автоматически.
У поля вопроса пользователь задаёт область поиска. При отсутствии выбранных
документов обычный диалог работает без поиска по базе. Клиенты API могут
передать одно из трёх значений `retrieval_mode` в запросе `/api/chat` или
`/api/chat/stream`.

| Значение | Когда выполняется поиск |
| --- | --- |
| `pull` | Модель сама обращается к инструментам поиска и чтения. |
| `push` | Лес ищет до первого вызова модели. Работает с моделью без вызовов инструментов. |
| `hybrid` | Лес передаёт первичную подборку. Модель может уточнить поиск или дочитать источник. |

Все варианты используют одну функцию поиска и дочитывания, проверку редакции,
допуск к источникам и общий бюджет контекста. Первичная подборка занимает
только доступную часть контекста. В Hybrid подтверждённый результат
вызова инструмента получает приоритет, а ссылка сохраняет идентификатор.
В списке источников отражаются материалы, дошедшие до модели.

В журнале запроса сохраняются режим, покрытие, поколение индекса и число
источников первичной подборки. Гибридный поиск по Server и Edge использует
один механизм публикации BM25. При обновлении меняются затронутые документы,
а выдача проверяет совпадение поколений векторного и лексического индексов.
