# Нативный координатор партии

829 добавляет [нативный HTTP-исполнитель целой партии](native-table-dispatch.md):
`api/src/index_batch.rs` соединяет конвертацию, inference и storage без Python
callbacks. В 830 [фоновый intake](native-intake-execution.md) запускает этот
исполнитель напрямую; ручной совместимый caller пока формирует конфигурацию/HTTP.
Партия не должна незаметно смешивать двух исполнителей.

Кандидат 822 ввёл `les_core_index_run`; в 829 штатный `_sync_parse` с собственным
нативным хранилищем подключён к полному Rust HTTP-исполнителю. Порядок, попытки, проверка регистрации, этапы, кеш/порции
векторов, публикация, восстановление, ошибки и итог принадлежат Rust.

| Владелец | Ответственность |
| --- | --- |
| `core/src/index_batch/mod.rs` | Выбор файлов, последовательность, подтверждение commit |
| `preparation.rs` | Неизменяемый JSONL, ограниченное чтение, SHA оригинала, временные файлы |
| `store.rs` | OS-блокировка набора, SQLite `les_index_batches`, этапы и ошибки регистрации |
| `policy.rs` | Коды, ограниченные повторы и время следующей попытки |
| `backend/native_index_batch.py` | Совместимый caller конфигурации и HTTP; без processing callbacks |

Адаптер не выбирает файлы и не пишет статусы, не принимает решения о повторе
или commit. Разбор поддерживаемых форматов, узлы/иерархия и исполнение
эмбеддингов в новом пути принадлежат Rust. Без нативного хранилища пока существует прежний путь;
его потребители и bootstrap закрываются до удаления общего runtime.

## Контракт и устойчивость

`les.index-batch.v1` получает серверные пути состояния, набор/коллекцию,
замороженный embedding descriptor и пределы партии. Модель не задаёт эти пути.
Прежняя строковая размерность descriptor сохраняется для fingerprint, но для
векторного IO преобразуется в проверенное целое.

Одна OS-блокировка принадлежит партии набора. Второй процесс получает
`INDEX_BATCH_BUSY`, не меняя текущий статус. После смерти владельца следующая
партия отмечает старую `INDEX_BATCH_OWNER_LOST` и продолжает PENDING; уже
подтверждённые документы не повторяются. Временные файлы зарегистрированы
в SQLite и очищаются по точным UUID-именам. Исходные папки не изменяются.

Этап и ошибка обновляют только начальную регистрацию: ID, путь, mtime, размер
и PENDING. Удалённая/заменённая строка не создаётся заново и не получает чужую
ошибку. Причина остаётся также в результате партии. Успешная обработка
подмножества не скрывает прежние ошибки других видимых документов.

SHA оригинала проверяется до разбора и перед эмбеддингами; публикация снова
проверяет оригинал и регистрацию перед commit. Все точки файла готовятся
заранее. При потере ответа Rust запрашивает восстановление и проверяет
фактические ID, SHA и число фрагментов в каталоге. Успешный ответ без commit
отвергается. Неизвестный/legacy-статус восстановления не равен восстановлению:
одного HTTP 200 недостаточно. Путь журнала определяет владелец Server/Edge.

Кеш не переключает модель. Fingerprint и выбранный эмбеддер заморожены;
ошибка другой модели терминальная. Отсутствующий обработчик требует ремонта
установки, а не бесконечного автоматического повтора.

Прежний бросаемый threadpool prefetch не используется этим путём. Пропускная
способность нескольких файлов с перекрытием OCR/эмбеддингов ещё требует замера;
ускорение только по факту переноса на Rust не заявляется.
