# Docling.rs и Xberg: граница замены парсеров

Стенд 871 завершил сравнение на 638 одинаковых оригиналах. Это отдельные
нативные пробники; приложение остаётся кандидатом 870, рабочий LES и индекс
не переключены. [Результаты и ограничения](../acceptance/native-parser-comparison-871.md).

## Закреплённые компоненты

| Компонент | Изолированный Rust-пробник | Назначение |
|---|---|---|
| Xberg 1.3.10, MIT | default-features=false; tokio-runtime, pdf, office, excel | Структура документов и геометрические PDF-таблицы |
| Docling.rs 2.82.1, MIT | default-features=false; pdf-text, preserve-order | DoclingDocument, слои, списки и объединённые ячейки |
| LES, кандидат 870 | Существующий форматный worker и прямой PDFium reader | Сравнительный нативный путь, OCR в этой серии недоступен |

Docling.rs — нативная Rust-библиотека, отличная от Python Docling. Обе
библиотеки собраны Rust 1.97. Xberg требует serde_json 1.0.154 против 1.0.150
в LES; транзитивная html-to-markdown-rs закреплена на 3.19.1, поскольку
3.22.0 требует Rust 1.99. Основные Cargo.lock приложения не менялись.

Отдельно проверены официальные оптимизированные Windows CPU CLI тех же
версий. Они стали итоговой серией на всём корпусе: текстовый слой,
структура, без OCR и без включения бинарных изображений в выдачу. У CLI
Docling присутствует ORT runtime, но ML/OCR-модели в этой серии не применялись.
Это другой профиль, его время нельзя смешивать с debug-пробниками.

Структурный Xberg включает `include_document_structure=true` и
`result_format=element_based`; Unified/plain не является полным документом.
Docling требует обхода `body/groups/texts/tables`, включая invisible-слои:
его стандартный Markdown не показывает скрытые листы.

## Решение по результатам

Победитель для замены всех форматов не принят. Предпочтительные роли для
следующей приёмки адаптера:

- DoclingDocument для DOCX: сохраняет контрольный текстовый блок колонтитула,
  ordered list и объединения. Большие деревья нужно выдавать порциями:
  два реальных DOCX превысили лимит JSON 96 МиБ даже без бинарных изображений.
- Xberg для геометрической структуры PDF: восстановил контролируемые таблицы
  из column-major потока, при affine-преобразовании и с продолжением строки.
  Четыре реальных PDF не уложились в 45 секунд. Существующий PDFium остаётся
  владельцем физического дочитывания и локатора страницы.
- Существующий Calamine-путь для таблиц: Xberg смещает адреса формул, а
  эквивалент `missing_formula_cache` у обоих кандидатов не принят. Формула
  и сохранённое значение должны оставаться разными данными.

Xberg не принят как замена DOCX: на отдельном воспроизводимом документе
пропущен текстовый блок колонтитула при сохранении обычного абзаца и таблицы
в том же колонтитуле. Это не исправляется включением структурного результата.

## Единый конвейер

```text
регистрация источника и редакции
  → ограниченный снимок исходных байтов, MIME и проверка архива
  → один изолированный обработчик формата
  → проверка полноты, OCR и локаторов
  → узлы LES: разделы, абзацы, таблицы/ячейки, ссылки на вложенные части
  → прежние нарезка, эмбеддинги и публикация поколения
```

Библиотека заменяет внутренний разбор, а не регистрацию, очередь, поисковый
индекс, координатор чата или проверку цитат. Её native IDs, MIME и binary hash
не заменяют doc_id, SHA-256 оригинала, редакцию и физическую страницу LES.
Нельзя передавать модели весь JSON дерева или создавать второй RAG-конвейер.

Существующий внешний worker сохраняет контроль путей и ZIP, лимиты/отмену,
причину ошибки, журнал восстановления и запрет публикации неполного документа.
Оба кандидата принимают повторяющийся `word/document.xml`: проверка дублей
остаётся снаружи. В пробнике снимка Xberg эта проверка отвергает такой архив.

Два реальных файла с расширением XLS содержат OOXML. Xberg File API их
отвергает; пробник определяет MIME по содержимому и читает оба через from_bytes.
У адресов формул это ничего не исправляет: `collect_sheet_formulas`
не учитывает `range.start()` при вычислении A1-координат.

Пустой успешный вывод не означает INDEXED. На 55 реальных PDF оба кандидата
вернули пустой текст при успешном выходе. Docling text-layer CLI не требует
OCR автоматически; Xberg имеет признаки scanned_pages, но их нужно перевести
в договор полноты LES. Сканы, рисунки/OLE и OCR-происхождение ещё не приняты.

## Условия удаления старого кода

Удалять текущий разбор формата можно после проверки canonical nodes,
оригинальных ячеек/координат, вложенных частей, статусов неполноты и
физических PDF-локаторов. Затем нужны публикация/восстановление на копии,
поиск и Qwen с цитатами. Извлечение текста само по себе этого не доказывает.

Стенд также обнаружил отдельный дефект LES: навигационная проекция
разреженного листа теряет заполненную первую строку при выборе заголовка.
Исправление должно отделить исходные ячейки от представления заголовка;
сырой читатель, публикация и поиск требуют собственной регрессии.

Источники: [Xberg 1.3.10](https://github.com/xberg-io/xberg/tree/v1.3.10),
[Docling.rs 2.82.1](https://github.com/docling-project/docling.rs/tree/v2.82.1).
