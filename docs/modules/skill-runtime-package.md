# Автономный Python только для внешних навыков

Кандидат 827 завершает отдельный механизм поставки исполнителя. Библиотекой,
разрешениями, очередью, журналом, лимитами и восстановлением по-прежнему владеет
Rust. Встроенные вычисления переносятся в Rust; внешний одобренный `.py` остаётся
без переписывания и запускается совместимым CPython.

Windows-сборщик `tools/skill_python_asset.py` копирует уже подготовленный
portable Python и его зависимости/лицензии в `native/skill-python`.
Он ничего не скачивает и не устанавливает. По умолчанию полный сборщик
берёт тот же locked-набор зависимостей, что был доступен прежде; отдельный
`--skill-python` позволяет сборщику явно передать подготовленный комплект.
Нет отбора зависимостей по предполагаемой теме задачи.

Выпускаются полный инвентарь SHA-256 и квитанция компонента. `_pth` содержит
только стандартную библиотеку, корень интерпретатора и `Lib/site-packages`.
Нет `import site`, путей приложения и исполнения `.pth`-кода. Сборщик отдельно
фиксирует существующие относительные каталоги зависимостей из `.pth`, без
выполнения строк `import` и без внешних/родительских путей. Rust проверяет
эти пути внутри дерева зависимостей. Каталог DLL pywin32 подключается явно
после установки ограничений процесса; startup-скрипт pywin32 не исполняется.
Симлинки/junction исходного комплекта не принимаются.

У выбора исполнителя один владелец: `core/src/skills/runtime.rs`.
Его используют Rust launcher и совместимый Python API. Новый полный пакет
содержит marker `native/skill-python-required.json`; повреждённый или
отсутствующий обязательный комплект даёт `SKILL_RUNTIME_INVALID`, без
подмены системным/app Python. Квитанция, exe, stdlib, `_pth` и инвентарь
проверяются при выборе. Полный хеш каждого файла дополнительно входит
в общий манифест установщика; запуск не повторяет хеширование всех библиотек.

Для прежних пакетов без отдельного компонента и обязательного marker сохранён
явный совместимый путь через прежний интерпретатор. Оператор может выбрать
свой program через `--skill-python` или `LES_SKILL_PYTHON`. Модель не задаёт
исполнитель или разрешённые пути зависимостей. Чтение инструкций/результатов
задания не требует работающего Python-исполнителя.

Старый `--skill-host` сохранён. Процесс запускается с `-I -S -B`: отсутствует
startup site, не создаются pyc в комплекте. API-ключи/PYTHONPATH не передаются,
нет импортов backend/proxy LES. Это доверенный, одобренный оператором код,
не sandbox произвольных программ. Лимиты/Job Object и подтверждённые строки
сохраняются. Недостающая библиотека получает `SKILL_DEPENDENCY_MISSING`,
читаемое сообщение и исходную причину в приватном `failure.json`.

Пока остальные части приложения требуют Python, переходный полный пакет
содержит и прежний app runtime, и отдельный исполнитель навыков. Это не
оптимизированный финальный установщик. После удаления серверного runtime
останется совместимый исполнитель внешнего кода. Приёмка чистой Windows
и полный Python-exit ещё открыты. [Проверки](../acceptance/native-builtins-runtime-827.md).
