# Автономный Python только для внешних навыков

В исходниках 955 Windows-установщики содержат описание отдельного архива
`LES-Skill-Python-<номер сборки>.zip`. Rust запрашивает этот архив по тегу
сборки после проверки разрешения, хеша скрипта и входных данных. Проверенные
файлы сохраняются в каталоге данных пользователя. Повторный запуск использует
сохранённый компонент. При сбое сети пользователь может повторить запрос.
Запуск Леса, обычный RAG, PDF и чтение инструкций навыков доступны сразу.
PDFium остаётся DLL в основном комплекте. Путь macOS Preview не менялся.

Кандидат 827 ввёл отдельный механизм поставки исполнителя. Библиотекой,
разрешениями, очередью, журналом, лимитами и восстановлением по-прежнему владеет
Rust. Встроенные вычисления переносятся в Rust; внешний одобренный `.py` остаётся
без переписывания и запускается совместимым CPython.

Windows-сборщик создаёт отдельную среду из группы `skill-runtime` в `uv.lock`.
В ней есть библиотеки для таблиц, PDF, Word, DXF, числовых расчётов и HTTP.
Проверенный экспорт группы состоит из 29 записей. Серверные пакеты FastAPI,
Uvicorn, LlamaIndex и Qdrant, а также фреймворки агентов, исключены из
этого экспорта. PDFium DLL для штатного PDF-читателя берётся из
зафиксированного wheel pypdfium2. Группа использует те же версии и SHA-256,
что и общий lock-файл.

Для внешнего навыка с дополнительными зависимостями сборщик принимает
подготовленный комплект через `--skill-python`. Его копирование, изоляция и
проверка остаются в `tools/skill_python_asset.py`. У сборочной среды и
macOS Preview свой набор зависимостей.

Выпускаются полный инвентарь SHA-256 и квитанция компонента. `_pth` содержит
только стандартную библиотеку, корень интерпретатора и `Lib/site-packages`.
Нет `import site`, путей приложения и исполнения `.pth`-кода. Сборщик отдельно
фиксирует существующие относительные каталоги зависимостей из `.pth`, без
выполнения строк `import` и без внешних/родительских путей. Rust проверяет
эти пути внутри дерева зависимостей. Каталог DLL pywin32 подключается явно
после установки ограничений процесса; startup-скрипт pywin32 не исполняется.
Симлинки/junction исходного комплекта не принимаются.

У выбора исполнителя один владелец: `core/src/skills/runtime.rs`.
Его используют Rust launcher и совместимый Python API. Старый Windows-пакет
с маркером `native/skill-python-required.json` сохраняет прежнюю проверку
при запуске. Пакет 955 фиксирует размер и SHA-256 архива и SHA-256 квитанции
в `native/skill-python-download.json`. Лес проверяет архив до распаковки,
устанавливает компонент атомарно, а при повторном запуске проверяет квитанцию,
exe, стандартную библиотеку, `_pth` и инвентарь.

Для прежних пакетов без отдельного компонента и обязательного marker сохранён
явный совместимый путь через прежний интерпретатор. Оператор может выбрать
свой program через `--skill-python` или `LES_SKILL_PYTHON`. Модель не задаёт
исполнитель или разрешённые пути зависимостей. Чтение инструкций/результатов
задания не требует работающего Python-исполнителя.

Старый `--skill-host` сохранён. Процесс запускается с `-I -S -B`: отсутствует
startup site, не создаются pyc в комплекте. API-ключи/PYTHONPATH не передаются,
нет импортов backend/proxy LES. Это доверенный, одобренный оператором код,
не sandbox произвольных программ. Лимиты/Job Object и подтверждённые строки
сохраняются. Недостающая библиотека получает `SKILL_DEPENDENCY_MISSING`,
читаемое сообщение и исходную причину в приватном `failure.json`.
