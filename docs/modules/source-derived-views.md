# Повторное чтение Word и рисунков

Кандидат 878, Rust. Рабочая установка и индекс не переключаются.

Полное представление Word принадлежит `core/src/document/conversion`.
Индексация и физический читатель используют один результат преобразования,
а подготовка поисковых фрагментов выполняется после него с текущими параметрами.
Производный кэш не содержит готовых ответов или результатов поиска.

`api/src/document_cache.rs` закрепляет представление за SHA-256 оригинала,
бинарного обработчика, парсеров, OCR-помощника и настройками извлечения.
Каждое чтение проверяет оригинал; наличие кэша не отменяет область доступа,
поколение индекса и проверку редакции. Для Word с вложениями сверяется также
опубликованный манифест объектов. Неполный файл кэша и неверная контрольная
сумма означают промах, а не пустой успешный документ.

`api/src/derived_cache.rs` хранит только производные данные в собственном
`storage/derived-views`: не более 16 МиБ на запись, 128 МиБ и 1024 записей
суммарно. Публикация через временный файл и переименование; вытеснение по
времени публикации. Ошибка записи кэша не заменяет результат чтения отказом.
Оригиналы, индекс и пользовательские файлы этот механизм не удаляет.
Ключи и контрольные суммы используют общее каноническое представление JSON,
чтобы порядок полей в разных обработчиках не создавал ложный промах.

Снимки физических PDF-страниц используют тот же кэш. Идентичность включает
страницу, SHA-256 оригинала и PDFium, версию парсера/обработчика и настройки OCR.
Запрос, окно текста и курсор применяются после получения полного снимка;
переиспользование не смешивает соседние страницы и редакции. Оригинал проверяется
до публикации производного снимка и перед возвратом пользователю.
При чтении нескольких страниц одного PDF в Windows запрос может удерживать
проверенный read-only handle без разрешения записи и замены. Тогда хеш
оригинала считается один раз на документ, а страницы используют типизированную
привязку к этому файлу и SHA-256. Параметр из JSON не может заменить проверку.
Дескрипторы закрываются при завершении запроса. При конфликте с открытым
писателем и на других платформах сохраняется проверка каждой страницы.

Каждый законченный результат распознавания рисунка публикуется отдельно.
После тайм-аута следующая попытка может использовать законченные объекты;
полное представление Word публикуется только по завершении преобразования.
Кэш не является журналом заданий и не обещает автоматический запуск повтора.

На Windows валидированные WMF переводятся GDI в EMF для чтения буквальных
Unicode-записей. Идентификаторы глифов, неизвестная кодировка, обрезка и
неподдержанные трансформации не угадываются: сохраняется путь растрового OCR.
Координаты и исходные текстовые записи доступны, но не объявляются пониманием
геометрии, стрелок или расчётных значений графика. Увеличение маленьких формульных
растров для OCR отклонено при проверке: терялись знаки и части формул. В продукт
этот эксперимент не включён; непрочитанный растр остаётся изображением,
а не догадкой, вставленной в текст.

Явное `read_source(view=part)` через MCP возвращает JSON и стандартный
`ImageContent` PNG для единственного выбранного вида. Совпадение SHA-256,
локальный владелец API, размер и габариты проверяются перед передачей.
При нескольких видах исходного объекта вид не выбирается скрыто. Отказ
загрузки изображения — `isError`, а не фиктивная картинка. В интерфейсе тот же
объект доступен в источнике через «Рисунки и вложения», с порциями и возвратом.

Формат MCP: [Tools / Image content](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).
GDI: [SetWinMetaFileBits](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-setwinmetafilebits),
[EMRTEXT](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-emrtext).

Фактические измерения и непроверенные сценарии фиксируются в отдельном
отчёте приёмки; наличие кэша само по себе не доказывает ускорение первого чтения.

Отбор контекста сохраняет прежнюю формулу MMR, порядок и бюджеты. Стоимость
единицы считается один раз; максимальная избыточность обновляется только для
нового выбранного фрагмента; вклад новизны считается по словам вопроса без
построения временной копии всего словаря. Это устранение повторных вычислений,
а не новая эвристика ранжирования. Edge при открытии обеспечивает keyword-индексы
для набора, пути и родителя; dense-векторы и версии документов не пересчитываются.
