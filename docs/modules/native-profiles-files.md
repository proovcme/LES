# Профили, реестр инструментов и чтение файлов в Rust

Кандидат 820. Владельцы логики: `core/src/chat_profiles/`,
`core/src/tool_registry.rs`, `core/src/filesystem.rs`, `api/src/profiles.rs`.

## Профили

Создание, проверка, публикация ревизий, выбор активного профиля, привязка к
разговору и компиляция инструкций выполняются Rust. Схема существующей SQLite
сохранена. Удаление записи из библиотеки не меняет ранее привязанный снимок;
активный пользовательский выбор не заменяется заводским при запуске.
Заводские контракты вынесены в `config/chat-profile-defaults.json` и
`config/builtin-tools.json`. Старый `chat_profile_service.py` — адаптер протокола,
его прежняя реализация хранения и проверки удалена.

Пути `/api/profiles`, редактирования/активации профилей, библиотеки текстов,
привязки к чату, инструкций и `/api/tools/registry` обслуживает Rust API без
Python backend. Описания MCP читаются только из явно выбранного кеша; чтение
реестра не подключается к серверу и не исполняет его инструкции.
Внешние ссылки JSON Schema запрещены. Клиент и исполнение MCP ещё требуют переноса.

## Файловые инструменты

`filesystem_roots/list/stat/read_text/search/hash` используют один нативный
исполнитель. Python-обход, вычисление хеша и чтение из прежнего harness удалены;
остались настройка разрешённых корней и передача результата в существующий
журнал инструментов. Сам общий trusted executor пока не перенесён.

Исполнитель принимает ключ разрешённого корня и относительный путь. Проверяет
реальный открытый Windows handle, исключает дочерние junction/symlink,
ограничивает обход, размер текста и время, сверяет изменение файла. Исходники
открываются для чтения. Неверный UTF-8 отмечается явным предупреждением.

Ошибки доступа, исчезновения/изменения файла, размера и времени сохраняют
отдельные коды. Ошибка чтения источника останавливает генерацию уверенного
ответа в контроллере, как и ошибка чтения PDF. Интеграционные проверки включают
реальную Windows junction за пределы разрешённого корня и неизменность исходника.

Это проверка исходников и отдельного API-процесса. Установленное приложение,
полный чат с Qwen, автономные старые навыки и отсутствие общего Python
этим документом не объявляются принятыми.
