# Контекст чата: единый Rust-владелец

873: `api/src/chat/evidence/pages.rs` собирает смежные передачи физической
PDF-страницы до разбора таблиц. Evidence остаётся единственным владельцем
текста; диапазоны проверяются по символам, источник — по документу, набору,
SHA-256 и странице. Полная страница обязательна как один блок; исходные
квитанции и журнал вызовов сохраняются. Между страницами, редакциями,
разрывами и окнами буквального поиска склейки нет.

873: терминальная проекция строк не задаёт формат выбора инструмента.
Search сохраняет ответ по достаточному предварительному чтению и возможность
уточнения; само наличие текста не доказывает выполнение чтения оригинала.
Оба читателя учитываются в действительном размере схем и жёстком лимите
профиля. [Проверка и ограничения](../acceptance/native-reader-admission-873.md).

867: диагностика fusion сохраняется в начальной квитанции, не повторяется
в явных поисковых обменах инструментов. Освобождение схем не создаёт
табличную ошибку и не меняет формат качественного ответа. Реальные ошибки
выбора строк сохраняют собственную обратную связь.
[Проверки и ограничения](../acceptance/native-fusion-867.md).

865: начальные фрагменты допускаются до расширения файлов; предварительный
предел вычисляется из окна модели, окончательный допуск выполняет общий packer.
Материализованные PDF-страницы дедуплицируются до квот. Новое чтение сохраняет
другие допущенные документы; навигация — необязательный checkpoint после фактов.
Квитанция уплотняется без изменения полного журнала. [Границы](../acceptance/native-source-selection-865.md).

863: необязательный документ сначала пробуется целиком, затем допускает целые
блоки при меньшем фактическом окне. Неполное включение явно отмечено; обязательные
чтения и пары инструментов не делятся. Это замена прежнего правила 861
«вся группа или ничего». [Причины и приёмка](../acceptance/native-context-budget-863.md).

862: `tabular.rs` показывает строки R и ячейки C1/C2, не угадывая значения
или назначение колонок. Пустота не становится нулём; исходный payload цитаты
не изменяется. В полной единице чтения имя документа выводится один раз.
Для табличных фактов в Push без активного табличного задания с любым профилем
и в документном чтении вне Agent
Qwen выбирает адреса строк; `chat/table_facts.rs` проверяет их по реально
доставленному окну и копирует исходные ячейки. Agent с инструментами в
Pull/Hybrid или активным табличным заданием этим финальным договором пока
не покрыт; проекция ячеек общая.
[Проверки и ограничения](../acceptance/native-numeric-evidence-862.md).

861: полные помещающиеся документы передаются как `les.evidence-unit.v1`:
упаковщик принимает или исключает всю группу страниц, сохраняя отдельные
типизированные номера источников. Цитаты из тела текста не расширяют их набор.
[Проверки и границы](../acceptance/native-context-selection-861.md).

860 удаляет второй реестр прочитанного и промежуточный объект его передачи.
`Evidence` сам выдаёт допустимые обязательные и необязательные блоки; повторный
признак строгости из координатора удалён. Подтверждение доставки сбрасывается
новым чтением. [Удалённое дублирование и проверки](../acceptance/native-rag-cleanup-860.md).

859 отделяет управляющий `source_index` от текста доказательства в блоке
`les.evidence-block.v1`. Буквальные номера источников в содержимом не расширяют
карту цитат. Подтверждение чтения требует передачи блока в текущем окне,
а не старой квитанции. [Границы приёмки](../acceptance/native-retrieval-859.md).

Кандидат 858 вводит скользящее окно внутри одного ответа и истории диалога.
Обязательны текущий запрос, последнее чтение целиком, текущая пара вызова и
результата инструмента, последний ход диалога и состояния активных заданий.
Ранее прочитанные доказательства, прежние пары инструментов и старые ходы
остаются целыми необязательными объектами. При нехватке места приоритет
получает недавняя история; перед отправкой восстанавливается хронология.
Provider call ID не перепривязываются и не разделяются со своим результатом.

Полные квитанции и тексты сохраняются в журнале запроса. Исключение из окна
не удаляет оригинал и не выдаётся за суммаризацию. Модель получает явное
предупреждение о границах окна; для новой цитаты выпавший текст нужно снова
прочитать. Допустимая карта источников строится только по реально включённым
блокам доказательств, а не по старой квитанции или памяти диалога. Текущий
блок, который сам превышает окно, по-прежнему даёт явное переполнение.

До следующего чтения `api/src/chat/budget.rs` тем же packer рассчитывает место
после обязательных инструкций, запроса, последнего хода, схем и активных заданий.
Из него резервируются 256 оценочных токенов для новой квитанции и покрытия.
Reader получает ограничение порции; индексированные фрагменты дополнительно
резервируют 1024 символа на идентификатор, указатель цитаты и покрытие каждого
целого блока. Это консервативный резерв метаданных, не предметное ранжирование.
Ограничение `max_chars` отражается в `result.context_budget`; неполнота не
скрывается. PDF продолжает по прежнему курсору. Проверки ID/SHA/страницы,
лимиты вызовов, окно модели и защита RAM сохраняются.

Расчёт токенов остаётся оценкой packer (два символа на токен с резервами),
а не подсчётом конкретным токенизатором модели. Реальное usage провайдера
сохраняется в подтверждённой трассе; оно не заменяется оценочным числом.

Кандидат 834 переносит целиком подготовку одного модельного контекста из
`chat_evidence_context.py` и расчёт покрытия из `section_coverage_service.py`.
Первый файл остаётся совместимым кодеком, второй удалён после проверки всех
потребителей. Второго packer и Python-решений о видимости источника нет.
Существующий бюджетный алгоритм `core/src/context.rs`
используется повторно, а не заменяется новым.

| Владелец | Ответственность |
| --- | --- |
| `core/src/chat_context/assembly.rs` | Кандидаты, обязательные объекты, два прохода упаковки, сообщения провайдеру |
| `core/src/chat_context/coverage.rs` | Полнота индексированного раздела, резерв места и финальная запись покрытия |
| `core/src/chat_context/presentation.rs` | Границы источников, профиль/навыки, trace, подготовка и подтверждение передачи |
| `core/src/chat_context/mod.rs` | Типизированная граница действий, отбор памяти и реально видимых источников |

ABI `chat_context` возвращает объект `value`. Прямой Rust-вызов принимает те же
JSON-данные и не требует Python callback, модели, сети или доступа к файлам.
Снимок профиля/память/найденные материалы передаются явно. Чтение реестра
промптов остаётся внешним входом: при отсутствии текста нужен явно переданный
`default_prompt`. Существующий профиль не вызывает чтение реестра по умолчанию.

Источник и его заголовок входят/выпадают вместе. После первого прохода удаляются
ссылки на выпавшее evidence; второй проход не может вернуть эти ссылки. Память
и старые сообщения не превращают источник в прочитанный. Текущий обязательный
результат инструмента и последний ход диалога не обрезаются: переполнение возвращается явно,
без готовых сообщений для модели. Native tool call/result сохраняются парой.

Отчёт покрытия считает уникальные point ID внутри dataset/document/parent.
Разные/неизвестные количества дают `unknown`, а не ложную полноту. Даже `complete`
касается только индексированных фрагментов, не полноты оригинала/OCR и не
возможности ответить. С 858 резерв покрытия выделяется для достижимых источников; финальная
запись не вытесняет доказательство. Trace скрывает текст профиля/вопроса/памяти;
показывает точный текст evidence и SHA. `prepared` не означает передачу модели.

Подтверждены совместимость сообщений/packet/trace на 180 дифференциальных случаях
и прежние регрессии PDF, таблиц, профилей. [Приёмка](../acceptance/native-chat-context-834.md).
Общий HTTP-путь чата, retrieval application, специальные обработчики,
реестр промптов и classic ещё не перенесены целиком. Эта сборка не означает
полный Python-exit и не установлена в рабочий LES. Внешние навыки сохраняют
отдельный автономный CPython; код приложения туда не переносится.
