# Готовый модуль работы с кодом · решение, не реализация

Выбран отдельный адаптер OpenCode. На машине разработки обнаружен OpenCode
1.18.23; новая зависимость не установлена и в пакет LES не включена. Проверена
локальная справка CLI. Документация поставщика: [server](https://opencode.ai/docs/server/),
[providers](https://opencode.ai/docs/providers/),
[permissions](https://opencode.ai/docs/permissions/).

LES остаётся владельцем пользовательского диалога, памяти, источников и истории
файлов. Модулю передаются задача, явное подключение модели и отдельная рабочая
копия. Результат — изменения с просмотром и применением через журнал LES.
Планируется Rust-владелец процесса с отменой, лимитами, прогрессом и журналом;
никакого обязательного Python-адаптера. MCP сохраняется для внешних интеграций.

До включения нужны проверка протокола именно установленной версии, отдельные
config/env без наследования ключей/глобальных инструментов, явные права на команды,
защита оригиналов и тесты отмены/сбоя/конфликта файлов. Разрешения OpenCode сами
по себе не являются ОС-песочницей. Не включать `--auto`, скрытое назначение модели,
сетевой fallback или автоматическую установку провайдера. Qwen3.5:9b разрешена
владельцем для проверки, но возможности кодового агента на ней ещё не измерены.

Критерий готовности: найти код → прочитать → предложить правку → проверить
разрешённой командой → показать diff → применить с откатом; отказ или остановка
сохраняют прежние файлы. Сейчас адаптер не подключён к чату и не заявляется готовым.
