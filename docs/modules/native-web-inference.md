# Интернет-инструменты и модельный транспорт в Rust

Кандидат 819. Это изменения исходников и отдельного стенда; рабочая установка,
её назначения моделей и индекс не переключались.

## Поиск и чтение интернета

`api/src/web.rs` обслуживает приватный `POST /api/light/internal-web`.
Доступ требует токен владельца runtime и отсутствие браузерного Origin.
Эту границу вызывают уже существующие инструменты чата `web_search` и
`web_read`. Python здесь передаёт JSON локальному Rust-процессу.

- Простой поиск: DuckDuckGo HTML, при отказе провайдера — Bing RSS. Переключение
  возвращает фактический `provider`, `degraded` и понятный `fallback_reason`.
  Пустая корректная выдача сама по себе не вызывает смену провайдера.
- Расширенный поиск сохраняет явно настроенный SearXNG и прежний переход
  к простому поиску при его отказе. Адрес сервиса берётся из конфигурации,
  а не из аргументов, предложенных моделью.
- У результатов остаются название, выдержка, домен, прямой URL и время
  получения. DuckDuckGo redirect декодируется один раз. Дубликаты удаляются;
  скриптовые ссылки, адреса с паролями и числовые частные адреса не источники.
- Нативное чтение выбранной публичной страницы не требует браузера/Crawl4AI.
  DNS проверяется до соединения, соединение закреплено за разрешённым IP.
  Каждый redirect проверяется заново; локальные, служебные, link-local,
  multicast и CGNAT-адреса недоступны. Максимум три перенаправления.
- Общий срок — 30 секунд, ответ — до 2 МиБ, текст страницы — до 4000 символов,
  выдача инструмента чата — до четырёх результатов. Число одновременных
  обращений ограничено семафором API. Тела ответов и запросы не пишутся в stderr.
- UTF-8, явно объявленные Windows-1251 и другие поддерживаемые charset
  разбираются в Rust. Неизвестная или повреждённая кодировка даёт ошибку.
  HTML разбирает согласованный `scraper`; скрипты, формы и скрытые элементы
  исключаются из текста. RSS разбирает уже используемый `quick-xml`, без DTD.
- Капча, ограничение запросов, тайм-аут и недоступность службы — статус
  `error` с объяснением, без выдуманного доказательства и пустого успеха.
- Режим «только выбранные источники» исключает оба интернет-инструмента.
- Нативные CLI/MCP публикуют `web_search` и `web_read` через общий
  `/api/tools/call`, с `readOnlyHint=true` и `openWorldHint=true`.
  Обёртка вызова инструмента пока обслуживается общим Python API.

Чтение через явно настроенный расширенный Crawl4AI пока остаётся прежним.
Работа страницы, требующей JavaScript/авторизации, не обещается обычным HTTP
reader. Поисковая выдержка не равна прочитанной странице. Содержание сайта
остаётся недоверенными данными, а не инструкциями пользователя.

Формат RSS поиска описан в первичном
[блоге Bing](https://blogs.bing.com/search/2005/1/RSS-Feeds-for-Search-Results/).
Доступность внешнего сайта не гарантируется этим протоколом; фактический
ответ отдельно проверен на стенде.

## Модельный транспорт

`core/src/model_profile.rs` владеет разрешением лимитов и пресетов;
250 замороженных случаев сравнивают результат с прежней реализацией.
`model_request.rs` готовит тела запросов, порядок системных сообщений,
изображения и точные JSON-аргументы инструментов. `model_capabilities.rs`
проверяет свежие наблюдения возможностей. `model_secrets.rs` разрешает
только допущенные ссылки env, защищает запись от потерянных параллельных
изменений и сохраняет посторонние строки конфигурации.

Приватный `/api/light/internal-inference` разрешает точную ревизию или явно
назначенную роль в SQLite, читает ключ, проверяет адреса и собирает запрос
без Python backend. HTTP/SSE/NDJSON и скрытые reasoning-дельты обрабатывает
Rust. Системный TLS-процесс принадлежит одному запросу, ограничен временем
и закрывается при отмене. Разрыв без завершения не превращается в успех.

Действующий чат умеет вызывать этот путь через адаптер с ID ревизии и
сообщениями. Общий контроллер чата, политика облачного допуска и часть
инструментов остаются в Python. `core/src/agent_loop.rs` — проверенный
кандидат координатора, но ещё не переключённый основной цикл приложения.
Согласованные ORT/jsonschema/mail-parser/scraper зафиксированы в Cargo.lock;
само добавление ORT не означает завершение переноса локальных моделей/OCR.

## Проверки

Целевые проверки: `tests/test_light_native_web.py`,
`tests/test_light_native_cli.py`, `tests/test_web_search_service.py`,
`tests/test_light_native_model_runtime.py`,
`tests/test_light_native_model_profiles.py` и
`tests/test_openai_compatible_transport_service.py`.

На отдельном экземпляре без Python backend проверены SearXNG-ответ через
инструмент чата, точные URL, выдержки и читаемая ошибка запрета локального
адреса. На живом интернете 07.11.2026 DuckDuckGo запросил капчу; резервный
Bing вернул четыре источника за 0,86 с. Публичная страница книги Rust
прочитана за 0,30 с: 944 символа, название и URL. Это проверка транспорта,
а не оценка качества генеративного ответа или ранжирования всего интернета.
Нативный stdio MCP проверяется настоящим MCP-клиентом на отдельном API.
Итоговые проверки и ограничения: [приёмка 819](../acceptance/native-web-inference-819.md).

Общий перенос Python остаётся незавершённым: полный цикл чата и исполнения
инструментов, все форматы/OCR/эмбеддеры, общий API/bootstrap и classic UI.
Совместимый автономный исполнитель прежних Python-навыков сохраняется
по явному требованию владельца. Общий код приложения в него не переносится.
