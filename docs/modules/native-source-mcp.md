# Источники RAG через MCP и CLI

Кандидат 876. Рабочая установка и её MCP-подключение не переключаются.

## Один читатель

`api/src/chat/tools/sources.rs` владеет поиском и чтением. `SourceContext`
содержит только запрос, замкнутую область документов и политику поиска.
Чат строит его из подготовленного хода; MCP — из пользовательского каталога.
Для чтения через MCP не создаются диалог, память, назначение модели ответов
или запрос к Qwen. Модель эмбеддингов требуется для смыслового поиска,
но не для чтения найденной физической страницы PDF.

`POST /api/rag/sources/call` принимает `tool` и `args`. Разрешены только
`search_sources`, `read_source`, `read_pdf_source`, `read_excel_source`,
`dataset_map`. Схемы проверяются общим реестром, доступ — нативной политикой.
Произвольные программы, HTTP-адреса и запись исходников здесь недоступны.
Совместимый `/api/tools/call` использует тот же путь для источников и общий
Rust-обработчик для явно вызванных `web_search`/`web_read`.

`runtime/src/cli/mcp_tools.rs` публикует те же описания источников из
`config/builtin-tools.json`; старое имя `query` у MCP-поиска переводится в
каноническое `q`. Команда `les tool` вызывает того же владельца. Удалена
отдельная проекция MCP-поиска через отсутствующий `/api/search`.

## Договор чтения

- `search_sources`: вопрос без ручного имени файла; `view=documents` возвращает
  только каталог. Имена, заголовки и статусы не становятся доказательствами.
- `read_source`: последовательные индексированные единицы, при необходимости
  поиск внутри документа, номер пункта или сохранённые части Word.
- `read_pdf_source`: настоящая страница оригинала, проверенная SHA-256;
  `next_offset` продолжает длинную страницу, не следующую страницу документа.
- `read_excel_source`: сохранённые индексированные разделы, не пересчёт
  формул и не обещание чтения всей книги за один вызов.
- `dataset_map`: ограниченная навигация. Для продолжения применяется
  `list_documents` с тем же набором и возвращённым смещением.

Возвращается исходный `les_tool_result_v1`, включая `sources`, `coverage`,
`next_offset`, `index_revision` и квитанцию чтения. Отдельный урезанный формат
`hits` больше не скрывает продолжение и идентификаторы. Это изменение JSON-
выхода `les search`/MCP; автоматическим клиентам следует читать `result`.

Для продолжения индексированного текста передаются прежние параметры и
`index_revision`. Изменившееся поколение даёт отказ, а не новую страницу по
старому смещению. `source_sha256` закрепляет оригинал. Совпадение имени или
текста не означает равенства редакций. Каталог имён не является снимком
содержимого; при изменении состава его обход следует начать заново.

Ссылки MCP абсолютные, с идентификатором документа, SHA-256 и `#page=N`
там, где есть физическая страница. Для Word страницы не выдумываются.
HTTP-отказ сохраняет безопасный код причины в MCP `isError=true`; ошибка
чтения не равна отсутствию ответа. Клиент отвечает только по полученным
данным, отмечает частичное покрытие и дочитывает нужные порции.

У физического PDF-чтения `max_chars` ограничен 12000, поисковая фраза —
200 символами. Координатор чата берёт предел из контракта читателя перед
назначением своей порции, а не создаёт параметры, которые сам же отвергает.
Фраза выбирает начальное окно страницы; последующее ненулевое смещение
продолжает ту же страницу, даже если фраза осталась в аргументах.

## Проверка

Изолированный stdio-сервер должен быть привязан к опубликованному адресу
копии и её `instance_id`; до и после запроса проверяется тот же владелец.
Штатный MCP не перенаправляется скрыто. Проверка поиска/чтения выполняется
без `les_chat`, чтобы отдельно оценивать данные RAG и генерацию ответа.

Модуль не доказывает качество всех обзорных ответов и не меняет рабочий
индекс. Приёмка на документах и незакрытые ограничения фиксируются отдельно.
