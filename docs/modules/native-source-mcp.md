# Источники RAG через MCP и CLI

Кандидат 877. Рабочая установка и её MCP-подключение не переключаются.

## Один читатель

`api/src/chat/tools/sources.rs` владеет поиском и чтением. `SourceContext`
содержит только запрос, замкнутую область документов и политику поиска.
Чат строит его из подготовленного хода; MCP — из пользовательского каталога.
Для чтения через MCP не создаются диалог, память, назначение модели ответов
или запрос к Qwen. Модель эмбеддингов требуется для смыслового поиска,
но не для чтения найденной физической страницы PDF.

`POST /api/rag/sources/call` принимает `tool` и `args`. Разрешены только
`search_sources`, `read_source`, `read_pdf_source`, `read_excel_source`,
`dataset_map`. Схемы проверяются общим реестром, доступ — нативной политикой.
Произвольные программы, HTTP-адреса и запись исходников здесь недоступны.
Совместимый `/api/tools/call` использует тот же путь для источников и общий
Rust-обработчик для явно вызванных `web_search`/`web_read`.

`runtime/src/cli/mcp_tools.rs` публикует те же описания источников из
`config/builtin-tools.json`; старое имя `query` у MCP-поиска переводится в
каноническое `q`. Команда `les tool` вызывает того же владельца. Удалена
отдельная проекция MCP-поиска через отсутствующий `/api/search`.

## Договор чтения

- `search_sources`: вопрос без ручного имени файла; `view=documents` возвращает
  только каталог. Имена, заголовки и статусы не становятся доказательствами.
- `read_source`: Word читается из проверенного оригинала через тот же нативный
  обработчик, что при индексации. Абзацы, заголовки, целые строки таблиц и
  повторённая шапка образуют самостоятельное представление чтения. Для других
  форматов сохраняются индексированные единицы, поиск внутри документа и пункты.
  `view=parts/part` сохраняет доступ к вложенным объектам Word.
- `read_pdf_source`: настоящая страница оригинала, проверенная SHA-256;
  сканы распознаются настроенным системным OCR. `next_offset` продолжает
  один хешированный снимок страницы, не следующую страницу документа.
  Успех OCR не подтверждает точность чисел или расположение ячеек.
- `read_excel_source`: сохранённые индексированные разделы, не пересчёт
  формул и не обещание чтения всей книги за один вызов.
- `dataset_map`: ограниченная навигация. Для продолжения применяется
  `list_documents` с тем же набором и возвращённым смещением.

Возвращается исходный `les_tool_result_v1`, включая `sources`, `coverage`,
`next_offset`, `index_revision` и квитанцию чтения. Отдельный урезанный формат
`hits` больше не скрывает продолжение и идентификаторы. Это изменение JSON-
выхода `les search`/MCP; автоматическим клиентам следует читать `result`.

Для продолжения индексированного текста передаются прежние параметры и
`index_revision`. Word и OCR-продолжения требуют `view_sha256`; он закрепляет
версию представления и его разбиение. Чтение Word не требует модели или
настроенного векторного индекса. Любой тёплый кеш повторно проверяет SHA-256
оригинала; отсутствующий/изменённый файл не прикрывается кешем. Изменившееся поколение даёт отказ, а не новую страницу по
старому смещению. `source_sha256` закрепляет оригинал. Совпадение имени или
текста не означает равенства редакций. Каталог имён не является снимком
содержимого; при изменении состава его обход следует начать заново.

Ссылки MCP абсолютные, с идентификатором документа, SHA-256 и `#page=N`
там, где есть физическая страница. Для Word страницы не выдумываются.
HTTP-отказ сохраняет безопасный код причины в MCP `isError=true`; ошибка
чтения не равна отсутствию ответа. Клиент отвечает только по полученным
данным, отмечает частичное покрытие и дочитывает нужные порции.

У физического PDF-чтения `max_chars` ограничен 12000, поисковая фраза —
200 символами. Координатор чата берёт предел из контракта читателя перед
назначением своей порции, а не создаёт параметры, которые сам же отвергает.
Фраза выбирает начальное окно страницы; последующее ненулевое смещение
продолжает ту же страницу, даже если фраза осталась в аргументах.

## Проверка

Изолированный stdio-сервер должен быть привязан к опубликованному адресу
копии и её `instance_id`; до и после запроса проверяется тот же владелец.
Штатный MCP не перенаправляется скрыто. Проверка поиска/чтения выполняется
без `les_chat`, чтобы отдельно оценивать данные RAG и генерацию ответа.

Модуль не доказывает качество всех обзорных ответов и не меняет рабочий
индекс. Приёмка на документах и незакрытые ограничения фиксируются отдельно.

## Автоматический контекст и окно источника

`search_sources(view=context)` вызывает тот же путь, что начальный RAG чата:
поиск → проверка области/поколения → план чтения общим селектором →
дочитывание запланированных оригиналов Word и сканированных PDF-страниц →
отбор целых прочитанных единиц тем же селектором. План учитывает текстовый
бюджет и сохраняет исходные ранги; отдельного порога по типу или имени файла
нет. Каталог остальных найденных документов остаётся доступным для дочитывания.
Ответная модель не
запускается. Это ограниченный контекст, не курсор полного корпуса; для
продолжения найденного документа применяется `read_source/read_pdf_source`.
Режимы `documents/passages` сохраняют назначение и непрерывную пагинацию.
Старые разорванные Word-фрагменты и индексный OCR в `passages` остаются
указателями с `evidence_admissible=false/read_required`, а не прочитанными
доказательствами. Новая структура чтения не требует пересчёта dense-векторов.

В Svelte окно источника вызывает `/api/rag/sources/call` по кнопке
«Прочитать текст». Оно показывает тот же текст, предупреждение OCR, продолжение,
возврат к предыдущей порции и причины отказа. Общие схемы инструментов
закрепляют 150 секунд и 24 000 символов конверта; отдельного укороченного
Word/OCR-читателя для MCP нет.

Автоматическое чтение Word ограничено 30 секундами на оригинал; явный обход
`read_source` сохраняет 120 секунд. Таймаут, ошибка OCR или неподдержанный
элемент одного оригинала не превращают весь поиск в пустой результат:
успешные чтения остаются, а `result.read_failures` перечисляет непрочитанные
источники, исходные коды и нужный читатель. Покрытие остаётся частичным.
Если прочитать не удалось ничего, возвращается ошибка, а не пустой успех.
Ошибки области, редакции и поколения по-прежнему прерывают весь запрос.
Чат передаёт ограничение модели, сохраняет причину в истории и показывает
независимое от текста модели предупреждение о неполном обзоре.

В ограниченном ответе первичный источник с SHA-256 и прочитанный текст имеют
приоритет над диагностикой слияния. Трасса рангов дополняется только в свободном
бюджете и явно сообщает полный размер/усечение. Если подробные дублирующиеся
происхождения не помещаются, `equivalent_sources_omitted` и
`provenance_coverage=primary_only` обозначают это явно. Они не становятся
дополнительными прочитанными редакциями; отличающийся текст остаётся отдельной
единицей. Для каталога и дальнейшего чтения доступны обычные поисковые режимы.

Сериализованные снимки ограничены: PDF — 8 МиБ/32 страницы, Word —
16 МиБ/16 документов. Это предел данных кеша, не всего рабочего набора процесса.
Для допуска исходного пула общего селектора действуют одновременно пределы
8 МиБ текста и 16 384 единицы, до контекстной дедупликации. Пределы итогового
контекста, модели, оригинального файла и процессов сохраняются.

Windows PDF OCR по умолчанию получает рендер 300 DPI с прежним пределом
размера изображения; явное значение пользователя сохраняет приоритет.
Ошибки распознавания не исправляются догадками или подстановкой индексного OCR.
Новый Windows-мост принимает несколько изображений через один процесс и один
экземпляр системного OCR. Rust владеет очередью, сроком, ограничением памяти,
завершением и повторным запуском процесса. Старый мост поддерживает прежний
одиночный вызов. Ошибка изображения остаётся ошибкой, а не пустым успехом.

## Границы Word

`core/src/document/structure.rs` сохраняет байтовые диапазоны нормализованного
текста, порядок и уникальные единицы. Текст шапки перед продолжением таблицы
отделён от тела через `context_prefix_chars`; `body_sha256` позволяет сверить
тело. Координаты относятся к представлению чтения, не к физическим страницам
Word. Оригинальные SHA-256 и ссылки сохраняются.

Svelte-читатель использует тот же вызов и курсор. Новая цитата Word передаёт
`ordinal` вместе с `view_sha256`: текст открывается с процитированной единицы,
а не с начала тома. Есть переход к началу; старые цитаты без закреплённой
единицы открываются с начала. Достижение конца после входа в середине не
называется чтением всего документа. Переход к началу сбрасывает снимок чтения,
но проверка SHA-256 исходного файла сохраняется.

Явно плавающие `wp:anchor`/абсолютные VML-объекты сохраняются отдельной историей
текста. Их номер страницы/надпись не вклеивается в слово, количество или ячейку
по XML-позиции якоря. Структура и вложения остаются в хранилище DOCX-частей.
Встроенные изображения, OLE и формулы сохраняют существующий обработчик.
Docling читает основную историю документа. Колонтитулы и примечания читает
нативный обработчик только по ссылкам оригинала: их маркеры не требуют
появления в теле Docling и не вклеиваются в обычные абзацы. Проверка пропущенных
или повторённых специальных маркеров основного тела остаётся строгой.

Одна чрезмерно большая строка таблицы не разрезается ради зелёного результата:
читатель возвращает понятный `SOURCE_ATOMIC_UNIT_OVERFLOW`, оригинал доступен.
Качество геометрии сложных сканов и всех авторских стилей Word не объявляется
подтверждённым только по наличию текста.
