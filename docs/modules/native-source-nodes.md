# Исходные узлы PDF и Markdown в Rust

Кандидат 826. `core/src/document/source_nodes.rs` владеет исходными узлами
перед финальной подготовкой 824: разбором маркеров физических страниц,
частями длинной страницы, Markdown-разделами, выбором порога короткого текста,
разбиением по выбранному токенизатору, ID и метаданными происхождения.
`backend/source_nodes.py` передаёт текст, сведения о страницах и готовые узлы;
алгоритмы разбиения в этом адаптере не выполняются.

Основной `_sync_markdown_nodes` использует нативного владельца для штатных
MarkdownNodeParser/StructureAwareSplitter. Явно предоставленные сторонние
parser/splitter сохраняют свой прежний совместимый путь. Сборка PDF-узлов
всегда нативная; обычный поток партии получает затем `les.nodes.raw.v1`.

Протокол `les.document-source-nodes.v1`, C ABI `les_core_source_nodes_run`:

- 0 — запрос очередной порции исходного текста по символьному курсору;
- 1 — передача готовой порции узлов;
- 2 — запрос необязательных паспортов для не более 64 выбранных страниц.

Текст передаётся порциями до 262 144 Unicode-символов. Курсор проверяется,
объём ограничен 200 МиБ, число узлов — 50 тысяч, узел — 8 МиБ, общий результат —
512 МиБ. Порции результата ограничены числом и сериализованным объёмом.
Пустые/повреждённые ответы моста не считаются успешной подготовкой. Вызывающий
получает узлы только после успешного завершения всего вызова. Здесь нет
записи исходников, сетевого поиска, выбора моделей или публикации индекса.

PDF сохраняет прежний UUIDv5 URL namespace и ключ dataset/file/page/part,
физический номер, часть страницы, source_ref, слой текста/OCR, stamp,
quality/signals и до пяти координатных фрагментов. Необязательная ошибка
паспортов записывается в журнал и сохраняет доступный текст. Повторный номер
страницы останавливает обработку с `PDF_PAGE_DUPLICATE`, чтобы один ID не
скрыл другой фрагмент. Номера ограничены физическим диапазоном 1–10 000.
Классификационные аннотации не перезаписывают физический номер, тип узла и
ссылку, созданные по источнику. Код отказа проходит через форматный процесс
как читаемая `DocumentExtractionError`, а не общий `FORMAT_READ_FAILED`.

Markdown получает воспроизводимый UUIDv5 по области, файлу, разделу, части
и содержимому вместо случайного исходного TextNode. Это меняет ID при новой
обработке обычного текста; документ публикуется прежним поколением целиком,
старые/новые узлы не смешиваются. Content-hash cache векторов сохраняется.
Все исходные узлы помечены `source_node_builder=rust.document.source-nodes.v1`.
Отдельные навигационные узлы создаются уже финальным построителем и не обязаны
иметь метку исходного узла.

Исправлен отдельный дефект финальной подготовки: подтверждённая непустая
физическая страница с коротким обозначением больше не удаляется общим порогом
в 20 символов. Бюджет и санитарная очистка сохраняются. Пустая страница и
`[no text extracted]` по-прежнему не создают доказательство.

Форматный процесс, первичная классификация, часть извлечения/сложных форматов,
контур паспортов, специальные узлы таблиц/почты ещё требуют дальнейшего
переноса. Этот этап не объявляет завершёнными API/bootstrap/classic,
автономный установщик или Python-exit.
