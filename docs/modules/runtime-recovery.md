## Windows desktop

Внешний Rust-наблюдатель запускает окно отдельным процессом. Окно ждёт назначения
в Windows Job Object до запуска служб. Наблюдатель остаётся вне этого job;
смерть окна закрывает его дочерние службы перед новым запуском. Второй владелец
того же канонического каталога состояния не создаёт дубликат. Python launcher
сохраняет собственную вложенную границу процессов и восстановление API/UI/Qdrant.

Окно отдельно следит за launcher: при неожиданном завершении записывает код и
перезапускает его. Внешний наблюдатель восстанавливает само окно. В обоих случаях
лимит — три автоматические попытки за пять минут, задержки 1/2/4 секунды.
Лимит останавливает цикл, показывает ошибку и оставляет причины в журнале.

Штатный выход записывает намерение с ID конкретного запуска. Устаревший маркер
не запрещает восстановление нового процесса. Для Svelte намерение записывается
после подтверждения сохранения черновика. Наблюдатель завершает работу, а не
открывает окно снова; итоговый `launcher-status.json` получает `stopped`.

## Причины и журнал

- `logs/lifecycle.jsonl`: Python launcher, run ID/PID, готовность, остановившаяся
  служба и её exit code, отказ health probes, повторные попытки и причина выхода.
- `logs/desktop-lifecycle.jsonl`: запуск/завершение launcher, принудительный stop
  по таймауту, штатный выход окна и Rust panic с расположением в коде.
- `logs/supervisor-lifecycle.jsonl`: запуск окна, код его завершения, штатный или
  неожиданный выход и исчерпание попыток. После смерти самого наблюдателя новый
  запуск фиксирует `previous_owner_missing`, не выдумывая причину прошлого выхода.

Записи имеют UTC Unix timestamp, JSON schema и стабильные reason codes. Файлы
ротируются по 1 МиБ: Python хранит три предыдущих, каждый Rust-компонент — один.
Текст документов, ключи и адреса провайдеров в эти события не включаются.
Отдельные API/UI/Qdrant console logs сохраняются для деталей ошибок парсера.
При штатной остановке ненулевой код принудительно завершённой службы сам по себе
не означает аварийный выход: контекст `stop_requested` сохраняется отдельно.

## Границы

Наблюдатель существует, пока запущен desktop; системная служба и автозапуск ОС
не устанавливаются. После уничтожения самого наблюдателя/всего дерева, выхода
из Windows или отключения питания нужен новый запуск. Прямой Python browser
launcher получает журнал причин, но не внешний Windows desktop-наблюдатель.
Причина исторической остановки без журнала не объявлена установленной.

Индексатор документов ещё использует Python-библиотеки в своих потоках. Отдельный
процесс парсера остаётся следующим этапом изоляции. Повторяемое падение нативного
парсера может исчерпать лимит восстановления; этот этап не обещает автоматического
исправления повреждённых документов или безошибочности OCR/модели.
