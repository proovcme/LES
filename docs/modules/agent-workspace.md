# Память агента и рабочие файлы · кандидаты 778–779

779 переносит в Rust также схему/привязку инструмента, scope, Unicode-окна,
пагинацию и advisory-проекцию памяти. Добавлены обратимое удаление, список
удалённых файлов и скачивание с проверкой ревизии. [Приёмка 779](../acceptance/agent-native-779.md).

Пользователь разрешил самостоятельное поддержание памяти между разговорами
с историей и откатом. Это отдельное постоянное разрешение на собственные файлы
Леса, не разрешение менять оригиналы, назначения моделей или внешние сервисы.

## Владение

`core/src/agent_files/` — единственный владелец файлов, ревизий и восстановления.
`agent_files`/`les.agent-files.v1` принимает доверенный корень состояния;
модель этот корень и project_id не задаёт. `api/src/agent_state.rs` обслуживает
GET/POST `/api/workspace/agent-state` напрямую с прежней проверкой пользователя.
В совместимом режиме тот же Rust вызывает тонкий `proxy/routers/agent_state.py`.
Нативное владение API: **22 из 267** пар; старые 265 контрактов сохранены,
добавлены только две пары. `--state` native API требует абсолютный каталог.

| Область | Файл внутри состояния |
| --- | --- |
| Предпочтения | `agent/USER.md` |
| Общая память | `agent/MEMORY.md` |
| Память проекта | `agent/projects/<id>/MEMORY.md` |
| Рабочие файлы | `agent/workspaces/<id>/<относительный путь>` |
| Правила самостоятельных действий | `agent/policy.json` |

Память до 128 КиБ, рабочий UTF-8 файл до 1 МиБ. Абсолютные пути, выход через `..`,
UNC/ADS, служебные имена Windows и ссылки/reparse points запрещены. Неизвестная
кодировка возвращает ошибку без перезаписи. Исходные папки остаются read-only.
Чтение отсутствующей памяти не создаёт каталог или пустой файл.

## Запись и история

SHA-256 ревизия обязательна для сохранения, точечной замены и отката. ОС-блокировка
сериализует собственные операции. Durable intent `pending.json`, атомарная
публикация, журнал before/after и восстановление защищают от завершения процесса
на каждой стадии. Если внешний редактор уже записал третью версию, она сохраняется,
а конфликт попадает в историю. Это проверка ревизий, а не ОС-изоляция от любого
процесса с теми же правами и не абсолютный CAS с несогласованными редакторами.
Откат сам сохраняется в истории; можно вернуть состояние до создания файла.
История постраничная, с автором, причиной, временем и просмотром обеих версий.

## Инструмент и контекст

`agent_workspace` — один встроенный инструмент с операциями read/list,
save/edit/delete, history/version/restore. Область берётся из текущего сохранённого
диалога. Пользовательские настройки не доступны инструменту. Эффект LOCAL_STATE
по умолчанию запрещён; только серверная привязка инструмента текущего диалога
разрешает его; Rust повторно проверяет policy под lease. Прежние подтверждения внешних действий
не обходятся. Shadow-исполнение не пишет. Факт сохранения подтверждается нативной
ревизией и execution receipt, не фразой модели. Поиск и чтение явно выбранных
источников сохраняют места в shortlist.

USER.md, общая и проектная MEMORY.md входят в реальный бюджет контекста как
advisory, не доказательства. Читаются целыми абзацами, суммарно до 5000 символов;
для остального передаётся явный указатель дочитывания. Недоступная память видна
как отказ, а не как пустая успешная выдача. Модель получает правило сохранять
устойчивые предпочтения и рабочие решения, избегать секретов и полной копии чата.
Инструкции из документов не дают права записи. Самостоятельность конкретной
модели требует отдельной end-to-end проверки; наличие инструмента её не доказывает.

## Интерфейс и остаток

Svelte `AgentMemory.svelte`: «О вас», «Память», «Рабочие файлы», выбор области,
autosave со статусом, конфликт двух версий, история/откат, два переключателя прав.
Штатное закрытие ждёт сохранения; при ошибке оставляет окно и текст. В 778
исправлены общий select и сжатая навигация classic; ширины проверяются отдельно.

Python пока связывает этот инструмент с существующим harness; вычисления scope,
окон и проекции из него удалены. Это не перенос harness целиком. Отдельный Memory Core, генератор
сводки и существующие заметки — прежние самостоятельные подсистемы. Бинарные
артефакты, запуск сборок и универсальное редактирование исходников этим инструментом
не реализованы. [Модуль работы с кодом](code-agent.md) остаётся следующим этапом.
Локальный 779 установлен с Rust launcher/API и новым чатом через стандартный
ярлык. [Итоговая приёмка](../acceptance/agent-native-779.md); [история 778](../acceptance/agent-workspace-778.md).
