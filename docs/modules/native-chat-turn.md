# Общий обработчик чата в Rust — кандидат 835

### Параметры генерации в кандидате 933

Для каждого вызова `chat_provider_request.sent_output_limit` показывает
переданный предел токенов. При проверке локального OpenAI-совместимого
подключения ЛЕС делает короткую пробу, если сервер обозначает себя как Ollama
или явно присылает рассуждения. Параметр `reasoning_effort: "none"`
сохраняется для этой редакции подключения, когда проба завершилась обычным
ответом без отдельного текста рассуждений. Он применяется при выключенном
режиме рассуждений. В журнале его видно как `sent_reasoning_effort`.
У существующего подключения без такой записи параметр появится после
успешной проверки. [Поддержка параметра в Ollama](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx)

### Диагностика запроса по папке в кандидате 932

У каждого сохранённого хода есть числовой `history_id`. Нативный API пишет
события в `logs/api-native-console.txt` в каталоге состояния ЛЕСа.
Поиск по этому номеру связывает начало и конец подбора источников, сборку
контекста, обращение к провайдеру и результат. `model_call` — номер попытки
генерации внутри хода. Сообщения о ходе размышления модели его не увеличивают.

| Событие | Что показывает |
| --- | --- |
| `chat_retrieval_started`, `chat_retrieval_finished` | Режим поиска, число наборов, найденных документов и источников, время чтения и число отказов читателей. |
| `chat_model_prepared` | Номера источников в подготовленном контексте этой попытки, оценка входных токенов и доступный бюджет вывода. `sections` показывает расход токенов по разделам, а `omissions` — число отброшенных элементов и причину. Последняя подготовка сохраняется в истории в `retrieval_trace.last_model_request` при ошибке. Номера раскрываются через сохранённую карту источников. |
| `chat_provider_request` | Назначенная модель и протокол, размер и SHA-256 сериализованного запроса, ограничение вывода, фактически включённое в JSON. Значение `null` у `sent_output_limit` означает, что поле отсутствует. Событие пишется перед HTTP-отправкой. |
| `chat_provider_finished`, `chat_request_failed` | При разборе ответа фиксируются принятые байты, обработанные строки, объёмы текста, отдельных полей рассуждения и вызовов инструментов. Для превышенного лимита сохраняются название проверки, фактическое значение и допустимый максимум. |

В OpenAI SSE пустые строки между событиями тоже учитываются в лимите строк.
Видимые токены ответа, число строк и размер ответа в байтах — разные величины.
В частном случае ошибки лимита числовая расшифровка и номер запроса
возвращаются обычным и потоковым API и сохраняются при повторном открытии
истории. Новые технические записи содержат счётчики и контрольную сумму.
Текст вопроса, отрывки документов, содержимое рассуждений и ключи доступа
в них не копируются. Карта исходных документов доступна внутри самого диалога.

### Явный выбор документов в кандидате 931

В окне «Где искать ответ» пункт «Конкретные документы» сохраняет в области диалога
`document_ids`. Режим поиска по папке по-прежнему выбирает кандидатов через Hybrid.
Для закреплённых файлов чат сначала разрешает все ID в пределах выбранных наборов,
затем вызывает читатель каждого документа. Этот же порядок применяется к путям
`target_file` и `target_files` при предварительном поиске. При Pull несколько
заданных путей или явный список ID также задают обязательное чтение. Один
старый `target_file` в Pull сохраняет чтение по запросу инструмента.
Текстовое упоминание имени в свободном вопросе не закрепляет файл.
Выбранные ID определяют обязательные оригиналы. Для последующих вызовов
инструментов действует область разрешённых наборов диалога.

Точный путь выбирает оригинал, короткое имя с несколькими совпадениями требует
уточнения. Набор выбранных документов определяется до ранжирования фрагментов.
Сервер проверяет ID, набор и SHA-256 каждого обязательного оригинала в собранном
сообщении. Если ни один фрагмент документа не поместился, сервер останавливает
запрос до отправки модели. Одностраничный PDF читается напрямую. Для длинного
PDF читатель может выбрать релевантные страницы по индексу. Первая страница даёт
ограниченное чтение. Для текстовых файлов используется действующий индекс,
для Excel — опубликованные строки книги. Объём чтения можно посмотреть в
`retrieval_trace.prefetch.required_documents`, доставленные фрагменты — в
`retrieval_trace.contexts`. Выбор файла сам по себе не доказывает полноту ответа.

Кандидат 858: поиск и навигация разделены, а успешное чтение обязательно в
нативном Pull/Hybrid с ответом только по источникам. Ограничения и распределение

Если буквальный запрос `q` отсутствует на выбранной странице PDF, адаптер
читает ту же физическую страницу без фильтра, с тем же ID/SHA-256. В квитанции
явно остаётся `literal_lookup.matched=false` и исходный `PDF_QUERY_NOT_FOUND`;
это не найденная цитата и не автоматическое подтверждение вопроса. Ошибки
страницы, ревизии, повреждения и незавершённого курсора не обходятся.

857: при явно выбранном файле не-PDF или смешанном выборе в небольшое
начальное окно схем попадает `read_source`, включая чтение частей DOCX.
При выборе только PDF сохраняется приоритет `read_pdf_source`. Остальные
разрешённые инструменты доступны через раскрытие расширений; порядок схем
не меняет права и не перенаправляет вызов модели на другой обработчик.
Ошибка физического чтения по-прежнему останавливает финальный ответ.
Для частей Word доступен `read_source view=part member=...`: точное имя
из manifest выбирает объект без копирования SHA-256. Одновременно указанные
имя и хеш должны совпасть; иначе цикл останавливается с сохранённой причиной.
Имена не нормализуются и не превращаются в пути файловой системы. Нулевой
OCR конкретной части остаётся нулевым и не заменяется текстом соседа.

Обычный JSON-ответ и SSE используют один request-owned путь: проверка запроса,
область документов, сохранённая ревизия модели, профиль, память, контекст,
модельный поток, AgentLoop, доверенный исполнитель и атомарная история.
Нет Python callbacks, HTTP fallback или запуска приложения в комплекте навыков.

Это **испытательный контур**, а не завершённая замена публичного чата.
POST `/api/light/internal-chat` и `/api/light/internal-chat/stream` доступны
только локальному владельцу с внутренним токеном модели, без браузерного Origin.
С 839 эти же обработчики доступны на обычных `/api/chat` и `/api/chat/stream`
в [явном испытательном режиме](native-public-chat.md). Штатный запуск сохраняет
прежнего владельца до полного паритета.
Рабочая установка, индекс и назначения моделей не переключены.

| Узел | Владелец |
| --- | --- |
| Запрос, область, точные номера заголовков | `core/src/chat_request/` |
| Квитанция, повторы, восстановление, история | `core/src/chat_request/journal.rs` |
| HTTP/SSE и отмена соединения | `api/src/chat/http.rs` |
| Реестр модели, контекст и цикл | `api/src/chat/{prepare,runner,model}.rs` |

## Гарантии

- `Idempotency-Key` привязан к нормализованному запросу и диалогу. Завершённый
  запрос возвращает сохранённый результат; выполняющийся/прерванный не запускается
  повторно. Другое содержимое с тем же ключом отклоняется.
- Квитанция и начальная строка истории создаются вместе. Финальный ответ и квитанция
  завершаются одной транзакцией. Каждый переданный текстовый блок сначала записывается
  в историю; после терминального состояния запись/очистка текста запрещена.
- После аварии восстанавливаются только строки этого нативного координатора.
  Частичный текст и причина остановки сохраняются. Активные legacy-запросы не трогаются.
- Закрытие SSE отменяет модельное чтение; отсутствующий конец потока не считается
  ответом. Ошибка чтения источника останавливает цикл до финальной генерации, включая
  вызов через общий инструмент расширений. Сырые исключения/секреты не публикуются.
- Физический PDF читается отдельным Rust-процессом по зарегистрированному ID,
  SHA-256 и однобазной странице. Все промежутки курсора должны быть дочитаны.
  Идентификатор фрагмента не подменяет идентификатор документа.
- Перед окончательной записью ответа повторно проверяется SHA физически
  прочитанного PDF; изменение во время генерации останавливает финализацию,
  сохраняя частичный текст и результаты инструментов в истории. Ссылка привязана
  к SHA читаемого дескриптора. Для ещё не проиндексированного PDF нужна явно
  известная редакция; без SHA чтение не разрешается.
- Выбранный файл с подпапкой может быть привязан по короткому имени только при
  единственном совпадении среди явно выбранных файлов. Чужой набор и выход за
  `selected_sources_only` запрещены, в том числе во вложенном инструменте.
- Поиск проверяет контракт эмбеддингов, поколение индекса и канонические точки,
  затем дочитывает сохранённые родительские разделы. Переполнение и неполное
  покрытие не превращаются в обещание полноты оригинала или правильности ответа.
- Схемы учитываются в бюджете отдельно от сообщений. Текст источника передаётся
  одним блоком доказательства, а инструмент ссылается на этот блок. Обязательные
  доказательства не обрезаются для вмещения. Trace скрывает вопрос, профиль и память.
- Избранные инструменты можно раскрывать порциями без расширения прав профиля.
  Внешний навык использует явно заданный автономный CPython и одобренный хеш скрипта;
  `backend`/`proxy` приложения ему недоступны. Встроенные вычисления остаются Rust.

GET/HEAD `/api/documents/by-id/{id}/raw` уже принадлежат Rust. Оригиналы открываются
по серверному каталогу, проверяются на том же файловом дескрипторе и выдаются
ограниченными порциями. Поддержаны одиночные byte-range/206 и ссылки старого вида
с точными dataset/name; неизвестный ID сам по себе не угадывается. Непроиндексированный
оригинал тоже можно открыть. Classic ещё нуждается в своём совместимом маршруте.

## Незакрытый паритет

В 837 [вложения и table_document](native-chat-attachments.md) соединены с общим
кандидатом: авторитетный preview, изображения и устойчивые табличные задания.
Старые пакеты таблицы не накапливаются в модельном контексте; незавершённые
решения обозначаются квитанцией, а не обещанием модели. Редкие форматы,
публичный upload ещё не перенесён целиком. В 838
[document_review](native-document-review.md) связан с общим циклом:
журнал, точные цитаты, Unicode-порции и подтверждение их передачи — в Rust.
Результат инструмента сохраняется до следующей генерации; сбой его не стирает.

В 836 [обновление сводки и команды](native-conversation-memory.md) получили
нативного владельца. Сохранение истории атомарно ставит задание памяти;
JSON/SSE учитывают ошибки финальной записи, сохраняя их точную причину.

До переключения публичного чата нужны: полноценная notebook/typed map и виртуальные
тома, специальные таблицы и vision, вложения,
политики чувствительных материалов, дополнительные режимы, проверка ответа,
семантический кеш и отключаемый реранкер. Явные неподдерживаемые флаги/вызовы
отклоняются; их работа не имитируется. `dataset_map` пока показывает инвентарь,
а `read_excel_source` читает проверенные индексированные разделы, как прежний инструмент.
Оставшиеся API/bootstrap/classic и специальные форматы также не объявлены перенесёнными.

Нужна отдельная приёмка отмены длительных вычислительных инструментов, полного
Server-конвейера и конкурентного обновления/падения Edge именно в новом обработчике.
Завершение модельного потока не является независимой проверкой фактов.

### Чтение ячеек в кандидате 935

Когда окно источников состоит из подтверждённых табличных представлений, модель
выбирает адреса строк. Rust копирует содержимое доставленных строк, проверяет
адрес и связывает цитату с версией документа. При поддержке структурированного
ответа и закрытом списке инструментов API передаёт провайдеру JSON Schema.
После свободного ответа или невидимого адреса допускается один повтор. Черновые
числа до проверки не попадают в поток пользователя. Отсутствие подтверждения
возвращает `insufficient_evidence`. В смешанном текстовом окне ссылка на
проверенную табличную выдержку требует выбора адресов. Ответ по одним текстовым
источникам сохраняет свободную форму. Корректность
выбора объекта моделью остаётся отдельной проверкой.

Потоковый клиент привязывает ключ запроса к одной отправке. При потере финала
повтор с тем же телом использует прежний ключ. Завершённое сообщение освобождает
ключ для следующего действия. Если доступна память вкладки, в ней сохраняются
только хеш отправки и ключ.

Для диагностики сохранённого хода выполните
`python -m tools.inspect_chat_turn "путь/к/meta.db" history_id`,
подставив числовой ID из ответа. Команда открывает базу только для чтения.
Она выводит поколение индекса, найденные документы и точки, отправленные
источники по вызовам модели, бюджет, причины пропусков, ссылки и адреса
подтверждённых строк. У завершившейся ошибкой попытки виден сохранённый
код. Пример содержит два вызова модели и одну выбранную строку.
[Пример из браузера](../acceptance/folder-trace-935.json)

При ссылках на видимые текстовые выдержки PDF ЛЕС также сверяет записанное
в ответе количество с величинами в той же единице из этих выдержек.
Если в них есть `17.25 m`, а черновик сообщает `999 m`, чат запрашивает
адрес выдержки и может вывести её дословно. Само совпадение числа и единицы
сохраняет обычный ответ со статусом `not_performed`. Оно не доказывает,
что модель выбрала верный объект. Проверка охватывает буквальные величины
с одинаковой записью единицы. Для свободных выводов, пересчётов единиц и
применимости редакций действует отдельная оценка качества.
## Кандидат 936. Чтение папки

В первом ходе обычного Hybrid-поиска встроенный профиль передаёт вопрос и
целые выдержки с номерами. Индекс, допустимые источники, история и бюджет
контекста остаются под контролем сборщика. Если требуется дочитать материал,
модели доступны инструменты. Пользовательские инструкции профиля сохраняют
свой договор.

Для строки Excel нативный поиск читает заголовки и ячейки из артефакта,
связанного с версией книги. При одном искомом названии в кавычках и выдаче
из типизированных строк модель может выбрать возвращаемые поля. Приложение
ищет точное значение среди допущенных строк и записывает лист, исходную строку
и номера столбцов в квитанцию. Пустое поле отображается как отсутствующее,
несколько подходящих записей требуют уточнения. Число совпадений относится
к прочитанным строкам. Запрос, которому нужны другие операции, возвращается
в обычный ход поиска. Старые индексы без сохранённых заголовков обслуживаются
прежним читателем.

В сборке 937 обычный ответ по папке может подтвердить строку PDF за один
вызов модели. Для этого ссылка должна указывать на одну показанную строку,
а в физической сетке должны быть явно подписаны столбцы количества и единицы.
При явном запросе количества и поддержке структурированного ответа модель
может дословно назвать позицию из вопроса. Лес ищет полное название среди
показанных строк, сверяет оригинал и читает ячейки по заголовкам. Такой выбор
записывается в квитанции как `named_pdf_position`. Пустая единица оставляет
подтверждённое количество в ответе. Значение `item: null` возвращает обычный
чат, если вопрос требует дополнительных сведений или другой операции.
Программа сверяет позицию из вопроса, число, единицу, хеш строки и версию
оригинала. Модель также может выбрать строку одной ссылкой. Чат показывает
количество и единицу из её ячеек, а в квитанции
`table_facts.selection` появляется `model_citation`. Если в ответе расходятся
значения и в показанном окне есть ровно одна подходящая строка с именем позиции,
модель может подтвердить её номер или отказаться. При неоднозначном выборе и
незнакомых заголовках действует общий порядок выбора строк.
Если модель вернула только служебную метку отсутствия подтверждения, чат
показывает сообщение об этом в пределах прочитанных фрагментов.

Короткая инструкция выбора полей действует только для поддерживаемого
табличного запроса. Обычный вопрос по папке получает инструкции профиля,
вопрос с условиями цитирования и доступные инструменты чтения. Наличие
табличного файла в выдаче само по себе не переключает этот режим.
