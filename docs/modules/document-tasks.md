# Универсальная работа с таблицами

Кандидат 791 переносит определение размеров и выборку первых строк
XLSX/XLSM для классификации, а также чтение листов XLSX для Parquet в Rust.
Сохраняются порядок листов и колонок, выбор заголовка из первых 20 строк,
разрывы, нули, булевы значения и сохранённые результаты формул. Числа
без дробной части передаются как целые. Формулы при индексации не пересчитываются.

Снимок для классификации и строки для Parquet читаются отдельно. Каждый
запрос проверяет неизменность оригинала по SHA-256. Книги с датами,
значениями вне точного целочисленного диапазона f64, нестандартной структурой
или сверх нативных лимитов идут через прежний адаптер. Существующие
правила нормализации, запись Parquet, запасная Markdown-конвертация, старый
XLS, публикация индекса и генерация ответа ещё выполняются на Python.

Проверка 791 сравнила старый и нативный путь от классификации до поисковых
узлов на книге с двумя листами. Маршрут, текст, ID и метаданные узлов
совпали. Собранный обработчик записал Parquet в отдельное состояние.
На контрольной книге совпали результаты пробы и 76 строк данных.
Медиана 11 повторов для пробы и чтения вместе составила 2,9 мс в Rust
и 22,4 мс через прежний читатель. Замер относится к одной книге.

Кандидат 790 использует Rust и Calamine для снимков XLSX/XLSM, которые
используют прикреплённые таблицы, чтение оригинальных строк из RAG и
`sum_excel_ranges`. Чтение открывает оригинал только на чтение, сверяет
SHA-256 до и после извлечения и ограничивает размер архива, распакованных
данных и число строк и ячеек. Схема снимка `les.table.v1` сохранена.
Расположение, скрытые листы, объединения и сохранённые результаты формул
остаются частью снимка. Макросы не выполняются.

Книги с датами, числами вне точного целочисленного диапазона f64,
неподдержанной структурой или снимком сверх бюджета ABI читает прежний
адаптер. Переход записывается в лог без путей и текста. Повреждение архива,
нарушение лимитов и изменение файла останавливают нативное чтение с понятной
ошибкой. CSV, просмотр оригиналов и оркестрация чата пока на Python.

В собранном кандидате загрузка через `/api/chat/attachments` вернула
координаты обоих листов, ноль и формулу. Повреждённая книга получила 422.
На контрольной книге из 77 строк совпали все 431 ячейка по содержанию и
координатам. Медиана 11 повторных чтений после прогрева: 2,8 мс в Rust и
26,8 мс в прежнем адаптере. Это измерение чтения одной книги.

Кандидат 789 добавляет `sum_excel_ranges` для книг XLSX/XLSM из текущей
области чата. Инструмент показывает доступные книги, имена листов и их
размеры. Сумма рассчитывается по явным адресам из одной книги, в том числе
с разных листов. Ответ может ссылаться на каждый диапазон. Перед чтением
проверяются запись каталога и хеш оригинала.

Расчёт охватывает все выбранные ячейки, включая строки за пределами
предпросмотра. Пустые ячейки учитываются отдельно. Для формул используются
числа, сохранённые в книге. Пересечения диапазонов, объединения, текст,
ошибки и формулы без сохранённого числа останавливают весь расчёт.
Выбор строк, исключение промежуточных итогов и сопоставление единиц
остаются явной частью запроса. Автоматического итога по произвольной
книге и пересчёта формул этот инструмент не выполняет.

Build 746. Самостоятельный код Light; предметных классификаторов и сметной логики нет.

Build 765: добавлены read_window (точное имя листа, начало строки/столбца,
окно до 4×8) и read_cell (координата, поле value/formula/cached, символьный
offset). Большое значение окна не обрезается: deferred явно направляет на
read_cell с next_offset. next_cursor окна проходит столбцы, затем строки;
при продолжении сохраняйте row_count/column_count. Объединённые продолжения
ссылаются на anchor; пустая координата имеет честный тип blank_or_absent.
Эти чтения не изменяют счётчики решений и не подтверждают oversized-строку.
Общий транспорт SQLite вынесен в document_task_database.py.
Проверка документов/разделов: [отдельный контракт](document-review.md).

`tabular_document_service.read_table` читает XLSX/XLSM/CSV в неизменяемый снимок.
Каждая непустая строка, включая заголовки и итоги, получает ID по номеру листа и строки.
Ячейки сохраняют координаты и типы; отсутствующая координата означает пустую ячейку.
Ноль и False сохраняются. Числа передаются десятичными строками. Формула и её
сохранённый результат разделены; отсутствующий результат требует проверки.
Макросы и формулы не исполняются. CSV использует существующий строгий декодер:
неуверенно определённая кодировка отклоняется с объяснением, а не угадывается.

Ограничения чтения: 64 МиБ исходника/распакованного XLSX, 20000 строк, 512 столбцов,
300000 ячеек (включая проверку площади XLSX-листа). Превышение останавливает чтение
целиком. Предпросмотр показывает только целые строки с явной отметкой неполноты.

`DocumentTaskStore` хранит метаданные, исходные строки, решения и квитанции пакетов
в отдельной `data/document-tasks.sqlite3` каталога состояния приложения. SQLite
соединения закрываются явно. Запись пакета атомарна: недостающая строка, дубликат,
чужая ячейка, неизвестное поле или устаревшая ревизия отменяют весь commit. Повтор
того же результата безопасен; другой результат по уже принятому пакету отклоняется.
Исходные значения не входят в изменяемые поля решения.

Инструмент `table_document` привязывается приложением к текущему диалогу и источнику.
Параметр пути не принимается. Изменение файла, выбранных датасетов, проекта, области,
ревизии модели или профиля не наследует прежние решения. В том же диалоге прежний
снимок доступен после перезапуска, даже когда вложение уже снято из поля ввода.
Новая цель: `start` создаёт отдельное задание по текущему вопросу. Продолжение:
`status` и выбор сохранённого task_id; активное задание тоже сохраняется.

`next` выдаёт до шести целых строк в пределах бюджета (до 6000 UTF-8 байт).
`record` требует решение по каждому ID пакета: reviewed, needs_review либо excluded,
с объяснением и точными координатами. Заголовки исключает модель с объяснением;
слово «всего» в примечании не является командой к исключению. Строка с ошибкой
или отсутствующим кэшем формулы не может стать reviewed. `results` читает сохранённые
решения и исходные ячейки страницами. Счётчики покрытия считает код.

Текущий пакет обязателен для ContextGovernor: он помещается целиком либо запрос
останавливается. После вызова последний шаг передаётся связанной парой assistant/tool,
включая ошибки валидации; пара целиком входит в обязательный бюджет. Старые шаги
не добавляются снова в prompt; полный журнал остаётся в trace и SQLite. Сводка диалога не используется
для установления покрытия. Бюджет токенов по-прежнему оценочный; точного счётчика
конкретной модели эта версия не добавляет. Инструменты, время и число вызовов
остаются ограничены действующим профилем. Долгое задание продолжается следующим
сообщением пользователя; фоновых самопроизвольных запросов к модели нет.

coverage_complete означает, что у каждой непустой строки есть записанное решение.
Это не доказательство правильности свободного текста модели. needs_review и excluded
видны отдельно. Исходные числа не изменяются, но фактическую истинность всех фраз
модели код не удостоверяет. Этапы потока показывают число обработанных строк.
При незавершённой обработке итоговый ответ предваряется отдельным уведомлением
с фактическим счётчиком журнала. Это не исправляет семантические ошибки модели.
Повторные вызовы ограничены в пределах ревизии задания: после сохранения пакета
следующий next разрешён. Повторный start текущего вопроса не сбрасывает пакет.
ID текущего пакета принадлежит приложению: record может его не передавать,
но явно переданный чужой ID не заменяется автоматически и отклоняется.

Открыто: строка больше бюджета остаётся blocked/pending (нет тихого обрезания),
требуется отдельный механизм чтения длинных ячеек; полноценный экспорт отчёта с
ревизиями и подтверждениями пользователя; удаление журналов заданий через UI;
генерации внешних поисковых индексов не входят в identity (кэш внешнего RAG здесь
не наследуется); произвольные цепочки MCP не возобновляются этим журналом.
Полноценная приёмка качества на реальной локальной модели и Windows GUI выделяется
отдельно от офлайн-тестов. Сметные функции в публичный пакет не входят.
