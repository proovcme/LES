# JSON/JSONL: нативный разбор и отказ без диагностических фрагментов

Кандидат 825 переносит JSON/JSONL из `converter.py` в Rust. Старый парсер
возвращал `[ERROR]`/`[WARN]` как обычный документ и пропускал повреждённые строки
JSONL. Такой результат мог стать поисковым фрагментом. Теперь синтаксическая
ошибка останавливает обработку с кодом, строкой и позицией; эмбеддинги и
публикация не выполняются. Пустые JSON/массив/объект дают `NO_SEARCHABLE_TEXT`.
Настоящий текст `[ERROR]` внутри валидных данных остаётся содержимым.

`core/src/document/json_source.rs` читает исходник только для чтения, разбирает
его и формирует текст. Вместо прежнего списка английских полей сохраняются
также произвольные ключи, числа, логические значения, вложенные объекты/массивы
и длинные строки. Поля диалога/заголовка выводятся перед обычными полями;
элементы массивов и записи сохраняют порядок. Пустые вложенные значения
различимы. Не выполняются инструкции, ссылки или код из документа.

Лимиты: 128 МиБ исходника, 2000 непустых записей, глубина вывода 64, заданный
сервером предел текста. Ограничение объёма явно отмечается в начале результата;
отсутствие ответа в неполном представлении не доказывает его отсутствие в файле.
Совместимые Python-значения NaN/Infinity выводятся буквально с отдельной пометкой.

UTF-8/BOM, UTF-16 и UTF-32 декодируются в Rust. Прежнее строгое определение
неоднозначных legacy-кодировок ещё в Python и вызывается только при необходимости.
Парсинг и формирование текста остаются Rust и в этом случае.

`les_core_json_run` использует заимствованный синхронный мост: операция 0 отдаёт
готовый текст ограниченными UTF-8-порциями, операция 1 запрашивает ограниченную
порцию совместимого декодирования. Сборка данных возвращается вызывающему
только после полного успеха. Временные копии JSON не записываются ни в папку
источника, ни в OS temp. Поток большего размера не превращается в один огромный
аргумент/ответ C ABI. Нужна capability `document_json_stream`; скрытого парсера
Python при несовпадении компонента нет.

Обычный `document/json_document` — чтение с ограниченным результатом для
диагностики. Команды записи (`output`) отвергаются. Общие сообщения находятся
в `config/extraction-errors.json`. В том же кандидате убран другой ложный
фрагмент: сообщение «нужна OCR» больше не подставляется вместо текста скана.

Ранее индексированные JSON надо повторно обработать, чтобы удалить старые
диагностические фрагменты и получить новые поля. Автоматическое переиндексирование
рабочей базы этим этапом не выполнялось; миграция нужна до полной поставки.
