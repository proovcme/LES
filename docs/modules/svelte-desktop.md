# Чат на Svelte и граница desktop

Кандидат 778 добавляет [редактор памяти/рабочих файлов](agent-workspace.md)
с историей и сохранением перед закрытием. Он ещё не установлен. Отдельный
[патч навигации classic](../acceptance/navigation-778.md) установлен поверх 773;
это не установка всех кандидатов 774–778.

В 772 добавлены нормальное закрытие через native flush/ack, execution receipts
и живая приёмка интерфейса. [Точные границы и результаты](../acceptance/safety-ui-772.md).

Build 771 — отдельный кандидат переноса интерфейса. Установленный 770 продолжает
работать. Основной запуск по умолчанию остаётся classic до приёмки остальных
экранов. Кандидат выбирается `--svelte` для desktop или `--frontend svelte` для
`tools/light_launcher.py`. `--state` desktop принимает только абсолютный путь;
ошибка аргумента не открывает рабочую базу вместо тестовой.

## Действующий путь

`desktop/light/frontend` — Svelte 5, TypeScript, Vite, локальная сборка с
package-lock. Node нужен разработчику/сборочной машине, в установку он не входит.
Tauri открывает статические файлы `/app/` на принадлежащем экземпляру API.
Renderer использует тот же origin; ключи провайдеров и адреса моделей в него
не передаются. Rust проверяет адрес loopback и instance_id перед переходом.
Новых маршрутов inference, поиска или обходов допуска памяти нет.

Перенесены: список обычных диалогов, сохранённая область поиска, поток чата,
остановка, состояния подготовки/чтения/ответа с временем ожидания, вложение для
чтения через обычный выбор файла, HTML drop одного файла, переключатель реранкера,
ссылки на реальные source_map, цитата, оригинал, возврат к ответу с черновиком,
прокруткой и фокусом. Статус назначения модели не выдаётся за проверку её доступности.
Ошибки инструментов, заблокированный/ограниченный поиск и частичный ответ видны.
Изображения PDF получаются через существующий renderer страницы; Office/text —
через существующий просмотрщик в sandbox iframe без доступа к родителю.

Одна навигация и широкая переписка. Источники и диалоги открываются по запросу.
Палитра, шрифт и размеры контролов следуют принятому «Лесу знаний»; новой темы нет.
Модальные окна используют dialog, Escape/закрытие, видимый фокус, native buttons.
Учитывается IME, Shift+Enter и reduced motion. DOM-тесты не доказывают WCAG целиком.

## Целостность состояния

С кандидата 776 реализация SQLite диалогов/черновиков находится в
`core/src/workspace/`; Python `chat_draft_service` — совместимый фасад.
В режиме `--native-api` HTTP-маршруты также Rust. [Граница](native-workspace.md).

`chat_draft_service` хранит отдельную таблицу `les_chat_drafts` в том же каталоге
SQLite, что и диалоги. Compare-and-swap revision, BEGIN IMMEDIATE и сериализация
записей защищают от позднего autosave и второго окна. Конфликт показывает обе
версии, выбор остаётся пользователю. Неопределённый результат записи после обрыва
HTTP сверяется по полному содержимому. Черновик очищается после подтверждения
приёма запроса сервером; при ошибке вопрос восстанавливается, следующий набранный
вопрос не затирается. Интервал autosave 400 мс. В 772 штатное закрытие ждёт
подтверждения flush; ошибка записи оставляет окно открытым. Аварийное завершение
WebView и последние неподтверждённые символы остаются отдельной задачей.

SSE декодируется инкрементально, включая разрезанную кириллицу/CRLF/JSON.
Отсутствие final — прерванный ответ. Остановка закрывает fetch; API сохраняет
частичный ответ существующим журналом. Автоматического повторного запроса нет.
Markdown очищается DOMPurify; model HTML не может создать собственную кнопку
доказательства, script, image, iframe или локальную ссылку на файл/API.

Ошибка чтения истории теперь отвечает 503 с понятной причиной вместо ложного
пустого списка. API черновиков требует той же авторизации, что диалоги. Исходные
файлы открываются по каталожной идентичности, пути от модели не принимаются.

## Сборка и проверки

1. `python tools/build_light_frontend.py`: locked npm ci без install scripts,
   Svelte/TS check, production assets, лицензии, receipt SHA исходников и файлов.
2. `npm.cmd test --prefix desktop/light/frontend`: транспорт, состояние,
   Markdown/XSS и DOM-путь источник → оригинал → назад.
3. `make verify`, `make test`, Rust desktop tests/build.
4. `tools/build_light_package.py` проверяет receipt, свежесть сборки, допустимые
   файлы и отсутствие подмен/лишних данных. Исходники frontend и node_modules
   в runtime не копируются. В CI frontend собирается перед package/test gate.

## Незакрытая часть переноса

- Проекты и их диалоги, редактор/выбор профилей и формат ответа.
- Подключения моделей: обнаружение, мастер API, проверка, явное назначение.
- Наборы: native выбор папки, watch, загрузка пачек, очередь, качество индекса.
- Лес знаний, память/контекст/суммаризатор, skills/MCP, почта и диагностика.
- Артефакты/экспорт, обратная связь и расширенные детали доказательств.
- Аварийное восстановление renderer и последних неподтверждённых символов,
  реальный WebView2 drag/drop, экранный диктор, масштаб и узкие размеры окна.
- Полный установщик, installed user journey, затем удаление NiceGUI из зависимостей.

Пока эти экраны остаются доступными через прежний интерфейс; общие контролы
возврата содержат ссылку «Новый чат». NiceGUI-процесс сохранён, поэтому выигрыша
его памяти и холодного старта в build 771 ещё нет. Python RAG/OCR/моделей также
сохранён. Этот этап не является полной заменой Python или публичным релизом.
