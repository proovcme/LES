# Порядок поиска и контекст ответа

Build 757: Qdrant dense + точный BM25 в SQLite postings → локальный RRF.
Кандидат 759: пустой лексический запрос использует явный dense-путь;
каналы и вид оценки отражаются в trace. API/MCP дочитывают контекст через
тот же проверяемый ChatSectionReader, что и чат.
Частоты обновляются по изменённым файлам, оценки считаются при запросе.
[Контракт BM25](bm25-index.md).
Начиная с 754, основной чат отдельно дочитывает родителей из Qdrant и сохраняет
собственную цитату каждого фрагмента: [контракт цепочки](chat-section-context.md).

Владелец порядка — `retrieval_service.retrieve_chat_chunks`: dense + BM25
RRF, lexical safety merge, явно выбранный реранкер, существующие guards точных
ссылок. Дочитывание выполняет контекстный этап чата после ранжирования.
Чат сохраняет порядок первых 10 попаданий перед добавлением соседей.
Повторный lexical boost в `saferag_service` допустим для старых самостоятельных
потребителей, но запрещён после этого конвейера в основном чате.

`backend/local_reranker.py` запускает отдельный ограниченный по времени worker.
Модель берётся только из существующего локального каталога/кэша, загрузка из сети
не выполняется. Настройки среды запуска: `LES_RERANK_PYTHON`, `RERANK_MODEL`,
`RERANK_DEVICE`. По умолчанию модель BAAI/bge-reranker-v2-m3, устройство CPU.
Включение в чате и API — явный `reranker_enabled`; по умолчанию выключен.
Сбой включённого этапа возвращает понятную ошибку и действие «отключить реранкер».
Результаты проверяются на число, конечность оценок и уникальные допустимые ID.
Worker удерживает модель до остановки приложения, смены конфигурации или таймаута.
Готовность внешнего Python окончательно подтверждается первым успешным вызовом.

Контекст сохраняет границы источников при ограничении бюджета. Полные тексты
не дублируются в SOURCE_MAP; карта ответа содержит только источники из фактически
отправленного модельного пакета. Это проверка происхождения, а не доказательство
истинности каждого утверждения. Короткий preview не заменяет чтение оригинала.

Переиндексация сначала получает все embeddings, затем записывает новые точки и
удаляет прежнее поколение. Ошибка получения/записи очищает только новые точки.
Кандидат 759 проверяет fingerprint оригинала до конвертации и перед публикацией.
Изменение файла сохраняет прежний индекс и возвращает ошибку. Writer lease
удерживается при публикации одного файла, не во время OCR/эмбеддингов партии.
Начиная с 750, окно прерывания процесса закрывает SQLite-журнал в собственном
каталоге состояния: до commit откатываются staged ID, после commit завершаются
замена и транзакционная запись FTS. Незавершённый журнал блокирует поиск;
восстановление возвращает документ в PENDING для проверки оригинала.
OS-блокировка исключает второго писателя, ревизия исключает результат поиска,
прочитанный во время замены. [Контракт и проверки](../acceptance/index-recovery-750.md).

Embedding-подключение сверяется с моделью паспорта индекса и фиксируется на весь
файл. Иерархия переиспользует один вектор вопроса во всех трёх проходах. Несовместимая
модель не вызывает автоматическую миграцию/смену роли. Совпадение model ID не
доказывает идентичность весов за изменяемым внешним endpoint.

Публичные ошибки модели переводятся в `public_error_service`: отсутствие назначения,
ключа, недоступность, таймаут, отказ API, обрыв потока. Интерфейс сохраняет вопрос
после ошибки и не подменяет сообщение сбоя статусом «Готово».

[Измерения и ограничения build 748](../acceptance/rag-audit-748.md).

## Кандидат 760

Lexical coverage использует тот же токенизатор и границы обозначений, что BM25,
включая нормализацию русских слов. Это диагностический сигнал, не оценка истинности.
Чат показывает предупреждение о слабых совпадениях. Счётчик источников имеет
нейтральный цвет; наличие цитаты не удостоверяет вывод. Numeric score остаётся
в trace/source map, но не в заголовке доказательства, отправляемого модели.
Исходная письменность цитат, включая CJK, сохраняется.

Если табличные колонки не соответствуют специализированной схеме, используются
исходные заголовки и строки таблицы. Пустая таблица не создаёт доказательство из
предупреждения; ошибка чтения не индексируется как текст. Оригинал не переписывается.
Отказ по памяти до начала parse оставляет документ PENDING/WAITING_RESOURCES,
не расходует попытку конвертации и не создаёт ложную ошибку документа.
Чат измеряет память у границы допуска и повторно после получения слота;
порог защиты не снижен. [Приёмка и границы](../acceptance/full-chat-760.md).
