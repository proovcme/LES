# Удаление набора документов

Владелец — `proxy/services/dataset_deletion_service.py`. Обычное удаление
сначала создаёт резервную копию SQLite и snapshot Qdrant. Удаление точек
подтверждается повторным count; затем очищаются лексические записи, собственное
хранилище набора переносится в recovery и последним изменяется каталог со связями.
Внешние исходные папки сюда не входят.

Build 769 проверяет путь до любых изменений и повторяет проверку перед переносом.
ID должен обозначать одного непосредственного потомка собственного storage root.
Выход через разделители, `..` или ссылку на чужой каталог отклоняется. Windows
может возвращать разные пути одного перенаправленного каталога: такой случай
разрешён только при положительном `samefile` родителя и зарегистрированного корня.
Совпадения строкового префикса или названия папки недостаточно.

Если путь изменился или перенос в recovery не удался, строки каталога и проектные
связи сохраняются. Qdrant, лексика и файловая система не имеют общей транзакции:
после сбоя поздней стадии для восстановления индекса может потребоваться
сохранённый snapshot/повторная индексация. Нельзя называть такую ошибку полностью
автоматическим откатом. Копии не удаляются при ошибке.

Проверки покрывают сетевые отказы, небезопасный ID/путь до начала изменений,
проверку идентичности перенаправленного каталога и отказ переноса файлов с
сохранением каталога. Установленная приёмка описана в
[отчёте Windows](../acceptance/installed-766.md).
