# Почта в нативном кандидате · 846

В самостоятельном Rust API доступны импорт OLM, локальных EML/EMLX/MSG,
Apple Mail, разовое чтение IMAP, локальный приём писем от Outlook и
просмотр и пересборка цепочек. Импорт OLM читает поля сообщения и тело
из XML и сохраняет EML-снимок в приватном наборе. Повторный импорт
дедуплицирует снимки, а `next_offset` продолжает обработку со следующей
записи архива. Вложенные объекты OLM за пределами XML письма не извлекаются.
PST читается через `outlook-pst` 1.2.0. Чтение ANSI и Unicode идёт по папкам
архива, по тому же API и с тем же `next_offset`. Архив открывается только
для чтения. Обычные файловые вложения сохраняются в EML до 10 МиБ на вложение.
Вложенные письма, ссылочные и слишком большие вложения учитываются в
`skipped_attachments`. Тело только в RTF пока не извлекается.
На [архиве Apache Tika](https://github.com/apache/tika/blob/main/tika-parsers/tika-parsers-standard/tika-parsers-standard-modules/tika-parser-microsoft-module/src/test/resources/test-documents/testPST.pst)
проверены четыре партии, семь писем, повтор без дублей и совпадение SHA-256
исходника. На [парных образцах Microsoft PST SDK](https://github.com/bslater/bodu/tree/master/samples/IO.Pst/Bodu.IO.Pst.Samples.PstBasics/Data)
проверены ANSI и Unicode с обычным файловым вложением.

Rust-лаунчер поддерживает испытательный режим `--native-only`. Он открывает Svelte через
Rust API и запускает отдельный интерпретатор по запросу внешнего навыка.
В изолированном Edge проверен импорт из собранного интерфейса без Python API.
В Windows-кандидате 847 этот режим используется по умолчанию.
Проверка живого IMAPS отложена.

Разовый импорт IMAP использует пароль только в текущей операции.
Фоновый разовый импорт отдаёт идентификатор почтового аккаунта. Его состояние
доступно через реестр аккаунтов. Локальный приём от Outlook сохраняет письмо
и его вложения в одном приватном снимке.

В испытательном Svelte-интерфейсе появился экран «Почта» с подключением
IMAPS, импортом архива, списком писем и просмотром снимка.

Кандидат без Python API ведёт прежний SQLite-реестр почтовых аккаунтов и
использует совместимые записи Windows Credential Manager. Пароль не попадает
в базу, HTTP-ответы или диагностические сообщения. Ручной IMAP-запуск выполняется
в фоне: выбор папки через EXAMINE, чтение через BODY.PEEK, запись контрольной
точки UIDVALIDITY/UID после сохранения оригинала. После потери процесса причина
MAIL_SYNC_INTERRUPTED видна в аккаунте; повторный запуск продолжает с последней
подтверждённой точки. Повторная доставка идемпотентна, изменённый снимок под тем
же Message-ID сохраняется отдельной редакцией.

Кандидат принимает EML и MSG от локального коллектора Outlook. Оригинал сохраняется
в состоянии Леса вместе с хешем, а запрос на индексацию остаётся в журнале.
Нативная очередь разбирает EML/EMLX и MSG на Windows, публикует фрагменты и сохраняет ссылку на
конкретные байты. Почтовые наборы закрыты для внешней модели; вручную изменённая
метка чувствительности эту защиту не отменяет. Отсутствие локальной модели
поиска оставляет сохранённые письма в очереди.

IMAPS устанавливает TLS 1.2 или выше до входа в аккаунт. Имя сервера и цепочку
сертификатов проверяет системный TLS. Открытый IMAP разрешён только для явно
указанного числового адреса loopback. Совместимость прежних форм
ответов и живое подключение остаются отдельными проверками.

В самостоятельном Rust API фоновый опрос работает для включённых IMAP-аккаунтов
при `LES_STARTUP_BACKGROUND_MUTATIONS=true`. Первый опрос начинается через
25 секунд, далее интервал задаёт `MAIL_IMAP_POLL_SEC` (180 секунд по умолчанию,
0 выключает опрос). Ручной и фоновый запуск используют одну блокировку и
одни контрольные точки. Сбой аккаунта не останавливает опрос следующих.

Реальный Outlook COM и внешний почтовый ящик не использованы в тесте.
Проверены локальный протокол сборщика на синтетических EML и MSG и отказ IMAPS
с недоверенным сертификатом до команды входа.
MSG использует [системное хранилище Windows](https://learn.microsoft.com/en-us/windows/win32/api/coml2api/nf-coml2api-stgopenstorageonilockbytes)
и [формат свойств Outlook](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxmsg/ed03f930-fdef-4cc8-b400-b69007d7f416).
На отдельном Edge-индексе проверены пять синтетических снимков и два файла
из копии проектного набора (PDF и XLS). После принудительного выхода во время
IMAP-загрузки фоновая синхронизация продолжилась с нужного UID. Ссылки вернули те же
байты EML, MSG, PDF и XLS; исходные файлы не изменились.

Классический Outlook открывает и выгружает письма через поставляемый COM-сборщик.
