# Изолированная обработка документов · кандидат 774

Rust-ядро владеет процессом `tools.light_document_worker`, JSONL-протоколом,
очередью вызовов, таймаутом и завершением дерева процессов. `format_process.py`
передаёт локальный запрос; удалённого исполнения команд или модельного инструмента
для запуска программ нет. Этот шаг **не удаляет Python из установки**.

В обработчик вынесена вся стадия `_convert_file_inline`: классификация PDF/Office,
чтение, OCR по прежнему явному назначению и подготовка узлов. Основной API сохраняет
проверки регистрации/исходного файла, окончательный бюджет чанков, эмбеддинги,
журнал замены и публикацию Qdrant/лексического индекса. Второй индекс не создаётся.
Письма сохраняют прежний локальный реестр происхождения вложений; обработчик не
отправляет письма и не обращается к чату/эмбеддеру. Явный VLM OCR остаётся возможен.

Обработчик используется повторно при одинаковых программе, каталоге и параметрах
чанкинга; изменение модели-токенизатора заменяет процесс. После 60 секунд простоя
один Rust-наблюдатель освобождает процесс. Завершение одной порции набора не отменяет
конвертацию другого набора. При ошибке текущий процесс завершается; следующий запрос
запускает новый. Скрытого повтора того же запроса нет. Штатная политика очереди может
повторить временную ошибку с прежним ограничением числа попыток.
При штатном shutdown API обработчик останавливается до ожидания потоков Python;
atexit остаётся дополнительной очисткой, а Windows Job покрывает аварийный выход.

Запрос ограничен 8 МиБ, строка ответа — 32 МиБ минус запас оболочки. Частичные,
неверные и слишком большие ответы отклоняются. stdout библиотек, включая вывод
C-расширений, перенаправлен в stderr; протокол использует отдельный дескриптор.
Сохраняются последние 64 КиБ stderr; в частный журнал API передаётся до 8000 символов,
PID, код ошибки и exit code. Пользователь получает понятное сообщение без traceback.
Ограничение по времени — 95% прежнего файлового таймаута, максимум час.

На Windows Job Object ограничивает обработчик и потомков суммарно 2 ГиБ commit memory
и 16 процессами. Закрытие handle при падении API завершает принадлежащее ему дерево.
Это предел отказа, а не гарантия обработки любого PDF: тяжёлый OCR/таблицы могут
потребовать пересмотра лимита после измерений. На Unix есть отдельная process group
и её завершение при штатном управлении; уничтожение родителя и лимит памяти там
ещё не приняты. Пределы не ослабляют существующую политику допуска по RAM.

`scan_sources` выполняет полный обход выбранной папки в Rust, только для чтения.
Символические ссылки/reparse points, служебные папки и `_originals` не обходятся.
Недоступный подкаталог, невалидное имя или превышение лимита отвергает весь результат:
такой обход нельзя трактовать как пустую папку и удалять записи индекса.
Это перенос `external_scan.source_files`, а не всех наблюдателей/обходов проекта.

Launcher выбирает строгий `LES_FORMAT_WORKER_MODE=native`. Режим `inline` оставлен
для модульных тестов и явно подготовленного отката; auto совместим со старым ядром.
Для отката runtime и DLL возвращаются совместно из резервной копии, индекс и
назначения моделей не меняются. Новых зависимостей и Rust executable не добавлено.
