# Поиск → чтение разделов → контекст чата

В кандидате 804 Rust сверяет попадания с текущими точками Qdrant и читает
родительские разделы. Он сверяет датасет, файл, раздел и координаты каждой
исходной цитаты, исключает навигационные точки и ограничивает объём чтения.
Кэш запроса и проверка поколения до и после чтения сохранены. Переходы между
страницами и продолжения таблиц пока читает совместимый адаптер.

Путь в датасете входит в ключ раздела. Одноимённые документы в разных папках
остаются отдельными источниками. Замена по тому же пути обновляет поисковую
версию. Поиск может показать несколько редакций и не определяет срок их
действия только по имени или времени изменения файла.

В ответе по документам метка `[Источник N]` относится к конкретному фрагменту.
Новый чат показывает отдельно процитированные фрагменты и найденные материалы.
Если модель не связала вывод с фрагментом, чат сообщает об этом. При сравнении
редакций модель получает указание ставить ссылку рядом с фактом из каждой.
Проверка ссылки сверяет её с источниками, доступными в конкретном ходе.
Она не проверяет истинность произвольных утверждений модели.

В кандидате 800 недостающие страницы PDF читаются одним ограниченным
запросом Qdrant. Условие связывает датасет, файл и номера страниц.
Превышение общего лимита переводит чтение на прежние независимые запросы,
поэтому переполненная страница не вытесняет другие. Сортировка, лимиты
крайних фрагментов, границы таблиц и адреса цитат сохранены.

В кандидате 788 основной чат читает структурированные фрагменты оригинала
DOCX из поисковой выдачи или явно выбранного файла. Проверяется хеш
индексированной версии. Учитываются стили заголовков и явные уровни
структуры Word. Таблицы читаются по строкам с сохранением номеров столбцов
и диапазонов объединённых по горизонтали ячеек.

Выбирается до двух документов и восьми фрагментов в сумме. Малые разделы
или таблицы помещаются целиком в заданный предел. Для больших разделов
диагностика показывает, сколько блоков было отобрано. Ссылка открывает
окно вокруг конкретного абзаца или строки. Текстовое извлечение остаётся
доступно для остальных результатов индекса. Сноски, вложенные таблицы
и содержимое текстовых полей не получают адресов этим способом.
Когда прочитаны все адресуемые блоки простого документа, старый дубликат
из индекса убирается из начального контекста. На тестовой ведомости Qwen3.5:9b
выбрала строку с количеством 7654321 и единицей «комплект». На сохранённом
ответе проверена канонизация явно подписанной ссылки, в браузере —
предпросмотр оригинальной строки. Повторную генерацию в финальном кандидате
остановила штатная защита памяти.

В кандидате 787 постраничный PDF дочитывается в существующем индексе.
Для первых четырёх найденных страниц проверяются соседние номера в том же
датасете и файле. В контекст добавляется до двух крайних фрагментов с каждой
стороны и до двенадцати на запрос. Первые попадания сохраняют приоритет,
дочитанные фрагменты цитируются со своих страниц. Пробел в нумерации не
перепрыгивается. Смена поколения индекса останавливает чтение.

При явной пометке «Продолжение таблицы N» или «Table N (continued)» Лес
может дочитать одну пару страниц оригинала. Проверяются хеш файла, номер
таблицы, однозначность сеток и совпадение колонок. Каждая часть остаётся
отдельным доказательством на своей странице. Неподтверждённая связь оставляет
доступные страницы отдельными источниками. Метод покрывает таблицы с
распознанными линиями и текстом, в том числе продолжение без повторной шапки.
Проверка не объединяет разрезанные строки и не вычисляет итоги.
В отдельной сборке Qwen3.5:9b прочитала два условия и две части таблицы
из тестового PDF. В браузере проверены ссылка на страницу 2 и возврат
с фокусом на цитате. Регрессия отдельно проверяет переход при одном попадании
в поиск и отклонение чужого файла, другой версии и несовпадающих колонок.

DOCX сохраняет в текстовом индексе заголовки, оформленные стилями Word.
В обычной проекции текст из ячеек может идти отдельными абзацами. Граница
страницы не задаёт структуру и адрес цитаты Word.

В кандидате 786 обычный вопрос по базе включает чтение строк оригиналов
XLSX, XLSM и CSV. Каталог ограничивает кандидатов датасетами и выбранными
файлами. Сначала проверяются книги из поисковой выдачи, затем остальные
подходящие оригиналы в пределах бюджета. Даже при пустой выдаче индекса
можно найти строку, которой нет в обзорных фрагментах. Хеш оригинала должен
совпадать с индексированной версией. Формулы читаются с сохранённым значением,
если оно есть. Лес не вычисляет формулы в этом маршруте.

На запрос проверяются до четырёх книг, с проверкой трёхсекундного бюджета
между книгами. Применяются действующие пределы чтения снимка таблицы.
В контекст отбирается до шести строк, каждая со своим листом и диапазоном
ячеек. Карточка источника открывает предпросмотр на процитированной строке.
Строки отбираются по совпадениям в данных, включая данные листов
за пределами индексного обзора. Выборочная выдача не подтверждает полный
итог по книге. Диагностика `table_originals` показывает покрытие и проблемы
чтения. Для книг с найденными строками начальный контекст использует оригинал
без дублирующего обзора индекса. Режим работы по источникам обходит кэш ответов.
В отдельной сборке обычный вопрос по базе на Qwen3.5:9b вернул 32 и 7654321
из двух листов одной книги. Вторая ссылка открыла строку 2003 оригинала.
Проверены переход в браузере и возврат с фокусом на цитате. Штатная установка
пока использует 785.

Начиная с build 754, основной чат связан с чтением индексированных родителей.
Это самостоятельная реализация, без переноса Legion. В build 755 основной
поиск дополнен полноценным BM25: [контракт индекса](bm25-index.md).

## Граница чтения

ChatSectionReader в chat_section_context_service.py принадлежит одному
запросу. После поиска и необязательного реранкера сохраняет первые 10 попаданий
в исходном порядке, проверяет их по текущим payload Qdrant и дочитывает до
8 уникальных родителей. Фильтр — dataset_id + file_name + parent_id;
navigation и evidence_admissible=false исключены. Первая проверка также
сверяет текст, страницу, порядковый номер и source_ref исходного попадания.

Чтение идёт страницами по 128 точек. Защитные пределы: 2048 фрагментов или
2 млн символов на родителя, 15 секунд на этап; превышение возвращает понятную
ошибку. В упаковку добавляются до 512 соседей по очереди из каждого родителя.
Первоначальные попадания имеют приоритет. Остаток найденной выдачи и фактическое
число включённых фрагментов отражаются в диагностике.

Журнал индекса проверяется до/после чтения и перед вызовом модели. Ревизия поиска
передаётся вместе с попаданиями; смена поколения останавливает запрос.
Кэш родителя работает только внутри одного запроса и одного поколения.
Ошибка чтения не подменяется успешным ответом по старой склейке.

## Модель и доказательства

Каждый прочитанный фрагмент становится отдельным Chunk, сохраняя собственные
point ID, текст, страницу и source_ref. Для atomic_evidence старый renderer
не склеивает соседей, не очищает исходный текст и не обрезает его по символам.
Чрезмерно большой фрагмент пропускается целиком; более короткий следующий
может войти. Заголовок честно называет материал фрагментом раздела.

Общий ContextGovernor учитывает профиль, запрос, историю и резервы ответа.
Источник попадает в модель целым объектом. Второй проход упаковки исключает
из SOURCE_MAP ссылки на не вошедшие доказательства. Источники итогового ответа
ограничены фактически отправленным пакетом; quote совпадает с текстом индекса.
section_coverage показывает индексированные, переданные и пропущенные фрагменты.
Полнота относится к индексированному родителю, не к качеству OCR оригинала.
Для постраничного PDF родитель ограничен страницей (для табличной строки
также конкретной таблицей на странице). Соседние страницы дочитываются
отдельно от родителя и сохраняют собственные ссылки.
С build 764 сведения о полноте передаются также модели через обязательный
небольшой объект запроса. Место резервируется до выбора доказательств; после
выбора меняется только зарезервированный объект, без повторной упаковки.
Отчёт различает `complete`, `partial`, `unknown` и не утверждает ответимость.

Один механизм применяется к первоначальному поиску, дополнительному
search_sources модели и повтору после пустого ответа. Прогресс сообщает
дочитывание и подготовку контекста. Память остаётся советом, не доказательством.

Подробная приёмка: [build 754](../acceptance/chat-section-context-754.md).

Кандидат 760: заводские профили публикуются как отдельные ревизии по хешу
содержимого. Сохранённые снимки чатов и активный выбор не обновляются скрыто;
новая заводская версия в существующей установке применяется явно. Письменность
цитат сохраняется, ranking score исключён из модельных заголовков доказательств.
[Штатный чат и ограничения](../acceptance/full-chat-760.md).

Кандидат 761: `model_policy.reasoning_enabled` задаёт размышление явно в новой
неизменяемой версии профиля; по умолчанию оно выключено.
`reasoning_budget_tokens` (512–8192, по умолчанию 2048) — общий выходной бюджет
размышления и ответа. Резерв ContextGovernor увеличивается до этого бюджета;
если он не помещается в проверенную ёмкость подключения, запрос отклоняется.
Короткий формат ответа не урезает общий бюджет размышления до 512 токенов.

Локальный совместимый API получает `chat_template_kwargs.enable_thinking`,
проверенный native chat — `think`. Облачное generic-подключение при явном
включении отклоняется с понятной ошибкой: его протокол reasoning не подтверждён.
Отдельные поля reasoning и inline `<think>…</think>` (включая заранее открытый
тег) отделяются от итогового текста. SSE сообщает «Модель думает», затем
«Модель пишет ответ»; содержимое размышления не передаётся клиенту.
Если общий лимит исчерпан до итогового текста, возвращается явная ошибка.
Модель, поиск, назначения и пороги памяти автоматически не меняются.
[Приёмка и ограничения](../acceptance/reasoning-761.md).
