# Остальные готовые компоненты

Сверено 12.11.2026 по исходникам и метаданным опубликованных Rust-пакетов.
Ни одна из этих библиотек пока не заменяет рабочий парсер, нарезку или
назначенную модель. Испытание координатора не смешивается с пересчётом
фрагментов и dense-векторов.

| Компонент | Конкретный кандидат | Применение и выявленные ограничения |
|---|---|---|
| Xberg | Опубликованный 1.3.10, отдельная проверка форматов | Продолжение Kreuzberg. Rust 1.92, MIT. PDF/DOCX/XLSX: сравнить текст, таблицы, страницы, вложенные объекты и OCR-происхождение. Не включать весь набор inference/загрузчиков ради парсера |
| Docling.rs | Опубликованный `docling` 2.82.1, сравнительный кандидат | Полноценный Rust-порт, а не Python-адаптер. Без default features доступны декларативные форматы; `pdf-text` отделён от ML-конвейера. OCR/layout/TableFormer требуют отдельных моделей. Проверить DoclingDocument, таблицы и локаторы на том же наборе, что Xberg |
| FastEmbed | 6.1.0 проверен отдельным offline-пробником, включение отклонено | Совпадение crate ort rc.13 недостаточно: FastEmbed включает `api-24`, текущие локальные assets используют Runtime 1.20.1. Последний FastEmbed 7.7.0 требует ещё и ort rc.15. Tokenizers 0.23.2 — отдельная от нашей 0.22.2 версия |
| text-splitter | 0.33.2 с адаптером текущего счётчика | Семантические границы текста/Markdown. Использовать наш токенизатор через ChunkSizer, не включать второй токенизатор ради нарезки. Структура разделов, таблиц и цитат остаётся за документным слоем |
| Candle | 0.11.1, резерв для конкретной модели | Дополнительный ML-backend оправдан измеренным отсутствующим сценарием. Генерация уже работает через Ollama/API, ONNX — через ort; отдельный Candle не устраняет координатор или поиск |

Kreuzberg 4.10.4 — отдельная MIT-ветка LTS в `kreuzberg-dev/kreuzberg-lts`:
только критические исправления до конца 2026 года, best effort. Новая
разработка идёт в `xberg-io/xberg`. Предварительное сравнение README по старой
ссылке смешивало разные ветки и не доказывало лицензионного конфликта; оно
исправлено по каноническим LICENSE, README и политике LTS. Для новой интеграции
основной кандидат — Xberg, а не v4.

Опубликованный Xberg 1.3.10 требует Rust 1.92. Git main на момент сверки уже
содержит 1.4.0/Rust 1.99 и ORT rc.15: main не является источником доказательств
совместимости опубликованной 1.3.10 с текущим Rust 1.97/ORT rc.13.
Docling.rs проверяется отдельно: `docling` и `docling-core` публикуются как MIT,
`docling-pdf` — MIT AND BSD-3-Clause. Поставляемые модели и остальные зависимости
имеют собственные условия, их нельзя приравнивать к лицензии ядра.

У опубликованного Xberg 1.3.10 ONNX optional: ort rc.13 с `api-18`,
Calamine 0.36.1 и `xberg-native-pdf` 1.3.10. У опубликованного Docling 2.82.1
Calamine 0.38, а ML-часть docling-pdf использует optional ort rc.14; её нельзя
просто включить в текущий процесс с закреплённым rc.13. Сначала сравниваются
декларативные форматы и `pdf-text` без моделей, ML — отдельно. Проверка
совместимости должна учитывать и Cargo features, и версию загружаемой DLL.

Возможная точка замены — существующий изолированный Rust-обработчик форматов,
с его таймаутом, отменой и договором документных узлов. Сторонние RAG-серверы,
MCP, собственные векторные базы и выбор моделей этих библиотек не нужны для
извлечения. Общий владелец локаторов, редакций и публикации LES сохраняется.
Нельзя принимать Markdown-текст за достаточный паритет: нужны порядок чтения,
ячейки/объединения, страницы, изображения/OLE и явный статус непрочитанного.

Модели и внешние OCR-сервисы не загружаются автоматически. Offline-пробник
должен использовать явно имеющиеся файлы; отсутствие модели — отдельный
понятный результат, а не повод менять роль или запускать скрытый fallback.

Каждый компонент принимается как замена конкретного владельца, с удалением
заменённого кода после проверки. Для парсера сравниваются реальные исходники
и локаторы, для splitter — границы/токены/стыки, для эмбеддера — модель,
нормализация, размерность и ранги. Установка всех библиотек сама по себе
не доказывает улучшение RAG.

## Фактический пробник 870

`text-splitter` 0.33.2 собран на Windows отдельно от приложения. 76 запусков
TextSplitter/MarkdownSplitter на 32 имеющихся текстовых образцах, их более
длинных объединениях и двух Unicode/табличных стресс-примерах прошли проверку
точных byte offsets, полного покрытия исходника, лимита 430 токенов и overlap
50. Использован наш tokenizers 0.22.2 через ChunkSizer. Это проверка базовой
сохранности текста, не паритет табличной семантики, родителей и цитат. Нарезка
рабочего индекса не изменялась.

FastEmbed 6.1.0 собран с `default-features=false, ort-load-dynamic`, без hub
и загрузки моделей. Попытка открыть имеющуюся BGE-M3 в отдельном процессе
закончилась аварийным завершением при инициализации ORT. Проверка manifest
обнаружила требование `api-24`, несовместимое с используемой DLL 1.20.1.
Численный паритет эмбеддингов не измерен. Никакой замены runtime, ролей,
весов или векторов не выполнено. До отдельной проверки совместимого runtime
это не готовая замена нашего эмбеддера.
