# Извлечение документов и цитаты — 783

Локальный патч 783 установлен; полный установщик и публичный релиз отдельно.
Исходные файлы только для чтения; индекс и роли моделей не меняются конвертером.

## Word

`core/src/document/legacy_doc.rs` читает Word 97–2003 в Rust. На Windows контейнер
открывается штатным read-only IStorage/IStream, без Word, макросов и внешних
конвертеров. Из FIB/CLX читается активная piece table, включая смешанные UTF-16
и FcCompressed, результаты полей и разделители абзацев/ячеек. Инструкции полей
не превращаются в текст. Структура, диапазоны и лимиты проверяются; шифрование,
неподдерживаемая версия или повреждение дают отдельную ошибку.

Это текстовая проекция; геометрия таблиц и номера страниц DOC не выдумываются.
Предпросмотр использует тот же native reader, экранирует HTML и явно сообщает,
что оформление/разбиение Word не воспроизводятся. Скачивание исходного DOC сохранено.
Linux/macOS сохраняют прежний адаптер. DOCX и остальные Office-форматы ещё Python.
Существующие библиотеки Rust не дополнены новыми зависимостями.
Основа реализации: [MS-DOC](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/),
[FcCompressed](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/aa2e55a2-f4f2-4795-bab5-6d9d7a0ed249),
[StgOpenStorage](https://learn.microsoft.com/en-us/windows/win32/api/coml2api/nf-coml2api-stgopenstorage).

## PDF и очередь

Классификация и текст читаются постранично существующим PDFium, без поиска
пересечений таблиц в probe. OCR обнаруживает также контуры букв без текстового
слоя; действительно пустая страница не выдаётся за ошибку скана. Существующий
Windows OCR читает только нужные страницы и освобождает bitmap после каждой.
Перед pdfminer проверяются native PDFium-объекты и сегменты путей. Сложная
геометрия свыше 2000 единиц откладывается для всего документа: страницы могут
делить ресурсы шрифтов/форм. Текст и настоящие ссылки на страницы сохраняются;
геометрический паспорт не выдумывается. Это ограничение автоматического
обогащения сложных чертежей; отдельный подробный аудит остаётся доступен.
Подсчёт страниц также через PDFium, без тяжёлого обхода pdfminer.
Инвентаризация текстовых страниц в проверке целостности использует тот же
постраничный reader; отказ чтения не считается пустым успешным документом.
Проверка требует наличия всех native текстовых страниц, но допускает также
страницы OCR и короткие листы: сравниваются наборы номеров, не только количества.

Быстрый текстовый путь выполняется до выбора вложенного процесса. Запрет
вложенного subprocess внутри format worker больше не отключает этот путь.
Короткий native текст векторного разделителя сохраняется, пустые TEXT-операторы
не вызывают OCR. Изображение со страницей-номером по-прежнему требует OCR.
Полностью белый отрендеренный лист не выдаётся за неудавшийся скан; чёрный или
нераспознанный непустой скан по-прежнему даёт ошибку, без частичного успеха.

`rag_page_metadata` освобождает pdfminer layout каждой страницы даже при ошибке;
длинный документ больше не удерживает все разобранные layouts до конца файла.
OCR_DISABLED/OCR_READ_FAILED и ошибки DOC проходят через format worker с кодом
и понятным сообщением, не превращаются в пустой успешный результат или чанки ошибки.
Ограничение процесса 2 ГиБ, таймауты и защита RAM сохраняются.
Запуск worker явно передаёт пакетный runtime в sys.path: embedded Python с
изолирующим ._pth больше не зависит от текущей папки. Причина форматной ошибки
передаётся в ограниченном диагностическом поле, не только через гонку stderr.

Исторические owner-файлы Office/метаданные с нулём фрагментов сохраняются в каталоге
как SKIPPED/TEMPORARY_SOURCE. Оригиналы и положительный старый индекс не удаляются.
Очередь дополнительно фильтрует такие имена до LIMIT. Новая регистрация уже
использует тот же договор `smart_index`; это восстановление старых записей.

## Цитаты

`core/src/citations.rs` владеет распознаванием ссылок и канонической записью
`[Источник N]`. Python-фасад не содержит прежнего regex-разбора. Источники только
из фактически переданной модели source_map; найденные кандидаты автоматически
не становятся процитированными. Неизвестные номера остаются неподтверждёнными.
Числа внутри имени файла не становятся номерами источников. Кодовые фрагменты
не преобразуются и не учитываются как цитаты.
Это включает двойные backticks, fenced-блоки и внешние Markdown-ссылки.
Явные Qn.Hm преобразуются только по имеющейся evidence_ref, с тем же parser
для manifest и счётчика; упоминание такого handle в коде не подтверждает цитату.

Пропущенная открывающая скобка исправляется только при полном совпадении с
сохранённым заголовком конкретного источника. Новые ответы сохраняются с
канонической записью; frontend умеет показать тот же точный старый заголовок
из истории без переписывания истории. Счётчик и manifest используют native parser.
UI предупреждает о недостающих/неизвестных ссылках. Наличие корректной ссылки
не объявляется проверкой истинности утверждения: claim_verification остаётся
not_performed, автоматического VERIFIED нет.
