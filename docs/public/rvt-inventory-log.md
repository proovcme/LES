# Как ЛЕС строит ведомости из Revit

26 ноября 2026 · кандидат 947

Папку с RVT можно подключить как датасет и спросить, какие краны заложены, что входит в систему или сколько мощности указано у оборудования. Точечный поиск по модели появился в предыдущей сборке. Теперь ЛЕС умеет обходить все прочитанные записи выбранной модели, собирать таблицу и считать итоги.

## Что внутри RVT

Для опыта взяли локальную модель водоснабжения и канализации Revit 2024 размером 59,1 МБ. Посмотрели потоки внутри файла и сверили его SHA-256 со снимком Увязки. В контейнере OLE/CFB оказалось 13 потоков.

| Поток | Что использует читатель |
| --- | --- |
| `BasicFileInfo` | Версия формата и сборка Revit. |
| `Formats/Latest` | Описания классов, полей и наследования. В исследованном файле прочитано 4 492 описания классов. |
| `Global/ElemTable`, `Global/PartitionTable`, `Global/DocumentIncrementTable` | Идентификаторы, разделы хранения и данные для выбора актуальной записи. |
| `Partitions/18` | Основная часть записей этой модели. Здесь найдены экземпляры, типы, определения параметров, системы и спецификации. Номер потока зависит от файла. |

Увязка через `rvt-rs` прочитала 17 546 нативных записей. В них входят стили, категории и другие служебные объекты. Среди прочитанного 129 экземпляров семейств, 379 типоразмеров семейств, 10 осей, 3 уровня, 4 трубопроводные системы и 37 спецификаций. ЛЕС выбрал классы, нужные для поиска, и сохранил 1 014 структурированных записей. Эти числа относятся к двум разным профилям чтения одной редакции.

Источники — [спецификация CFB](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cfb/53989ce4-7b05-4f8d-829b-d08d6148375b), [исходники rvt-rs](https://github.com/DrunkOnJava/rvt-rs), [объекты и параметры Revit API](https://help.autodesk.com/cloudhelp/2025/ENU/Revit-API/files/Revit_API_Developers_Guide/Introduction/Elements_Essentials/Revit_API_Revit_API_Developers_Guide_Introduction_Elements_Essentials_General_Properties_html.html).

## Как собирается строка ведомости

ЛЕС хранит доступные параметры, ID и связи прочитанного объекта. Запись закреплена за датасетом, файлом, SHA-256 и ElementId. Для ведомости ЛЕС читает страницы этих записей из индекса и связывает экземпляр с типом в той же редакции файла. Заполненное поле экземпляра имеет приоритет перед типом. Если на одном уровне обнаружены разные значения выбранного поля, результат помечает конфликт.

У крана в имени типоразмера может стоять только `3/4″`. «Кран шаровый полнопроходной» хранится в `ADSK_Наименование` типа, рядом с изготовителем. Этаж и система привязаны к экземпляру. В таблице они собираются в одну строку. Источник показывает документ и ElementId, а структурированный результат сохраняет ID параметра и объекта, откуда взялось значение.

В Увязке уже есть ведомости по параметрам. При проектировании мы сверили её контракт с полями `instance`, `type` и `effective`. ЛЕС выполняет выборку локально по собственному индексу.

## Что можно спросить

Выберите датасет с проиндексированным RVT и задайте один из следующих вопросов.
С кандидата 950 чат передаёт вопрос модели. Ведомость строится, когда
модель вызывает `model_inventory`. Через MCP инструмент можно вызвать напрямую.

| Запрос | Что вернёт ЛЕС |
| --- | --- |
| «Перечисли все краны в модели» | Экземпляры с ElementId и доступными этажами, помещениями и системами. |
| «Где стоят краны в модели?» | Таблицу с сохранёнными привязками. |
| «Что входит в систему В1 1?» | Элементы с сохранённой привязкой к системе с таким именем. |
| «Составь вендор-лист оборудования в модели» | Позиции по типизированным экземплярам с маркой, артикулом, изготовителем, поставщиком и количеством. |
| «Посчитай мощность системы В1 1» | Номинальную мощность в Вт и полную в ВА отдельными суммами. Рядом число использованных и пропущенных значений. |

Таблица содержит до 24 строк за страницу. Для продолжения можно повторить вопрос с «страница 2». Итоги считаются по всей выбранной совокупности записей. Codex получает те же данные через MCP `model_inventory` с `dataset_id` или `dataset_ids`. Режимы `list`, `vendors` и `power` возвращают структурированные строки. `doc_id` сужает запрос до одного RVT, `q` фильтрует наименования, `system` задаёт имя системы. Для следующей страницы передаются `next_offset` и `index_revision` с прежними фильтрами.

## Как считаются количество и мощность

Вендор-лист считает размещённые экземпляры. Позиции объединяются по изготовителю и артикулу при совпавших марке и поставщике. Если артикула или изготовителя нет, группировка ограничена моделью и типом. Изготовитель и поставщик остаются разными полями. В выборку могут попасть типизированные экземпляры с незаполненными закупочными полями.

Число в RVT, вид физической величины и формат отображения хранятся отдельно. В тестовой модели значение `26909,776…` для номинальной электрической мощности во внутренних единицах Revit соответствует **2 500 Вт**. ЛЕС пересчитывает только поддерживаемые виды величин и сохраняет исходное число вместе с ID параметра. Номинальную мощность и полную мощность считает отдельно. [Документация Autodesk по единицам](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Introduction/Application_and_Document/Revit_API_Revit_API_Developers_Guide_Introduction_Application_and_Document_Units_html.html).

## Границы охвата

- Ведомость относится к прочитанным классам текущей редакции индекса. При смене редакции во время чтения расчёт прерывается. На запрос отведено до 32 моделей, 50 000 структурированных записей и 64 МиБ данных записей.
- Старые RVT-индексы без структурированных записей требуют повторной индексации. Ответ показывает охват по моделям. Доступность помещений, элементов связанных моделей и данных о расположении зависит от извлечения.
- Состав системы берётся из сохранённой принадлежности. Для физической связности соединителей, маршрутов цепей и поиска обслуживаемых помещений нужны дополнительные связи.
- Увязка читает определения и сохранённые ячейки спецификаций. Для совпадения с официальной ведомостью Revit нужно отдельно сверить стадии, варианты, поля, правила группировки и формулы. [Доступ к данным спецификации в Revit API](https://help.autodesk.com/cloudhelp/2024/PTB/Revit-API/files/Revit_API_Revit_API_Developers_Guide/Basic_Interaction_with_Revit_Elements/Views/View_Types/TableView/ViewSchedule/Revit_API_Revit_API_Developers_Guide_Basic_Interaction_with_Revit_Elements_Views_View_Types_TableView_ViewSchedule_Working_with_ViewSchedule_html.html).

## Проверка кандидата

Кандидат проверили в отдельном профиле Windows на копии индекса 946. Чат и MCP работали с одной редакцией. На время проверки Windows блокировала открытие исходного RVT. После прогона сборка 946 открыла те же датасеты и снова нашла параметр типа обычным поиском.

| Проверка | Результат |
| --- | --- |
| «Перечислить все краны в модели» | 9 экземпляров двух типоразмеров среди 261 прочитанного экземпляра. Результат совпал с прямым обходом записей. |
| Вендор-лист | 36 позиций из 129 типизированных экземпляров по правилам группировки выше. |
| Состав системы В1 1 | 131 элемент с сохранённой привязкой. |
| Мощность системы В1 1 | 2 500 Вт номинальной и 2 500 ВА полной мощности из одного подтверждённого элемента. Для 130 остальных в этой выборке значения в итог не вошли. |
| Продолжение списка | Две страницы по закреплённой редакции вместе дали те же 9 ElementId, что и запрос одной страницы. |

Для утверждения «все краны исходной модели» нужна сверка со спецификацией Revit по тем же категориям, стадиям и вариантам. Состояние выпуска ведётся в [журнале выпусков](../RELEASE_LEDGER.md).
