# LES RAG — выпуски

## Исходники 955 и загрузка Python для Windows по запросу

Штатный Windows-пакет содержит PDFium и описание отдельно поставляемой среды.
Лес загружает Python при выполнении одобренного скрипта внешнего навыка.
[Компонент навыков](modules/skill-runtime-package.md).

Удалены семь Python-модулей без действующих точек входа. Проверены
импорты, команды запуска и состав поставки.
[Граница переноса](modules/python-exit.md) · [Карта кода](CODE_RUNTIME_MAP.md).

## Кандидат 954 и прямой подсчёт экземпляров RVT

ЛЕС собирает ведомость по типам и уровням из сохранённых записей RVT.
Поддерживается отбор по ID категории Revit. Новый режим доступен через
`model_inventory` в чате, API и MCP. Подсчёт не требует векторного индекса.
На локальном контрольном RVT результат совпал с прямым извлечением
установленной читалкой Увязки по ID 183 экземпляров и ID уровня.
В отдельном профиле без Qdrant Inkling получил готовую строку ведомости
и выдал количество и уровень со ссылкой на тот же RVT.
[Читалки инженерных файлов](modules/native-engineering-readers.md).

## Кандидат 953 и строки таблиц DWG

ЛЕС сохраняет строки нативных таблиц и восстанавливает строки поддерживаемых
сеток из линий и текста. Чат, API и MCP читают таблицы из индекса с адресами
ячеек. У надписей доступны слой и точка вставки. Для появления строк в
существующем наборе требуется повторная индексация нужных DWG.

На локальном стенде набор с DWG и текстовым файлом вернул 43 строки
экспликации и отдельную строку итога. В обычном чате Inkling назвал обе
площади и выдал перечень. На образце AutoCAD проверено чтение 15 строк
из сохранённого блока нативной таблицы.
[Чтение DWG и таблиц](modules/native-engineering-readers.md).

## Кандидат 952 и ведомость в обычном чате

Поиск по индексу ограничивает ведомость двумя вызовами. После получения результатов
модель получает готовые метки источников по строкам, а вендор-лист сообщает
ID типа. Повтор одинаковой надписи на листе и слое DWG уступает место другим
фрагментам в окне чата. Доступ к ведомости через MCP и агентский режим сохраняется.

## Кандидат 951 и поиск по датасету при упоминании Excel

Чат по набору объединяет строки названной книги с результатами поиска по набору.
В начале контекста чередуются строки книги и фрагменты из других документов.
При недоступности общего поиска модель получает строки книги и сообщение
об ограничении. Сверка DWG с Excel запускается вызовом `model_inventory`.

На копии индекса комплекта ЭО один и тот же вопрос с именем книги в 950
передал тестовой модели только Excel. В 951 в первом запросе были строки
книги и девять фрагментов DWG. Проверены явное ограничение области одной
книгой, чтение книги при недоступном сервере поиска и откат к 950.

## Кандидат 950 и ведомости по вызову модели

В обычном чате ЛЕС передаёт вопрос модели и предлагает ей `model_inventory`
при наличии индексированных DWG или RVT в выбранной области. Кандидат
убирает запуск расчёта по фразам. MCP сохраняет прямой вызов операции.
[Публичный лог по DWG](public/dwg-inventory-log.md).

## Кандидат 949 и сверка DWG с Excel

Чат и локальный MCP сверяют количества в одном датасете. Суммы выносок
и вставок показаны отдельно, возможные связи помечены. Поддерживаются
индексированные данные кандидата 948.
[Публичный лог с результатами](public/dwg-inventory-log.md).

## Кандидат 948 и ведомости по DWG

Чат и локальный MCP считают прямые вставки блоков в пространстве модели
выбранного датасета и складывают мощность из атрибутов. На контрольном плане
получены 24 светильника четырёх типов и 588 Вт. Текстовый поиск нашёл
примечание исходного листа с тем же итогом. Нативный прогон проверен
в отдельном профиле Windows. [Публичный лог по DWG](public/dwg-inventory-log.md).

## Кандидат 947 и ведомости по RVT

Чат и локальный MCP строят списки, вендор-листы и суммы мощности по
сохранённым записям ревизии RVT в датасете. Проверен локальный
кандидат в отдельном профиле Windows на копии индекса 946.
После прогона сборка 946 открыла те же датасеты и нашла параметр типа.
[Публичный лог с устройством модели и примерами](public/rvt-inventory-log.md).

## Кандидат 946 · параметры типа Revit в контексте ответа

При индексации RVT сохраняется структурированная запись для каждого
прочитанного объекта. Поиск контекста следует от найденного экземпляра
к его типу в той же модели и редакции. Подходящие по вопросу параметры
передаются с адресом записи типа. [Чтение инженерных файлов](modules/native-engineering-readers.md).

## Кандидат 945 · связи RVT и чтение IFC

ЛЕС принимает IFC из внешних папок. В поисковых фрагментах сохраняются
имена связанных систем, уровней и типов вместе с ID из исходной модели.
Для RVT восстановлены связи элементов с системами и разрешаются доступные
имена уровней и типов. [Чтение инженерных файлов](modules/native-engineering-readers.md).


## Кандидат 944 · контекст листа в DWG

ЛЕС добавляет имя листа и однозначную крупную надпись к поисковым карточкам
объектов, которые декодер связал с этим листом. Привязка сохраняет handle
объекта, листа и надписи. [Чтение DWG и RVT](modules/native-engineering-readers.md).

## Кандидат 943 · чтение DWG и RVT из папки

Штатная очередь ЛЕС запускает отдельные локальные читалки, формирует поисковые
записи с handle или ElementId и сохраняет SHA-256 исходника. На двух исходниках
проверены форматный обработчик под надзором штатного процесса и поиск BM25.
[Порядок сборки и приёмка](modules/native-engineering-readers.md).

## Кандидат 942 · обычный чат по папке

Обычный вопрос по выбранному набору использует индекс, подбирает соседние
фрагменты и отправляет их модели одним запросом. Ссылки строятся из карты
переданного контекста. В браузере проверено открытие точной строки Excel.

На проверочном корпусе из 325 документов и 50 585 фрагментов с живой моделью
прошли 11 из 12 основных вопросов и три новых. Пятнадцать ответов потребовали
по одному запросу к модели. В одном ответе модель добавила неподтверждённую
оговорку к верным исходным данным. Проверка качества выполнена на стенде.
[Маршрут поиска](modules/native-chat-context.md).

## Локальный кандидат 935 · проверка табличных ссылок

Чат сохраняет происхождение ячейки при переходе от PDF-страницы к поисковой
выдержке. Для ответа по строке модель выбирает адрес, ЛЕС подставляет значения
по этому адресу. Клиент запоминает ключ одной отправки до получения результата.
Сборщик отслеживает встроенные Rust-файлы и проверяет вариант API при упаковке.
Отдельный откат установки получил журнал восстановления.
Полный Windows-установщик обновил рабочую 928 до 935, запуск и сохранность
состояния проверены. На стенде выполнен цикл 927 → 935 → 927. На смешанной
папке живая Qwen 3.5 2B один раз отказалась выдать количество, хотя нужная
строка была в первом окне. Этот сценарий качества остаётся открытым.
[Проверки и границы кандидата](acceptance/folder-facts-935.md).

## Локальный кандидат 934 · размер выдачи для модели

В 933 при обычном вопросе по папке и окне 8192 токена в первую попытку
попали все три контрольных факта, вместе с ними — 44 другие выдержки.
Повтор расширил подборку до 60. Qwen вернула оба давления, но ошибочно
отнесла условие охлаждения только к северному участку и добавила проверку
шин тележки. Синтаксическая проверка ссылок пропустила этот ответ.

В 934 начальный тематический поиск по нескольким документам применяет
параметр профиля `model_evidence_k` при упаковке материала. Пропуск
крупной выдержки по бюджету оставляет место в счётчике для следующей.
Координатор учитывает разницу между недоставленным обязательным чтением
и результатами за границей намеренно ограниченной подборки. Размер пула
поиска и выбор оригиналов по ID регулируются независимо.

На папке из 60 файлов принимающая сторона подтвердила хеш запроса,
шесть выдержек и все три контрольных факта уже в первом сообщении.
Проверены окна 8192 и 24 000 токенов. При полном вытеснении источников
обязательным вложением ЛЕС вернул `SOURCE_CONTEXT_WINDOW_EMPTY` до обращения
к модели.

С живой Qwen 3.5 2B на обычном пути чата ни один из трёх вопросов,
для которых в папке есть ответ, полностью не прошёл приёмку. На первом
запросе исчерпан повтор для цитат, на втором инструкция к смесителю
попала в ответ про насосы, на третьем модель пропустила давление тележки
в первом же источнике. Срок гарантии модель оставила неизвестным.
Для установленной версии и качества всего корпуса эти измерения
оценки не дают. Решение о переключении обычного чата отложено до
сравнения на независимых примерах.

С Qwen 3.5 9B через тот же API прошли два из трёх вопросов с ответом
и отрицательный контроль. Переформулированный вопрос завершился ошибкой
проверки цитат. В отдельном сравнении на 20 фиксированных вариантах выдачи
точный набор абзацев получен в 12 случаях у 2B и в 15 у 9B. Все пять
ошибок 9B относятся к частичной потере источников составного ответа.

`make verify` прошёл. Отдельные проверки дали 33 успешных теста сборки
контекста и 11 успешных тестов нативного API. В итоговом `make test`
1939 тестов прошли, 317 пропущены, три упали. В полном наборе наблюдение
за папкой посчитало файл новым при смене маршрута, хотя отдельно тест
прошёл. Вторая ошибка относится к коду выхода аварийного обработчика
формата, третья — к эталону вместимости профиля модели. Эти же три
теста падали в 932. Четыре других прежних падения устранены в проверках
самого стенда: дочерний Python теперь получает зависимости из активного
окружения, а проверка команд Make читает ASCII-имена файлов из байтов
вывода. Рабочая установка — 928. Установщик 934 на чистой Windows
предстоит проверить.

На отдельном стенде сравнили чат 934 с готовым сборщиком LlamaIndex на
одной локальной Qwen 3.5 9B. На девяти одинаковых наборах выдержек
чат прошёл 4 проверки, штатный сборщик — 6, тот же сборщик с правилом
отказа ЛЕСа — 8. В обычном HTTP-чате на папке из 59 файлов оба шаблона
прошли по два случая из трёх. Настроенный вариант однажды потерял
184 кПа, хотя верный источник стоял первым. В другом корпусе оба
шаблона назвали отменённый срок действующим. Интеграцию проверяли
на стенде кандидата 934. [Протокол сравнения и ответы модели](acceptance/llamaindex-934/README.md)

Эксперимент с раздельным чтением свойств дал 5/9 за 43 вызова модели.
Отдельно проверили штатный фильтр Qdrant на границе действия двух

## Локальный кандидат 933 · выдержки и предел ответа

Для поиска по папке действуют два проверяемых правила.

- Обязательные сообщения и ранжированные выдержки первыми занимают место
  в окне модели. Отчёт о покрытии получает остаток. Размер отчёта считается
  по его окончательному тексту. На узком окне ЛЕС может передать сводку
  или пропустить отчёт. Номера цитат соответствуют попавшим в запрос текстам.
- Каждый вызов получает явный предел генерации, рассчитанный по собранному
  запросу. Для локального совместимого сервера, который возвращает отдельные
  рассуждения, ЛЕС проверяет возможность выключить их на контрольном
  сообщении и запоминает результат для данной редакции подключения.

Регрессия сравнивает одни и те же 60 ранжированных текстов с данными для
отчёта о покрытии и без них. На 932 множество доставленных выдержек менялось
при окнах 1400 и 8192 токена. На 933 совпадают тексты в подготовленных
сообщениях и их номера во всех трёх окнах, включая
24 000 токенов. Проверены также обязательные чтения, целые страницы, приоритет
недавнего диалога и пары вызовов инструментов в тестах сборки контекста.

## Локальный кандидат 932 · журнал вопроса по датасету

По номеру запроса `history_id` можно сопоставить результаты поиска, номера
выдержек в каждой попытке, размер отправленного пакета и причину остановки.
При превышении ограничения ответ API показывает измеренную величину и предел.
Они сохраняются в истории вместе с номером вызова модели. Технический журнал
содержит размеры и контрольную сумму запроса. Тексты сообщений и рассуждений
модели в эти события не записываются.

На стенде сравнивались нативные API 931 и 932, один индекс BGE-M3 и одна
папка из 60 тестовых TXT. Вопрос задан по всему датасету, без выбора файлов.
Ollama обслуживала `qwen3.5:2b` через OpenAI SSE, профиль ЛЕСа — 8192 токена.

| Проверка | Наблюдение |
| --- | --- |
| 931, давление на двух участках и условие начала испытаний | HTTP 503 с общим `UPSTREAM_RESPONSE_TOO_LARGE`. Журнал указывал вызов № 2. Не сохранились ни тип ограничения, ни измеренное значение. |
| 932, тот же вопрос, два прогона | Поиск вернул 60 документов за 3,43 и 4,12 с. На стороне ЛЕСа обе попытки были первыми, в обеих передано 0 выдержек. Отправлено 11 772 байта. ЛЕС рассчитал 3079 доступных токенов вывода. Поле предела вывода в запросе отсутствовало. На 24 633-й строке SSE при максимуме 24 632 обработчик остановился. В первом прогоне прошло 127,75 с, поступил 65 441 байт в поле рассуждений. В итоговой сборке — 120,84 с и 65 036 байт. В обоих случаях текст ответа и данные инструментов заняли 0 байт. |
| 932, срок гарантии, которого в папке нет, два прогона | В первом прогоне обработчик остановился на строке 24 769 при максимуме 24 768. Получено 77 499 байт в поле рассуждений, 0 байт в поле ответа. В итоговой сборке выдача также дошла без выдержек, но модель успела ответить, что не может подтвердить срок. В журнале сохранены обычное завершение через 38,22 с, 7088 строк и 702 байта текста ответа. |

Порог строк учитывает и пустую строку между событиями SSE. Число строк
само по себе не измеряет длину ответа в токенах.

В сохранённом контексте контрольного запроса на 8192 токена у всех 60
выдержек указана причина `budget_exhausted`. После сборки остались только
инструкции профиля (727 токенов по оценке ЛЕСа) и раздел вопроса вместе со
служебным отчётом об источниках (3872). В коде сборки отчёт резервирует
место до окончательного выбора выдержек. После подстановки окончательного
отчёта программа пересчитывает расход. Повторного заполнения освободившегося
места в этой ветке нет. Это отдельный дефект сборки контекста.

Проверены нативный API и ядро 932. Прошли `make verify`, пять целевых
автотестов и отдельные проверки обычного JSON и потока Ollama NDJSON.
В полном `make test` прошли 1928 тестов, пропущены 315, упали те же семь
проверок, что на 931. Рабочая установка — 928. Полный установщик 932 на
чистой Windows в этом прогоне не проверялся.
