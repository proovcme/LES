# LES Light: целевые сценарии и граница с большим ЛЕС

Название продукта с build 740 — **LES RAG**, короткое имя в интерфейсе — «Лес».
Прежние application_id и каталоги установки/состояния сохраняются
для совместимости. Это переименование продукта, а не создание второй базы.

Статус: договор работ, не отчёт о готовности. Пользователь отклонил перенос
стиля, выполненный преимущественно через палитру и отступы (build 731–733).
Принятый эталон — действующий экран леса знаний, включая его оболочку,
типографику, навигацию и спокойное разделение рабочих областей.

## Что должно стать единым

| Сценарий | Общие данные и правила | Проверяемый результат |
|---|---|---|
| Подключение модели | Реестр подключений, проверенные возможности, явное назначение | Имя модели/сервиса совпадает в настройках и чате; отказ виден; ничего не назначено скрытно |
| Подключение папки | Один контракт допустимого документа для регистрации, просмотра, счётчиков и леса | Временные файлы не становятся документами; исключение не удаляет оригиналы |
| Подготовка к поиску | Раздельно: обнаружение, обработка, текст/фрагменты, поисковый индекс | INDEXED сам по себе не превращается в «готов к поиску»; отсутствие данных не означает успех |
| Контроль ресурсов | Решение допуска операции и его пороги | UI не пишет «памяти достаточно», если та же операция заблокирована; защита не ослаблена ради демо |
| Диалог | Сохранённый чат, явно выбранные источники и профиль | Возврат сохраняет черновик; ошибки инструментов не маскируются ответом |
| Проверка ответа | Один идентификатор документа и его происхождение | Ссылка ведёт к нужному оригиналу; видны найденные фрагменты или честное отсутствие текста |
| Внешние инструменты | MCP-клиент подключает только явно выбранные инструменты чтения | Вызов и отказ видны; сметный сервер остаётся отдельным подключением |
| Доступ к поиску извне | Отдельный MCP-сервер Light вызывает текущий API поиска | Внешний клиент получает фрагменты, происхождение и ссылки; служебные данные не раскрываются |

## Оболочка вместо перекраски

Общие навигация, логотип, шапка, размеры текста, основной и второстепенный
контролы должны совпадать с лесом. Новую визуальную систему не придумывать.
Таблица/список — для выбора файла; рабочая область — для просмотра содержимого.
Не вкладывать карточку в карточку для каждого уровня каталога.
Не оставлять второй язык дизайна внутри детали набора и модальных окон.

В Light нет сметного сценария. Статусы сметной базы, доменные мастерские,
низкоуровневые параметры RRF/dense/sparse и сырой протокол допуска не входят
в основной экран пользователя. Необходимая диагностика доступна отдельно;
её отсутствие на главном экране не означает удаления механизмов RAG.

## Последовательность замены

1. Согласовать данные: временные файлы, счётчики, готовность, причины отказов.
2. Общая оболочка и компоненты по эталону леса: навигация, шапка, поиск,
   список, просмотр, форма, обратная связь. Проверить адаптивность и возврат.
3. Перевести целиком сценарий «Данные → файлы → оригинал → назад», затем
   «Чат → источники → оригинал → назад». Не считать один изменённый экран
   завершённым сценарием, если следующий открывает наследованный интерфейс.
4. Подключения моделей, проекты, память, скиллы и почта используют ту же
   оболочку. Старые реализации убирать из доступных Light-маршрутов после
   проверки замен; физическое удаление зависимостей — отдельная задача.
5. Подтвердить установленный результат; только затем готовить полный установщик.

## Границы доказательств

Нужны тесты согласованности между API/представлениями, проверки отказов
и завершённых сценариев, а не только наличие CSS-класса или русской строки.
Количество тестов не является оценкой качества продукта. Проход HTTP не
является визуальной приёмкой. Запрет Computer Use сохраняется; непроверенное
в установленной геометрии явно отмечать, использовать присланные снимки.

Открытые дефекты и правила продолжения — docs/UI_CONTINUITY.md.
Промпты модели, профессиональные решения и память не менять под видом
фронтенд-рефакторинга. GitHub не публиковать без отдельной команды.


## Уточнение владельца 03.10.2026: простой и дружелюбный ЛЕС

Основной путь — подключить модель, добавить папку и задать вопрос. Обнаружение
запущенных локальных движков и список моделей выполняются автоматически;
назначение модели остаётся явным. Совместимый API подключается коротким мастером.
Диагностика, адрес Qdrant и ручные параметры находятся в дополнительных разделах.
При подключении папки видимый переключатель включает дальнейшее автообновление.
Технические термины и множество мелких настроек не должны быть условием работы.

Ответ сопровождают читаемые ссылки с настоящим названием документа и доступным
локатором. Нажатие открывает цитату и оригинал. Доказывать утверждения источниками
должен ЛЕС. Нельзя выдавать присутствие файла или статус INDEXED за готовность
поиска без проверки фрагментов и действующего индекса. Дружественный интерфейс
не скрывает отказ, не выдумывает уверенность и сохраняет введённое при повторе.

## Уточнение владельца — 3 октября 2026

«В лесу нельзя заблудиться. Лес помнит. Лес знает. Лес не врёт. В лесу красиво».
Основной путь: установил → подключил модель → добавил датасеты → создал проекты → работаешь.
Qdrant входит в пакет и управляется приложением. Пользовательские папки — read-only;
индекс, база, извлечённый текст, память и временные файлы только в состоянии Леса.
Автообнаружение моделей, обновление папок и контекст не требуют технического пульта.
Настройки для специалистов раскрываются отдельно. Проверять кириллицу, смешанные
языки, BOM и старые кодировки, пробелы и спецсимволы в путях; оригиналы неизменны.
