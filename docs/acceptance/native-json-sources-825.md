# Кандидат 825: JSON/JSONL без Python-парсера и ложных фрагментов

Состояние: исходники и изолированные регрессии. Рабочая установка не заменена,
существующие JSON в рабочем индексе автоматически не пересчитаны.

Итоговый прогон замороженного кода: `make verify` — 1829 collected;
`make test` — **1826 passed, 3 skipped**, 18 subtests, 254,28 с.
Пропуски: POSIX reuse, macOS supervisor и необязательная offline embedding spec.
Rust core/API с Edge/runtime — **63/10/7** тестов. Целевые проверки JSON,
Unicode, адаптеров, нарезки, почты, подготовки узлов и партии — **126 passed**;
дополнительные потоковые Unicode/legacy-сценарии — в итоговом общем прогоне.
`make public-check` и `git diff --check` завершились успешно. Эти проверки
не заменяют установочный пользовательский путь, новую обработку рабочего
корпуса и приёмку чистой Windows.

Проверены через настоящий C ABI:

- произвольные ключи, числа, нули, false, массивы, вложенные поля и длинный текст;
- читаемая ошибка повреждённого JSON/JSONL с позицией, отказ пустым данным;
- остановка до encode/publication и `ERROR` в каталоге вместо фрагмента `[ERROR]`;
- сохранение настоящих слов `[ERROR]` в пользовательских данных;
- порядок записей, автоопределение нескольких JSON-значений и явная пометка лимита;
- буквальные NaN/Infinity с пометкой совместимости;
- UTF-8 BOM/UTF-16/UTF-32, совместимый CP1251 и сохранность исходных байтов;
- UTF-8 JSON больше 8 МиБ без вызова прежнего декодера;
- передача большого Unicode-результата и legacy-текста частями без порчи символов;
- запрет записи из читателя, неизменность папки исходника;
- отказ скану без извлечённого текста вместо поискового узла «нужна OCR».

В начальном формате/диспетчере и определении legacy-кодировок ещё остаётся
Python. Общий runtime, специальные обработчики, API/bootstrap/classic и
конечная автономная поставка старых навыков не закрыты этим шагом.
Нужен отдельный переход прежних JSON-индексов на новый парсер. До завершения
общего переноса и приёмки очистка исходников, push и merge не выполняются.
