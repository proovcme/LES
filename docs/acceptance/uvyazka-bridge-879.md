# Кандидат 879: источник Увязки в LES

Изменены исходники LES и приёмник ссылок во вьювере Увязки. Рабочая пара
приложений, пользовательский индекс и MCP не переключались. Это не релиз.

## Проверенный путь

В отдельном временном проекте создан синтетический DXF и прочитан настоящим
`ezdxf` через `ModelData` Увязки. Её обычный HTTP API отдал снимок Rust-адаптеру
LES. Сверены состав объектов и ID; снимок попал в общую очередь импорта.
Оригинал до специально внесённого изменения сохранил прежний SHA-256.
Ссылка во вьювер несла проект, снимок, точный object ID и SHA оригинала.
После изменения DXF старый снимок не импортировался повторно, ссылка была
заблокирована. После остановки тестового сервиса получен отдельный отказ
доступности. Временные проект/состояние и дочерние процессы закрыты.

**Это не проверка выдачи RAG:** в этом проекте не назначались модели и не
публиковался поисковый индекс. Проверены чтение, обмен, очередь и защита редакции.
Сохранённый объект не объявляется найденным семантическим поиском по этому опыту.

## Автоматические границы

- Rust-адаптер: все разделы, пустая страница с продолжением, Unicode-порции
  объекта, точные счётчики, отказ при смене оригинала или недостающих объектах.
- Настоящий Rust-обработчик JSON-проекции и окончательная подготовка узлов:
  native ID и исходная редакция переживают нарезку; родительские/соседние окна
  не смешивают разные объекты. Неполная проекция не индексируется как обычный JSON.
- Компоненты: явное подключение, выбор проекта, очередь вместо ложной готовности,
  сброс старой ссылки при смене адреса, недоступная Увязка → установка с GitHub
  и повтор. Скачивание/исполнение установщика не выполняется.
- Приёмник Увязки: правильный проект/SHA/native ID, отказ от неоднозначной
  подсветки, точное отображение больших целых свойств, TypeScript и сборка кандидата.

Для источника требуется совместимый собранный вьювер с маркером возможностей.
Старый установленный выпуск не считается обновлённым по наличию исходников.

## Не принято

Сквозной установленный переход из результата RAG в подсветку реальных DWG/RVT;
качество поиска/генерации по инженерным моделям; покрытие всех версий форматов;
визуальная и клавиатурная приёмка пары окон; автоматическая синхронизация;
модели выше лимита первой версии. Установка GitHub-выпуска человеком также
не выполнялась — проверен доступный переход к официальным выпускам и инструкции.

Текущий этап импортирует уже созданные в Увязке снимки. Запуск первичного чтения
зарегистрированного файла прямо из формы LES требует следующего явного действия
подключения, без скрытого включения инструментов записи стороннего MCP.

## Проверки исходников

Core: 139; API с Edge: 99; runtime: 8; frontend: 52. Приёмник Увязки:
четыре проверки идентичности/порций/ошибок, TypeScript и отдельная сборка.
После последнего уточнения отказа доступности повторены три теста адаптера,
runtime, форма и синтетический DXF-путь на пересобранном API.

`make verify` собирает 2217 случаев. Полный `make test` был остановлен
проверкой упаковки: форма изменилась во время прогона, паспорт статического UI
стал устаревшим. До неё прошли 1450 случаев, два пропущены. После пересборки UI
повторена упавшая проверка и все следующие файлы исходного набора:
765 passed, 18 subtests passed. Итого выбранный набор покрыт двумя частями;
это не выдаётся за один непрерывный зелёный запуск `make test`.
Проверка публичных файлов пройдена. Числа характеризуют только этот набор,
а не качество поиска или поддержку всех инженерных файлов.
