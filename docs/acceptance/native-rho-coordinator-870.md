# Rho в основном координаторе — кандидат 870

Проверяется отдельная копия корпуса. Рабочее приложение, его индекс и
назначения моделей не переключаются. Это приёмка исходников и отдельного
локального API, не установленной пользовательской версии и не релиза.

## Что заменено

Rho SDK 5.15.2 исполняет последовательность модель → инструменты → модель
в основном Rust API и совместимом ABI. Старые agent_loop, его runner/answer,
отдельный счётчик harness и Python HarnessLoop удалены. Python-модуль с
допуском доказательств переименован по его оставшейся ответственности;
он не планирует вызовы.

[Границы координатора](../modules/native-rho-coordinator.md) сохраняют
существующих владельцев контекста, таблиц, памяти, областей доступа,
редакций, PDF и цитат. История вызовов берётся из Rho; отдельного журнала
планирования в API больше нет. Завершение ответа допускается только после
проверок LES и окончательного EndTurn SDK.

При переносе обнаружены и исправлены две причины повторных действий:
результат эффекта мог подтверждаться до обновления эпохи таблицы, а новая
эпоха памяти разрешала повторить уже выполненную запись. Фиксация состояния
теперь синхронна до подтверждения, идентичная запись связана с неизменяемыми
аргументами/ожидаемой ревизией; повторное чтение после изменения разрешено.

Внутренние курсоры зарегистрированы по происхождению, а не распознаются по
префиксу call_id. JSON-выбор старого модельного протокола не превращается
в выдуманные native tool_calls. Исходный native call_id и аргументы
предложения сохраняются в канонической истории.

## Проверки исходников

- 115 тестов Rust-ядра и 68 Rust API прошли.
- 58 целевых нативных интеграций поиска/чата прошли без пропусков: контекст,
  OCR-происхождение, курсор PDF, редакции, цитаты, поток и ошибки истории.
- Отдельные ABI-проверки исследовательского цикла и реальной записи USER.md
  прошли; повтор эффекта не создаёт второе изменение истории.
- `make verify` прошёл, собраны 2179 тестов.
- `make test`: 2177 прошли, 2 пропущены, 18 subtests прошли. Пропуски —
  POSIX-семантика TCP и macOS lifetime supervisor на Windows. Это не
  пропущенные нативные проверки Rho или документов.

Модели и веса не загружались автоматически. Автономный интерпретатор внешних
Python-навыков сохранён; сборка не требует от него координировать приложение.

## Реальный Qwen на копии

Повтор основного `/api/chat` с прежней Qwen3.5:9b выполнен на тех же
39 контрольных вопросах: 20 прежних точечных, 15 отложенных и четыре
обзорных. В запрос передаются вопрос и два набора документов, без doc_id,
имён выбранных файлов и эталонного ответа. Индекс и embeddings не меняются.

| Группа | Запросы | Ответ HTTP 200 | Остановка проверкой |
|---|---:|---:|---:|
| Обзорные | 4 | 4 | 0 |
| Отложенные точечные | 15 | 14 | 1 |
| Прежние точечные | 20 | 20 | 0 |

Один запрос остановлен с SOURCE_CITATION_MISSING; ошибки runtime Rho не
обнаружены. В 235 записях source_map сохранены doc_id/dataset_id/SHA-256,
117 записей имеют локатор физической страницы. Это записи выдачи по всем
запросам, не 235 уникальных документов и не оценка Recall. Поколение Edge
и контрольная сумма BM25 после прогона совпадают с исходной копией.

18 ответов совпали с сохранёнными ответами предыдущих кандидатов буквально;
это диагностический счётчик, не доказательство полного паритета. Сравнивается
не одна заново исполненная старая сборка, а сохранённые результаты 867/868.

Успех HTTP и метка `source_rows_verified` не считаются правильной или полной
справкой. Ни один из четырёх обзорных запросов не дал готовой справки:
подборка точных выдержек и два ответа о недостаточности вместо синтеза.
В числовом случае прежняя остановка TABLE_VALUE_INVALID сменилась точной
цитатой другого варианта/стадии документа. Это не доказательство правильного
выбора редакции и не засчитывается как улучшение качества. Защита SHA-256
и ссылки не заменяет проверку соответствия стадии вопросу.

Выполнены ещё три реальные SSE-проверки без выбранного файла: Search/Hybrid,
Search/Pull и Agent/Pull. Во всех единственный финал совпал с опубликованными
фрагментами текста. В Agent/Pull прошёл настоящий search_sources и 111
событий токенов; первый — через 2,927 с. В Search-режимах публикуется один
проверенный блок после проверки, а не неподтверждённый черновик.
Эти числа не являются сравнительным тестом скорости.

Ни в одной из трёх дополнительных проверок Qwen не вызвал read_pdf_source,
несмотря на прямую просьбу проверить оригинал PDF. Agent/Pull ограничился
неудачным поиском и сообщением об отсутствии найденных документов. Это
незакрытая проблема выполнения поручения и достаточности поиска; реальное
дочитывание PDF с Qwen в основном чате в этой серии не подтверждено.
Реальные страницы/курсоры, смена редакции и остановка после ошибки чтения
прошли нативные интеграции с управляемым поставщиком модели; их нельзя
выдавать за успешное выполнение той же задачи настоящим Qwen.

Перенос координатора подтверждён тестами, но приёмка качества RAG/читателя
и общего агента остаётся открытой. Рабочая установка не переключена.
Проверенный отдельный API после серии остановлен своим контроллером.

## Остальные готовые компоненты

[Сверка и отдельный пробник](../modules/native-component-candidates.md):
text-splitter прошёл 76 базовых проверок с нашим токенизатором. FastEmbed
собран отдельно, но не принят из-за несовместимости с имеющейся ORT DLL;
численного паритета нет. Xberg является продолжением Kreuzberg; Docling.rs
— полноценный Rust-порт для отдельного сравнения структуры. Эти парсеры
и новый ML-backend не подменяют действующий конвейер в этом кандидате.

## Временные данные

Повторно использован один Cargo target, incremental отключён. Второй индекс
для этой приёмки не создавался: использована прежняя изолированная копия.
Сохраняются компактные журналы и результаты вне публичного репозитория.
Автоматическая проверка безопасности отклонила удаление собственных
завершённых каталогов rho870-gate/rho870-target; они остаются на диске.
Удаление не повторялось другим способом. Свободный запас превышает 20 ГиБ.
