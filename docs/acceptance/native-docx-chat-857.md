# Кандидат 857: выбор читателя и точная часть DOCX в чате

Проверяются Rust-исходники и отдельный экземпляр API на прежнем испытательном
Edge/SQLite. Рабочая установка, назначения моделей, исходные папки и её индекс
не меняются.

## Воспроизведённые проблемы

После приёмки 856 выполнены два вопроса в Push и Hybrid с уже назначенной
локальной Qwen3.5:9b: прямой факт с титула и чтение конкретного рисунка,
у которого нет OCR-текста. Всего четыре ответа на каждом этапе, не независимая
широкая оценка качества RAG.

Первый Hybrid показал `read_pdf_source` для выбранного DOCX и завершился
`PDF_SOURCE_INVALID`. При малом окне схем универсальный `read_source` оставался
за инструментом раскрытия. После изменения порядка схем модель смогла читать
части Word, но выбрала хеш соседнего изображения и выдала его надпись за надпись
запрошенного. Правильная ссылка на документ сама по себе эту ошибку не ловила.

## Изменение

- Для явно выбранных не-PDF и смешанных файлов `read_source` доступен в
  начальном окне схем. Для выбора только PDF приоритет физического читателя
  сохраняется. Права, лимит вызовов и доступ через раскрытие не меняются.
- `read_source` 1.2 принимает `view=part` и точное `member` из manifest.
  Имя сравнивается буквально; оно не превращается в путь файловой системы.
  Можно выбрать оригинал без копирования SHA-256. Старый `part_id` совместим.
- Если указаны имя и хеш, они должны относиться к одной части или её видимому
  представлению. Неизвестное/неоднозначное имя и несовпадающий хеш дают явную
  ошибку. Одинаковые байты у разных имен не переименовывают выбранный объект.
- Результат сообщает точное имя части и запрещает объявлять соседние имена
  псевдонимами. Пустой OCR возвращается пустым. Навигация по частям не становится
  фактическим доказательством и не пополняет карту источников.
- Ошибка чтения по-прежнему останавливает цикл до следующей генерации;
  человекочитаемая причина и код сохраняются в истории.

## Контрольный повтор

На том же индексе и тех же байтах Qwen верно вернула год и шифр с титула в обоих
режимах. Для непрочитанного рисунка Push указал ограничение; Hybrid прочитал
именно запрошенный `member`, получил пустой OCR и сообщил о необходимости
визуальной проверки. Соседнюю надпись в этом повторе не подставил.
Финальный повтор после сборки сохранил тот же результат. Ссылки на оба
оригинала и байты выбранной части проверены через HTTP по SHA-256.

Эти четыре ответа не доказывают отсутствие всех галлюцинаций, понимание схем
или смысловую правильность каждой цитаты. Совместимый вызов только по хешу
по-прежнему требует от клиента выбрать правильную часть. Ограничения OCR из
[приёмки 856](real-corpus-856.md) сохраняются.

## Регрессии и границы поставки

Целевые проверки API/чата/частей и режимов поиска: 31 passed, 1 skipped.
Проверены точный объект с пустым OCR, отсутствие текста соседа в сообщении
модели, остановка после несовпадения и сохранение причины в истории. Это
контролируемые данные для идентичности, не тест точности OCR.

Финальные проверки после сборки:

- Rust API с Edge: **20 passed**.
- `make verify`: версии, карта кода, контракт API и синтаксис; **2 115 collected**.
- `make test`: **2 113 passed, 2 skipped**, 44 предупреждения,
  18 subtests passed, 807,33 с. Включены проверки папок/SMB, падения публикации,
  истории, памяти и автономного исполнителя внешних навыков.
- Повтор живой Qwen на финальном debug API: четыре HTTP 200; прямой факт
  верен в Push/Hybrid, для рисунка без OCR оба ответа обозначают ограничение.
- Исходники Rust форматированы, договор версии синхронизирован; локальные
  ссылки документации проверены. Успешные тестовые каталоги очищаются после
  закрытия ресурсов. На завершении оставалось около 29,6 ГиБ свободного диска.

Установщик, установка, нативное окно пользователя и публичный выпуск этим
проходом не проверяются. Оптимизированная сборка 856 не объявляется сборкой 857.
