# Embedding: контекст, память и повторные запросы — кандидат 762

Дата: 2026-10-11. Apple M4, 24 ГБ. Испытание выполнено в отдельном установленном
Mac preview с авторским синтетическим набором. Рабочие назначения моделей,
пользовательский индекс, история, галерея, промпты и постоянные журналы не читались
и не заменялись. [Измерения и квитанции](embedding-762-results.json).

## Изменение

Подключение локальной Ollama получает `native_embedding_v1` только после живой
проверки ответа `/api/embed`. Совместимый путь сохраняется для остальных
подключений и при неподтверждённом нативном протоколе. Во время выполнения
ошибка нативного запроса не приводит к скрытому повтору через другой протокол.

Нативный запрос передаёт выбранный эффективный лимит контекста, `truncate=false`
и управление резидентностью. Последний пакет поискового запроса освобождает
модель; при индексации она остаётся загруженной между пакетами до 60 секунд.
Пакеты по 16 текстов и разделение только при превышении размера ответа сохранены.
Превышение контекста возвращает ошибку, без обрезки исходника или переиндексации.
[Договор API Ollama](https://docs.ollama.com/api/embed).

Кэш запросов — только в памяти: до 128 записей, до 8192 значений на запись,
срок 60 секунд. Ключ содержит хэши подготовленных текстов, ревизию подключения,
endpoint, модель, снимок возможностей, эффективный профиль и размерность индекса.
Перед lookup проверяется доступность назначения. Ошибки не кэшируются; ответы
возвращаются копиями. Документы, поисковые результаты и ответы модели не кэшируются
этим механизмом: поиск читает актуальное поколение индекса.

## Измерения

На прежнем совместимом пути qwen3-embedding:0.6b занимал 5 776 426 925 байт
с контекстом 32768. При выбранных 8192 — 2 857 191 341 байт: экономия 2,92 ГБ,
около 50,5%. После поискового запроса модель отсутствовала в `/api/ps`.
Число параметров и размерность 1024 не менялись.

На трёх коротких синтетических текстах значения векторов совпали точно. На 20 вопросах
максимальное абсолютное отклонение — 0,000138298, минимальный cosine —
0,9999992412. Побитная идентичность во всех случаях не заявляется.
Через установленный обычный `/api/search` сравнили оба реально проверенных
протокола на том же синтетическом индексе: 20/20 совпадений порядка попаданий
и 20/20 совпадений текстов. Это ограниченная регрессия, не оценка любого корпуса.

Первый поиск по трём вопросам занял 1,6351 / 1,1029 / 0,7068 секунды;
повторный — 0,1115 / 0,1121 / 0,1129. Вектор повторного одиночного запроса
в установленном клиенте получен из RAM за 0,000081 секунды вместо 0,611 секунды.
Эти числа не описывают ускорение всей генерации ответа. Первые вызовы разных
протоколов включали разное состояние загрузки; их время не является чистым A/B.

## Реальный чат и ограничения

Штатный `/api/chat/stream` с локальным текстовым Qwen3.6-35B-A3B-oQ3,
размышлением и бюджетом 2048 завершил вопрос e9 за 36,48 секунды:
«Нет. Согласно [Источник 1], именной билет обмену не подлежит».
Следующий e11 вернул CHAT_MEMORY_PRESSURE. Пороги RAM/swap не снижены;
устойчивую работу 35B на 24 ГБ и её общую точность это испытание не подтверждает.

Шесть endpoint загрузки экрана подключений в установленном кандидате вернули 200.
Причина ранее сообщённой ошибки 404 в настройках не воспроизведена; этот патч
не объявляется исправлением геометрии/кликов или всех ошибок интерфейса.

75 целевых теста прошли; `make verify` собрал 1261 тест; `make test`:
1205 passed, 56 skipped, 18 subtests passed. Хэши четырёх установленных файлов
совпали с исходниками. Полного установщика 762 нет; рабочая установка остаётся
отдельной от кандидата. Смена весов за тем же model ID во время TTL кэша не
обнаруживается автоматически; для управляемой замены нужна новая ревизия.
