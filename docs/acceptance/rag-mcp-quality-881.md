# 881: проверка данных RAG через MCP

Кандидат в исходниках и отдельном экземпляре с исследовательским индексом.
Установленный LES 880, его профиль, назначения моделей и рабочий индекс не
переключались. Оригиналы документов только читались. Приватные запросы,
полные ответы и сверки оригиналов хранятся вне публичного репозитория.

## Метод

Вход — вопросы и два ранее подключённых набора. В поисковые запросы не
передавались эталонные `doc_id`, имена файлов или ожидаемые числа. После
поиска использовались только возвращённые идентификаторы. Чтение проверялось
настоящим JSON-RPC MCP через нативный stdio-сервер, подключённый к API копии.
Это общий читатель чата, а не параллельный тестовый алгоритм.

Основные случаи: состав документации, обзор электроснабжения, количество
оборудования, расходы воды, различия источников и вопрос без подтверждённого
ответа. Дополнительные вопросы — пожарная безопасность, другой вид
оборудования и электрические мощности. Ответная модель не запускалась;
использовалось существующее назначение эмбеддингов, необходимое для dense.

## Причины и исправления

| Причина | Системное изменение | Практическая проверка |
|---|---|---|
| Резервирование лидеров BM25/dense повторно меняло порядок; соседи получали выдуманный ранг по месту в массиве | Лидеры сохраняются в пуле без продвижения наверх; контекст получает исходный `fusion_rank`, а дочитанный сосед вне найденных ID — `rank=null` | Регрессии проверяют сохранение обоих лидеров, убывание исходных оценок и отсутствие ложного ранга у резервного кандидата и соседа |
| Полное представление таблицы заменяло найденный фрагмент вместе с его оценкой и происхождением | Проекция Word/PDF сохраняет исходный score, ранг и якорь; канонический ID чтения остаётся отдельным | Регрессия использует разные ID найденной нарезки и прочитанной единицы, проверяет полный текст, исходный ранг и неизменность поисковой записи |
| Отказ проверки одной PDF-таблицы обрывал весь поиск | Ошибка структуры таблицы изолирует непрочитанную физическую страницу; другие проверенные источники сохраняются вместе с причиной и предупреждением | Два ранее падавших вопроса возвращают непустой частичный контекст; отвергнутые страницы отсутствуют в доказательствах |
| Поиск внутри документа не видел буквенную часть составного слова через дефис | Общий анализатор чтения на Snowball сохраняет полное слово и буквенные компоненты; версии postings и dense не меняются | Реальная строка с составным названием доступна по отдельному слову; синтетические проверки сохраняют неделимые числовые коды и десятичные значения |
| Исчерпание совпадений принималось за чтение всего документа | Общие `reading_scope`, `document_fragments`, `matches_exhausted`; выборка по вопросу/пункту не получает полное покрытие | Выборка строк книги содержит меньше единиц, чем документ; конец совпадений явно отделён от полноты документа. Word проверен тем же контрактом |

Проверка PDF-таблиц **не ослаблена**. Независимое чтение оригиналов показало
ошибки проекции: линии оформления склеиваются с содержимым, отдельные ячейки
разделяются неправильно. Неподтверждённая геометрия остаётся ошибкой, а не
исправляется догадками или заменой индексным OCR.

## Проверенные границы доказательств

- Для 38 уникальных ссылок из окончательного и дополнительных прогонов сверены
  зарегистрированный оригинал, SHA-256, адрес документа и страница PDF.
  `HEAD` ссылки возвращает размер именно этого оригинала.
- Для шести найденных строк одной книги количество и единица независимо
  сверены с исходными колонками XLSX по листу и номеру строки. Число,
  встретившееся где-то на листе, не считалось подтверждением строки.
- Чужая контрольная сумма, неверная страница и несовместимый датасет
  отвергаются MCP; отказ не подменяется успешным чтением другого источника.
- Физическая ошибка страницы сохраняется в `read_failures`; успешная другая
  страница того же документа допускается отдельно. При частичном чтении
  сохраняются предупреждение и неполное покрытие.
- MCP и источник API чата дали одинаковые строки, область чтения, поколение
  индекса и идентичности цитат на окончательном бинарнике.

## Незакрыто

Сравнение уже имеющихся RRF/DBSF на одинаковых вопросах показало, что сама
смена формулы не устраняет посторонние источники. На копии восстановлены
исходные настройки RRF; рабочий профиль не менялся. Ошибка резервирования
лидеров исправляется в общем механизме, а не настройкой под вопрос.

Эксперимент с удалением делителя стоимости в MMR отклонён: на реальной
выдаче длинная PDF-страница заняла место нужной строки XLSX. Формула
бюджетного отбора сохранена; добавлена отдельная регрессия на конкуренцию
длинного родителя и компактной таблицы. Успешные модульные проверки
эксперимента не считались доказательством качества реальной выдачи.

Автоматический контекст широкого вопроса всё ещё содержит посторонние
разделы и нормативные упоминания вместо полного состава томов. Одна выдача
из ограниченного пула не доказывает полноту справки. Для сравнения редакций
проверена защита идентичности источника, но не принята автоматическая
интерпретация всех различий ПД/РД. Различные SHA-256 сами по себе не задают
отношения «предыдущая/последняя редакция».

OCR помечается непроверенным для чисел. Корректная ссылка не доказывает
правильное прочтение каждой цифры и связи числа со строкой сканированной
таблицы. Вопрос без подтверждения не получил доказанный ответ; это не
доказывает отсутствие сведений во всех непрочитанных документах.

Холодное автоматическое дочитывание основных случаев заняло примерно
18–98 секунд, дополнительных — 21–30 секунд. Ускорение всего конвейера
не объявляется: некоторые оригиналы снова достигают таймаута чтения.

Проверки: core — 141; API без Edge и с Edge — по 106; `make verify` —
2218 собранных тестов; полный `make test` — 2216 passed, 2 skipped,
18 subtests. После окончательных изменений раскрытия отдельно прошли
70 профильных проверок читателей, MCP/CLI, чисел и представления источников.
Первый общий прогон остановился на устаревшей сборке интерфейса после смены
номера; интерфейс пересобран, общий прогон повторён успешно.

Отдельный офлайн-эксперимент с уже имеющимися весами BGE-reranker-v2-m3
переставлял только полученные MCP-фрагменты. На вопросе об оборудовании
посторонняя сантехника ушла с первого на последнее место; состав томов
этот эксперимент не восстановил. Обработка нескольких готовых фрагментов
занимала около 4–6 секунд на CPU. Это не весь пул поиска, не проверка
истинности и не подключённый этап приложения; Python использовался только
в отдельном исследовательском процессе. Модели приложения не назначались.

Успех регрессионных проверок не закрывает перечисленные ограничения
качества. Визуальный интерфейс и установленный экземпляр этим прогоном
не принимались.
