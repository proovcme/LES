# Как ЛЕС 935 передаёт модели ответ из папки

**Решение по результату опыта.** В случае с Alpha item индекс нашёл нужную строку, а ЛЕС отправил её целиком. Упрощение сообщения вернуло модели способность прочитать число. Для замены обычного чата требуется ещё надёжно выбрать столбец и единицу в рабочих книгах. В этом опыте такого результата достичь не удалось.

## Один вопрос, одни источники, одна модель

В изолированной копии проиндексированного набора 935 повторили вопрос «Какое количество Alpha item указано в реестре? Укажи единицу и источник». Локальный ретранслятор передал байты обычного запроса ЛЕС в Ollama и записал тело первого сообщения. В положительном случае все четыре источника, их номера, порядок и отпечатки совпали с журналом первоначальной установки. Подлинность оригиналов проверена по SHA-256. В отрицательном случае из цифрового PDF удалены все четыре ячейки строки, рядом оставлены строка Beta item и прежняя текстовая заметка про Alpha item. Изменённая папка прошла индексацию BGE-M3 и тот же Hybrid-чат. В полном входе отрицательного случая число 17.25 отсутствует. [Первоначальный опыт](../folder-install-935.json) · [Запрос с фактом](present.json) · [Запрос после удаления строки](removed.json)

Исходный вызов ЛЕС в обоих случаях дошёл до конца. При наличии строки ЛЕС показал ложный отказ. Следующие серии повторяли **первый** запрос к Qwen3.5:2b через локальный Ollama с тем же окном 32768, температурой 0.1 и выключенным thinking. Для каждой формы заданы seeds 17, 29 и 43. Один вызов инструмента учтён как запрос следующего шага. Продолжение диалога в этих сравнениях не выполнялось. Три повтора одного вопроса характеризуют устойчивость на примере.

| Что видела модель | Когда строка есть | Когда строка удалена |
|---|---|---|
| Полное сообщение 935, 1828 входных токенов при наличии факта | 3 ложных отказа | 3 отказа |
| Только заголовки и правильная строка, 114 токенов | 3 раза нашла число. В одном ответе противоречиво описала единицу | 3 отказа на одних заголовках |
| Четыре короткие выдержки, 154 токена | 3 раза нашла число и сослалась на №1. Один ответ назвал штуки, другой опустил единицу, ещё один написал «единиц» | 3 отказа по смыслу |
| Те же короткие выдержки и оба исходных инструмента, 819 токенов | 3 ответа с 17.25, pcs и ссылкой №1 | 3 обращения к инструменту |
| Четыре выдержки и текстовая инструкция вернуть номера столбцов | 3 неверных выбора, в том числе столбец 17 при ширине 4 | 3 ответа вне договора |

Значение проверено по смыслу утверждения. В одном полном сообщении модель процитировала 17.25 внутри объяснения отказа и назвала количеством 1. Поиск подстроки дал бы ложноположительный результат. Отдельно по одному менялись последняя инструкция, оформление строк и наличие инструментов. Каждое из этих трёх изменений по отдельности оставило три ложных отказа на положительном вопросе. Таким опытом можно локализовать сбой на чтении переданных данных, но нельзя приписать его одному конкретному полю промпта. [Ответы по пяти вариантам](trials.jsonl) · [Проверки трёх отдельных изменений](components.jsonl)

## Проверка на оригиналах Excel

Из сохранённого хода рабочего чата взяты две строки из двух разных XLSX одного набора. Файлы открыты локально в режиме чтения, отпечатки сверены с источниками. Обе строки читались с заголовками из оригиналов. По каждой позиции был новый вопрос о количестве и единице. Затем в переданном модели наборе убирали целевую строку целиком и отдельно убирали только её единицу. Рабочие XLSX не редактировались и не переиндексировались. Этот опыт проверяет чтение известных строк. Доля правильных ответов по всему рабочему архиву остаётся неизвестной.

Каждый вариант получал те же строки. Программа сверяла строку, обе ячейки и источник. Для положительного результата обязательны количество, исходная единица и номер правильной строки-источника. Для отрицательного результата обязателен явный отказ. Если формат ответа нарушен или адрес недопустим, это ошибка чтения. Верно оформленный выбор чужой строки тоже считается ошибкой.

| Способ передачи ответа | PDF с фактом | PDF без строки | Excel с фактом | Excel без строки | Excel без единицы |
|---|---:|---:|---:|---:|---:|
| Адрес строки и буквы столбцов по JSON-схеме | 0/3 | 0/3 | 0/6 | 0/6 | 0/6 |
| Дословные значения и номер источника по JSON-схеме | 0/3 | 3/3 | 0/6 | 6/6 | 0/6 |
| Дословные значения и номер источника одной строкой, с коротким примером | 3/3 | 3/3 | 0/6 | 2/6 | 0/6 |

У первого способа модель могла выбрать допустимые адреса в чужой строке. Во втором и третьем способах проверка находила обе цитаты в одной исходной строке, проверяла их однозначность и возвращала оригинальные значения. На действительных строках Excel третий способ шесть раз отверг ответ по формату или из-за несовпадения с ячейкой. Один пример — модель скопировала всю строку с описанием позиции. Поэтому результат 0/6 означает отсутствие готового проверенного ответа. Он не означает шесть выдуманных моделью чисел. Общие журналы содержат только результаты и технические адреса. [Адреса ячеек](cell-transfer.jsonl) · [Цитаты по схеме](literal-transfer.jsonl) · [Дословный ответ с примером](quote-transfer.jsonl)

## Обычный текст

Короткий вариант получил шесть прежних вопросов по двум другим папкам, в том числе с отсутствующим фактом, частичным ответом и сменой редакции. Использованы тексты первой фактической выдачи и её порядок из прежнего опыта. В каждом из трёх повторов правильные факты и требуемые ссылки были у пяти вопросов из шести. В частичном ответе модель все три раза верно указала температуру и отсутствие срока, но пропустила ссылку на температуру. Номера ссылок проверены нативным обработчиком цитат 935. В предыдущем полном прогоне на этих шести вопросах ЛЕС дал 3/6, два варианта LlamaIndex — по 4/6. Текущее сравнение короткого текста с предыдущим прогоном не является повтором трёх движков при идентичных условиях. [Ответы по текстам](prose.jsonl) · [Исходные вопросы, порядок выдачи и результаты предыдущего сравнения](../folder-transfer-935.json)

## Что менять следующим

1. Для обычного ответа по тексту передавать вопрос и подтверждённые выдержки с номерами. Проверять каждый подтверждённый пункт частичного ответа, включая ссылку.
2. Для таблиц испытывать табличный запрос над оригиналом. Входом служат условие выбора записи и имена возвращаемых полей. Программа привязывает их к реальным заголовкам, проверяет число подходящих строк и читает значения с адресами ячеек. Отдельно проверить неоднозначные заголовки, повторы позиций и пустую единицу. Текущие три прототипа ещё не решают задачу выбора полей по произвольному вопросу.
3. Сравнивать кандидата с 935 через обычный чат по папке, открывая ссылку на оригинал. Расширить серию независимыми рабочими папками с таблицами и абзацами. Основанием для переключения считать повторяемое улучшение по фактам, ссылкам и корректным отказам на новых данных.

## Повтор опыта

Из корня репозитория при уже доступном локальном Ollama и установленной Qwen3.5:2b следующие команды пишут результаты в новые файлы. В репозитории есть оба синтетических PDF, заметки и точные тела двух первых запросов провайдеру. Чтение личных файлов по умолчанию отключено.

```powershell
python -m tools.evaluate_folder_window --output trials.jsonl
python -m tools.evaluate_folder_window --arms question_only plain_evidence no_tools --output components.jsonl
python -m tools.evaluate_folder_window --prose --output prose.jsonl
python -m tools.evaluate_folder_tables --reader cell --output cell.jsonl
python -m tools.evaluate_folder_tables --reader literal --output literal.jsonl
python -m tools.evaluate_folder_tables --reader quote --output quote.jsonl
```

Для сравнения на своих оригиналах у последней группы команд есть параметр `--workbooks local.json`. Локальный файл задаёт массив `rows`. Для каждой строки нужны `path`, `sha256`, `sheet`, `row`, `header_row`, `max_column`, `source` и буквенные `item_column`, `value_column`, `unit_column`. Номера строк и столбцов начинаются с единицы. Последние три поля служат построению вопроса и сверке с эталоном. Модель видит все непустые подписанные ячейки строки. Журнал фиксирует исход проверки без текстов рабочих вопросов и ответов.
