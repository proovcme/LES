# Кандидат 820: Edge, BM25 и эмбеддинги

Проверено на отдельной копии реального индекса. Рабочий LES, его назначения
моделей и исходные документы не изменены. Закрытые экспорты и результаты
по отдельным документам находятся вне репозитория и не публикуются.

## Полученные результаты

- Перенесены 43 219 точек. Проверены все UUID/payload, dense/sparse-векторы
  с допуском 0,000001. Исходный экспорт остался неизменным.
- Жёсткая остановка после 256 записей: продолжение с подтверждённого курсора,
  полная последующая сверка. Прерванное хранилище не принимало запросы.
- Жёсткая остановка во время BM25 на наборе 8192 точек: повторная публикация
  postings, затем успешный гибридный запрос. Половина индекса не объявлялась готовой.
- Rust-проверка смены редакции: пересчитаны только два фрагмента изменённого
  файла, второй файл не перерабатывался; незавершённая публикация и старый
  stamp отвергнуты. Проверен фильтр с дробными границами диапазона.
- BGE-M3, 32 текста: максимальное расхождение компонентов с прежним
  SentenceTransformer 0,000000884; минимальное cosine-сходство 0,99999952.
  На реальной копии Top-10 совпал во всех 32 запросах.
- Общая цепочка через Rust API без Python backend и Qdrant Server:
  8 результатов, 8 родительских разделов, 48 фрагментов. Время первого
  запроса 6,47 с с проверкой/загрузкой модели, повторных 0,94 и 0,96 с.
  Это измерение конкретного запроса; не SLA и не оценка качества всего корпуса.
  Повтор на финальном API: 5,19 с холодный запрос и 1,38/1,38 с повторные.
  Ускорение локального эмбеддера по этим замерам не заявляется.
- Локальный исполнитель повторно использован, затем аварийно завершён
  адресно; новый процесс дал те же векторы. Несовпадающая модель и ревизия
  отклонены без HTTP fallback.
- Канонические эмбеддинги Ollama/OpenAI с фиктивными ключами прошли после
  остановки совместимого Python backend. Заголовки, роль, модель и тело
  запроса принадлежат Rust; отключённое подключение остановило запрос.
- Unicode сверён с независимым прежним oracle: изменяемые символы Unicode
  15.1, Hangul, случайные комбинации диакритики, нормализация и casefold.
- Холодный запуск Rust API после убийства владельца Edge: staging откатан,
  committing завершён, прерванный BM25 перепубликован. Без Python backend.
  При отсутствии записи документа или новой точки API сохраняет журнал,
  возвращает точную причину и оставляет доступной страницу профилей.
  Пять сценариев выполнены отдельными настоящими процессами.
- Нативные профили пережили создание, привязку к разговору, удаление библиотечного
  текста и перезапуск API; привязанный снимок не изменился. Проверена совместимость
  прежних сценариев и числовых полей, включая Unicode-цифры и огромные значения.
- Шесть файловых инструментов используют Rust; проверены отказ выхода из корня,
  настоящая Windows junction наружу, Unicode, хеш, предупреждение о кодировке,
  неизменность исходника и остановка ответа после неудачного чтения.

Целевые проверки: Rust core 53, API 9 с Edge и 9 без Edge, vector 3;
миграция — 4 passed; холодное восстановление Edge — 5 passed.
`make verify`: 1744 теста собраны. Общий поведенческий прогон: 1741 passed,
3 skipped, 18 subtests passed. Новые профили, файловые операции и восстановление
входят в этот прогон. Два пропуска — платформенные POSIX/macOS проверки на
Windows. Третий — ML-тест без параметра ресурса в общем прогоне; он отдельно
повторён с настоящим offline BGE-M3 и прошёл: reuse, запрет чужой ревизии,
адресное убийство исполнителя и повторный запуск с теми же векторами.

Совместимый HTTP-путь чтения точек также проверяет поколение до и после
операции. Во время следующего обновления он не обходит защиту нативного
гибридного поиска; после явного восстановления снова допускает чтение.

## Что этим не принято

Установленная версия не обновлена. Общий цикл чата/исполнителей, оставшаяся
документная оркестрация, сложные OCR/форматы, bootstrap и classic UI ещё
требуют переноса. Все функции чистой установки без общего Python, старые
навыки автономно, MCP/CLI и полный разговор Qwen во время аварии нового
продуктового Edge-модуля этой приёмкой не объявлены проверенными.

Тестовая ONNX Runtime DLL взята из существующего локального окружения.
Перед поставкой её нужно разместить и лицензировать как отдельный нативный
ресурс; путь внутри Python package не является допустимым устройством релиза.

Общие gates фиксируются после завершения текущего набора изменений.
