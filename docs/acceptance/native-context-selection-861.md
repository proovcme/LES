# Кандидат 861: граница страницы не ограничивает чтение

Работа в исходниках и на прежней отдельной копии двух пользовательских наборов.
Рабочая установка, назначения моделей, оригиналы и индекс не переключены.

## Причина и исправление

Поиск верно находил первую страницу небольшого PDF. Но родитель совпадения
представлял только эту страницу. Остальные страницы документа не участвовали
в раскрытии, а свободный бюджет расходовался на другие найденные разделы.
У подтверждённого случая все четыре страницы уже были в индексе и занимали
4898 символов. Это ошибка выбора единицы чтения, а не отсутствие текста.

Теперь общий читатель проверяет возможность перехода от найденного фрагмента
к полному индексированному документу. Проверка ограничена одной порцией
до 33 фрагментов: не более 32 могут попасть в окно. Есть предел текста и
ответа хранилища; большие документы не вычитываются до конца для этой проверки.
Далее один распределитель бюджета выбирает в порядке ранга:

1. Полный документ, если помещается.
2. Иначе совпавший фрагмент.
3. После ранжированных совпадений — полные помещающиеся родители и соседние
   фрагменты с общими прежними лимитами.

Низкоранговый небольшой документ не вытесняет более раннее совпадение.
Правило одинаково для форматов и не распознаёт тему, обозначения или ответ
на контрольный вопрос. Ранжирование Dense/BM25/RRF не меняется.
Явное чтение конкретного пункта не расширяется до всего документа.

Проверка Hybrid выявила второй источник потерь: при учёте схем инструментов
повторение реквизитов на каждой странице и отдельные отчёты о родителях могли
вытеснить уже прочитанную полную единицу. Общие ID/набор/SHA-256 теперь
представляются один раз, местоположение и ссылка — отдельно на каждом блоке.
Покрытие полного документа считается по уникальным фрагментам всей единицы,
а не по независимым родителям страниц. Резервы модели не ослаблены.

Полный выбранный документ передаётся существующему упаковщику как неделимая
единица `les.evidence-unit.v1`. Внутри остаются отдельные типизированные блоки,
идентификаторы, хеши и ссылки физических страниц. Если единица не помещается
в фактическое окно, она исключается целиком с диагностикой; частичный текст
не объявляется полным. Строка вида `[Источник N]` в тексте не создаёт новый
допустимый источник.

Проверки области, текущего поколения, соответствия зарегистрированному
документу и SHA-256 сохранены для всех дополнительных страниц. Полнота
индексированного текста не означает полноту OCR, изображений или верность
вывода модели.

## Проверки

До исправления регрессия с небольшим 12-страничным PDF воспроизвела потерю
продолжения в настоящем публичном маршруте чата. В запросе нет имени файла
или идентификатора документа. Четыре поисковых совпадения не могут сами
покрыть все страницы.

После исправления та же проверка проходит и подтверждает передачу всех
12 страниц и действительных постраничных ссылок в окне 8192 токена.
Отдельно проверены неделимость группы при тесном окне, единственная передача
общих реквизитов, отсутствие ложного допуска цитат из тела текста и подсчёт
покрытия по всей группе. Повреждение хеша страницы продолжения даёт
`INDEX_CHANGED_DURING_SEARCH` до вызова модели; причина сохраняется в истории.

42 модульные проверки Rust API и 41 целевая интеграционная проверка прошли.
`cargo fmt --check` и `make verify` прошли, собраны 2139 тестов.
Окончательный `make test`: 2137 passed, 2 skipped, 18 subtests passed
за 855,73 с. Эта серия выполнена после всех правок кода и целевых проверок.
Первый целевой запуск после пересборки не был проверкой кода: его остановила
проверка несовпадающей квитанции DLL. После записи квитанции фактической
отладочной библиотеки серия пройдена; проверка квитанций не отключалась.

## Qwen на настоящем корпусе

Окончательная сборка проверена на той же копии двух наборов: 638 документов,
82 203 фрагмента. Qwen3.5:9b, окно 8192 и назначенная bge-m3 не менялись.
Пять вопросов переданы в Push, составной вопрос к PDF — также в Hybrid.
В запросах только исходный вопрос и область двух наборов: нет имени файла,
ID нужного документа, номера нужной страницы или ожидаемых значений.
Идентификаторы ожидаемых документов используются исключительно при оценке.

| Проверка | Результат |
| --- | --- |
| Составной PDF, Push | До исправления доходила страница 1; теперь подтверждена передача страниц 1–4 одной единицей. |
| Тот же PDF, Hybrid | После устранения повторной метаинформации страницы 1–4 присутствуют в обоих подтверждённых окнах: 4583/4941 и 6141/6479 токенов. |
| Ссылки | Для страниц сохранены зарегистрированный ID документа, SHA-256, ID индексированного фрагмента и физическая `#page=N`. HEAD оригинала возвращает PDF, HTTP 200. |
| Строка Excel и изменение редакции | Получены основные сведения о строке/листе и изменении. Это контроль соседнего поведения, не приёмка всего ответа. |
| Запрос гарантии и согласования | Нужный вид источника по-прежнему не гарантирован поиском. Выдержки не дают права объявлять просмотренным весь документ. |

В приватном доказательстве сохранены хеши всех реально переданных единиц и
состав источников каждого окна, полные вопросы и ответы. HTTP 200 не является
критерием смысловой точности. Повторы использовались для диагностики отбора,
а не для выбора самого удачного ответа.

## Незакрытая смысловая приёмка

Потеря третьей страницы устранена в этих проверках. При этом Qwen на полном
правильном тексте выдаёт внутренне противоречивые числовые выводы: смешивает
число позиций и количество оборудования, меняет итог внутри ответа.
Например, Hybrid пишет 273, цитируя строку 272, и затем называет другой итог.
Такой ответ не засчитывается как правильный даже при корректной странице.
Добавлять подстановку ожидаемых чисел или особое правило для этого файла
не стали. Происхождение цитаты и семантическая верность утверждения — разные
проверки; второе остаётся открытым.

Полное чтение здесь означает полный индексированный текст документа,
поместившийся в ограничение, а не гарантию полноты OCR, рисунков и вложений.
Для больших документов сохраняется ограниченное чтение разделов; этот
проход не объявляет решённым поиск всех частей произвольного большого файла.
Рабочая установка и публичный выпуск не обновлялись.

Проверки использовали один прежний индекс и один временный каталог. Два
отладочных PDB завершённых модульных тестов удалены после проверки их
принадлежности и успешного результата; рабочие бинарные файлы, модели,
базы и общий кеш сборок целиком не удалялись. Серверы приёмки остановлены.
