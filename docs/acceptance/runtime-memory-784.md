# 784 — память исполнения и native jobs: установленный локальный патч

Установлен и открыт обычным Windows-ярлыком build 784. Проверены кандидат и
установленное приложение, затем удалены только собственные QA набор/проект
через штатное удаление с резервной копией. Полный установщик и публикация GitHub
не выполнялись. [Контракт](../modules/runtime-memory.md),
[остаток Python](../modules/python-exit.md).

## Что изменилось

- Rust владеет SQLite таблицей jobs, переходами и атомарным recovery. Python
  JobService — facade/codec без SQL; старый store/policy находятся только в tests/oracles.
  Большие целые, Unicode и двоичная точность float внутри result сохраняются как JSON-текст.
- Освобождаются временный Qdrant HTTP-пул, недостижимые объекты, простаивающий
  форматный процесс и неиспользуемые Windows heap-кэши. Работающий worker не отменяется.
- Использованная локальная BGE освобождается после порции индексации; внутри
  порции переиспользуется. При нехватке RAM освобождается вызванная Qwen. Перед
  первым ответом можно освободить проверенную назначенную роль, оставшуюся от
  прошлого запуска. Удалённые/custom/auth подключения и чужие model_id исключены.
- HTTP освобождения ограничен 8 секундами, ожидание устойчивой RAM — 5 секундами.
  Допуск остаётся прежним: по умолчанию 4 десятичных GB; при раннем запросе
  очистка и полный допуск проверяются заново. Если памяти действительно нет,
  остаётся понятный отказ, порог не обходится.
- Статус готовности и состояние RAM используют один живой снимок. Кэш с прежней
  нагрузкой больше не создаёт отдельного ложного разрешения/запрета.

## Установленная проверка

В отдельный собственный набор загружены три копии настоящих PDF и контрольный
UTF-8 текст: 4 документа, 1 605 фрагментов. Исходные файлы пользователя
только читались; размеры/mtime проверены. Сразу после индексации обычный чат Qwen
вернул контрольный код и цитату; второй запрос через SSE вернул точное число и
цитату. Проверены token/progress/final, no_changes и готовность следующего вопроса.
RAM после ответов: 4.50 и 4.46 десятичных GB. Ни ручной выгрузки,
ни перезапуска между индексацией и ответами; PID служб совпадают до/после.
В браузере проверены inline-цитата → фрагмент → оригинал с тем же числом →
возврат к сохранённому ответу. Следующий вопрос доступен: после ввода текста
кнопка отправки активна. Проверочный черновик очищен, вкладка закрыта; рабочее
нативное окно осталось в исходном пустом диалоге. Полная визуальная/WCAG
приёмка этим узким путём не объявляется выполненной.

После удаления QA: 337 прежних ID,
324 INDEXED, 13 SKIPPED, 43 217 записей индекса; нет пустых INDEXED.
Назначения моделей, хэш конфигурации и все 17 прежних строк jobs сохранены.
Аудит исходного корпуса healthy, BM25/журнал согласованы; активных заданий нет.
Хэши 19 установленных файлов сверены с замороженным кандидатом.
Резервные копии и обратная замена файлов проверены до применения.

## Проверки и обнаруженные дефекты

make verify и make test: 1587 passed, 2 skipped; почтовый gate 66 passed,
Rust core 30 passed. Отдельно проверены конкурентный слот, busy worker, отмена,
ошибка очистки, SQLite rollback/terminal protection, большие числа/Unicode,
смена живой RAM при устаревшем кэше в обе стороны. Вёрстка не менялась;
проверки frontend предыдущего этапа не считаются новой визуальной приёмкой.

Живая проверка отвергала промежуточные варианты: BGE оставалась в Ollama на 60 с;
Qwen от прошлого запуска занимала память до нового запроса; один замер после
освобождения не подтверждал устойчивую готовность; статус ещё использовал старый
кэш, хотя реальные замеры/генерация уже были готовы. Эти случаи сохранены в
частных отчётах и исправлены до итоговой установленной приёмки. Дополнительный
порог удержания модели не введён.

## Что не закрыто

Это 4 файла/1 605 фрагментов, а не длительная повторная индексация всего корпуса
на разных объёмах RAM. Не обещается постоянное удержание 9B при произвольной
нагрузке других приложений. Очистка best effort; внешний сервер и параллельные
сторонние клиенты Ollama не принадлежат Лесу. Большой выигрыш скорости и качество
RAG на 100 размеченных вопросах этим путём не доказаны.

Scheduler/job_tracker/HTTP jobs, большая часть API, сеть/streaming/отмена,
executor/MCP, сводки, dense/реранкер/родители/публикация индекса, прочие форматы
и NiceGUI ещё Python. Автономные прежние Python-навыки сохраняются по требованию
владельца. Буквально Python-free установка не объявляется готовой.
