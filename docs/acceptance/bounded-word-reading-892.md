# Ограниченное чтение Word · кандидат 892

Статус: проверка исходников и отдельной копии, **не обновление рабочего LES 880**.
Без Qwen, переиндексации, смены BGE и включения реранкера. Поиск получает вопрос,
наборы документов и лимит, без ожидаемого имени файла, ID документа или страницы.

## Причина и исправление

Автоматический читатель превращал каждое совпадение Word в весь документ;
поздний селектор повторно выбирал нужное из тысяч посторонних единиц.
`sources/word/window.rs` теперь сохраняет проверенные поисковые якоря и расширяет
их по структуре раздела и расстоянию до соседей. Вложенные подразделы относятся
к родителю; чужие соседние главы не раскрываются. В длинном разделе действует
лимит окружающего текста. Обязательный якорь не режется этим лимитом.

Связь проверяется по редакции, исходному ordinal и хешу текста. Старый якорь
без структурной привязки разрешается только единственным буквальным совпадением.
Неоднозначность возвращает `WORD_ANCHOR_UNRESOLVED`, а не скрытое чтение всего
файла. Сохраняются канонические таблицы, шапки, строки, формулы, ordinal,
идентичность оригинала и **глобальный** курсор для `read_source`.
Продолжить чтение оригинала явно можно; снимок context/overview не выдаёт
недействительный поисковый курсор и не объявляется полным документом.

Первичная конвертация Docling всё ещё строит структурное представление всего
Word. Исправлено раздувание **автоматического пула доказательств**, а не выборочное
чтение ZIP/XML с диска. Разбор может повторяться после пересборки API, вытеснения
из ограниченного кэша или превышения лимита записи. Задача кэша остаётся открытой.

## Протокол и границы сравнения

Одна прежняя копия: 638 документов, 88 175 точек. Временный контроль full/section
использовал один двоичный файл, неизменные BGE, индекс, RRF, отбор и лимиты.
Четыре периода с обратным порядком на половине вопросов: **108 × 2 = 216 вызовов
настоящего stdio MCP**. Контроль полного автоматического чтения затем удалён
из текущей реализации; ограниченный путь становится обычным в кандидате.
Рабочая установка и её MCP не переключены.

Исходный диагностический набор 100 вопросов: SHA-256
`a57ea79f2049413d93cf0589200e02d67c7783c1b30c6d34bc9a68bb866b1677`.
Манифест 108 вопросов с восемью описательными пробами без полного эталона:
`8f902e27a1ab9b11877218b1c48c03e9f87ac98ee8d99cc3f332da27df1024f5`.
Это многократно использованная разработческая выборка, не независимая приёмка.
В исходной сотне 90 положительных случаев, 3 отрицательных и 7 диагностических
визуальных; 69 случаев имеют текстовый эталон. Восемь новых описательных проб
не получают выдуманную оценку качества без полного эталона.
Эталон применяется **после** поиска. Метрики сопоставляют SHA-256 оригиналов,
поскольку идентификаторы документов в копии отличаются; одинаковые байты не
доказывают актуальность нормативной редакции.

Первый незавершённый прогон остановлен на 12 002 символах под лимитом 12 000:
предварительный расчёт нормализованного текста не совпадал с буквальной передачей.
Оба финальных плеча используют общий исправленный допуск фактического тела
контекста для compact и обычного JSON. Непомещающиеся целые единицы пропускаются;
строки таблиц не подрезаются. Незавершённый прогон сохранён и не оценивался.
Поэтому прямой межсборочный контраст с 891 не изолирует только Word-окно.

Сокращение пула **90,73%**, в четырёх обзорах 22 862 → 1 558 единиц.
Это повторяющиеся чтения, не число уникальных единиц корпуса. Все 216 парных
сверок порядка/содержимого первых двух стадий равны: поиск и план до Word-окна
не изменились. В обзорах по-прежнему теряются три пары вопрос/источник на финальном
допуске; пять других отсутствуют во всех наблюдаемых пулах, их ранг неизвестен.

Разбор отдельных изменений сохранён: один положительный случай приобрёл нужный
источник и цитату; ещё один — цитату. В одном случае покрытие короткого эталона
из оглавления упало 1 → 0: вместо строки с номером пункта пришли содержательные
абзацы о тех же инженерных системах. Этот спад **не исключён** из метрики, эталон
не менялся. В отрицательной пробе изменился состав контекста; без генератора
это не проверка правильного отказа модели и не доказательство отсутствия галлюцинаций.

Общее ускорение **не доказано**. Для двух медленных обзоров разбор Word занял
48,85/68,34 с против 25,08/3,79 с в контроле при 4/7 против 2/1 промахах кэша.
Упаковка в тех же запросах сократилась с 1,46/2,01 с до 0,068/0,111 с.
Это локализует наблюдаемую задержку, но не даёт честного контраста холодного
разбора: состояние ограниченного кэша зависело от порядка. Не повышать размер
кэша и не снимать проверки редакций ради красивой цифры.

Проверки оригинальных файлов / PDF-страниц / Word-курсоров по периодам:
156/182/119, 155/203/122, 151/190/110, 167/211/123; **ошибок 0**.
Это точное совпадение байтов и единиц читателя, не независимая оценка OCR.
Все 638 строк каталога и хеши исходников неизменны. Минимум свободной RAM
6,04 ГиБ, максимум рабочего набора собственного дерева служб 3,08 ГиБ.
Резерв RAM/диска не нарушен; ещё один индекс не создавался. Прогон — 2 430,71 с.

## Проверки окончательного кандидата

После удаления контрольного полного пути собран API из `abd0da681eec46d6f15d4d341f5647dd75eda192`:
SHA-256 `838a587badd102c6e37bd36f6b4d5114a6495ab75a6535305aff31ef0cfddecf`.
API edge: **147 passed**. Нативный MCP-регрессионный сценарий: **1 passed**;
`make verify` — **2 240 collected**, публикационная проверка пройдена.
На прежней копии повторены два вопроса без фильтра файла уже с обычным ограниченным
путём. Тексты, канонические структуры и все привязки совпали с соответствующими
ответами сравнительного прогона; нормализован только случайный порт loopback,
путь/параметры ссылки и идентичность оригиналов сохранены. Проверки оригиналов
и точного чтения вновь прошли. Это проверка механического удаления контрольной
ветки, не новый независимый опыт качества или скорости.

Полный набор приложения ещё выполняется на этом же двоичном файле с режимом
ограниченного чтения по умолчанию. Итог фиксируется после завершения;
установка и релиз не объявляются.

Автоматический MCP-регрессионный сценарий проверяет поздний раздел Word,
сохранность чисел 17.25 и 117.25 в разных строках, шапки и каноническую таблицу,
глобальный курсор, точное повторное чтение и отказ при смене оригинала.
Генератор не вызывается. Шесть Rust-регрессий покрывают границы разделов,
вложенность, вводный абзац родителя, несколько якорей, атомарную строку и
неоднозначный старый якорь; отдельный тест — фактический бюджет обоих JSON-видов.

Частные ответы, вопросы, пути, оригиналы и журналы остаются вне Git.
Публичны только протокол, агрегаты, хеши когорт и код проверок. Качество
обзорных ответов и независимая приёмка RAG остаются открытыми.
