# Обычный вопрос по папке в ЛЕСе

Пользователь выбирает папку или датасет и задаёт вопрос. Для начала поиска ему достаточно области. Обязательное чтение по ID требуется, когда пользователь явно выбрал конкретный документ. В контрольном прогоне в области было 60 коротких файлов на русском языке. Эталоны написаны по содержимому файлов. [Корпус и вопросы](../../tests/fixtures/rag/folder-chat-v1.json)

## Что сломалось и на каком участке

| Наблюдение | Участок | Что изменилось |
| --- | --- | --- |
| На вопрос о двух насосах 932 нашёл 60 документов. При окне 8192 служебный отчёт оставил модель без текстов. | Сборка запроса | В 933 обязательные сообщения и выдержки получают место первыми. Размер отчёта вычисляется по его окончательному содержимому. На заполненном вложением окне с нулём выдержек ЛЕС останавливается до обращения к модели. |
| На том же задании локальный сервер продолжал выдавать рассуждения до предела потока. | Отправка провайдеру | ЛЕС передаёт рассчитанный предел генерации. Для локального совместимого сервера возможность выключить отдельные рассуждения проверяется коротким вызовом и привязывается к редакции подключения. |
| В 933 модель увидела 47 выдержек, при повторе 60. В профиль уже было записано шесть. | Отбор текста для ответа | В 934 обычный ранжированный поиск применяет лимит профиля к фактически поместившимся выдержкам. Поисковый пул остаётся доступен для дальнейшего чтения. |
| На переформулировке 934 привёл реальную ссылку на паспорт смесителя как подтверждение условия испытания насоса. | Выбор факта и составление вывода | Ошибка открыта. Проверка существования ссылки успешно находит документ с паспортом. Принадлежность утверждения другому оборудованию выявляет сверка с эталоном. |

Контрольный HTTP-приёмник пересчитал SHA-256 принятых байтов. В первом сообщении было шесть выдержек, в том числе оба давления и условие для обоих участков. Это проверено при окнах 8192 и 24 000. В опыте на пустом окне число обращений к приёмнику равно нулю. Такие проверки воспроизводят решения программы независимо от ответов модели. [932](folder-chat-932.json) · [933 и 934](folder-chat-934.json)

## Что увидел бы человек в 934

Обычный запрос к публичному API стенда использовал поиск по всему датасету, BGE-M3 и локальную Qwen 3.5 2B. Окно в ЛЕСе было задано в 8192 токена.

| Вопрос | Ожидается | Что вернул чат |
| --- | --- | --- |
| Давление на двух участках и условие допуска | Север 184 кПа, Юг 273 кПа, на обоих участках охладить теплоноситель до 26 °C | Ошибка проверки ссылок после двух вызовов. |
| Те же сведения другими словами | Те же три факта | Оба давления верны. Для начала работ модель потребовала паспорт и форму 136. Этот текст относится к смесителю. |
| Давление в шинах тележки и периодичность проверки | 315 кПа, ежемесячно, оба факта в первом фрагменте | Модель пропустила 315 кПа и дала противоречивое объяснение периодичности. |
| Срок гарантии | В папке нет срока | Модель сообщила об отсутствии срока. |

Ни один из трёх вопросов с известным ответом не прошёл целиком. На отрицательном примере модель воздержалась от назначения срока. Четыре вопроса, из которых два проверяют один факт в разных формулировках, годятся для локализации этих ошибок. Для оценки процента точных ответов по пользовательским датасетам нужна отдельная выборка. [Полные ответы и ссылки](folder-chat-934.json)

На той же сборке повторён обычный путь с уже установленной Qwen 3.5 9B. По исходному вопросу она вернула оба давления и общую температуру с точными ссылками на 017.txt, 056.txt и 032.txt. По тележке вернула 315 кПа и «ежемесячно» со ссылкой на 070.txt. По гарантии сообщила об отсутствии срока. При переформулировке вопроса о насосах ЛЕС отклонил ответ после повторной проверки цитат. Итого у 9B полностью прошли два из трёх ответимых вопросов и контроль без ответа. Отдельный HTTP-приёмник подтвердил дословную доставку трёх полных исходных текстов, включая слова «на обоих участках», на обоих размерах окна. [Сравнение в обычном чате](folder-chat-934.json)

## Проверка другой архитектуры

Готовый модуль цитирования LlamaIndex проверен отдельно с живой Qwen 3.5 9B на сохранённых выдержках, через обычный чат на 59 файлах и на втором корпусе с разными редакциями. Потерю найденного факта и применение отменённого срока удалось воспроизвести. [Протокол и решение по замене сборщика](llamaindex-934/README.md)

В отдельном опыте модель получала только вопрос и пронумерованные абзацы из зафиксированной выдачи. Она могла вернуть список адресов или пустой список. Допустимые адреса перечислялись в JSON Schema. Код проверял завершение ответа, существование адресов и точное совпадение выбранного набора с эталоном. При перестановке абзацам назначались новые адреса. Программа может по принятому адресу дословно показать нужный текст и подставить ссылку. Релевантность выбранного абзаца остаётся измеряемой ошибкой модели.

В 20 вариантах использовались исходный и перемешанный порядок, только эталонные абзацы, удаление всех подтверждений и поочерёдное удаление одного факта из составного ответа. Для вопроса о гарантии сразу передавались только посторонние абзацы. Qwen 3.5 2B правильно выбрала весь набор в **12 из 20**. При удалении всех подтверждений из вопроса о насосах она выбрала давление шин. В переформулированном вопросе даже среди трёх правильных абзацев она выбрала только условие охлаждения. Это опыт чтения уже найденного материала. В нём отсутствуют поиск, история диалога, инструменты и свободный пересказ. [Все попытки](folder-selection-934.json)

В идентичной серии Qwen 3.5 9B дала **15 из 20** точных наборов. Она правильно выбрала источники в исходной выдаче всех четырёх вопросов и воздержалась при удалении всех подтверждений. Все пять ошибок пришлись на частичное удаление. Например, после удаления общего условия она выбирала третьим источником инструкцию о подаче сигнала начала работ. Это сразу выделяет следующий критерий для читателя по папке — сохранить подтверждённую часть и назвать недостающую. [Попытки 9B](folder-selection-934-9b.json)

Команда запускает повтор из корня репозитория с уже установленной моделью.

```powershell
uv run python -m tools.evaluate_folder_evidence --fixture tests/fixtures/rag/folder-chat-v1.json --api-url http://127.0.0.1:11434/v1 --model qwen3.5:2b --output .test-tmp/folder-selection-new.json
```

Отчёт записывается в новый файл. Ненулевой код выхода означает хотя бы одну ошибку выбора или протокола. Этот же корпус принимает существующий инструмент `tools/evaluate_light_chat.py` для прогона через загрузку документов и обычный потоковый чат. [Проверка отбора](../../tools/evaluate_folder_evidence.py) · [Проверка пути приложения](../../tools/evaluate_light_chat.py)

## Порядок изменений

Для исходного вопроса план чтения должен охватывать давление на Севере, давление на Юге и общую предпосылку испытаний. Каждая найденная позиция получает значение, единицу, объект и адрес выдержки. Исходный вопрос и его разбор сохраняются рядом, чтобы видеть, где потерялось требование. Текстовый ответ может соединить две позиции в одно предложение. При этом он сохраняет область действия каждой позиции и ссылку на неё. Программа проверяет ID, редакцию, границы выдержки и точность переноса значений. Решение, отвечает ли отрывок про нужный объект, оценивается отдельно, в том числе на фрагментах с теми же числами или похожим названием.

В коде первым стоит вынести из координатора чата отбор видимых источников и итог каждой попытки чтения в один общий результат. Этим результатом должны пользоваться отправка, проверка цитат и журнал. Тогда для исправления формы ссылки можно повторно использовать ту же сохранённую подборку, а для поиска недостающего условия — делать новый поисковый запрос с собственной квитанцией. [Координатор](../../api/src/chat/runner.rs) · [Сборка видимого контекста](../../core/src/chat_context/assembly.rs) · [Существующая привязка к строкам и абзацам](../../api/src/chat/table_facts.rs)

| Шаг | Изменение | Как принять |
| --- | --- | --- |
| 1. Сделать доставку наблюдаемой | По одному запросу связать область поиска, число кандидатов, номера переданных источников, причину пропуска, размер и хеш отправки, причину окончания вызова. В 932–934 основной путь и сборка окна уже покрыты. | На тестовом приёмнике байты совпадают с квитанцией. Для каждого пропуска известен этап. Текст личных документов в обычном журнале не нужен. |
| 2. Выделить чтение фактов | Поиск отдаёт идентификаторы документов и фрагментов. При запросе фактов читатель предлагает утверждение с адресом абзаца или ячейки. Программа разрешает адрес только внутри реально переданного окна, получает текст, редакцию и локатор. Для обычного пересказа сохраняется возможность писать связный ответ. | На размеченных примерах раздельно считать выбор правильного объекта, полноту составного ответа, ложный ответ при удалённом источнике и правильность ссылки. Ошибочный адрес отклонять до показа. Закрепление файла пользователем для этого не требуется. |
| 3. Проверить составные и неполные ответы | Если подтверждена часть запроса, вернуть подтверждённые части и честно обозначить пробел. Ограниченный повтор поиска должен хранить причину и показывать, какие новые источники он добавил. | Удаление только южного давления сохраняет северное и общее условие. Удаление общего условия сохраняет оба давления. Посторонние единицы, похожие пункты и старые редакции не засчитываются. |
| 4. Выбрать маршрут и модель по парному испытанию | Прогнать обычный чат и новый путь на одинаковой выдаче. Затем повторить с включённым поиском. В отдельном наборе зафиксировать реальные вопросы до изменения промпта, эталоны и допустимые варианты ответов. Включить TXT, PDF и Excel, историческую редакцию, одинаковые числа в разных документах и вопрос без источника. | По каждому пути сохранить фактический ответ, точность набора источников, пропущенные факты, необоснованные утверждения, частоту отказа на ответимых вопросах, число вызовов и время. Тестовые 60 файлов и внешний RAGHOUND считать отдельными сериями. |
| 5. Переключить путь поиска по папке | После успешной приёмки провести тот же путь через установщик на чистой Windows. Только после этого удалять дублирующие ветки расширения контекста и исправления цитат, для которых уже есть замена. | Проверить поток и обычный HTTP-ответ, цитату по клику, источники по ID, продолжение Excel, отмену и повтор запроса. Зафиксировать версию установки и результат каждого сценария. |

В Dify поиск по базе можно проверить отдельно от ответа чата. В Haystack есть отдельные оценки для попадания документов в выдачу и для вывода утверждений из контекста. Эту границу можно провести и в текущем коде ЛЕСа. Оценке моделью последнего этапа нужна собственная проверка на размеченных ошибках.
