# Swiftide Query: реальные справки на копии

**Решение: замену не включать.** Испытание 875 относится к стенду, а не к
новой сборке приложения. Текст стал связным, но содержательная приёмка
провалена. Рабочий LES, его индекс и назначения моделей не изменены.
Старый код приложения по результатам этого эксперимента не удаляется.

## Что действительно проверено

В прежнем изолированном Rust-проекте собран `swiftide-query = 0.34.0`.
В отличие от сравнения агентных SDK в 869 здесь готовые `Pipeline`,
`Embed`, `Retrieve`, `TransformResponse` и `answers::Simple` управляют
последовательностью вопрос → поиск → раскрытие → ответ. Отдельно проверен
`GenerateSubquestions`. Прежний цикл Rho и финальное копирование выбранных
строк LES в генерации кандидата не участвуют.

Использована одна существующая копия Edge/SQLite с двумя наборами и 638
зарегистрированными документами. Новых копий корпуса и dense-векторов нет.
Оригиналы открываются только для чтения и сверки SHA-256. Все шесть итоговых
запросов прочитали одно поколение индекса. Ручного выбора файла, передачи
эталонного ответа или идентификаторов ожидаемых документов модели нет.

Модели прежние: локальные Qwen3.5:9b и bge-m3. Окно Qwen — 8 192 токена,
выход — до 1 800, резерв — 512. Контекст источников ограничен 10 000
символами с учётом метаданных; допускаются целые единицы. Максимальный
фактический вход — 4 093 токена. Обрыва выхода в итоговой серии нет.

SDK использует адаптеры LES для прежнего dense + BM25 + RRF, чтения родителей,
области доступа и поколения. Эти адаптеры не стали готовой реализацией
Swiftide. Прикладные проверки оригинала, SHA-256, страницы и адреса остаются
необходимыми. Индексирование Swiftide, смена парсеров, память чата, история,
отмена, обновление и аварийное восстановление этим опытом не приняты:
первый барьер — пригодная справка — уже не пройден.

Внешний испытательный драйвер на Python передаёт I/O между Rust-пробником,
локальной Ollama и API копии; он не планирует шаги и не входит в приложение.
Это не проверка полностью самостоятельного дистрибутива Swiftide.

Сохраняется прежняя Windows-поправка Swiftide Core 0.34.0: Unix-импорт
`OsStrExt` заменён использованием `as_encoded_bytes`. Это сборка с поправкой,
а не доказательство неизменённой совместимости опубликованного SDK с Windows.

Проверка ручная, по переданным выдержкам и независимым оригиналам, а не по
статусу завершения или наличию ключевых слов. Полный текст запроса, ответа,
модельного входа, выдачи и допущенного контекста сохранён в частном журнале.
Два последних вопроса взяты из существовавшего до опыта контрольного набора.
Один шаблон просил 250–450 слов даже для коротких вопросов: это ограничение
стенда, поощряющее избыточные пояснения. Нельзя приписывать все ошибки SDK;
вывод касается только испытанной конфигурации. Пропуски обзорных справок и
неподтверждённое сравнение стадий достаточны для отказа от её включения.

## Локализация причин

1. **Поиск не равен отбору контекста.** В вопросе о томах полный документ
   состава найден на позиции 27 из 32, но не допущен к модели. Вверху —
   содержание одного тома, обложки и посторонние страницы. Следовательно,
   отсутствие справки нельзя объяснять отсутствием документа в корпусе.
2. **Идентичность файла не устраняет дублирование содержания.** В сравнении
   стадий четыре допущенных источника — копии одной страницы состава,
   сохранённой в разных PDF. Дедупликация по документу/странице/единице
   честно различает файлы, но не освобождает место для другого основания.
3. **Дочитывание ещё требует отбора.** Найденная единица не теряется при
   раскрытии, но бюджет заполняется ранними совпадениями; связанные разделы
   с нагрузками не получают гарантированного места. SDK исполняет этот
   адаптер и не проверяет достаточность сведений для частей вопроса.
4. **Достоверный адрес не подтверждает произвольный вывод.** Qwen может
   сослаться на правильный файл и при этом изменить вид оборудования,
   приписать стадию или заявить полноту обследования корпуса. Проверка
   существования ссылки таких ошибок не обнаруживает.

Эти причины не доказывают непригодность Swiftide вообще. Они доказывают,
что проверенный конвейер с текущим поиском/адаптером не является готовой
заменой прикладной связки LES.

## Ссылки и предыдущие попытки

Модель выдаёт `[Источник N]`; только известный номер приложение превращает
в ссылку с именем файла, зарегистрированным ID, SHA-256 и физической страницей
PDF. Неизвестные номера и посторонние адреса считаются ошибкой. Модель не
должна самостоятельно печатать внутренний адрес. Это форматирование по
проверенным метаданным, а не исправление смысла её ответа.

В итоговой серии: 35 вхождений источников, 24 оригинала, 71 ссылка в ответах,
16 вхождений с адресом PDF-страницы. Все 24 уникальных адреса оригиналов
доступны; неизвестных номеров/адресов нет. Исходные хеши сверены. В этом
стенде PDF-контекст получен из сохранённых представлений страниц через
нативное чтение индекса; новое физическое извлечение PDF по ходу ответа
не проверялось. Доступность оригинала не равна проверке каждого утверждения.

Ранние попытки не скрыты из результата: вариант с дополнительными вопросами
увёл запросы в общие нормы и обложки, а два ответа достигли ограничения
выхода; они отклонены. Исправлена ошибка адаптера, терявшего найденную
единицу за слишком большим родителем. Базовый вариант затем дал связный,
но ложный вывод об отсутствии всей I категории вместо I особой категории;
в итоговой формулировке этот конкретный вывод не повторился. Первоначальные
буквальные ссылки `(URL)` исправлены передачей известных номеров, а не
разрешением произвольных адресов. Финальная серия остаётся непринятой.

## Следствие для архитектуры

До удаления существующей связки нужны: сохранение найденных содержательных
единиц при ограничении бюджета; объединение одинаковых выдержек с сохранением
всех их происхождений; достаточное основание для каждой части обзорного
вопроса; запрет вывода о совпадении стадий без прочитанных решений обеих
стадий. Проверять надо итоговую справку с основанием каждого существенного
вывода, а не только корректность ссылок. Это требования к общему пути,
без правил по имени конкретного файла и без ответов, зашитых в тест.

Никаких изменений приложения по одному удачному узкому ответу, переключения
рабочей установки, релиза или удаления действующего кода не выполнено.
Зависимость остаётся в стенде; Cargo.lock приложения не изменён.
Сервер копии остановлен, наблюдение копии восстановлено, Qwen выгружена.
Частные входы и ответы не включены в Git. Обезличенные измерения —
[JSON](native-swiftide-query-875.json).
