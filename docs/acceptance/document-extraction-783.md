# 783 — извлечение документов и цитаты: локальная установка

01.11.2026. Локальный патч 783 установлен поверх 782, стандартный ярлык снова
открыл Rust launcher/API и Svelte-чат. Новые модели и зависимости не добавлены;
явные назначения Qwen3.5:9b и BGE-M3, конфигурация и исходные папки сохранены.
[Контракт](../modules/document-extraction.md), [остаток переноса](../modules/python-exit.md).

## Прежние отказы и исправления

Из 108 прежних ERROR: 13 служебных owner-файлов Office, 51 настоящий DOC и
44 PDF. Owner-файлы оставлены в каталоге как SKIPPED/TEMPORARY_SOURCE, исходники
не удалялись. Все 95 настоящих источников дали положительные форматные результаты
в отдельном native worker: 7 826 подготовленных узлов за суммарные 482,85 с.
Это узлы до embeddings и финализации, а не доказательство рабочего поискового
индекса. Размеры и mtime всех исходников совпали с исходным замером; сплошной
криптографический baseline оригиналов не снимался. DOC дали 300 670 символов.

Причины устранены по отдельности: отсутствие Windows DOC-reader; тяжёлая
геометрия/подсчёт страниц PDF; выключенный быстрый путь внутри format worker;
удержание layouts до конца файла; ложный OCR на пустых разделителях; запуск
embedded Python с изолирующим ._pth. Ошибки имеют стабильный код и понятное
сообщение; ограниченная диагностика сохраняется, пустой результат не становится
успешной индексацией. Лимит процесса 2 ГиБ, таймауты и RAM guards сохранены.

  17 проверок документов; четыре ownership-сценария затем проверены отдельно.
  Финальный набор документов: 20 passed; все эти сценарии включены в полный gate.
- Реальные CFB-fixtures: UTF-16/FcCompressed, русский/японский/emoji, результаты
  полей без инструкций, шифрование/повреждение, неизменность fixture-оригинала.
- Раздельное состояние пакетного кандидата: настоящий embedded interpreter,
  Rust format host и нативный Qdrant. DOC и растровый PDF прошли регистрацию,
  извлечение, embeddings и основной RAG API. Реальная Qwen дала значение из DOC

- В браузере оба пути: inline-ссылка → фрагмент → оригинал → возврат к ответу.
  Для DOC оригинал открывается как экранированная текстовая проекция с явным

Ссылки/manifest/счётчик используют единый Rust parser и только модельную source_map.
Известный сломанный заголовок исправляется по полному совпадению. Неизвестные
номера, числа в именах файлов, код и внешние Markdown-ссылки не подтверждают
источник. Исправление синтаксиса не проверяет фактическую истинность утверждений;
claim_verification остаётся not_performed, автоматического VERIFIED нет.

## Установка и рабочий корпус

Подготовлены before/after, SHA-256 manifest 27 файлов, резервные SQLite-копии
и проверка отката. Первый apply остановился на вложенном массиве двух ярлыков
во вспомогательном локальном скрипте; программные файлы автоматически вернулись
к 782, исходные ярлыки не менялись. После исправления скрипта Apply/Rollback
проверены на копиях обоих ярлыков. Повторный apply успешен: 27 новых hash совпали,
состояние не изменено применением файлов. Лес закрыт штатно с пустым черновиком
и без фоновой обработки, затем открыт стандартным ярлыком. В native WebView
проверены новый чат и назначенная Qwen; новое окно работает через Rust API.

Установленный основной чат ответил по прежнему реальному Excel: значение совпало
с контрольной строкой, цитата учтена. Все 337 исходных идентификаторов документов
сохранены. После миграции: 229 INDEXED, 95 ERROR и 13 SKIPPED; ровно эти 95
положительно проверенных настоящих файлов возвращены в штатную очередь.

Рабочая повторная индексация завершилась: 95/95, 95 batches, errors=0,
remaining_pending=0. Итог: 324 INDEXED, 13 SKIPPED, без ERROR/PENDING и без
INDEXED с нулём фрагментов. Все 337 идентификаторов и размер/mtime оригиналов
сохранены. После первой очереди каталог содержал 44 702 индексных записи; итог после
дочитывания трёх старых PDF — 43 217 записей с полным проверенным покрытием страниц.

Первый обычный hybrid-запрос после ремонта обновил отложенное поколение BM25:
с 21 446 до 44 702 строк, точное совпадение rows/corpus/catalog, revision совпадает
с журналом, журнал idle. Запрос с обновлением занял 37,029 с; это не тёплая
задержка поиска и не сравнение ускорения с прежней версией. Перенос работы с
первого запроса в видимое завершение индексации остаётся задачей.

В installed-проверке обнаружен ещё один прежний pdfplumber-путь — инвентаризация
текстовых страниц при аудите целостности. RSS API достиг примерно 2,9 ГиБ;
проверка остановлена штатным закрытием пустого чата после завершения очереди.
Исходники и индекс не откатывались. Дополнение candidate-v7 переводит этот путь
на постраничный PDFium и не считает отказ чтения пустым успехом. Два регрессионных
теста проверяют сложную геометрию/реальные номера страниц без pdfplumber и явный
отказ повреждённого PDF. В отдельном пакетном процессе все 44 PDF проверены за
22,443 с, наблюдаемый RSS до 251,3 МиБ. Один дополнительный программный файл
установлен с SHA-256 baseline/candidate и проверенным откатом: всего 28 уникальных
файлов этапа 783. Данные, роли, ярлыки и конфигурация дополнением не менялись.

Первый безопасный аудит нашёл 26 расхождений страниц: 23 ложных сравнения
(дополнительные OCR/короткие страницы) и три настоящих пробела прежнего индекса,
не входивших в 95 ERROR. Сравнение теперь требует включения всех native текстовых
страниц, сохраняя дополнительные OCR-страницы; равное число страниц при разных
номерах не считается совпадением. Три новые регрессии проверяют эти случаи.
Последнее дополнение candidate-v8 меняет тот же программный файл; уникальных
файлов этапа по-прежнему 28. Только три настоящих пробела возвращены в очередь.
Три старых PDF реально переиндексированы. Защита памяти приостанавливала
очередь после файла (2,46/2,41/2,33 ГиБ свободной RAM), штатное автоматическое
возобновление завершило все три. Промежуточные задания PARTIAL сохранены в
диагностике, последнее — COMPLETED, ошибок нет. Лимиты не ослаблялись. Для
освобождения накопленной памяти после массовой индексации выполнен штатный
перезапуск пустого чата; автоматическое освобождение — отдельный остаточный долг.

Повторный установленный аудит: 324 checked/indexed/clean, damaged=0, missing=0,
contract_ok=true, fts_ok=true, обе orphan-проверки = 0. BM25 содержит 43 217 строк,
их количество совпадает с каталогом, поколение совпадает с журналом (idle).
После трёх замен обычный hybrid-запрос с обновлением занял 11,330 с; это ещё
один холодный запрос с другой работой, не парный benchmark ускорения.
Установленная Qwen дала дословную цитату восстановленного DOC, она сверена с
текстом источника. source_counts = 1 найден / 1 передан / 1 процитирован,
execution=no_changes. В браузере установленного приложения пройден путь
inline-цитата → фрагмент → текстовый оригинал DOC → возврат с тем же ответом.
Временный проверочный проект удалён, исходный набор сохранён. Все 27 hash
основного патча и итоговый hash дополнения совпали. Назначения/конфигурация и
оригинальные идентификаторы сохранены. Модель, загруженная проверкой, выгружена
из Ollama без смены назначения.

Аппаратное ограничение остаётся: при удержании проверочной Qwen свободная RAM опускалась до
3,5–3,7 ГиБ; guard требует 4 ГиБ и отклоняет следующий локальный ответ при
недостатке. Успешный контрольный ответ не доказывает устойчивую работу 9B под
текущей нагрузкой других приложений. Лимит не ослаблен, чужие процессы не завершались.
После выгрузки проверочной модели свободно 4,94 ГиБ, chat_generation_allowed=true.
Следующий запрос загрузит назначенную модель автоматически. Устойчивость работы
при её удержании остаётся открытой ресурсной границей, отдельно от извлечения/цитат.

## Границы

Полный установщик и GitHub не обновлены. Это локальный патч, не публичный выпуск.
DOC — текстовая проекция без геометрии/выдуманных страниц. Для сложных PDF
автоматическое геометрическое обогащение откладывается целиком; текст и ссылки
на реальные страницы сохраняются, подробный аудит остаётся отдельным действием.
OCR не объявляется безошибочным: в контрольном английском тексте встречались
похожие кириллические символы; контрольный код прочитан верно. Нужен отдельный
языковой/табличный benchmark. 100 размеченных RAG-вопросов, Recall@5/@10 и
проверка каждого утверждения по источникам не выполнены этим прогоном.
Все прежние форматы, чистая Windows, WCAG/экранный диктор и аварийное закрытие
новой сборки не принимаются по этим ограниченным сценариям. Остальные парсеры,
сеть/streaming, очередь и большая часть API ещё Python. CPython для автономных
прежних навыков остаётся согласованным исключением из целевого удаления Python.

Полные логи, manifest, приватные вопросы/ответы и тексты источников находятся
в отдельном локальном каталоге приёмки, вне репозитория. Ранние неудачные
кандидаты/прогоны сохранены, DOC/OCR/UI были проверены на candidate-v6; дополнения аудита — на candidate-v7/v8.
