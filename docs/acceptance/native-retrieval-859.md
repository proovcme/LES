# Кандидат 859: поиск, чтение и передача доказательств

Это кандидат исходников. Рабочие документы, индекс, назначения моделей и
установленный LES не переключены. Проверки выполняются на одной отдельной
копии двух наборов: 638 документов, 82 203 фрагмента. Имена, пути, вопросы и
полные ответы этой проверки остаются в частном журнале.

## Причины и системные решения

| Причина | Решение в общем пути | Проверка границы |
| --- | --- | --- |
| Вызов инструмента ошибочно подменял факт чтения. Rust уже раскрывал родителя, но модель должна была читать его повторно и иногда уходила в начало документа. | Общий читатель выпускает квитанцию `les.indexed-read.v1` с поколением и фактически прочитанными point ID. Начальная подборка и модельный инструмент проходят один допуск содержимого. | Прочитанные Rust разделы допускают ответ без повторного вызова; устаревшая квитанция не допускается. |
| Выбор инструмента смешивался с оформлением окончательного ответа. | Один `SourceFlow` владеет переходами обнаружение → чтение → подтверждённая передача. Выбор инструмента получает точный вопрос и область, но не указания формата финала или отклонённый черновик. | Pull с действительным чтением, отклонение метаданных/пустого текста/ошибок и сохранение причины отказа. |
| Успешный статус и карточка принимались за достаточную проверку. | Требуются непустой текст, зарегистрированная идентичность и присутствие прочитанного блока в последнем подтверждённом окне модели. | Манифест частей, поиск только имён и чтение, выпавшее из окна, не разрешают финал. Это проверка происхождения, не смысла. |
| Первый PDF определял читатель для всей смешанной выдачи. | Тип читателя определяется всем набором форматов найденных/выбранных кандидатов. | Перестановка PDF и Excel не меняет доступность чтения. |
| Дублированные карточки переполняли контекст до чтения. | Ограниченная проекция обнаружения: карточки, идентификаторы, путь, курсор. Сырые результаты остаются в журнале; метаданные не становятся цитируемым текстом. | Большие карточки укладываются в бюджет, курсор не пропускает скрытые строки. |
| Буквальный `[Источник N]` в документе мог разрешить чужую цитату. | Управляющий номер хранится отдельно в типизированном блоке `les.evidence-block.v1`. | Типизированный и старый строковый блок с ложным номером внутри содержимого. |
| В журнале отсутствовали фактические аргументы читателя. | Частный журнал сохраняет ограниченные аргументы чтения из белого списка. Модельная проекция их не дублирует. | Запрошенный размер сопоставляется с выданным бюджетом; посторонние поля и секреты не копируются. |
| В обычном Push модель приглашалась вызвать недоступный инструмент. | Инструкции стадии ответа учитывают фактическую доступность инструментов; при её отсутствии требуется обозначить неподтверждённую часть. | Инструкции без инструментов не рекламируют `search_sources`. |
| Финальная сверка проверки документа теряла причину недоступности и сообщала, будто источник изменился. | Квитанция и история сохраняют `source_errors`; журнал API пишет безопасный код и ID единицы. Изменение оригинала, неизвестная версия и недоступность имеют разные коды. | Управляемый отказ индекса после записи, сохранение причины и восстановление без повторной записи. Изменённый SHA остаётся причиной перепроверки. |

## Чувствительность ранжирования

Без изменения индекса на 20 контрольных вопросах сравнивались RRF-константы
2, 10, 30, 60 с одинаковым эмбеддингом вопроса и областью. Проверяется попадание
заранее размеченного документа, не полнота всех релевантных фрагментов.

| RRF k | Документ в первых 4 | В первых 5 | В первых 10 | В первых 64 |
| --- | --- | --- | --- | --- |
| 2 | 13/20 | 14/20 | 17/20 | 18/20 |
| 10 | 16/20 | 17/20 | 17/20 | 19/20 |
| 30 | 14/20 | 15/20 | 16/20 | 19/20 |
| 60 | 14/20 | 15/20 | 16/20 | 19/20 |

Это диагностическая выборка, использованная для настройки, не независимая
приёмка и не Recall@K. В кандидате значение 10 задаёт общий владелец политики
профиля; явное прежнее значение 2 сохраняется. Один вопрос об аннулировании
редакции ухудшился с позиции 2 до 5; вопрос о заключении остаётся слишком
низко, ещё один нужный документ не попал в 64 результата при всех настройках.
Медиана времени отдельных поисков — 0,82–0,88 с в этом стенде; это не задержка
полного чата. Изменение не объявляется решением всех проблем поиска.

## Обычный поиск и агент

Профиль `search` без явной настройки использует Push: Rust выполняет поиск и
чтение, формирует ограниченный контекст, модель получает данные без схем
инструментов. Профиль `agent` сохраняет Pull. Явно сохранённые Push, Pull и
Hybrid имеют приоритет; роли моделей не меняются. Сервер отдаёт значения
по умолчанию интерфейсу из того же владельца политики.

Hybrid допускает уточняющий поиск и чтение, но не требует повторять чтение,
уже выполненное Rust. В Pull остаются управляемые моделью инструменты;
одна попытка исправить финал без доказательств не обнуляет бюджет. Push без
проверенного текста завершается с `SOURCE_EVIDENCE_MISSING` до вызова модели.
Ошибки сохраняются в истории.

Смена значения по умолчанию для «Поиска» остаётся частью непрошедшего
смысловую приёмку кандидата. Она не раскатана в установленный LES. Агентный
профиль сохраняет прежний путь; проверка Push не доказывает качество всех
пользовательских режимов.

Квитанция подтверждает происхождение и передачу материала. Она не определяет
нужный вид документа, не подтверждает отсутствующие сведения и не проверяет
каждое утверждение.

## Проверки и незакрытые условия

Прошли 39 модульных проверок Rust API, 53 целевые регрессии чата и контекста,
77 проверок API/проверки документов/квитанций/совместимости профилей, 42 проверки
интерфейса и его сборка. Повтор Qwen завершён ниже; общий gate повторяется.

Предварительные прогоны выявили подмену запрошенного вида источника,
недочитывание строки большого Excel и смешение строк разных документов.
Совпадение числа и HTTP 200 не засчитываются как правильный ответ. Повтор
оценивается по исходному документу, редакции, физической странице/листу/строке,
полноте ответа и ложным утверждениям об отсутствии данных.

Первый повтор подготовленного Push на восьми вопросах вернул восемь HTTP 200.
Только три ответа содержали все основные запрошенные факты из нужного документа
(кабель, строка Excel, исключённая коробка). Остались ошибочное количество
датчиков, неполный составной ответ, неподходящий источник согласования и
недостающие подтверждения редакции/отрицательного ответа. В PDF-тексте число
датчиков присутствовало, но границы таблицы были плоскими; модель выдала
противоречивый вывод. Это отказ смысловой приёмки, а не восемь успешных тестов.
Эта серия предшествует изменению RRF и повторяется отдельно.

Повтор после изменения RRF также вернул восемь HTTP 200. Нужный документ был
виден в 6/8 случаях вместо 4/8, основные запрошенные факты получены в 5/8
вместо 3/8. Это ручная диагностика тех же примеров, не независимая оценка.
Исправились количество датчиков и привязка помещения к изменённому листу;
сохранились неправильный вид источника согласования и неподтверждённые
части составного/отрицательного ответа. У составного вопроса в контексте
есть первая страница нужной ведомости, но нет требуемой третьей страницы.
Задержка p50 этих восьми Push-вызовов: 15,17 → 13,08 с; одну серию нельзя
считать устойчивым ускорением. Назначение модели и окно не менялись.

Первая общая серия остановилась на проверке длинного документа: 1021 passed,
2 skipped, 1 failed. В сохранённом журнале есть обе прочитанные порции и
записанное решение, но финальная сверка имеет `blocked_units=1`. Исходный
код причины был потерян квитанцией. Отдельный повтор и весь прежний модуль
прошли; причина первоначальной недоступности не установлена. Исправлена
диагностика, добавлен управляемый отказ/возврат индекса. Общая серия должна
быть повторена; этот сбой не объявляется устранённым только по одиночному
успешному запуску. Исторические квитанции с одними счётчиками сохраняют
совместимость; новые причины передаются явно.

## Редкий обрыв отказа HTTP

Следующий общий запуск остановился на `WinError 10053` при отказе служебного
модельного API: 830 passed, 2 skipped, 1 failed. Отдельный стенд воспроизвёл
2 обрыва на 1200 маленьких POST. Контроль с `Connection: close` оставил один
обрыв на 5000; контроль GET без тела дал 0/5000. Ранний отказ не дочитывал
тело запроса.

Общий `transport::reject` дочитывает и отбрасывает известное небольшое тело
(до 64 КиБ, максимум 250 мс). Для большого, неизвестного или медленного тела
соединение закрывается явно. Авторизация, запрет Origin и проверка цели не
ослаблены; отказанный запрос не разбирается как команда и не пересылается.
Этот путь применён к отказу доступа, неверной цели и схеме локального
модельного моста. Регрессия проверяет последующие запросы и лимиты чтения.
На том же POST-стенде после изменения 0 обрывов на 5000 запросов; сохранён
SHA-256 проверенного API. Это ограниченное измерение, не доказательство
отсутствия любых сетевых отказов.

Общий запуск без остановки на первом отказе прерван после локализации
этой причины, до изменения бинарного файла. Он не засчитывается как gate.
77 связанных проверок прошли на новом бинарном файле; полный gate запускается
заново без дополнительных модельных и нагрузочных опытов параллельно.

Открыты измеренная полнота поиска по всему контрольному набору, семантическая
приёмка утверждений и отрицательных ответов, общий курсор дочитывания
индексированного текста и проверки установленного приложения. Публичный
выпуск этим отчётом не подтверждается.
