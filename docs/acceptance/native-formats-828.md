# Кандидат 828: нативные извлекатели таблиц и презентаций

Состояние: исходники и отдельные проверочные компоненты. Рабочая установка,
модельные назначения и рабочий индекс не переключены.
[Контракт](../modules/native-format-conversion.md).

Проверены настоящий C ABI и standalone Rust exe при недоступном Python:
XLSX/XLSM/XLS, неправильное расширение контейнера, даты/длительности,
сохранённые значения формул и отсутствие кеша, листы, типы значений,
пропущенные строки, ограничение большого окна, CSV с Unicode/кавычками/
переносами и повреждениями. Для PPTX проверены порядок связей, номера
слайдов, таблицы, XML-сущности, заметки и кеш диаграмм, отказ при DTD,
повторном слайде, внешнем пути и незакрытом XML.
Проверки PPTX используют контрольные OOXML-пакеты: настоящих пользовательских
PPTX в выбранном корпусе нет. Приёмка файла в приложении PowerPoint и сравнение
с прежним Python-PPTX не выполнены: optional Python-PPTX в текущей среде отсутствует.

Реальный worker повторно использован, его точный процесс принудительно
остановлен и заменён supervisor; следующий документ прочитан. Отдельный
прогон good → bad → good сохранил конкретный код причины и продолжил работу.
Вызов конвертера приложения прошёл с запрещёнными Pandas/MarkItDown;
структурный XLS-путь прошёл с запрещённым прежним временным XLSX-конвертером.

Standalone Rust worker прочитал все **138 настоящих таблиц** зарегистрированного
корпуса: **119 XLSX и 19 XLS**, **227 листов**. Ошибок после исправления двух
XLSX с расширением `.xls` нет. Проверены 140 текстовых контрольных ячеек;
SHA-256 всех оригиналов до/после совпали. Для 98 листов явно обозначена
навигационная проекция, один лист ограничен окном чтения. Весь файл в контекст
при этом не обещается. Время worker + контрольного чтения/хешей — 10,51 с;
это не замер полной индексации и не сравнение скорости с Python.

Отдельно пройден штатный `_convert_file` настоящего XLS, с производственными
диспетчером/классификатором и приватным каталогом производных файлов.
Получен 31 исходный узел. В дереве процессов непосредственно после чтения
подтверждён Rust `--serve-document-formats`. Общий Python HTTP backend не
запускался; внешний Python-форматный процесс всё ещё присутствует.

На отдельной копии индекса XLS подготовлен и остановлен непосредственно перед
публикацией. Старое поколение сохранилось целиком; параллельно прочитана
настоящая физическая страница 1 другого PDF корпуса. Новый владелец продолжил
партию и сохранил 31 фрагмент. Причина `INDEX_BATCH_OWNER_LOST` проверена
по **точному PID остановленного владельца**, а не по старым событиям журнала.
Остальные **43 188 точек** полностью совпали по ID/payload/векторам.
Поиск дал 5 результатов, дочитаны 4 родительских раздела, оригинал и отпечаток
эмбеддера сохранены. Один вектор взят из кеша, 30 рассчитаны локальным Rust/ORT.
108,82 с включают подготовку, остановку и повтор, это не штатная задержка поиска.
Этот сценарий повторяет тот же XLS; новую редакцию PDF он не имитирует.

Целевые проверки форматов: **27 passed**. Финальный `make verify`:
**1903 collected**. Финальный `make test`: **1900 passed, 3 skipped**,
18 subtests, 278,03 с. Пропуски: POSIX reuse, macOS supervisor и необязательная
offline embedding spec. Rust core/API с Edge/runtime: **65/10/7**.
Совместимость автономных навыков и их отдельного runtime включена в gate.
Документы: **23 passed**; public-check/diff-check прошли.
Это не приёмка установленного приложения.

Общий форматный процесс/классификация и специальные обработчики ещё Python.
Не проверены этим кандидатом модельный ответ Qwen, чистая Windows и новая
редакция PDF при аварии Edge. Полное удаление app Python не объявляется.
