# Проверка поиска и происхождения источников · 805

Кандидат сохраняет Qdrant, SQLite, текущие назначения моделей и ранжирование.
Диагностика в «Лес знаний → Проверить поиск» вызывает `/api/search` с
трассой и ограниченным дочитыванием. Генерация ответа не выполняется.
Трасса показывает сведения, доступные для фактически использованных каналов.

При полном обходе папки пропавший источник получает `MISSING`. Синхронизация
сохраняет его поисковые данные. Чат и просмотр индексированных документов
исключают помеченный источник. При недоступности или неполном обходе статус
отсутствия не выставляется. Отдельный администраторский запрос
`POST /api/rag/external/purge-missing` принимает `path`, `dataset_id`,
`file_names` и подтверждение `"confirm": "purge_missing_index"`.
Оригиналы остаются доступны только для чтения.

Новые записи индекса сохраняют SHA-256 файла. Источник с таким отпечатком
проверяет текущие байты перед открытием. При подмене файла сохранённая цитата
остаётся видимой. Старые ссылки без отпечатка помечаются отдельно. Отпечаток
различает версии файла, а применимую редакцию надо определять по самому
документу и доступным сведениям о его статусе.

`GET /api/documents/by-id/{doc_id}/clause?number=15.3` читает индексированные
фрагменты явно нумерованного заголовка в одном документе. Похожие номера
отсекаются, а содержимое и происхождение подтверждает текущий Qdrant.
Действие доступно из лаборатории, через `read_source` с аргументом `clause`
и через `les tool read_clause` / одноимённый MCP-инструмент. Покрытие
ограничено структурой, которую сохранил парсер. Результат помечен
`indexed_fragments`. Если на странице нет выделенного заголовка, точное
чтение может не найти пункт.

## Сравнение с Msty Studio 3.0.0

Один каталог с копиями трёх файлов. LES 804 искал в отдельном тестовом наборе
с BGE-M3. Msty использовала стандартную локальную модель `TaylorAI/gte-tiny`
и Chunks Console. Генератор в сравнении не участвовал.

| Контроль | LES 804 | Msty 3.0.0 |
|---|---:|---:|
| Точное значение из TXT | 1 | 1 |
| Точная дата из PDF | 1 | 3 |
| Название строки и значение из XLSX | нет в первых 10 | 2 |
| Вопрос без ответа | выданы кандидаты | выданы кандидаты |

Для XLSX проверялось одновременное наличие подписи и значения. Одно и то же
значение встречалось в нескольких строках. В LES 804 подпись отсутствовала
и при чтении всех индексированных фрагментов файла. Кандидат 805 добавляет к
нормализованным строкам исходные ячейки, имя листа и физический номер строки.
На тех же файлах после повторной индексации LES 805 вернул нужную строку на
месте 3. Просмотр открыл лист `01-01-01`, строку 12. Скачанный оригинал совпал
побайтно с тестовой копией. Ссылка с другим отпечатком вернула конфликт.
Задание продолжилось после перезапуска и освобождения RAM, итог 3/3 файла.
В процитированной строке просмотр показывает сохранённое значение ячейки
и формулу, когда оба присутствуют в исходной книге.

## Отдельный разбор PDF

`uv run --isolated --locked --extra parsers python -m tools.evaluate_pdf_structure MANIFEST OUTPUT`
запускает локальный эксперимент с Docling 2.101.0. Манифест содержит
`documents` с `id`, `path` и списком `checks` с `id`, `page`,
`text` и необязательным `kind`. Скрипт сверяет SHA-256 перед разбором и
после него. В отчёт попадают метрики и совпадения, исходные фрагменты в
него не копируются.

На одном проектном PDF оба парсера нашли 2/2 ожидаемых якоря (LES 2,02 с,
Docling 41,62 с с инициализацией). На искусственной двухстраничной таблице
оба сохранили 3/3 строк на правильных страницах (0,02 с и 3,51 с).
Выборка подходит для дымовой проверки. Оценка качества сканов и сложной
вёрстки на реальном корпусе требует отдельной разметки. Рабочий парсер не менялся.
Обход дерева моделью по образцу PageIndex оставлен для сравнения с точным
чтением по корпусу с несколькими редакциями и размеченными пунктами.
