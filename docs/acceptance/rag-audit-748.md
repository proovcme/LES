# Build 748: аудит RAG, реранкер и ошибки

## Исправления

- Отключаемый локальный cross-encoder, offline worker с таймаутом, проверкой
  результата и статусом доступности. Чат, search API и debug принимают явный выбор.
- Устранена повторная сортировка в чате по совпадениям слов после RRF/реранкера:
  она отодвигала прямой ответ, найденный отдельным поисковым API на первом месте.
- Удалены точные дубли контекста, заголовки источников сохраняются вместе с текстом,
  карта доказательств ограничена реально переданным модели контекстом.
- Короткие тематические коды сопоставляются целыми словами: «ОВ» больше не
  совпадает с серединой «шкафов». Удалён скрытый extractor без назначения модели.
- Неудачное получение embeddings/частичная запись новых точек не удаляет старый
  индекс файла. Пустой результат чтения считается ошибкой, а не INDEXED с нулём.
- Понятные ошибки модели, сохранение вопроса и нового черновика, отсутствие
  ложного «Готово» после сбоя. Ошибка транспорта не запускает повторную генерацию
  с ещё одним полным таймаутом.

## Измерения поиска

Изолированная копия индекса: два настоящих проектных документа PDF/DOCX,
227 точек. Исходники только читаются. Фиксированная выборка 40 вопросов:
32 положительных и 8 без ответа. Положительные размечены по точным цитатам до
просмотра рангов. Это ещё не целевые 100 случаев и не весь пользовательский корпус.

| Режим | Evidence Recall@5 | Evidence Recall@10 | Медиана поиска |
|---|---:|---:|---:|
| Dense + Sparse + RRF, без реранкера | 53,1% | 95,3% | 0,28 с |
| С BGE-reranker-v2-m3, GPU | 96,9% | 100% | 2,67 с |

Метрика — средняя доля найденных размеченных опорных фрагментов по 32 вопросам;
несколько допустимых фрагментов могут подтверждать одну опору. Отрицательные
вопросы исключены из Recall, выдача поиска сама по себе не означает ответ.
Результат относится к этой модели и машине; Qwen3-Reranker и BGE-M3 late interaction
не сравнивались. Использованы уже имеющиеся среда и веса, ничего не установлено.

## Генерация и скорость

На шести вопросах Mara выявлена фактическая ошибка без реранкера и сомнительное
обоснование даже при правильном числе с реранкером. Найденное различие между
выдачей API и источниками чата воспроизведено на установленном приложении и
сведено к повторному lexical boost. После исправления установленная Mara получила
прямой ответ первым и указала правильные два устройства по 1250 кВА со ссылками
на подтверждающую страницу. Полный ответ занял 99,4 с при основном бюджете:
проблема скорости остаётся открытой. Метрики поиска нельзя выдавать за точность
ответов. Структурная проверка ссылок не проверяет смысловую подтверждённость.

В отдельном эксперименте уменьшение контекста до 24 000 символов и компактная
SOURCE_MAP дали успешные ответы примерно за 34–74 с, но связь с моделью несколько
раз обрывалась. Ошибочные попытки исключены из оценки скорости. Этот эксперимент
не доказывает устойчивого ускорения; уменьшенный бюджет не перенесён в основной
профиль. Главная задержка остаётся в обработке контекста моделью.

## Проверка и установка

Полные `make verify`, `make test`, `make public-check` выполнены. После исправления
порядка — 1 092 теста и 18 subtests без падений. Тесты включают ошибки
транспорта, повреждённые оценки реранкера, потерю источников при ограничении
контекста, отказ embeddings, частичную запись индекса и сохранение черновика.

Локальный патч 15 runtime-файлов поверх 747 и последующее исправление порядка
трёх файлов установлены с резервными копиями. Экспериментальный табличный harness
746 в установленный пакет не включён. Проверка выполняется установленным
embedded Python и нативным Qdrant на отдельном состоянии. В браузере подтверждены
включение/выключение реранкера, подсказка доступности, закрытие и повторное открытие
настроек. Чистая Windows, нативное окно и экранный диктор этим не проверены.
Полный установщик и публичный выпуск не обновлены.

В установленном интерфейсе отдельно отключено подключение в испытательном
профиле: показана причина с действием «включите в Подключениях», вопрос вернулся
в поле ввода, статус остался ошибкой. Основное подключение пользователя не отключалось.
На высоте окна 720 px автопрокрутка может увести сообщение выше видимой области;
оно доступно прокруткой, но это незакрытый дефект удобства.

## Открытые критерии

1. Проверка утверждение → точный фрагмент → оригинал, полные цитаты вместо preview.
2. 100 размеченных случаев, включая противоречия/устаревшие источники; измерение
   ложных подтверждений и отдельное сравнение судей. Судья не установлен.
3. Привязка fingerprint индекса/кэша к фактическому явному подключению embeddings.
4. Журнал поколений индекса и восстановление после аварийного завершения процесса.
5. Холодный запуск и память worker, удобная подготовка реранкера на чистой Windows.
6. Стабильные замеры полного ответа и первого токена без сбоев сети.
7. Фокус/автопрокрутка к сообщению об ошибке на невысоком экране.

Наличие этих критериев не позволяет объявить весь RAG проверенным или релиз готовым.
