# Проверка реального корпуса · кандидат 853

Проверка выполняется в отдельном локальном состоянии. Два предоставленных
каталога содержат 2011 файлов, среди которых 638 допускаются текущим
документным конвейером. Копии для аварийного сценария содержат настоящий
проектный PDF и книгу Excel. Исходники и назначения моделей рабочей
установки сохраняются. Личные пути, тексты и ответы находятся в приватном
рабочем каталоге вне репозитория.

## Обнаруженные и исправленные дефекты

- Word отвергал пользовательские стили, обычное оформление и объединения
  ячеек. Чтение стилей и таблиц расширено в `core/src/document/docx/`.
  Рисунки, формулы, сложная нумерация и иные неподдерживаемые структуры
  требуют отдельного расширения. Ошибка файла сохраняется в каталоге.
- Имя книги с точкой перед расширением давало недоступный служебный Parquet.
  Имена каталогов производных привязаны к SHA-256 полного ключа документа.
- Декларация диапазона XLSX включала десятки тысяч пустых оформленных строк.
  Потоковый reader теперь проверяет фактическое содержимое всего ограниченного
  XML и отказывает при содержимом за разрешённым окном.
- Иерархическое дополнение вытесняло точную строку таблицы из короткой выдачи.
  Server и Edge используют общий шаг сохранения двух сильнейших глобальных
  совпадений. Дочитывание родителей сначала передаёт совпавшие фрагменты.
- Резерв генерации зависел от большой заявленной ёмкости сервера при явно
  выбранном окне 8192. Он рассчитывается по выбранному окну. Полная страница
  заменяет прежние фрагменты этой страницы в модельном контексте.
- Поиск ограниченно повторяет чтение при конкурирующей публикации с проверкой
  поколения. Переполнение пишет размеры частей контекста в структурный лог.
- Занятые другие наборы голодали плановые сверки. Планировщик проверяет сроки
  между партиями. Ручное присоединение к автоматическому заданию сохраняет
  публичную квитанцию после его завершения.

## Проверка модели

На одинаковых контрольных вопросах использованы локальные BGE-M3 и Qwen3.5.
Пять вопросов охватывают количество в PDF, длину кабеля, два количества в
согласовании, физическую строку многостраничной книги и отсутствующее свойство.
Ответы сопоставляются с отдельно прочитанными страницами и ячейками. Совпадение
цифры в тексте ответа само по себе не засчитывает правильность.

Qwen 2B путала значения и инструментальные аргументы. Qwen 9B вернула правильные
длину кабеля, количества оборудования и параметры провода с листом и строкой.
Для Qwen 9B сохранены также ошибочное отсутствие датчика в Hybrid и остановка
Pull с `SOURCE_EVIDENCE_MISSING`. Режимы пока требуют дальнейшей оценки.
В одном ответе Hybrid модель добавила `file://` к относительным адресам API:
адреса оригиналов в карте источников работали, но ссылки в самом ответе были
неправильными. Этот дефект выдачи ссылок остаётся открытым.
Это контрольные сценарии, оценка качества всего корпуса ими не установлена.

## Авария публикации настоящего PDF

В тестовом экземпляре находилась копия реального многостраничного PDF,
276 точек прежней редакции. Во второй тестовой редакции переставлены две
существующие страницы. Исходный PDF сохранён побайтно.

Процесс остановлен в `staging` после подтверждения первой точки новой
редакции. Независимое чтение остановленного Edge обнаружило 276 прежних
точек и одну новую. После холодного запуска публикация завершилась.
Прежних точек осталось ноль, новая редакция содержит 276 точек. Старая
ссылка с SHA вернула 409, скачанный новый оригинал совпал с новым SHA-256.
История запроса, попавшего под остановку, сохранила `CHAT_INTERRUPTED`.

Qwen 9B прочитала оригинал на физической странице 5 до изменения и на
странице 6 после восстановления. В этих двух проверках номер страницы
был указан явно. Дополнительный запрос после восстановления прошёл через
`search_sources` и `read_pdf_source` без подсказки номера страницы. Модель
вернула нужную цитату со ссылкой на физическую страницу 6.

## Завершение приёмки

Все 638 допущенных документов обработаны до конечного состояния:
584 проиндексированы, 54 завершились с ошибкой. В двух исходных наборах
создано 73 437 фрагментов. Ещё 1373 файла из каталогов не входят в текущий
перечень документных форматов, включая DWG и служебные файлы. Наличие файла
в каталоге не означает поддержку его формата.

| Формат | Проиндексировано | Ошибки |
| --- | ---: | ---: |
| DOC | 106 | 0 |
| DOCX | 32 | 46 |
| PDF | 252 | 8 |
| XLS | 20 | 0 |
| XLSM | 6 | 0 |
| XLSX | 168 | 0 |

Ошибки: 46 `DOCX_READ_FAILED` и 8 `OCR_NO_TEXT`. Задания с такими файлами
имеют итоговый статус ошибки; успешное завершение всей партии не заявляется.
SHA-256 всех 638 исходных файлов повторно сверены с исходным снимком:
изменений нет.

На шести запросах к полному корпусу оптимизированный Rust API вернул HTTP 200.
Медиана внутреннего поиска dense + BM25 + RRF с иерархией составила
5111 мс; отдельная медиана эмбеддинга — 1881 мс. В эти числа не входят
генерация ответа и дочитывание родителя. В части замеров параллельно работал
контрольный чат, первые эмбеддинги были холодными; это наблюдение стенда,
не чистый сравнительный бенчмарк. Edge сообщил 73 862 точки и столько же
индексированных векторов, включая отдельные контрольные копии. Незавершённый
граф не объясняет измеренную задержку. Изоляция причин и ускорение открыты.
При длительной конкурентной публикации также наблюдался `INDEX_UPDATE_BUSY`
после исчерпания ограниченных повторов.

Проверки окончательных исходников: `make verify`, полный набор — 2057 passed,
2 skipped, 18 subtests, 43 warnings за 838,81 с. Пропуски относятся к POSIX TCP
и надзору за процессом macOS. Также выполнены 93 Rust unit tests и 41 целевой
тест оптимизированного API. Зелёные тесты не снимают перечисленные ограничения
форматов, качества ответов и скорости.

Проверен отдельный испытательный экземпляр 853. Установка пользовательского
патча, обновление рабочего индекса, публикация и выпуск этим отчётом не
подтверждаются. Приватные журналы и один повторно используемый индекс
для незавершённой оценки качества хранятся вне репозитория.
