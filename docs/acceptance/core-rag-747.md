# Build 747: основной путь RAG

## Найденные и исправленные дефекты

- Реальный PDF проходил OCR, но падал при получении векторов: общий транспортный
  лимит 32 КиБ не вмещал пакет embeddings. Клиент явно назначенной поисковой модели
  теперь посылает до 16 фрагментов и ограничивает ответ своего транспорта 1 МиБ.
  При превышении лимита пакет делится; одиночный отказ остаётся ошибкой.
  Модель закреплена на весь вызов, порядок, число, конечность и размерность векторов
  проверяются, частичный результат не возвращается. Общий транспортный лимит не изменён.
- Цитата с ID фрагмента открывала raw PDF внутри sandbox iframe, где плагин браузера
  не показывал страницу. Теперь просмотрщик разрешает исходник по ID/набору/имени,
  затем использует стабильный ID документа для собственного постраничного renderer.
  Доступны номер страницы, переходы, масштаб, оригинал, состояния загрузки/ошибки.
- Локатор `page=14` отображается как «стр. 14»; просмотр занимает ширину панели.
- Проверка поддержки инструментов получает 128 выходных токенов вместо одного:
  сервис Mara отвергал прежний слишком короткий запрос. Проверка остаётся
  настоящим вызовом требуемого инструмента, без подстановки успешного результата.

## Живая проверка кандидата

Отдельные каталог состояния, Qdrant и назначения моделей. Источники только читаются;
пользовательский индекс и назначения не изменены. Два настоящих документа PDF/DOCX,
227 фрагментов. Сбой PDF до исправления воспроизведён, после исправления оба готовы.

На локальной Mara четыре контрольных запроса дали:
- три категории надёжности: II / I / III — соответствуют странице оригинала;
- система заземления: TN-C-S — соответствует источнику;
- температура для теплозащиты: −24 °C — соответствует источнику;
- гарантийный срок кабеля: число не выдумано, заявлено отсутствие сведений.

Это малая функциональная выборка, не Recall@k и не доказательство качества на 100
контрольных вопросах. Ответ об отсутствии сведений ограничен просмотренными
фрагментами, а не доказывает отсутствие во всём корпусе. Генерация заняла 50–88 с;
поиск — доли секунды. Латентность модели и избыточный контекст требуют отдельного замера.

Целевые регрессии: 84 прошли, включая реальный рендер PDF, неизменность оригинала,
ID фрагмента → исходный документ, последовательные/разделённые пакеты embeddings,
дрейф размерности и отказ без частичного результата.

## Статус поставки

`make verify`, `make test` (1065 тестов, 18 subtests, 24 предупреждения) и
`make public-check` прошли. Локально установлены семь runtime-файлов с проверкой
baseline 745, резервной копией и SHA-256. Экспериментальные файлы табличного harness
746 в установленный патч не включены; они остаются только в исходном кандидате.

На установленном embedded Python и отдельном проверочном состоянии подтверждены:
сохранённый диалог после перезапуска, открытие доказательства на странице 14,
переход 14 → 15 → 14 с настоящим изображением PDF, закрытие панели и возврат к
диалогу. Сохранён снимок установленного просмотрщика. Источники пользователя,
его основной индекс и назначения моделей при этой проверке не изменялись.

Пятый вопрос отправлен через интерфейс установленной версии: мощность ТП —
2×1250 кВА, ссылка на правильную страницу 14, завершение через 75 с. Отдельно
измерен настоящий SSE: первый текст через 53,625 с, семь порций, последний через
58,573 с, корректный ответ со ссылкой. Статусы и завершение присутствуют;
ожидание первого текста остаётся открытой задачей производительности.

После отдельного подтверждения владельца Mara назначена моделью ответов в основном
состоянии Light. Проверки chat/streaming/tools прошли; основной API ответил «готово».
Смена использует новую редакцию назначения с проверкой предыдущей редакции;
старое подключение сохранено, поисковая модель не менялась. Перед сменой сохранена
резервная копия базы. Это отдельное разрешённое изменение после изолированной приёмки.

Публичный EXE и GitHub не изменены. Проверка браузера не заменяет приёмку
нативного WebView2, экранного диктора и чистой Windows.
