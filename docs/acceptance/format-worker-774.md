# Кандидат 774 · обработчик под управлением Rust

Статус: исходники и отдельная библиотека. Установленный локальный патч 773 не
менялся. Полного установщика, установленной приёмки 774 и публичного выпуска нет.
Изменений интерфейса в этом этапе нет. [Контракт](../modules/format-worker.md).

## Проверено без моделей

- Новый Rust core собран offline из существующего Cargo-кэша в отдельный каталог;
  квитанция ABI/SHA сохранена. Установленная DLL не заменялась.
- Rust: 11 тестов, включая bounded framing и полный обход с Unicode/лимитом.
- Новый интеграционный gate: 12 тестов. Повторный вызов использует тот же PID;
  stop завершает его; авария с exit 37, неверный JSON, оборванный ответ, поток
  свыше лимита и зависание дают ожидаемые коды. Следующий файл запускается чисто.
- Отмена активного задания завершает его потомка; на Windows аварийный выход
  родительского тестового процесса автоматически завершает принадлежащее ему дерево.
  Завершались только собственные процессы стенда, без поиска по общим именам.
- Штатный shutdown API зарегистрирован с остановкой обработчика; это проверяется
  с живым тестовым worker. Отдельный idle-прогон освободил процесс за 64,94 с
  после последнего ответа (60 с простоя + период проверки до 5 с).
- Штатный `_convert_file` сравнивался с inline-путём: PDF с текстовым слоем,
  DOCX, XLSX, CSV, UTF-8 и уверенно распознанный CP1251, EML с русским содержимым.
  Текст, route и payload совпали; случайные UUID MarkdownNodeParser не сравнивались.
  SHA исходных файлов не изменились. Ни чат, ни эмбеддинг-модель не вызывались.
- Проверены понятное сообщение и ограниченная политика повтора таймаута.
  Результат обхода с превышением лимита/нечитаемой папкой не принимается как пустой.

Существующие mock-тесты парсеров явно используют inline, новый интеграционный
gate выбирает native и запускает настоящий адаптер. Поэтому весь общий тестовый
прогон нельзя называть полной приёмкой native-парсеров на пользовательском корпусе.
Первый общий прогон выявил тест отказа доступа, привязанный только к `os.walk`;
он расширен на оба движка с сохранением требования отказа вместо пустого результата.

## Ограничения

Это не доказательство корректности любого файла. Не приняты тяжёлый Docling/OCR,
все старые Office/MSG/PST, токенизаторы всех моделей, live embeddings и публикация
реального пользовательского набора через новый worker. Сквозной установленный путь
и измерения холодного старта/памяти/скорости остаются отдельной приёмкой.
Rust-ограничение памяти сейчас 2 ГиБ на дерево Windows-обработчика; сложным файлам
этого может не хватить. На Unix аварийный выход родителя и memory cap не приняты.
Новый обход заменяет только `external_scan.source_files`; остальные walkers и
watchers остаются Python. Сам Python runtime и форматные зависимости не удалены.

## Общие gates

- `make verify`: синтаксис, версия/карта runtime, 1422 собранных теста.
- `make test`: 1418 passed, 4 skipped, 18 subtests; 116,93 с.
- `make test-mail`: 66 passed, 7,99 с.
- Rust fmt check и `cargo test --locked --offline`: 11 passed.
- `git diff --check`: без ошибок пробелов.

Новые native-тесты требуют отдельно собранной DLL и `LES_CORE_LIBRARY`;
пустой/corrupt receipt не обходится. Общий прогон выполнен с новым ядром и
`LES_CORE_MODE=native`, форматный режим большинства mock-тестов — inline,
нового интеграционного gate — native. Модели и пользовательский корпус не менялись.
