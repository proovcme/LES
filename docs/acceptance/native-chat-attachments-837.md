# Приёмка кандидата 837

Область: нативные вложения и table_document. Рабочий экземпляр и его индекс не
переключены, установщик не выпущен. [Контракт](../modules/native-chat-attachments.md).

Выполнены реальные вызовы Rust DLL и отдельного Rust API с недоступным Python
приложения и пустым PATH. Модельный транспорт в автоматических регрессиях —
детерминированный HTTP-стенд; он проверяет исполнение, не качество модели.

- Rust core: 90 passed, включая семь новых проверок
  оригиналов/JSON-коллизии/истечения/изображений/координат CSV.
- Rust API: 16 passed с Edge и 16 без Edge, включая повторяющиеся provider ID
  в разных группах вызовов. Удаление старого табличного пакета не удаляет чужой результат.
- Целевой gate: 65 passed (native chat/вложения/форматы/табличный журнал/
  адресные окна/очистка), включая автономный внешний Python-навык.
- После приёмки Qwen уточнены доступность схем и восстановление вызова:
  native chat/вложения — 19 passed. Проверены read → save → повторный read через
  общий доступ, сохранение допусков и чтение настоящего PDF после ошибки аргументов.
- `make verify`: 2015 collected. Финальный `make test`: 2013 passed, 2 skipped,
  18 subtests passed, 567,82 с. Есть предупреждения прежнего NiceGUI/lifespan/
  локального Qdrant; ошибок очистки временных каталогов нет.

Проверены хеши оригинала, недоверенный preview, ошибка модели в истории,
реальное декодирование изображения, отсутствие image data URL в ответе,
сохранение всех решений и исключение старых пакетов из контекста,
незавершённая квитанция и продолжение задания после остановки процесса.

Успешные тесты удаляют данные после teardown и закрытия SQLite; намеренно упавшие
call/teardown сохраняют диагностические файлы. Пустой каталог резервирует имя
pytest и исключает повторное использование пути, ещё находящегося в кеше.
Два предварительных прогона остановились на этой коллизии имён и на Windows-
перекодировании CRLF тестового CSV. Исправлены очистка/fixture, строгие ожидания
и сохранение настоящих пустых строк оставлены. Финальный полный gate пройден.

## Адресное чтение: контролируемый замер

Синтетический снимок: 20000 непустых строк, окно 4 × 4, 20 чередующихся прогонов.
Проверено точное равенство результата прежнему Python-пути восстановления

В замер входят получение данных из SQLite, разбор и построение окна; Rust вызван
через ABI. Модель и HTTP не входят. Это ускорение адресного чтения, не всего чата
и не доказательство ускорения всех вариантов Excel/парсеров.
Временная база бенчмарка удалена сразу после замера.

## Настоящая Qwen и копия корпуса

Выборка из нашего ранее скопированного корпуса: два реальных документа, PDF и XLS.
Native API работает с недоступным приложением Python/пустым PATH и отдельным Edge.
Qwen3.5:9b нашла документ, по повторному запросу вызвала `read_pdf_source` для
страницы 2. Подтверждены ID, полнота страницы, ссылка, совпадение SHA-256 выданного
оригинала и неизменность обоих исходников. Те же PDF и XLS загружены multipart
через Rust: текст получен, хеши сохранённых оригиналов совпадают. PDF-вложение
передано настоящей Qwen; клиентский поддельный preview не использован.

Первый путь Qwen не завершал дочитывание: были поиск без чтения, ошибка схемы
расширения и остановка после списка. Добавлены явная схема при ошибке и видимое
чтение PDF в режиме документов. После этого физическое чтение прошло по отдельному
повторному запросу. Выполнение всей инструкции с первого сообщения **не доказано**;
соответствующая задача в бэклоге остаётся. Нельзя считать исправленным поведение
модели только потому, что инструмент работает. Независимая проверка фактов не проведена.

Копия индекса, состояния и исходников удалена после проверки; оставлены компактные
журналы/ответы вне репозитория. Загруженная для проверки Qwen выгружена. Установка,
назначения моделей и рабочий индекс пользователя не изменялись.
Это не доказательство полного Python-exit или всех режимов публичного upload.
