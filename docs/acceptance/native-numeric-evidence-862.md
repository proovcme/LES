# Кандидат 862: число связано с ячейкой, а не порядком PDF-потока

Работа в исходниках и на прежней отдельной копии пользовательских наборов.
Установленный LES, его индекс и исходные файлы не переключены. Назначения
Qwen3.5:9b и bge-m3, окно 8192 и резервы модели не менялись.

## Подтверждённые причины

1. Визуально обычная таблица PDF извлекалась по порядку команд рисования:
   единицы и номера колонок оказывались отдельно от названий и количеств.
   Наличие всех страниц ещё не обеспечивало связь числа с нужной позицией.
2. Простой вывод Markdown не делал связь с колонкой достаточно явной.
   В документе изменений Word модель подменяла номер листа кодом изменения;
   исходная строка содержала оба числа в разных столбцах.
3. Подмена поискового текста геометрической таблицей ухудшила ранжирование.
   Этот промежуточный вариант отклонён. Улучшать представление для чтения
   нельзя ценой неявного изменения Dense/BM25.
4. Модель самостоятельно объединяла похожие наименования и выдавала
   незапрошенные суммы. Представление данных и договор ответа проверяются
   раздельно; исправление парсера не объявляется доказательством всех выводов.
5. В Push оставалось требование отвечать обычным текстом, конфликтующее с
   формой табличного ответа. Форма теперь выбирается один раз на раунд.
   Составные пары числовых адресов и выбор заголовка моделью также отклонены
   после повторов: адрес строки стал одним буквальным `S…R…`, заголовки модель
   не назначает. Это изменения общего договора, а не словаря под документы.
   Из договора убран пример с действительным числовым адресом: он не должен
   конкурировать с настоящими идентификаторами из контекста.

## Конечный путь данных

`исходный PDF → прежний поисковый текст + геометрические ячейки страницы`

`Dense/BM25/RRF → проверенный индексированный родитель → представление ячеек → бюджет окна → Qwen выбирает строки → Rust копирует значения и формирует цитаты`

PDFium читает символы, координаты и преобразованные линии сетки, включая
вложенные формы. Подтверждаются границы ячейки, а не названия колонок по
предметному словарю. Многострочное содержимое остаётся внутри своей ячейки.
Незаполненное количество не становится нулём. Обе стороны толстой линейки
не создают дополнительный столбец. Между соседними исходными цифрами
не добавляется пробел по расстоянию между нарисованными контурами.
Символы вне подтверждённых ячеек сохраняются отдельно с явной пометкой.

Поисковый `text` не меняется геометрическим представлением. Поле
`pdf_page_view` со схемой `les.pdf-page-view.v1` и SHA-256 записывается один
раз на физическую страницу, на первый индексированный фрагмент. При
дальнейшем разбиении под эмбеддинги это поле не дублируется. Полный временный
набор представлений не копируется в каждый payload или журнал маршрутизации.
Пределы: 16 000 символов на представление, 1 МиБ представлений на файл;
более крупные данные сохраняют прежнее чтение, не объявляются ячейками.

Общий читатель проверяет поколение, область, хеш оригинала и хеш представления,
затем заменяет фрагменты одной страницы одним её представлением. Квитанция
указывает действительный индексированный якорь, в payload которого хранится
прочитанное представление. Поиск и модельные инструменты используют тот же
читатель. Неверный хеш даёт `PDF_PAGE_VIEW_INVALID` до вызова модели и
человеческую причину с предложением повторной обработки документа.

Общий упаковщик показывает табличные ячейки с адресами C1, C2 и т.д., строки — R.
Позиции пустых ячеек сохраняются адресами; одинаковые соседние значения
записываются диапазоном колонок, без угадывания смысла. Это проекция для
модели: исходные цитаты в журнале и текст для поиска остаются прежними.
Правило применяется к полным строкам PDF/Word Markdown, без имён файлов,
терминов проекта или ожидаемых ответов. Общие имя документа и реквизиты
передаются один раз в полной единице чтения, ссылки остаются постраничными.

Одного договора ответа оказалось недостаточно: Qwen продолжала ошибаться при
переписывании уже правильно переданных значений. Поэтому для табличных фактов
модель копирует буквальные адреса видимых строк, не переписывая ячейки.
`api/src/chat/table_facts.rs` строит реестр только из целых блоков, реально
поместившихся в окно. Неизвестная строка не принимается. Rust копирует исходные
ячейки в ответ и добавляет ссылки. Заголовок допускается только по явному
Markdown-разделителю этой непрерывной таблицы, не переносится через обычный
текст или с другой страницы. Если его нет, показывается исходная строка,
без выдуманных названий колонок и служебных C-адресов в пользовательском ответе.
В смешанной выдаче текстовый фрагмент (например, строка Excel с полями)
имеет отдельный идентификатор `S…`: физический номер строки не выдаётся за
адрес извлечённой таблицы. Граница цитаты хранится байтовым `body_offset`
в исходном блоке без второй копии текста; при выборе копируется именно
оригинал цитаты, без служебных ID/SHA и заголовка источника.
Строки Excel с настоящими `sheet_name`/`row` помечаются как структурированные
записи: форма «именованные поля» не обходит контроль таблицы. Для числового
ответа по обычному тексту в режиме чтения действует тот же финальный договор:
цифровой черновик вызывает один повтор с выбором исходного фрагмента. Поэтому
собственный противоречивый расчёт модели в старом DOC не попадает в ответ.
Обычный ответ без цифр может оставаться текстом. Агентные операции и диалог
без документного контекста этой проверкой не переводятся в извлечение цитат.
Граница чтения: Push без активного табличного задания с любым профилем
и документный ответ в профилях кроме Agent. Штатный новый диалог имеет
профиль Agent; это не выключает проверку
в Push, где инструменты всё равно не предоставляются. Agent с инструментами
в Pull/Hybrid или с активным табличным заданием не объявляется покрытым
этим договором.

Суммы по явно выбранным колонкам вычисляются проверенной десятичной арифметикой
с 12 знаками после запятой. Пустое значение не ноль, разные единицы не складываются,
повторная ссылка на строку не удваивает сумму. Переполнение даёт отказ.
Пробелы допускаются как правильная группировка тысяч; раздельные числа или
переносы строки не склеиваются в одно значение. Оригинальные ячейки не меняются.
Арифметика принимает только отдельные числовые ячейки: значения внутри обычного
текстового фрагмента или записи «имя поля: значение» не извлекаются для суммы
по догадке. Такие фрагменты доступны для буквального цитирования.

Свободный числовой ответ в документном режиме чтения не выдаётся вместо этого договора.
Есть один повтор в существующем цикле чата, затем понятная ошибка. Сырые JSON
и отвергнутые модельные числа не отправляются в поток. Артефакт
`les.table-facts.v1` сохраняет строки, ячейки, реквизиты источника и операнды суммы;
`source_rows_verified` означает подтверждённое копирование, а не семантическую
правильность выбора позиции. Обычный ответ без чисел не получает эту отметку.
Проверка не доказывает релевантность выбранной строки и не является судьёй
выводов об отсутствии данных. Эти ограничения проверяются отдельно на корпусе.
Защита не зависит от флага «только выбранные источники»: обычный чат с наборами
использует тот же договор при наличии фактически доставленных доказательств.
Черновик документного ответа удерживается до проверки; статусы продолжают
поступать. Обычный чат и агентный поток сохраняют прежнюю передачу текста.

Выбранная строка также становится `source_map.quote` только для совпавших
номера, документа и SHA-256. Она сохраняется в истории и открывается по
цитате: отсутствие snippet у индексированного родителя больше не создаёт
пустое окно источника после проверенного числового ответа.

Форма не полагается только на промпт: если подключение подтвердило
`structured_output` и раунд уже без инструментов, используется существующий
`response_format`. В Ollama это нативный [`format` с JSON Schema](https://github.com/ollama/ollama/blob/main/docs/capabilities/structured-outputs.mdx).
До 512 допустимых адресов задаются перечислением для декодера, при большем
числе остаётся ограничение формы и независимая проверка адреса в Rust.
У совместимых API схема формы учитывается в резерве контекста; возможности
провайдера не предполагаются без проверки. Неизвестная возможность оставляет
тот же проверяемый JSON-договор и один повтор, без отключения проверки ячеек.

Проверка Ollama подтверждает JSON через тот же нативный транспорт с отключённым
размышлением и проверкой завершения, которым пойдёт чат. HTTP 200 совместимого
маршрута с пустым ответом не считается подтверждением схемы. Пустой `rows`
даёт ограниченное сообщение о недостаточности прочитанных данных и статус
`insufficient_evidence`, а не подтверждённый факт об отсутствии в целом файле.

## Проверки

До исправления два варианта PDF с записью по колонкам воспроизводили потерю
связи строк; обычный текст проходил. Проверены перенос/масштабирование сетки,
толстые линии, многострочная ячейка, десятичные/отрицательные значения, ноль
и пустая ячейка. Контроль обнаружил и устранил искусственный пробел внутри
десятичной записи. Сквозная проверка подтверждает прежний поисковый текст,
ячейки в настоящем запросе к модели и отказ при повреждённом хеше.

51 модульная проверка Rust API и 54 целевые интеграционные проверки прошли.
Отдельно прошли все 17 проверок режимов поиска: прежние модельные заглушки
обновлены под договор выбора исходной строки, проверки области, повторов,
истории и ошибок сохранены.
Окончательные `make verify` и `make test` прошли: 2154 passed, 2 skipped,
18 subtests passed; общий прогон занял 952,88 с. Промежуточные варианты
не засчитываются как финальная приёмка Qwen.

## Реальные документы и границы

На прежней копии повторно обработаны три PDF из двух наборов; SHA-256
оригиналов сохранились. Промежуточный вариант изменял поиск и не принят.
После разделения представлений поисковый текст каждой страницы контрольного
PDF совпал с исходным, нужный документ снова находится первым. Идентификаторы
точек при публикации могут изменяться; они не выдаются за прежние идентификаторы.

В запросы Qwen передаются только исходные вопросы и область двух наборов.
Ожидаемые документы, страницы, строки и числа находятся лишь у проверяющего.
Полные вопросы, ответы, матрицы и хеши доставленного текста остаются в
приватных доказательствах вне публичного репозитория.
Независимая сверка 12 ответов (Push, Hybrid и браузерный диалог) проверила
17 привязок выбранных строк/фрагментов к фактически переданному контексту,
документу и SHA-256: расхождений копирования нет. Нерелевантный, но точно
скопированный источник при этом остаётся смысловой ошибкой.

## Смысловая проверка Qwen и открытые дефекты

Это контрольная серия на копии корпуса, не оценка качества всех подключённых
документов и не закрытый набор из 100 вопросов. Ожидаемые значения, строки
и документы не передаются модели.

| Сценарий | Наблюдение | Что не засчитывается как успех |
|---|---|---|
| Шесть положительных числовых вопросов, Push | Нужные значения и документы присутствуют во всех шести ответах; копирование связано с переданными строками/фрагментами | Иногда выбираются дополнительные заголовки или связанные строки; это не доказательство идеальной точности отбора |
| Вопрос о неподтверждённом сроке | Финальный контроль вернул `insufficient_evidence`, без вымышленного срока | Нужная спецификация не найдена; отсутствие показателя во всём документе не установлено |
| Вопрос о конкретном согласовании | Скопированы значения из технического обоснования; самодельный противоречивый расчёт не выпущен | Нужное заключение не найдено. Чужой документ с совпадающими числами не подтверждает согласование; сценарий не принят |
| Три вопроса с инструментами, Hybrid, профиль Search | Два содержат нужные строки; один завершился ограничением данных после новых поисков | Общая цепочка выбора и удержания источников ещё нестабильна |
| Новый диалог, профиль Agent по умолчанию, Push | Найдены нужные строки разных страниц; по ссылке показаны сохранённая цитата и оригинал нужной страницы, проверен возврат | Это браузерный контур на копии, не установленное Windows-окно |
| Новый диалог, Agent/Pull | Модель не нашла существующий нужный документ | Режим поиска по инициативе модели остаётся открытым дефектом; default не переключён скрытно |

Браузерный Push-путь проверен без прошлых ответов и ручного выбора файла:
два исходных набора → исходный вопрос → ответ → цитата → реальная страница
PDF → возврат → перезагрузка → та же сохранённая цитата. Режим Push выбран
явно только в отдельном проверочном диалоге. Назначения моделей не менялись.
Проверка источников и точности выбора требует дальнейшего отдельного цикла;
`source_rows_verified` не превращает перечисленные отказы в успешные ответы.

Существующим PDF для автоматического использования сохранённых ячеек нужна
повторная обработка. Явный `read_pdf_source` читает геометрию оригинала сразу;
версия такого результата отмечается `les.pdfium.page.layout.v2`. Обычный текст
без подтверждённой сетки сохраняет прежнее представление. Этот этап не
добавляет распознавание структуры растровых сканов и не гарантирует правильность
всех числовых выводов модели. Рабочий индекс и публичный выпуск не обновлены.
