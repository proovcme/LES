# Источники, контекст и достаточность ответа — кандидат 865

Продолжение [аудита 864](rag-architecture-audit-864.md). Рабочая установка и индекс
не переключаются. Используется прежняя копия корпуса: 638 документов, 82 203
исходных фрагмента, два набора. Новых моделей, назначений, зависимостей,
реранкера или отдельного судьи нет.

Расширенная [проверка обзорных справок](rag-synthesis-865.md) выявила
невыполненные задачи синтеза: четыре задачи, десять запросов, ни одна готовая
справка не принята. Результат 16/20 ниже относится только к точечным вопросам.

## Причины и исправления

| Причина | Изменение | Граница доказательства |
|---|---|---|
| Настройка краткого ответа обрезала служебные вызовы и JSON выбора строк | Дополнительный ограничитель краткости применяется к завершению без схем. Вызовы и structured output используют уже зарезервированный лимит профиля | Окно, назначение модели и верхняя граница профиля не увеличены |
| После успешного Rust-чтения промпт всё равно требовал выбрать инструмент перед ответом | В Search подтверждённые доказательства переводят модель на договор ответа; уточняющие инструменты остаются доступны. Агентный договор действий сохраняется | Отдельная проверка сравнивает фактический промпт до и после чтения |
| Навигация содержала только первые прочитанные совпадения | Карточки начального поиска охватывают найденный пул, до 64 документов. Они отделены от доказательств | Наличие карточки не означает чтение и не гарантирует релевантность |
| Несколько поисковых фрагментов одной материализованной PDF-страницы тратили квоту, а после раскрытия превращались в одну страницу | Совпадающие единицы чтения определяются до квоты документа и начального лимита. PDF без полной проекции сохраняет отдельные фрагменты | Идентичность учитывает набор, путь, SHA-256 и страницу; явная пагинация поиска сохраняет весь пул |
| Подготовка жёстко отсекала текст на 6000 символах до учёта реального окна | Предварительный IO-предел вычисляется из назначенного окна и резервов, не выше прежней границы reader 16 000. Окончательный допуск остаётся у общего packer | Контекст и роль модели не увеличены; проверяется весь помещающийся PDF длиннее прежнего порога |
| Полное раскрытие первого файла вытесняло другие найденные фрагменты | Сначала допускаются ранжированные начальные фрагменты, затем полные документы и родители в оставшемся бюджете | Не меняется Dense/BM25/RRF, текст не обрезается внутри блока |
| Дополнительное чтение могло неявно сузить область фактов и потерять уже прочитанную сторону сравнения | Такой фильтр исключён: допущенные чтения сохраняются, приоритет и вытеснение определяет общий packer | Отбор релевантных источников не подменяется удалением уже полученных доказательств |
| Дополнительные карточки раздували обязательный запрос | Начальная навигация ограничена 2400 символами и передаётся как необязательный checkpoint после доказательств. Квитанция инструмента использует меньшую проекцию | Скрытые карточки не объявляются проверенными |
| Исполнитель считал вложенные массивы источников и квитанций отдельными результатами | Для нативных search/read_source/read_excel установлена граница 256 вложенных элементов; прежние 24 000 символов и максимум 32 фрагмента reader сохранены | Общая политика внешних/MCP-инструментов не ослабляется |
| Переполненная ссылка хранилища принималась за полноценный ответ инструмента | Адаптер проверяет также имя tool. Ошибка сохраняет TOOL_RESULT_BUDGET_EXCEEDED вместо TOOL_RESULT_MISMATCH и не становится доказательством | После ошибки чтения уверенный ответ не допускается |
| Модель смешивала doc_id одного файла с dataset_id другого | Обычная схема reader для модели требует один зарегистрированный doc_id; страница и SHA-256 остаются | Публичный API и проверки явных пар dataset/path сохранены; конфликт не исправляется угадыванием |
| Совпадение названия строки принималось за наличие показателя | Финальный табличный договор требует answerable, rows, sums. false допускает только пустые строки/суммы; true требует строки видимого окна | Решение модели не является независимой проверкой смысла |
| Суммирование предлагалось для текстовых абзацев | При отсутствии числовых ячеек schema запрещает операции суммирования | Прежняя точная арифметика и проверка единиц сохранены |
| Схема суммы разрешала любой положительный номер колонки, включая несуществующий | Номер ограничен шириной видимой таблицы и колонками с числовыми ячейками; текстовый абзац не создаёт арифметический операнд | Финальная проверка выбранных строк и единиц остаётся обязательной: колонка, допустимая в одной таблице, может быть недопустима в другой |
| Расширение окна считалось уже потраченной попыткой исправить числовой ответ | Переход к финальному окну отделён от одной попытки исправления структурированного выбора. Обратная связь сообщает ошибку операции без возвращения отвергнутых значений как доказательств | Повторная неверная операция останавливает ответ и сохраняет причину; общий срок и лимит вызовов не увеличены |

## Отклонённые эксперименты

Дополнительная стадия выбора документов Qwen по карточкам, даже с локальными
номерами и кратким исходным текстом, ухудшила ответы на ранее рабочих вопросах.
Она удалена вместе с ReadPlan и отдельным модулем выбора. Дополнительного
вызова модели перед обычным RAG нет.

Выделение слов источника моделью и отдельный BM25 по целым физическим
документам проверялись только в исследовательском контуре. На одинаковых
вопросах устойчивого улучшения не показали; в приложение не перенесены.
Принудительное дочитывание после неподтверждённого первого ответа также
ухудшило один ранее рабочий вопрос: модель выбирала другой вид источника.
Этот эксперимент удалён вместе с его состоянием и предвалидацией.

Усиление поиска по имени файла проверялось отдельно, без изменения индекса.
Без учёта обозначения и вида документа оно поднимало одноимённые ведомости
другого раздела. Ограничение по буквенно-числовым обозначениям не устранило
регрессии, поэтому вариант в приложение не перенесён.

Индекс, статистика BM25, формула RRF и назначения моделей не изменены.

## Отдельная причина лексических промахов

В `core/src/lexical.rs` анализатор `les.lexical.v2` снимает первое совпавшее
окончание из собственного списка. Он не эквивалентен русскому морфологическому
анализатору: `заключение` и `заключения` дают `заключен` и `заключени`,
`ведомость` и `ведомости` — `ведомост` и `ведомос`, `система` и `систем` —
`систем` и `сист`. Формула BM25 при этом остаётся корректной, но совпадающие
по смыслу словоформы попадают в разные postings.

Это подтверждённый долг анализатора, не объяснение всех ошибок ранжирования.
Пробные добавления окончаний только в запрос не дали устойчивого улучшения
и в продукт не включены. Молча менять `v2` нельзя: уже сохранённые postings
построены с прежними правилами. Нужны версия анализатора, одинаковая подготовка
индекса и запроса, проверка обозначений/чисел и сравнение на копии до миграции.
Изменение словаря анализатора не требует повторного расчёта dense-векторов,
но требует совместимой переподготовки лексического индекса.

## Проверки

`make verify` выполнен: договор версии, карта исполнения, 269 пар method/path,
синтаксис и сбор 2172 тестов. Это сбор тестов, не результат их исполнения.

До последнего изменения состояний ядра Rust API дал 67 passed. Регрессия
«расширение окна → неверная сумма → исправление / повторная ошибка» показала,
что раздельных флагов в API недостаточно: `AgentLoop` возвращал
`AGENT_COMPLETION_REVISION_INVALID`. Подготовка финального окна теперь
выделена в `prepare_answer_window`, а `revise_completion` сохраняет одну
попытку исправления. В обоих переходах инструменты остаются закрыты,
бюджет действий и срок не восполняются. Добавлен отдельный тест ядра.
После исправления переходов ядро и API пересобраны в общем графе с Edge:
110 тестов ядра и 67 API прошли. Через настоящий Rust HTTP-путь выполнены
шесть случаев Search/Agent: обычное расширение, исправление неверной суммы
после расширения и повторная ошибка с остановкой и записью исходной причины.
Все шесть прошли. Это управляемые ответы провайдера, не проверка качества Qwen.

Локальная отладочная DLL получила новую квитанцию с фактическим SHA-256,
`build_profile=debug`, `acceptance_only=true`, `remapped_paths=false`:
сборка не выполнялась с remap-флагами. Такая квитанция годится для локальной
приёмки и намеренно не подходит для публичного staging. Ложный признак
`remapped_paths=true` не переносится из прежнего файла.

Предшествующая сборка прошла две серии по 20 запросов к назначенной Qwen3.5:9b
на копии корпуса, без ручного выбора файла. В последней серии 18 ответов
вернулись без ошибки API; 15 из 20 соответствуют эталонным источникам,
значениям и требуемым страницам/строкам. Это ограниченный диагностический набор,
не оценка качества всего корпуса и не 100 контрольных вопросов.

В той серии оставались пять случаев: поиск нужного согласования, ограниченный отказ без
проверки нужной спецификации, отказ на вопрос о турникетах и две ошибки
табличной операции. Последние две требовали проверки после исправления переходов
ядра и не засчитывались исправленными по одному успешному повтору другого вопроса.
В положительных ответах встречаются лишние строки — наличие всех нужных
данных не доказывает точность отбора каждой добавленной строки.

Для распределённого по нескольким строкам списка изменений эталон проверяет
все требуемые номера в записях аннулирования нужного документа. Требование
уместить весь список в одну строку было ошибкой измерителя; оно исправлено
только в частном испытателе, без изменения ответа приложения.

После исправления переходов выполнена ещё одна серия из тех же 20 вопросов,
с тем же назначением Qwen3.5:9b и без выбора файла. В 16 случаях присутствуют
все требуемые эталонные сведения и правильные ссылки; 19 запросов завершились
без ошибки API. Независимая проверка этих 19 ответов подтвердила копирование
выбранных ячеек/выдержек из последнего переданного окна и совпадение ID,
SHA-256 и цитат. Она не доказывает релевантность выбранной строки.

Четыре случая остаются открытыми: нужное согласование не найдено; отказ о
гарантии не опирается на нужную спецификацию; запрос о турникетах не даёт
подтверждения; запрос о разъёмах повторно выбирает неприменимую табличную
операцию и завершается `TABLE_VALUE_INVALID`. Прежняя ошибка на запросе о
массе/количестве щита в этой серии устранена с корректной строкой источника.
Это наблюдение одного повтора, не гарантия устойчивости всех ответов модели.
Медиана полного ответа — 14,105 с; ускорение по этому прогону не заявляется.

Полный `make test` кандидата 865 завершён: **2170 passed, 2 skipped,
18 subtests passed**, 53 warnings, 1076,93 с. `make verify` также прошёл.
Автоматическая проверка
отклонила удаление собственных временных каталогов и отладочных символов
с причиной `blocked by policy`, в том числе после повторного явного разрешения
пользователя. Вместо удаления применено обратимое NTFS-сжатие завершённых
тестовых данных, символов и отдельных библиотек кэша сборки. Содержимое
сохранено; рабочие данные и модели не затронуты. Запас места восстановлен,
сборка продолжена. Порог 20 ГиБ не снижался.
Первый запуск остановился после 214 успешных тестов: дополнительный режим
`tmp_path_retention_policy=failed` удалял пустые резервации имён, оставляемые
штатной очисткой проекта. Следующий тест получал прежний абсолютный путь и
попадал в кэш Folder Watch предыдущего теста. В частном запускателе возвращён
штатный режим, проверки не изменены; четыре теста Folder Watch прошли.
Повторный полный прогон прошёл с неизменёнными ожиданиями. Тестовые процессы
Rust API после него завершились; в итоговой проверке свободно 22,63 ГиБ
на диске и 13,41 ГиБ RAM. Это снимок ресурсов, не измерение потребления LES
и не доказательство ускорения приложения.

Проверяются отдельно: соответствие вида источника, нужные значения/позиции,
физические страницы, отказ при отсутствующем показателе, отсутствие подмешивания
другого документа, сохранение причин ошибки. Точное копирование ячейки и HTTP 200
не засчитываются как доказательство правильного выбора источника.

## Состояние поставки

Кандидат исходников. Рабочий LES, назначенные модели и рабочий индекс прежние.
Установленный пользовательский путь, новая Windows-сборка и публикация этим
отчётом не объявляются выполненными. Семантическая приёмка остаётся открытой
до закрытия открытых случаев; регрессионные тесты с управляемыми ответами её не заменяют.
