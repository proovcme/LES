# Рабочий локальный патч 762 и предел памяти 35B

Дата: 2026-10-11. [Квитанции](embedding-762-installed-results.json).
Это обновление установленного runtime, не новый установщик или подписанный DMG.

## Рабочее приложение

Прежние launcher/API/UI/Qdrant проверены по PID: все завершились до обновления.
Из текущего проверенного исходного состояния подготовлен пакет кода; заменён
41 отличающийся файл программы и маркер bundle. Прежние файлы сохранены для
отката. `.venv`, нативные assets и пользовательский каталог состояния не заменяли.
SHA-256 всех 41 установленных файлов проверены после запуска. API сообщает 762.

Launcher запущен отдельно от сессии терминала, с отключёнными автоматическими
фоновыми мутациями; явные пользовательские действия остаются доступны. Проверены
API готовности и UI healthz. Снимки назначений моделей до/после совпали.
Тому же назначенному embedding-подключению повторили проверку возможностей:
нативный протокол подтверждён. Модель и роль не заменяли. Шесть endpoint загрузки
настроек вернули 200. Это не доказательство геометрии интерфейса или всех кликов;
причина ранее сообщённого 404 остаётся невоспроизведённой.

Откат воспроизведён на одноразовой копии 41 файлов: все прежние SHA восстановились,
новые файлы удалялись только при совпадении SHA обновления, синтетический файл
состояния сохранился. Скрипт отката рабочего приложения отказывает при живых
процессах или изменении файлов после патча. Пользовательскую историю, промпты,
документы, галерею и постоянные журналы при этой проверке не читали.

## Три отдельные проверки 35B

Apple M4, 24 ГБ; прежний синтетический индекс; тот же локальный текстовый
Qwen3.6-35B-A3B-oQ3; размышление и бюджет 2048. Рабочая роль ответов не менялась.
Весовые файлы занимают 15,91 ГБ; после ответа MLX удерживает около 16,24–16,25 ГБ
активных массивов. Кэш свободного allocator — отдельная память, не веса и не KV.
[Договор MLX](https://ml-explore.github.io/mlx/build/html/python/_autosummary/mlx.core.set_cache_limit.html).

| Настройка испытательного сервера | e9, полный ответ | RAM после ответа | Второй вопрос e11 |
| --- | ---: | ---: | --- |
| Штатный allocator, prefill 2048 | 57,78 с | 2,29 ГБ | CHAT_MEMORY_PRESSURE |
| Allocator cache 256 МБ, prefill 2048 | 53,90 с | 3,18 ГБ | CHAT_MEMORY_PRESSURE |
| Cache 256 МБ, prefill 512, wired limit 12 ГиБ | 72,74 с | около 3 ГБ | CHAT_MEMORY_PRESSURE |

Последний вариант уменьшил пик MLX с 17,74 до 16,71 ГБ, но не обеспечил требуемые
4 ГБ свободной системной RAM. Снижение wired limit было отдельным экспериментом
с резидентностью, не изменением системных настроек; веса не менялись.
[Договор wired limit](https://ml-explore.github.io/mlx/build/html/python/_autosummary/mlx.core.set_wired_limit.html).
Эти варианты не включены в приложение и не применены к рабочему серверу модели.

Температура 0,1, длина ответов и состояние других приложений различались; времена
не являются чистым измерением ускорения. Три ответа e9 учли исключение именного
билета, но после первого отказа каждый прогон остановлен. Это не полноценный
quality benchmark 35B и не доказательство устойчивости. Пороги RAM/swap сохранены.
Тестовые серверы и кандидат остановлены; рабочий локальный runtime оставлен.

Исходный код 762 прошёл 1205 тестов и GitHub Windows CI. Этот документ фиксирует
новую установку и отрицательные испытания, без изменений кода или номера сборки.
