# Swiftide и Rho: отдельное сравнение харнесса

Дата: 12.11.2026. Номер 869 относится к испытательному стенду,
а не установленной сборке продукта. Рабочий LES, его индекс,
конфигурация и назначения моделей в этом сравнении не меняются.

## Условия

Одна замороженная копия двух наборов, 638 зарегистрированных документов.
Qwen3.5:9b, окно 8192, максимум ответа 1200 токенов, temperature=0,
одинаковый seed. Реранкер и эмбеддинги не меняются. Поиск — существующий
Edge + SQLite BM25 + общий RRF. Tantivy в это сравнение не включён:
смена поиска не должна маскироваться под улучшение харнесса.

SDK действительно управляет последовательностью модель → инструменты →
модель. Внешний испытательный контроллер предоставляет одинаковый
транспорт, сериализацию и доступ к существующим Rust-читателям. Он не
запускает старый AgentLoop и не выбирает ответный файл по эталону.

Вопросы взяты из прежней приёмки: точечные факты, числовые таблицы,
разные редакции, отсутствие ответа и четыре обзорные справки. Эталонные
идентификаторы, ответы и страницы в запрос модели не передаются. Порядок
двух SDK чередуется, чтобы уменьшить преимущество прогретого кеша.

Первичный поиск один и тот же. Явное чтение возвращает полный сохранённый
родительский раздел через Rust read_sections либо физическую страницу
через Rust/PDFium. Идентификатор, SHA-256 редакции, страница и продолжение
остаются связанными. Вложения и парсеры этим не заменяются.

## Проверенные различия SDK

| Свойство | Rho SDK 5.15.2 | Swiftide Agents/Core 0.34.0 |
|---|---|---|
| Сборка опубликованного пакета на Windows | Прошла | Ошибка безусловного Unix-импорта |
| Поправка в испытательном стенде | Не требуется | Убран OsStrExt; используется as_encoded_bytes |
| Реальное чтение PDF и сохранение результата в истории | Проверено | Проверено после поправки |
| Восстановление завершённой сессии без повторного эффекта | Проверено | Проверено через восстановление MessageHistory |
| Постепенная доставка трёх отдельных текстовых порций | Проверено | Проверено |
| Чтение реального PDF порциями с точным продолжением | Сборка страницы совпала с полным чтением | Сборка страницы совпала с полным чтением |
| Незавершённый текст после обрыва потока в снимке SDK | Сохранён | В истории SDK отсутствует; виден в событиях |
| Два вызова с одним call_id в ответе модели | Эффекты не выполнены; запрос исправления | Оба вызова выполнены |
| Остановка по лимиту шагов | Типизированный MaxSteps | В проверенном случае NoNewMessages |
| Отмена во время модели и инструмента | Проверена через токен SDK | Проверена через отмену future хозяином |
| Попытка исправить неверную страницу | Проверена | Проверена с tool_retry_limit=1 |
| Уверенное завершение после ошибки редакции без политики LES | Возможно | Возможно |
| Та же ошибка с общим запретом завершения LES | Ответ остановлен | Ответ остановлен |

Синтетическая ошибка модели в таблице проверяет протокол и побочные
эффекты, а не достоверность ответа Qwen. Ограничитель шагов — не замена
лимиту всех вызовов: несколько инструментов могут прийти за один ход.

Через оба SDK проверены существующие Rust-владельцы памяти, записи
рабочего файла с откатом, MCP с UTF-8 и автономного внешнего Python-навыка.
Для этого созданы только маленькие отдельные каталоги тестовых данных;
рабочая память, файлы и подключения пользователя не используются.

## Граница удаления своего кода

| Узел LES | Что может взять SDK | Что остаётся политикой продукта |
|---|---|---|
| agent_loop и его runner | Очередь ходов, вызов модели/инструментов, готовая сессия | Допуск чтения, контроль редакции, запрет неподтверждённого завершения |
| harness | Лимит модельных шагов, отмена, состояние выполнения | Общий срок, лимит инструментов, идемпотентность и ревизии изменяемых ресурсов |
| protocol и история обменов | Типизированные сообщения и пары вызов/результат | Совместимость сохранённой истории LES и проекция доказательств |
| api/chat/runner | Передача цикла одному владельцу | Подготовка области, контекст, журнал, проверка результата, SSE/API |
| MCP и рабочие файлы | Регистрация callback-инструментов | Разрешения, закреплённые схемы, пути, атомарная запись и откат |
| Сжатие контекста | Планирование/вызов суммаризатора | Точный бюджет и сохранение исходных доказательств |

Четыре старых файла координатора содержат около 700 строк до тестовых
модулей. Это верхняя граница области разбора, не обещание удалить все
700 строк: в них есть нужные продуктовые проверки. Файлы evidence,
reader, table_facts и весь API runner нельзя считать удаляемыми целиком.

Больший список возможностей Swiftide не равен большему удалению в LES.
Его RAG-конвейеры не заменяют автоматически публикацию поколений Edge,
проверенное дочитывание и цитаты. Готовое ContextCompression пересказывает
историю; оно не сохраняет договор LES, где модель выбирает исходные
реплики и не превращает план в выполненный факт. ToolSummarizer также
требует исключить первичные доказательства из пересказа и усечения.

## Решение

Для замены координатора выбран **Rho SDK 5.15.2**.
У обоих SDK подтверждена одна и та же граница удаления своего цикла.
Дополнительное безопасное удаление за счёт широких конвейеров Swiftide
не доказано. При этом Swiftide требует поправки Windows и дополнительных
адаптеров для проверки повторяющихся идентификаторов, сохранения
незавершённого потока и точной причины исчерпания шагов. У Rho эти
механизмы уже есть. Поэтому в проверенном контуре у Rho меньше
самописного кода, который придётся оставить или написать взамен.

Это выбор владельца цикла, не попытка заменить RAG целиком. Внешние
модели, MCP, память, файлы, навыки и форматные читатели остаются за
существующими host-инструментами. Бюджет контекста, исходные доказательства,
редакции, цитаты и остановка после ошибки чтения сохраняются как политики
LES, с одним владельцем каждой проверки. Второй агентный цикл поверх
Rho не добавляется.

Рабочий LES не переключён; Cargo.lock приложения не менялся.
make verify прошёл: договор 269 API-маршрутов сохранён, собрано 2179 тестов.
Сборка тестового SDK-пробника выполнена отдельно. Полный make test приложения
в этом сравнении не выполнялся: код приложения здесь не менялся.
Удаление старого координатора допускается после переноса этих политик
и приёмки полного API/SSE/истории приложения. Сравнение на копии не
объявляет installed user journey или сохранение всех функций приложения
уже принятыми. Публичных исходных документов и приватных подключений
в этом отчёте нет.
