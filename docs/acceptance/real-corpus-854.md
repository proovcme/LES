# Исправления по реальному корпусу · кандидат 854

Продолжение [приёмки 853](real-corpus-853.md) в том же отдельном состоянии.
Оригиналы, рабочая установка и назначения её моделей сохраняются. Личные
пути, документы и ответы остаются вне репозитория.

## Поиск

В Edge отсутствовали payload-индексы `node_role`, `ancestor_ids` и
`evidence_admissible`. Особенно дорогой была проверка недопустимых доказательств
без индекса булевого поля. Схемы создаются при первом индексе и холодном
восстановлении существующего Edge. Server получает их при подготовке.
Векторы, RRF и контракт эмбеддингов не заменяются.

BM25 выбирает потомков независимым SQL semijoin вместо повторной проверки JSON
предков для каждого posting. Сохраняются глобальные IDF, средняя длина,
фильтры, оценки и однократный учёт пересекающихся маршрутов.

## Чат

Hybrid получает до четырёх начальных кандидатов и 6000 символов, как Push.
Прежние два кандидата могли исключить нужный третий документ, найденный общей
выдачей. Инструменты дочитывания остаются доступны.

Если модель с инструментами завершает документный запрос без доказательств,
при доступном индексе выполняется один поиск в разрешённой области.
Неподтверждённый черновик удаляется, та же модель получает реальные выдержки.
Повтор отмечается в истории и итоговой трассе. Пустая выдача не становится
ответом. Модель получает различие между короткой выдачей и полным чтением файла.

Обработчик цитат убирает ошибочный `file://` только при полном совпадении
оставшегося адреса с URL в видимой карте источников. Код, чужие адреса и другая
страница не переписываются. Это исправление синтаксиса, не фактический судья.
Обычная Markdown-ссылка на известный URL также засчитывается. Для нескольких
видимых фрагментов с одним адресом сохраняется весь набор, без выбора одного
случайного фрагмента. Если модель не указала ссылок или использовала неизвестный
номер, разрешён один повтор оформления с теми же доказательствами и закрытыми
инструментами. Бюджет действий не пополняется. Повторный отказ даёт
`SOURCE_CITATION_MISSING`; неподтверждённый текст удаляется, причина сохраняется.

## Word и OCR

DOCX-reader читает прямую многоуровневую нумерацию из `numbering.xml`: начальные
значения, переопределения, перезапуск, буквенные и римские метки. Контейнеры
управления содержимым и smart tags сохраняют видимый текст.

Рисунки, встроенные объекты, формулы, неразрешённые исправления, неизвестные
специальные символы и неподдержанная нумерация дают отдельные коды с понятным
действием. Они не игнорируются ради статуса готовности. Полный reader сложных
DOCX этим кандидатом не заявляется.

При пустом или крайне малом результате OCR пробует повороты и перекрывающиеся
области с большим разрешением. Ограничены bitmap, срок страницы, размер текста
и срок форматного процесса. Временные bitmap удаляются после вызова.
Существующий текстовый слой страницы сохраняется. Выбор по объёму токенов и
отсев случайных глифов не проверяют достоверность OCR и не восстанавливают
таблицу или схему. Содержимое чертежей требует отдельной оценки качества.
Признак OCR доходит до карты источников и предупреждения в контексте модели.

## Ошибки HTTP и временные файлы

Дополнительный тест воспроизвёл `WinError 10053` на прежнем API: отклонённое
тело с неверным Content-Type оставалось непрочитанным в HTTP/1 соединении.
Теперь тело сначала вычитывается в прежнем ограничении 1 МиБ, затем возвращается
ошибка. Тест проверяет восемь разделённых на части загрузок и последующие
успешные обращения по тому же клиентскому соединению.

Принудительный таймаут форматного процесса оставлял bitmap, поскольку его
деструктор уже не мог выполниться. Windows-владелец API при запуске и подготовке
OCR очищает только старые `page-PID-nonce.bmp` в своём `storage/ocr-tmp`, когда
подтверждено завершение PID. Живой или недоступный для проверки процесс,
недавние файлы, ссылки и посторонние имена сохраняются. Реальное повторное
открытие стенда удалило три старых bitmap; тест сохраняет файл живого процесса.

## Результаты

Повторно поставлены в очередь ровно 54 ранее ошибочных документа в приватном
каталоге. Остальные записи и оригиналы не менялись. Итог: 596 проиндексированных
документов, 42 ошибки и 77 041 поисковая запись в двух исходных наборах
(`chunk_count` каталога, включая навигационные узлы). Дополнительно
прочитаны и опубликованы четыре DOCX и все восемь ранее отклонённых PDF.
Все 638 исходных SHA-256 повторно сверены, изменений нет.

Один большой PDF дважды превысил файловый срок, третья ограниченная попытка
завершилась. В ожидании повтора наблюдался технический `INDEX_NO_PROGRESS`;
эта подпись требует улучшения. Увеличение лимитов и обход защиты памяти
для получения зелёного статуса не применялись.

На неизменном снимке из 73 862 точек один одинаковый запрос с иерархией в трёх
повторах ускорился с медианы 5166 мс до 83 мс. После повторной публикации медиана
шести прежних запросов по полному корпусу — 217 мс, эмбеддинга отдельно — 47 мс.
Время генерации и дочитывания в эти измерения поиска не входит; результаты
относятся к данному стенду и не описывают все вопросы и объёмы базы.

Qwen3.5:9b ответила на пять контрольных вопросов в Push/Pull/Hybrid: всего 15
ответов. Проверены запрошенные числа, единицы, страницы и строка таблицы;
прежний пропуск нужного документа и остановка Pull без доказательств в этом
повторе не воспроизвелись. Вопрос без ответа получил ограничение прочитанными
выдержками. Все ответы имеют известные цитаты. Пять разных URL процитированных
оригиналов вернули 200 и совпали с SHA-256; проверены страницы PDF и лист/строка
Excel. Ошибочных `file://` в итогах нет. Один ответ потребовал повторного поиска,
шесть — повтора оформления цитат. Медиана полного ответа — 9,97 с.

Это контрольные значения и проверка происхождения на четырёх выбранных файлах,
не оценка Recall по всему корпусу и не доказательство правильности каждого
дополнительного пояснения модели. Семантический судья не подключён. Качество
распознавания сложных схем и оставшиеся ограничения DOCX остаются открытыми.

Проверки окончательных исходников: `make verify` — 2076 собранных тестов;
`make test` — 2074 passed, 2 skipped, 18 subtests, 44 warnings за 809,06 с.
Пропуски: POSIX TCP и надзор за процессом macOS. Rust-ядро — 97 unit tests.
Целевые сценарии документов/поиска/чата — 81 passed; затем отдельные новые
HTTP/cleanup-проверки — 3 passed в debug и 3 passed в оптимизированном API.
Старая сборка воспроизвела ошибку транспортного теста с `WinError 10053`.

Оптимизированный API собран. Испытательный сервер остановлен после приёмки;
для незавершённой оценки качества сохранён один приватный индекс вне репозитория.
Установка рабочего патча, push/merge и публичный выпуск не выполнялись.
