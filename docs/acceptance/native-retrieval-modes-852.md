# Приёмка Push, Pull и Hybrid

Штатный Rust API работал с отдельным Qdrant Server и синтетическим набором.
Оба документа получали одинаковые тестовые эмбеддинги. При этом BM25 поднимал
документ с нужной характеристикой. Три режима вернули одну и ту же точку и
идентификатор оригинала.

- **Push.** Уже в первом вызове модель получила фрагмент. Модельный запрос
  не содержал схем вызова инструментов. Результат не приписал модели
  инструментальных действий.
- **Pull.** Первый вызов модели прошёл без фрагмента. После
  `search_sources` появился тот же фрагмент и сохранилась ссылка.
- **Hybrid.** Модель увидела первичную подборку, вызвала `search_sources`
  и получила уточнённый контекст с прежним номером источника.
- **Обычный чат.** При выбранном Push и пустой области вызовов эмбеддера
  не было. Недопустимый режим возвращает 422 до обращения к модели.
- **Локальная Qwen3.5:2B.** На том же синтетическом наборе через реальную
  Ollama в режиме Push модель ответила «17,35 кВт». Карта ответа указала
  на тот же документ и версию. Модель чата привязывалась только в
  временной базе. Лексический и смысловой поиск в этом прогоне использовал
  локальный тестовый эмбеддер.

Проверка обнаружила расхождение поколений BM25 на Qdrant Server.
Нативная публикация обновляла векторы и каталог, а обслуживающие поиск
postings обновлял только адаптер Edge. Публикация и восстановление Server
теперь используют общий Rust-модуль `core/src/index_postings.rs`. Сверка
поколений выполняется перед выдачей. Регрессия Folder Watch проверяет,
что поколение BM25 после восстановления совпадает с журналом.

Режимы реализованы в `api/src/chat/runner.rs`, `api/src/chat/evidence.rs`
и `core/src/chat_request/`. Первичная подборка использует ту же
`search_sources` и упаковку источников. Приёмка сравнивает содержимое
реальных запросов к тестовой модели в `tests/test_light_native_retrieval_modes.py`.
В интерфейсе проверены доступность вариантов и восстановление предпочтения.
`make verify` собрал 2052 теста. `make test` — 2050 пройдено, 2 пропущено.
Проверки фронтенда — 41 тест, `npm run check` и `npm run build` прошли.
Замеры качества на проектном корпусе и проверка внешней сильной модели
остаются отдельными сценариями.
