# Чтение составного вопроса и проверка редакций

На стенде 934 сравнили готовый сборщик LlamaIndex с экспериментом, в котором модель отдельно разбирает каждое запрошенное свойство. Входом служили тот же вопрос и те же пронумерованные выдержки. Без изменения поисковика можно проверить, помогла ли сама сборка ответа.

## Девять одинаковых выдач

| Вариант на одной локальной Qwen 3.5 9B | Полный ответ и правильные источники | Вызовы модели |
| --- | ---: | ---: |
| Обычный чат 934 | 4/9 | 11 |
| CitationQueryEngine со штатным шаблоном | 6/9 | 9 |
| CitationQueryEngine с правилом отказа при отсутствии сведений | 8/9 | 9 |
| Эксперимент с отдельным чтением свойств и повторной проверкой | 5/9 | 43 |

На второй формулировке без южного давления эксперимент сохранил северное давление и сослался на общее условие, но в следующей строке объявил это условие неизвестным для Юга. При удалении северного давления под заголовком о Севере появилась дословная цитата о Юге. Код подтвердил существование фразы и её адрес. Модель ошиблась при выборе, к какой строке ответа относится фраза. [Исходные девять ответов](nine.json) · [Оценка каждого ответа](review.json)

## Другие вопросы

На шести сохранённых выдачах второго корпуса эксперимент получил 4/6 при 20 обращениях к модели. По тому же критерию прежний сборщик с правилом отказа получил 4/6 за шесть обращений. Наборы ошибок различаются. После удаления действующей редакции эксперимент верно сохранил срок доставки и обозначил срок возврата как неизвестный. Когда обе действующие редакции присутствовали, проверка модели ошибочно исключила действующий документ о доставке. При конфликте двух утверждённых дат запуска ответ сообщил, что сведений нет. [Шесть ответов и решения о редакциях](transfer.json) · [Прежнее сравнение](../README.md)

Две фиксированные выдачи с папки из 59 файлов проверили отдельно. В обеих у модели первым был исходный документ с северным давлением. Полный зачёт получил один из двух ответов. [Повтор на двух выдачах](cross.json)

## Обычный чат по папке

Ещё шесть запросов прошли через публичный HTTP-чат кандидата 934. Три изолированные папки заново проиндексировали настоящими BGE-M3 и Qdrant, ответ строила локальная Qwen. Обработчик стенда сверил текст и хеш каждого короткого TXT с материалом, отправленным чатом. Для выданных ссылок оригиналы заново скачали по API и сравнили байты. Получили четыре полных ответа из шести.

| Папка | Результат |
| --- | --- |
| 59 файлов, документ с южным давлением удалён | Обе формулировки дали 184 кПа на Севере, явный пробел по Югу и 26 °C для обоих участков с правильными ссылками. Про гарантию получен ответ об отсутствии сведений без ссылок. Прошли 3/3 |
| 6 файлов, есть обе действующие редакции | Доставка 7 рабочих дней указана верно. Действующий документ о возврате стоял первым, но модель пометила его отменённым из-за фразы о замене прошлой редакции. 30 календарных дней в ответ не попали. Прошли 0/1 |
| 5 файлов, действующая редакция возврата удалена | Для текущих правил верно сохранился срок доставки и обозначен пробел по возврату. При явном вопросе о редакции 2029 года модель исключила эту редакцию, хотя архивный документ оказался первым. Прошёл 1/2 |

Основное решение для папок — оставить прежний сборщик с цитатами в числе кандидатов. Вводить экспериментальное многократное чтение в рабочий чат оснований нет. Для корпуса с подтверждёнными датами применим обычный фильтр поиска. Произвольной папке ещё нужен способ получить подтверждённые сведения о редакциях и явно сохранять неизвестный статус. [Ответы чата, стадии модели и хеши оригиналов](live.json) · [Запуск на изолированном нативном API](../../../../tools/evaluate_part_reader_chat.py)

## Как это решают готовые компоненты

* Azure AI Search умеет разбивать сложный запрос для поиска по частям, объединять результаты и возвращать журнал и исходные записи. Отдельный режим извлекает дословный ответ из документа, если находит подходящую фразу с достаточной уверенностью. [Поиск по частям](https://learn.microsoft.com/en-us/azure/search/search-agentic-retrieval-concept) · [Извлечение ответа](https://learn.microsoft.com/en-us/azure/search/semantic-answers)
* У LlamaIndex есть штатный разбор на подвопросы и сборщик цитат. Предыдущий локальный опыт показал 3/9 у разбора на подвопросы с общей фиксированной выдачей. В этой проверке подвопросы не запускали новый поиск по папке. [Штатные компоненты](https://developers.llamaindex.ai/python/framework-api-reference/query_engine/citation/) · [Результаты ЛЕСа](../README.md)
* Qdrant поддерживает фильтрацию по датам в метаданных. На поставляемом нативном сервере Qdrant 1.19.1 проверены две редакции инструкции о доставке. Интервалы для опыта задали по прямо указанным в исходных документах датам. Добавили контрольную запись с неизвестным периодом. При запросе на 31 декабря 2030 года вернулась старая редакция, на 1 января 2031 года — новая. После исключения новой редакции из области поиска запрос на 1 января вернул пустой список, а на 31 декабря — старую. Все четыре проверки прошли без модели. Это отдельный опыт с метаданными. Он не проверяет автоматическое определение даты у произвольного файла. [Данные, запросы к Qdrant и результаты](qdrant-period.json) · [Фильтры Qdrant](https://qdrant.tech/documentation/search/filtering/)

## Как устроен стенд

Готовый CitationQueryEngine нумерует источники. Экспериментальный сборщик просит модель назвать свойства и их область действия. Для указанного периода модель может исключить редакции с указанием исходной фразы. Затем она выбирает адреса предложений для каждого свойства. Последний вызов модели сверяет предложенные пары. Адреса ограничены перечнем в JSON Schema и повторно проверяются кодом. Программа подставляет исходный текст и номер источника. В журналах остаются план, решения об исключении, выбранные фразы, результат последней сверки и хеш каждого структурированного запроса. В рабочем чате этот вариант не включён. [Сборщик](../../../../tools/llamaindex_part_reader.py) · [Вход для повтора](../../../../tools/evaluate_llamaindex_folder.py)

Из корня репозитория этот опыт можно повторить с локальной моделью и установленными зависимостями проекта.

```powershell
uv run python -m tools.evaluate_llamaindex_folder --fixture tests/fixtures/rag/folder-chat-v1.json --native docs/acceptance/llamaindex-934/native.json --routes parts --api-url http://127.0.0.1:11434/v1 --output .test-tmp/parts-repeat.json
```

Для повтора на папках нужны нативные `LES_TEST_NATIVE_API`, `LES_TEST_NATIVE_QDRANT` и библиотека кандидата `LES_CORE_LIBRARY`, обе указанные модели Ollama и отдельный временный каталог. Стенд использует только синтетические файлы из репозитория и тестовую роль провайдера. Установщик и нажатие ссылки мышью здесь не проверялись.

```powershell
uv run python -m tools.evaluate_part_reader_chat --scratch (Resolve-Path .test-tmp).Path --output .test-tmp/parts-http-repeat.json --model qwen3.5:9b --ollama http://127.0.0.1:11434
```

Критерии полного зачёта взяты из прежней проверки. Недостаточно получить правильный набор номеров документов, если извлечённое значение оказалось под заголовком другого объекта. Эти небольшие наборы использовались при разработке, результат относится к измеренным случаям.

После изменений прошли 21 целевая проверка и `make verify` со сбором 2265 тестов. В `make test` прошли 1945 тестов, 317 пропущены, повторились три известных падения кандидата 934. Это наблюдение за сменой маршрута файла, код завершения аварийного обработчика форматов и вместимость профиля модели. [Версии и хеши проверенного кода](protocol.json)
