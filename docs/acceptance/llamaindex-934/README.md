# Проверка LlamaIndex на выдаче ЛЕСа 934

Цель опыта — выяснить, способен ли готовый сборщик ответа сохранить известные факты и явно назвать недостающий. Из документов удалили южное давление. В оставшихся документах есть северное давление 184 кПа и общее условие для обоих участков — охлаждение теплоносителя до 26 °C.

**Решение.** Готовый модуль можно подключить к действующему поиску по папке. Переводить на него рабочий чат пока рано. На одинаковых выдержках он чаще давал полный ответ, но через обычный чат всё ещё мог потерять факт из первого документа. На независимом примере оба шаблона выдали срок из явно отменённой редакции за действующий.

## Парное сравнение

На изолированном нативном API 934 создали по маленькой папке для каждого варианта выдачи. Пользовательский запрос шёл через `POST /api/chat` в режиме Hybrid. Поиску в этой серии давали заранее выбранные фрагменты и тестовые векторы. На границе провайдера записали порядок полных текстов, хеш запроса и параметры генерации. Каждому варианту LlamaIndex передали точно те тексты в том же порядке. Промпты различались по устройству сборщика. Все вызовы шли к одной живой локальной Qwen 3.5 9B, с температурой 0,1 и выключенными рассуждениями. У вариантов LlamaIndex использовался предел генерации из первого нативного вызова соответствующего случая. Обмен ЛЕСа был потоковым, библиотека получала завершённый ответ.

Проверяли правильность всех требуемых фактов, обозначение пробела и набор источников, на которые ссылается сам ответ. Номера проверяли по исходным документам в данной попытке. Дополнительная ссылка на правдивую, но постороннюю инструкцию лишает полного зачёта. Поэтому число полных зачётов отличается от числа ответов с правильным основным значением. Вопросы повторяются и относятся к синтетическим TXT. Процент для произвольных пользовательских папок из этих чисел вывести нельзя.

| Способ | Полный зачёт | Вызовов модели на 9 вопросов | Обе формулировки без давления Юга |
| --- | ---: | ---: | ---: |
| Нынешний чат 934 | 4/9 | 11 | 1/2 |
| LlamaIndex CitationQueryEngine | 6/9 | 9 | 2/2 |
| Тот же CitationQueryEngine с правилом ЛЕСа для неполных ответов | 8/9 | 9 | 2/2 |
| LlamaIndex SubQuestionQueryEngine с тем же читателем | 3/9 | 44 | 1/2 |

При обычном цитировании LlamaIndex оба давления и условие допуска имели правильные ссылки в обоих полных примерах. Если исчезало северное или южное давление, оставшаяся часть ответа сохранялась. При удалении условия допуска в ответ попало сообщение о том, кто подаёт сигнал начала работ. При удалении всех подтверждений модель отдельно оговорила отсутствие нужных сведений, но процитировала шины тележки и сигнал. По гарантии она верно воздержалась, однако добавила все шесть ссылок. У варианта с разбиением на подвопросы дополнительные вызовы часто приносили такие необязательные сведения в итоговый текст.

Использован пакет `llama-index-core 0.14.22` из рабочего окружения разработки. У прямого цитирования и разбора на подвопросы сначала оставили встроенные шаблоны. Локальный адаптер передавал общую инструкцию отвечать на языке вопроса, сохранять номера источников и обозначать пробелы. Для подвопросов использован штатный `LLMQuestionGenerator` с той же моделью. [Документация CitationQueryEngine](https://developers.llamaindex.ai/python/examples/query_engine/citation_query_engine/) · [Корпус и эталоны](../../../tests/fixtures/rag/folder-chat-v1.json) · [Нативные ответы и полученные окна](native.json) · [Ответы и промежуточные вызовы LlamaIndex](stock.json)

Штатный шаблон просит сослаться хотя бы на один источник в каждом ответе. После первого сравнения настроили шаблоны ответа и уточнения. Если в источниках вообще нет запрошенных сведений, модель может сообщить об этом без ссылок с помощью уже существующей в ЛЕСе метки `[[NO_EVIDENCE]]`. При частичной опоре она должна привести известное и назвать недостающее. На прежних девяти случаях исправились оба полных отказа. Осталась подмена отсутствующего условия допуска указанием, кто подаёт сигнал. Эти девять случаев использовались при настройке. ## Проверка через приложение

В другой папке оставили 59 из 60 файлов контрольного корпуса. Удалён только 056.txt с давлением Юга. Все 59 файлов заново проиндексированы с реальным BGE-M3 на Ollama. Через обычный API задали три вопроса. На месте провайдера отдельного стенда был подключён обработчик с CitationQueryEngine и живой Qwen. Каждый переданный короткий TXT сверялся с видимым текстом и хешем источника. Исходные цифровые ссылки библиотеки вернулись в обычный нативный обработчик цитат. Для каждой связанной ссылки скачали оригинал через API и сверили его байты с текстом контрольного файла.

| Вопрос по папке | Штатный шаблон | С правилом ЛЕСа |
| --- | --- | --- |
| Давление на двух участках и общее условие | Все доступные факты, две верные ссылки, пробел по Югу указан | То же |
| Те же требования другими словами | Все доступные факты, две верные ссылки, пробел по Югу указан | Условие 26 °C и его ссылка верны. Модель объявила неизвестным также давление Севера, хотя 017.txt с 184 кПа пришёл первым |
| Гарантия на насосы | Сообщил об отсутствии сведений и добавил шесть лишних ссылок | Сообщил об отсутствии сведений, список ссылок пуст |

Каждый вариант дал два полных зачёта из трёх. При двух независимых индексациях состав посторонних документов немного различался. Поэтому дополнительно подали обеим настройкам одни и те же два набора в исходном порядке, выровняв предел вывода до 4462 токенов. Штатный шаблон прошёл оба повтора. Настроенный прошёл один. На втором он привёл верное северное давление и одновременно объявил сведения о давлении неподтверждёнными. Эти одиночные повторы показывают, что одного попадания документа в выдачу мало. Частоту ошибки по ним оценить нельзя. Стенд проверял поиск, реальную генерацию, штатную обработку ответа и загрузку оригинала по публичному API. Начальная настройка роли модели была тестовой. Установку на чистой Windows, щелчок мышью, PDF, Excel, длинные документы и продолжение диалога этот опыт не покрывает.

## Проверка на других вопросах

Для второго корпуса заранее сохранили шесть вопросов, порядок отрывков и эталоны. Использовали те же два варианта прямого цитирования с той же моделью. Оба дали верные запрошенные значения или верно указали пробел в пяти из шести случаев. При строгой проверке набора ссылок исходный шаблон прошёл 3/6, настроенный — 4/6. Дополнительная ссылка в пояснении о старой редакции снижала строгий балл даже при правильном основном значении.

## Что менять в ЛЕСе

В последующем опыте реализовали отдельное чтение каждого свойства и проверили даты настоящим фильтром Qdrant. Дополнительные вызовы модели снизили полный результат на девяти случаях с 8 до 5. Фильтр по известным датам прошёл все четыре контрольные проверки. [Устройство опыта и результаты](parts/README.md)

Поиск по папке уже доставил 017.txt первым. Менять поисковик для исправления этого сбоя оснований нет. Граница для замены проходит после поиска. ЛЕС передаёт сборщику вопрос и упорядоченные выдержки с постоянными адресами. Уже сейчас по этим адресам ЛЕС открывает оригиналы.

Следующий кандидат стоит проверять на двух конкретных требованиях. Для составного вопроса он должен отдельно показать ответ или пробел по каждой запрошенной части и источник каждого значения. Для вопросов со сроком действия он должен исключить явно отменённую редакцию из возможных оснований для утверждения о текущем значении. Затем тот же тест следует повторить через обычный чат на папке, при другой формулировке и после удаления действующей редакции. Для решения о поставке также нужны повторы на независимых папках и документах обычной длины.

## Повтор

Из корня репозитория команда запускает оба штатных варианта на сохранённой выдаче и пишет полный отчёт в новый файл. Нужны проектное Python-окружение, уже установленная локальная модель из отчёта и работающий совместимый API на указанном порту.

```powershell
uv run python -m tools.evaluate_llamaindex_folder --fixture tests/fixtures/rag/folder-chat-v1.json --native docs/acceptance/llamaindex-934/native.json --api-url http://127.0.0.1:11434/v1 --output .test-tmp/llamaindex-repeat.json
uv run python -m tools.evaluate_llamaindex_folder --fixture tests/fixtures/rag/full-chat-v1.json --native docs/acceptance/llamaindex-934/transfer-windows.json --routes citations les-citations --api-url http://127.0.0.1:11434/v1 --output .test-tmp/llamaindex-transfer-repeat.json
```

Инструмент сверяет хеш корпуса, идентичность каждой исходной выдержки и номера документов. В отчёт попадает текст каждого ответа и каждой промежуточной попытки. Оценку смысла ответа проводят по сохранённым эталонам. [Код повтора](../../../tools/evaluate_llamaindex_folder.py)

Для повтора настроенного варианта на первых девяти вопросах к первой команде добавьте `--routes les-citations` и укажите новое имя результата. Для перекрёстного повтора на двух выдачах используйте корпус `folder-chat-v1.json` и вход `cross-windows.json`.

В полном прогоне `make test` прошли 1940 тестов, 317 пропущены, повторились три известные ошибки кандидата 934. Они относятся к наблюдению за папкой, завершению аварийного работника форматов и эталону вместимости профиля модели. После окончательной настройки шаблона повторены `make verify` (2260 тестов собрано) и модуль проверки источников (16 прошли). [Проверки стенда и подмены источника](../../../tests/test_light_grounding_760.py)
