# Внутренняя целостность RAG · build 750

Установлен локальный патч из 13 runtime-файлов поверх 749, с проверкой хешей
и резервной копией каждого заменённого файла. Публичный выпуск и полный установщик
не обновлены. Табличный эксперимент 746 не входит в локальный патч.

## Исправления

- Перед поиском и обработкой каждого файла назначение embedding-модели сверяется
  с моделью существующего индекса. Несовместимость останавливает операцию до
  сетевого вызова, в том числе при полном попадании в кэш embeddings.
- Назначение фиксируется на весь файл и все проходы одного иерархического
  запроса. Смена роли между пакетами не смешивает векторы разных моделей.
  Размер возвращённых векторов также проверяется.
- Durable SQLite-журнал сохраняет все новые ID перед первым upsert и решение
  о завершении замены перед удалением прежнего поколения. До решения восстановление
  убирает staged ID, после решения завершает замену и восстанавливает FTS.
- Восстановление происходит до готовности коллекции и перед следующей индексацией.
  При недостающих новых точках журнал сохраняется, поиск блокируется. Документ
  после восстановления получает PENDING: изменившийся во время сбоя оригинал
  должен пройти обычную проверку, а не получить ложный INDEXED.
- Системная блокировка исключает конкурирующих писателей/восстановителей.
  Запрос проверяет ревизию до и после чтения и не возвращает смесь поколений,
  если запись началась или закончилась во время поиска. Последняя проверка выполняется
  после реранкера и раскрытия родительского контекста, перед выдачей результата.
- Замена FTS выполняется одной транзакцией. Ошибка больше не скрывается за
  успешным статусом документа.
- Иерархический поиск использует одно embedding-представление вопроса для
  глобального, навигационного и уточняющего проходов. Dense + sparse + RRF
  и состав проходов сохранены.
- Проверка ссылок явно сообщает `claim_verification=not_performed`.
  Ссылка на несуществующий источник считается ошибкой даже при пустой карте.
  Смысловая достоверность ответа этим не подтверждается.

## Проверка

17 новых регрессий: пять настоящих `os._exit` при записи постоянного локального
Qdrant, повторное восстановление, сохранение чужого dataset, неполный commit,
конкурирующий писатель, смена ревизии, откат частично выполненной FTS-транзакции,
фиксация подключения и размерности, один embedding на три прохода, неверная ссылка.
Понятные ошибки проверены также для отсутствующей роли, таймаута и HTTP 404
поисковой модели. Полный `make test`: 1109 passed, 18 subtests passed;
`make verify` и `make public-check` пройдены. После изменения карточки ошибки
прошли 59 целевых UI-тестов и повторный полный gate.

Повторный поиск выполняется на копии прежнего контрольного корпуса с неизменными
точками и вопросами. Это 40 случаев по двум документам, а не обещанная приёмка
100 случаев на полном корпусе. Результаты повторного прогона:

| Режим | Evidence Recall@5 | Evidence Recall@10 | Медиана поиска |
| --- | ---: | ---: | ---: |
| Без реранкера | 53,13% | 95,31% | 0,238 с |
| С локальным BGE | 96,88% | 100% | 2,641 с |

Это средняя полнота размеченных групп доказательств на 32 положительных случаях;
8 случаев без ответа не включены в Recall. Первый запрос с загрузкой реранкера
занял 44,8 с. В свежем сравнительном прогоне 749 без реранкера дал медиану 0,269 с,
Recall@5 53,13%, Recall@10 96,88%. Один фрагмент колеблется между местами 10 и 11:
повтор 749 нашёл обе группы в 3 из 6 запросов, 750 — в 6 из 6. Результат указывает
на существующую нестабильность около границы top-k; не объявляем это доказательством
роста точности и не переносим миллисекунды поиска на полную задержку генерации.

Установленные API и UI запущены на встроенном Python и отдельной копии состояния.
Проверены обычный поиск, блокировка несовместимой назначенной модели, незавершённого
журнала и сохранение вопроса в поле ввода. Ошибка содержит причину и действие;
технический код убран из основного текста карточки. Назначения в основном Лесе
и его корпус не менялись. Дополнительно проверен перезапуск установленного приложения
с незавершённым журналом: автоматическое восстановление завершилось, поиск снова
вернул фрагменты, документ получил PENDING. При этой проверке найден и исправлен
способ закрытия клиента Qdrant; отдельная регрессия проверяет именно startup-wrapper,
а не только алгоритм восстановления. Финальный установленный поиск успешно
прошёл с выключенным и включённым локальным реранкером; хеши всех 13 runtime-файлов
совпали с подготовленным патчем. Нативное окно Windows и экранный диктор
этим не проверены.

## Открытые границы

- Нет полноценного независимого проверяющего смысловую поддержку утверждений.
- Пока нельзя обещать длительность полного ответа: текущая доступность сервера
  ответов и большая длина контекста требуют отдельного живого измерения.
- Совместимость существующего индекса проверяется по модели/профилю/размерности;
  смена самих весов за тем же ID у внешнего сервера не обнаруживается автоматически.
  Произвольная новая embedding-модель требует отдельного явного создания индекса.
- Журнал восстанавливает операции, начатые этой версией. Незавершённые записи
  старой версии без журнала требуют проверки целостности.
- Проверено прерывание процесса, не аппаратное повреждение накопителя.
- Нужна расширенная независимая разметка 100 контрольных вопросов.
