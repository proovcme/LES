# Приёмка наблюдения за папками в Rust

## Сценарии

- Два исходника были проиндексированы в отдельном Windows-состоянии. Замена байтов с прежним размером и mtime была обнаружена во время работы и после остановки владельца. На Windows SMB первая замена была обнаружена по штатному таймеру без ручного запроса на сверку.
- SMB проверялся через настоящий UNC-путь к общей папке Windows на этой машине. Тестовый каталог временно перемещался из доступного пути. В API появился статус «Папка недоступна», а состояния ранее известных файлов сохранились. При возврате папки состояние снова стало доступным. Сетевой разрыв на отдельном NAS не моделировался.
- Файл, убранный из доступной папки, получил статус «Файл отсутствует» после полного обхода. Если другой файл удерживался открытым на запись, сверка откладывалась и пропажа не регистрировалась. Успешный обход пустой папки фиксировал отсутствие всех её файлов. Прежние поисковые данные оставались в хранилище.
- Qdrant Server. Тестовый прокси задержал подтверждение реального upsert. Перед принудительной остановкой Rust API журнал находился в состоянии `staging`, в каталоге был прежний SHA, а в Qdrant уже были точки новой редакции. После перезапуска прежняя незавершённая запись была восстановлена, очередь закончила обновление и журнал вернулся в `idle`. Из двух поколений обновлённого документа в поиске осталось новое.
- Qdrant Edge. Владелец был остановлен после входа в `staging`. Прямое чтение остановленного тестового хранилища обнаружило точки прежней и частично записанной новой редакций. После запуска сработало восстановление, автоматическое задание завершилось. Итоговая выдача содержала новую редакцию.
- Браузер поверх отдельного штатного Windows runtime. «Данные» → добавить папку → «Подробнее» → «Приостановить» → «Возобновить». Для файла без модели поиска интерфейс показал «Ожидает индексации» и объяснил, что назначить. Это сценарий в браузере. Визуальная геометрия нативного WebView2 и обновление рабочего приложения в эту проверку не входили.

Во всех сценариях использовались синтетические документы, отдельные состояния
LES и модельная заглушка на локальном адресе. Прогоны сохраняют рабочий индекс,
назначения моделей и установленный экземпляр пользователя.

## Изменённые модули

- `api/src/intake.rs`, `core/src/catalog/intake/watch.rs`, `core/src/catalog/intake.rs` — реестр и расписание, полная сверка, статусы и журнал очереди.
- `core/src/files.rs`, `core/src/index_batch/`, `api/src/index_batch/configuration.rs` — безопасный SHA-256, проверка источника, привязка индексации к обнаруженному содержимому.
- `api/src/library.rs`, `DataLibrary.svelte`, `FolderWatches.svelte` — видимые статусы и управление наблюдением.
- `tests/test_light_native_folder_watch.py`, `FolderWatches.test.ts` — воспроизводимые сценарии API, SMB, обрыва процесса и интерфейса.

Проверка UNC на Windows включается переменной `LES_TEST_SMB_LOOPBACK=1` при
доступном локальном SMB. Для Edge нужен штатный тестовый `LES_TEST_EDGE_VECTOR`.
В итоговом прогоне кандидата 852 прошли все три варианта сценария (локальная
папка, Windows SMB и Edge). Результат `make test` — 2050 пройдено, 2 пропущено.
