# Аудит ЛЕС 909 · 18 ноября 2026

Проверена локальная ветка `codex/rag-evidence-repair`, коммит `59eae530` с рабочими изменениями 908–909. В инвентаризации 1477 отслеживаемых файлов. Ручной разбор охватывает подключение папки, подготовку документов, публикацию индекса, поиск Dense/BM25, чтение, сборку сообщений, проверку ответа, показ ссылок, оценку прогонов, запуск и упаковку Windows и связь с macOS Preview. Глубина проверки различна. Пять временных XLSX прошли через существующий нативный обработчик сборки 909. Доставка в Qwen проверена по сохранённым фактическим сообщениям, новый прогон модели и проверка установленной 880 в этот аудит не входили.

## P1. Строки Excel теряются до эмбеддингов

| Вход в нативный обработчик | Фактический выход |
|---|---|
| Заголовок `ID, Qty`, строка `early-proof, 7`, строка с тремя текстовыми полями, строка `last-proof, 8` | Заголовком стала строка 3. В структурированной таблице осталась только строка 4. Индексация завершилась успешно с одним узлом. В его тексте отсутствует `early-proof`. |
| Заголовок в физической строке 21 и данные в 22 | Структурированное чтение вернуло пустой список листов, индексация завершилась `NO_SEARCHABLE_TEXT`. |
| Заголовок и 600 однотипных строк | 600 узлов типа `table_row`. |
| Та же структура и 601 строка | Один узел типа `table_navigation_projection`. |
| Заголовок в строке 1 и единственное значение в строке 20002 | `SPREADSHEET_LIMIT`. Ограничение зависит от физической координаты даже у почти пустого листа. |

Воспроизведение использовало `les-api.exe --serve-document-formats`, `pipeline=nodes` и штатный порог числа табличных фрагментов. Для первых двух книг отдельно вызван `view=tables`. Измерено число подготовленных узлов до публикации в Qdrant.

**Причина потери начала листа.** `to_table` оценивает заполненность первых 20 физических строк. Длинный текст получает больший вес, чем число. Все строки до победителя и сам победитель исключаются из данных. Развёрнутое описание позиции легко выигрывает у короткой шапки. Если таблица начинается позднее, выбирать не из чего. Исправление должно сохранять содержимое и физические координаты независимо от уверенности в заголовке. Для уже опубликованных неполных таблиц потребуется повторная обработка оригинала. [Выбор заголовка](../../core/src/document/workbook_index.rs#L61) · [Табличный вход индексации](../../core/src/document/conversion/pipeline.rs#L285)

**Причина провала после 600.** Полные подготовленные строки пишутся в Parquet, затем размер определяет представление в поисковом индексе. В обзор попадают до 20 разных примеров по каждому из нескольких полей. Обычный чат-инструмент `read_excel_source` вызывает тот же `retrieval::read`, что и чтение индексированных фрагментов. Поиск явных адресов также запрашивает точки Qdrant по листу и строке. Поэтому поиск может обнаружить книгу, а штатная команда чтения Excel вернёт её обзор без нужной ячейки. Выход — использовать обзор для обнаружения книги, а чтение строки или диапазона привязать к уже сохранённой таблице и её редакции. После восстановления этого пути можно отдельно подбирать размер поисковых блоков. [Создание Parquet и проекции](../../core/src/document/conversion/pipeline.rs#L300) · [Читатель Excel](../../api/src/chat/tools/sources.rs#L274) · [Явные адреса](../../api/src/chat/tools/sources/retrieval/addressed_rows.rs#L14)

Отдельное ограничение на 20 000 в параметрах структурированного чтения прерывает индексацию всего листа при превышении окна. Ошибка явная. Для разреженных листов разумно ограничивать объём фактически прочитанных данных и хранить их реальные координаты. [Проверка размера](../../core/src/document/conversion/spreadsheet.rs#L486)

## P1. Поиск внутри большого документа может остановиться до первого результата

Для индексируемых форматов на общем пути чтения `read_source(q=…)` и `read_source(clause=…)` обходят быстрое чтение по позициям. Сканер получает все payload порциями по 128, копирует их в память, затем ранжирует. На 4097-й точке или после 16 МиБ сериализованного JSON возвращается `SOURCE_READ_LIMIT`. Даже `limit=1` применяется позже. Продолжение с новым `offset` повторяет обход и вычисление релевантности. У Word отдельный ранний переход к читателю оригинала. У позиционного чтения без запроса есть быстрый путь. Это вывод по исполняемым веткам, частоту на пользовательском корпусе аудит не измерял. Использовать существующие поисковые postings с фильтром документа для запроса и устойчивым порядком продолжения. [Маршрутизация](../../api/src/chat/tools/sources/retrieval.rs#L1226) · [Сканирование и предел](../../api/src/chat/tools/sources/retrieval.rs#L1315)

## P1. Адрес уже прочитанного абзаца меняется между сообщениями модели

В сохранённом обычном Hybrid 909 одна и та же строка спецификации была `S1P3` в первом сообщении и `S1P2` в последнем. Абзац Word перешёл из `S5P9` в `S5P8`. Номер источника и содержимое сохранились. `terminal_block` убирает одну служебную строку. Для неканонического текста и обычных Markdown-таблиц адрес вычисляется по номеру строки всего оформленного блока. Модель, которая перенесёт ранее увиденный адрес в финальный выбор, может получить ошибку валидации или сослаться на другую существующую строку. В сохранённом удачном ответе Qwen выбрала актуальные адреса. Исправление — назначать адрес из исходной единицы один раз и использовать его при отображении и проверке. [Финальное представление](../../api/src/chat/evidence.rs#L698) · [Нумерация абзацев](../../core/src/chat_context/prose.rs#L21) · [Нумерация строк](../../core/src/chat_context/tabular.rs#L42)

## P1 для оценки качества. Отказ получает видимость ответа с цитатами

В сохранённом Hybrid 908 итог имел статус `insufficient_evidence`. Модель выбрала ноль строк, но ответ содержал **10 ссылок**. При пустом выборе `Rows::finish_checked` сам добавляет до 16 номеров видимых источников. Интерфейс включает ссылки из текста в «Цитаты в ответе». Скрипт оценки определяет cited coverage по синтаксису ссылок, а delivered coverage объединяет все подтверждённые раунды. Эти две метрики измеряют другие величины, чем использование фактов и доставка в последнее окно. Более того, документ в оценке определяется по имени без расширения, поэтому одноимённые файлы могут совпасть. Хранить отдельно просмотренные материалы и выбранные доказательства, при отказе считать выбранные доказательства по пустой квитанции. Для фактического качества сверять значение, источник и лишние выбранные фрагменты. [Генерация ссылок отказа](../../api/src/chat/table_facts.rs#L337) · [Оценка прогонов](../../tools/evaluate_light_chat.py#L71) · [Показ цитат](../../desktop/light/frontend/src/components/Answer.svelte#L55)

## P2. Повторная работа и ограничения охвата

- **Настройка разнообразия документов.** В Rust `document_diversity_k` нормализуется при чтении профиля. Поиск по всем исходникам API и core обнаружил только это упоминание. Общий отбор использует собственную политику и предел 64 или 32 единицы. Поэтому изменение этой конкретной настройки не передаётся в штатный отбор. Договор сборки 864 в документации обещает её применение. Следует либо провести значение до отбора и показать разницу на одном запросе, либо убрать обещание и настройку. [Профиль](../../core/src/chat_profiles/mod.rs#L88) · [Вызов отбора](../../api/src/chat/tools/sources/retrieval/packing.rs#L85)
- **PDF в первом Pull-поиске с явным `view=passages`.** После подготовки пагинированной выдачи тот же запрос повторно вызывает `passages` для первых 32 PDF-точек из уже найденного пула. Первое чтение навигационное, второе раскрывает контекст. Дополнительная ветвь может завершиться ошибкой, видимой лишь в серверном журнале. Пользователь получает успешную навигацию без этих дополнительных выдержек. Предположение о влиянии на общую задержку требует замера. [Повторная подготовка и ошибка](../../api/src/chat/tools/sources/retrieval.rs#L492)
- **Компактный пакет источников.** При успешном проверенном чтении `Evidence::add` сначала декодирует пакет для проверки, `add_passages` снова получает развёрнутые фрагменты, затем `Self::passages` вызывается ещё раз для учёта прочитанного. Декодирование клонирует JSON и источники. Здесь можно один раз проверить и раскрыть пакет на входе. Это подтверждённое дублирование работы, его вклад в миллисекундах не установлен. [Вход](../../api/src/chat/evidence.rs#L738) · [Учёт](../../api/src/chat/evidence.rs#L793) · [Декодер](../../api/src/chat/tools/sources/packet.rs#L42)
- **Навигация по большой таблице и точный адрес.** При выдаче следующей страницы совпадений для явного адреса обработчик пропускает весь лист в этой ветви. Так же поступает с адресами, встретившимися у нескольких владельцев. Это предохраняет от угадывания книги, но причина пропуска адресного отбора не возвращается из функции вызывающему коду. [Обработка неполного списка](../../api/src/chat/tools/sources/retrieval/addressed_rows.rs#L39)
- **Совместимость при подключении папки.** В нативном Windows-режиме запрос к `/api/rag/index-external` без `background=true` уходит к upstream. Если его нет, транспорт возвращает 501. Python-модель запроса по умолчанию использует false. Текущий интерфейс и нативный MCP явно передают true, поэтому для них этот дефект не установлен. [Ветка API](../../api/src/intake.rs#L126) · [Транспорт](../../api/src/transport.rs#L125) · [Клиент](../../desktop/light/frontend/src/components/DataLibrary.svelte#L61)

## Что осталось от Python

- Git содержит **731 файл Python и 174 283 строки**. Карта импортов относит 417 модулей к достижимым из пяти исторических точек входа, 5 к обслуживанию runtime, 286 к тестам и инструментам, 23 к кандидатам без пути от этих корней. Для Windows число 417 нельзя использовать как число запущенных модулей. Desktop передаёт `--native-only`; API и штатный процесс обработки документов здесь нативные. Отдельный Python обязателен при запуске Windows-пакета для среды навыков. [Метод подсчёта](../../tools/code_runtime_map.py#L20) · [Запуск](../../desktop/light/src-tauri/src/launcher.rs#L78) · [Проверка среды](../../runtime/src/config.rs#L185)
- **Среда навыков наследует зависимости всего приложения.** Повтор штатного `uv export --frozen --extra mcp --no-dev --no-emit-project --no-emit-package nicegui` в офлайн-режиме дал 193 строки зафиксированных зависимостей с учётом платформенных условий. В списке присутствуют FastAPI, Uvicorn, LlamaIndex, qdrant-client, google-adk, qwen-agent и soundfile. Это список экспорта, число реально установленных дистрибутивов на Windows может отличаться. Из той же среды сборщик забирает PDFium DLL для нативного чтения. Для сокращения пакета нужен отдельный список зависимостей поддерживаемых навыков и явный источник PDFium. Удаление файлов старого чат-сервера само по себе состав пакета не исправит. [Экспорт и сборка](../../tools/build_light_package.py#L214) · [Зависимости проекта](../../pyproject.toml#L8)
- **Python остаётся внешней точкой совместимости и разработки.** macOS Preview вызывает старый `stage_code` и копирует Python-деревья. `make verify` извлекает OpenAPI через `proxy.app.create_app()`. Поэтому отсутствие LlamaIndex в окружении разработки может остановить проверку контракта даже после успешной нативной сборки. Проверка маршрутов самого Rust-сервера должна быть отдельной. [macOS](../../tools/install_light_macos.py#L65) · [Python-база контракта](../../tools/native_api_contract.py#L19)
- **Показатель в самодиагностике неоднозначен.** `les-runtime --contract` всегда печатает `python_core_remaining=true`. Он не различает рабочий Windows-режим, совместимый Python-host и отдельный Python для навыков. [Контракт запуска](../../runtime/src/main.rs#L184)

23 кандидата карты занимают 4724 строки. Для трёх дополнительно проверены имена модулей и публичных функций по исходникам. В репозитории найдены определения без внешних вызовов этих функций.

| Кандидат | Что делает | Что проверить перед удалением |
|---|---|---|
| `proxy/services/parent_card_hydration_service.py` | Старая Python-реализация раскрытия родительских фрагментов | Динамические вызовы внешней интеграции и macOS Preview |
| `proxy/services/document_outline_service.py` | Распознавание запроса оглавления, поиск и форматирование разделов | Старый Python-чат и сторонние импорты |

Есть группы кандидатов, которые импортируют друг друга. Например, `agent_router_service` вызывает `les_md_chat_service`, `preset_chat_service` и `glossary_chat_service`. Проверять и удалять их следует по точке входа группы. [Инвентарь](../CODE_RUNTIME_MAP.md) · [Импорты группы](../../proxy/services/agent_router_service.py#L49)

По хешам всех отслеживаемых файлов найдено пять групп точных копий размером более 30 байт. Это корневая и публичная лицензия, SVG, лицензия Unicode, две схемы Tauri и две копии `CODE_REVIEW.md`. У лицензий, схем и публичного логотипа есть причины поставки. Для обзора кода можно оставить один редактируемый оригинал и проверять или генерировать публичную копию, если она нужна. Локальный `core/target` занимал около 5,16 ГиБ, `.test-tmp` около 10 МиБ и содержал в том числе доказательства прогонов. Массовая очистка дала бы мало для качества RAG.

## Как соотносится с предыдущим аудитом

Передача фактического `q` в `controlled_query` прослеживается. Для штатного overview код теперь явно возвращает `context_fallback`. Сохраняются несколько ограничителей объёма, приблизительный расчёт токенов и необязательный статус прочитанного в части финальных окон. Холодное чтение Word в этом аудите повторно не измерялось. По старой претензии к разнообразию найдено конкретное расхождение профиля и потребителя в текущем коде. Причина единственного HTTP 503 из прошлого прогона неизвестна. Запись успешного повтора не позволяет восстановить ошибку первой попытки.

## Очерёдность

1. Восстановить доступ из обычного чата к точной строке большой книги. Принять на двух версиях одной книги по обе стороны порога и на факте из конца таблицы.
2. Сохранять исходные строки и координаты при неопределённом заголовке. Принять на поздней шапке и текстовой строке, которая раньше побеждала заголовок.
3. Закрепить адрес фрагмента между раундами, отделить просмотренные ссылки от выбранных цитат. Взять тот же фактический запрос Qwen и отдельный вопрос с действительно отсутствующим значением.
4. Перенести фильтрацию большого документа до полной выгрузки. Измерить число считанных точек и байтов отдельно для первой и следующей порций.
5. Отдельно сократить Python-пакет навыков и проверить кандидатов на удаление на поддерживаемых платформах.

Результаты 909 дают масштаб только для одного вопроса по трём оригиналам. В успешном повторе дошли и были использованы 3 из 3 фактов, 2 из 5 выбранных фрагментов были лишними. Для общего корпуса доля потерь и эффект предложенных исправлений пока неизвестны.
