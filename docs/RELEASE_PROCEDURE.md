# Выпуск LES RAG для Windows

1. Зафиксировать исходники и версию `config/version.json`; выполнить `make verify`,
   `make test`, `make test-mail` и сборку desktop с locked-зависимостями.
2. Проверить публичный состав, отсутствие личных данных и совместимость лицензий.
   Сохранить лицензии и уведомления зависимостей в поставке. Пользователь выбирает
   лицензию проекта; сборщик не меняет её автоматически.
3. Собрать полный и сетевой установщики, манифест обновления и SHA-256. Проверить
   размер и хеш полного EXE; не заменять бинарные файлы после приёмки.
4. Выполнить installed user journey именно этого EXE: сохранность состояния,
   запуск, модель, документы, источник/оригинал, память, папки, OCR, поток и CLI.
   Исходные пользовательские папки доступны только для чтения.
5. Пройти интерфейс, возврат и клавиатуру; отдельно записать границы проверки
   WCAG, чистой Windows и реальной почты. Автотесты не заменяют ручную приёмку.
6. Создать release draft в `proovcme/LES`, приложить проверенные байты и отчёт.
   Публикация выполняется по прямой команде владельца. Если обязательная проверка
   не пройдена, не маркировать её выполненной и не объявлять stable готовым.
7. Проверить загрузку опубликованных assets и SHA-256 через CLI/загрузчик;
   проверить сохранность состояния при обновлении. Повреждённый пакет не запускается.

Обновление сохраняет baseline → candidate → rollback. Откат возвращает приложение,
но не должен стирать документы или пользовательское состояние. Публичные материалы
содержат ограничения и понятный бэклог; исторические личные отчёты не публикуются.
